# E5-M1 — CSS Grid core layout design note

Scope: add **CSS Grid** as a third parallel layout mode (alongside block/inline
and flex). `display:grid` (+ `inline-grid`) makes a grid container; its in-flow
children are placed into a 2D track grid built from explicit
`grid-template-columns`/`grid-template-rows` (with `px`/`%`/`fr`/`auto`/
`repeat(n, …)`), `gap`/`row-gap`/`column-gap`, line-based item placement
(`grid-column`/`grid-row` as `N`, `N / M`, `span N`), and row-major
auto-placement of unplaced items (adding implicit rows). Touches
`starfish-style` (new `Display` variants + grid properties) and `starfish-layout`
(a new `layout_grid` path). **Paint needs no changes** (grid items are ordinary
boxes with absolute coords).

Guiding rule (project CLAUDE.md "Simplicity First"): the **minimum correct**
grid for the common cases. Alignment, named areas → **E5-M2**. We defer
`minmax()`/`min-content`/`max-content`/`fit-content()` (pragmatic `auto`),
subgrid, `grid-auto-flow: column`/`dense`, `auto-fill`/`auto-fit`, masonry,
baseline. Deviations called out in §8.

This note is pinned to the **real** current APIs (E2-M1..M5 + flex E2-M3 landed).
Verified shapes the design relies on:

- `starfish-style`: `ComputedStyle` is a plain public-field struct built by
  `ComputedStyle::initial()` and mutated by `apply_declaration(style, decl, ctx)`
  (a big `match decl.name.as_str()` in `properties.rs`). `Length::{Px(f32),
  Percent(f32), Auto}`. `Display::{Block, Inline, InlineBlock, Flex, InlineFlex,
  None}`. `inherit_from` copies only the inherited set. `row_gap`/`column_gap:
  Length` **already exist** (flex M3) and are reused. Types re-exported from
  `lib.rs`.
- `starfish-css`: `Component::{Keyword(String), Number(f32), Dimension{value:
  f32, unit: String}, Color, Function{name: String, raw_args: String}, Comma,
  Str, Raw, …}`. A value's whitespace-separated tokens become **separate**
  components, so `100px 1fr auto` → `[Dimension{100,"px"}, Dimension{1,"fr"},
  Keyword("auto")]`. `1fr` tokenizes as `Dimension{value:1.0, unit:"fr"}` (the
  tokenizer lowercases any ident unit, no special casing). `repeat(3, 1fr)`
  arrives as `Component::Function{name:"repeat", raw_args:"3, 1fr"}` (verbatim
  inner text). `50%` → `Dimension{value:50.0, unit:"%"}`. A `/` between values
  arrives as `Component::Raw("/")` (same as `border-radius` already relies on).
- `starfish-layout`: `BoxKind::{BlockContainer, InlineBox, InlineBlock,
  AnonymousBlock, TextRun, LineBox, Marker, Image}`. `LayoutBox { kind, style,
  text, dimensions: Dimensions, children }`. `Dimensions { content: Rect,
  padding, border, margin: EdgeSizes }` with `padding_box()/border_box()/
  margin_box()`. `layout_block(b, containing, styled, doc, m, images, floats)`
  does width→position→**dispatch**→height; it **already** dispatches to
  `flex::layout_flex` when `display` is `Flex|InlineFlex` (block.rs lines 42-48).
  `resolve(len, cb_width) -> Option<f32>` / `resolve_or_zero` in block.rs.
  `translate_box(b, dx, dy)` (inline.rs, `pub(crate)`) shifts a subtree.
  `style_of(styled, b) -> ComputedStyle`, `is_normal_flow(&style)`,
  `is_out_of_flow(&style)` in boxtree.rs. `flexify_children(children, elem)` is
  the model to mirror for grid items. `mod` list in lib.rs: `block, boxtree,
  dimensions, flex, float, inline, measure` — add `grid`.
- `starfish-paint`: `role()` (display.rs) reclassifies only
  `BlockContainer|InlineBlock|InlineBox`; a block-level grid container is a
  `BlockContainer`, inline-grid is an `InlineBlock` — both paint in the in-flow
  pass; their items are ordinary boxes. **No paint change.**

The flex module (`crates/layout/src/flex.rs`, `docs/design/E2-M3.md`) is the
structural template: a new layout function dispatched from `layout_block`,
sizing items via `layout_block`, positioning via `translate_box`, returning the
container's content height. Grid mirrors this exactly.

### 1.2 New value types (`computed.rs`)

```rust
/// One explicit track size in a `grid-template-columns`/`-rows` list.
/// `minmax()`/`fit-content()`/`min-content`/`max-content` deferred (E5 non-goal).
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum TrackSize {
    /// Fixed length, e.g. `100px`. (`em`/`rem` already folded to px at compute.)
    Px(f32),
    /// `<percentage>` of the grid container's content size on that axis.
    Percent(f32),
    /// Flexible `<flex>` track, e.g. `1fr`. Distributes leftover free space.
    Fr(f32),
    /// `auto` — sized to the max content size of items in the track (§3).
    Auto,
}

/// One end (start or end) of a grid item's placement on one axis.
/// `grid-column`/`grid-row` and their `-start`/`-end` longhands resolve to a
/// `{ start, end }` pair of these. Named-line/`<custom-ident>` deferred (M2).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum GridPlacement {
    /// `auto` — line chosen by placement/auto-flow (§4).
    Auto,
    /// An explicit 1-based line number. Negative counts from the end line
    /// (`-1` = last line). `0` is invalid → normalized to `Auto` at parse time.
    Line(i32),
    /// `span N` — spans N tracks from the opposite, resolved edge (N ≥ 1).
    Span(u32),
}

/// A resolved placement for one axis: the `start` and `end` lines.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct GridLine {
    pub start: GridPlacement,
    pub end: GridPlacement,
}

impl GridLine {
    pub const AUTO: GridLine = GridLine {
        start: GridPlacement::Auto,
        end: GridPlacement::Auto,
    };
}
```

(`row-gap`/`column-gap`/`gap` arms already exist from flex M3 and are reused.)

**Track list parsing.** A `grid-template-columns`/`-rows` value is a flat list of
track components. We walk the components; a `repeat(n, <tracklist>)` function is
expanded inline. `auto-fill`/`auto-fit` inside `repeat()` are **deferred**: a
`repeat(auto-fill, …)` whose first arg is not an integer is ignored (the whole
declaration is dropped → `None`, leaving the initial empty list). `none` → empty
list.

```rust
/// Parse a `grid-template-columns`/`-rows` track list. `None` (declaration
/// ignored) on an empty/`none`/unsupported (`auto-fill`) value.
fn track_list_of(comps: &[Component], em_basis: f32, rem: f32) -> Option<Vec<TrackSize>> {
    // `none` → empty list (no explicit tracks).
    if let [Component::Keyword(k)] = comps {
        if k.eq_ignore_ascii_case("none") {
            return Some(Vec::new());
        }
    }
    let mut out: Vec<TrackSize> = Vec::new();
    for c in comps {
        match c {
            Component::Function { name, raw_args } if name.eq_ignore_ascii_case("repeat") => {
                expand_repeat(raw_args, em_basis, rem, &mut out)?;
            }
            _ => {
                let t = track_size_of(c, em_basis, rem)?; // unknown token → whole list fails
                out.push(t);
            }
        }
    }
    if out.is_empty() { None } else { Some(out) }
}

/// One track component → `TrackSize`. Recognizes px/em/rem (→Px), %, fr, auto.
fn track_size_of(c: &Component, em_basis: f32, rem: f32) -> Option<TrackSize> {
    match c {
        Component::Dimension { value, unit } => match unit.as_str() {
            "px" => Some(TrackSize::Px(*value)),
            "em" => Some(TrackSize::Px(*value * em_basis)),
            "rem" => Some(TrackSize::Px(*value * rem)),
            "%" => Some(TrackSize::Percent(*value)),
            "fr" => Some(TrackSize::Fr(value.max(0.0))),
            _ => None,
        },
        // `0` (a bare Number) is a valid `0px` track.
        Component::Number(n) if *n == 0.0 => Some(TrackSize::Px(0.0)),
        Component::Keyword(k) if k.eq_ignore_ascii_case("auto") => Some(TrackSize::Auto),
        _ => None,
    }
}

/// Expand `repeat(<int>, <tracklist>)`. `raw_args` is the verbatim inner text,
/// e.g. `"3, 1fr"` or `"2, 100px 1fr"`. Re-parse it via the CSS tokenizer/parser
/// path is overkill; we split on the FIRST top-level comma (count, then the rest
/// as a sub-track-list) and re-tokenize the sub-list. `auto-fill`/`auto-fit`
/// count → unsupported → return None (drop the declaration). (§8)
fn expand_repeat(raw_args: &str, em_basis: f32, rem: f32, out: &mut Vec<TrackSize>) -> Option<()> {
    let (count_str, rest) = raw_args.split_once(',')?;
    let n: usize = count_str.trim().parse().ok()?; // non-integer (auto-fill) → None
    if n == 0 || n > 1000 { return None; }         // guard absurd counts
    // Re-tokenize the sub-track-list `rest` into components and parse them.
    let sub = parse_components(rest); // see note below
    let mut one: Vec<TrackSize> = Vec::new();
    for c in &sub {
        one.push(track_size_of(c, em_basis, rem)?);
    }
    if one.is_empty() { return None; }
    for _ in 0..n {
        out.extend(one.iter().copied());
    }
    Some(())
}
```

> **`parse_components(rest)` note.** `repeat()`'s inner track list arrives as raw
> text, not pre-tokenized components. The cleanest implementation re-runs the CSS
> value tokenizer on `rest`. `starfish-css` does not currently expose a
> "components from a value string" helper. **Impl choice (pick one, note in PR):**
> (a) add a small `pub fn parse_value_components(s: &str) -> Vec<Component>` to
> `starfish-css` that runs the existing value-classification path on a synthetic
> `x:<s>` declaration and returns the components (a few lines, reuses
> `parse_stylesheet`); or (b) a tiny local splitter in `properties.rs` that splits
> `rest` on ASCII whitespace and maps each token (`100px`, `1fr`, `auto`, `50%`)
> to a `TrackSize` directly without going through `Component`. Option (b) is
> simplest and self-contained (no css API change) and is recommended for M1 since
> the repeated sub-list is always simple track keywords/dimensions. The signature
> above is written against (a); for (b), fold `track_size_of` into a
> `str → TrackSize` parser. Either is acceptable; **(b) preferred** (Simplicity
> First — no cross-crate API addition).

**Placement parsing.** `grid-column`/`grid-row` accept `<start> [/ <end>]`; each
side is `auto`, an integer line, or `span <int>`. The `/` arrives as
`Component::Raw("/")`.

```rust
/// `grid-column`/`grid-row` shorthand → a `{start, end}` pair. Splits the
/// component list on the `/` Raw token; each side parsed as a placement. A
/// missing end side → `Auto` (CSS: omitted end = auto, unless start was a custom
/// ident — not supported in M1). Returns None if neither side parses.
fn grid_line_shorthand(comps: &[Component]) -> Option<GridLine> {
    let mut sides = comps.split(|c| matches!(c, Component::Raw(s) if s == "/"));
    let start = placement_of(sides.next().unwrap_or(&[]));
    let end = placement_of(sides.next().unwrap_or(&[]));
    if start == GridPlacement::Auto && end == GridPlacement::Auto && !comps.is_empty() {
        // value present but unrecognized → ignore declaration
        return None;
    }
    Some(GridLine { start, end })
}

/// One side: `auto` | `<integer>` | `span <integer>`. Defaults to `Auto`.
fn placement_of(comps: &[Component]) -> GridPlacement {
    match comps {
        [Component::Keyword(k)] if k.eq_ignore_ascii_case("auto") => GridPlacement::Auto,
        // bare line number (parser yields `Number` for an unitless integer)
        [Component::Number(n)] => {
            let i = *n as i32;
            if i == 0 { GridPlacement::Auto } else { GridPlacement::Line(i) }
        }
        // `span N`
        [Component::Keyword(k), Component::Number(n)] if k.eq_ignore_ascii_case("span") => {
            GridPlacement::Span((*n as i32).max(1) as u32)
        }
        _ => GridPlacement::Auto,
    }
}

fn set_placement_start(comps: &[Component], slot: &mut GridLine) {
    slot.start = placement_of(comps);
}
fn set_placement_end(comps: &[Component], slot: &mut GridLine) {
    slot.end = placement_of(comps);
}
```

> Note: `grid-column-start`/`-end` overwrite only their side, so the longhands
> mutate one field of the existing `GridLine` in `style`. Because they're applied
> in cascade order over the same `style`, set_placement_* read-modify-write the
> current value. The shorthand (`grid-column`) sets both sides.

Export from `lib.rs` (`pub use computed::{…}`): add `GridLine`,
`GridPlacement`, `TrackSize`.

## 2. Box generation (`boxtree.rs`)

A grid container is a **BlockContainer-like box laid out by the grid algorithm**,
mirroring flex. No new `BoxKind`.

`build_node`'s display match (currently exhaustive over the 6 `Display`
variants) gains two arms:

```rust
            Display::Block => BoxKind::BlockContainer,
            Display::Flex => BoxKind::BlockContainer,
            Display::Grid => BoxKind::BlockContainer,       // NEW: block-level grid
            Display::Inline => BoxKind::InlineBox,
            Display::InlineBlock => BoxKind::InlineBlock,
            Display::InlineFlex => BoxKind::InlineBlock,
            Display::InlineGrid => BoxKind::InlineBlock,     // NEW: atomic-inline grid
```

**Grid items.** The container's in-flow children become grid items, blockified
exactly like flex items: drop whitespace-only runs, wrap inline-level runs in an
`AnonymousBlock` so each becomes a block-level item, pass block-level children
through. The existing `flexify_children` is **identical** to what grid needs, so
extend the post-build hook:

```rust

                                | Display::Grid | Display::InlineGrid) {
                b.children = flexify_children(std::mem::take(&mut b.children), id);
            }
```

(Rename is optional; `flexify_children` is already generic "blockify in-flow
children into items". Keep the name or rename to `gridify_children`/

keeping `flexify_children` to minimize the diff, or rename to a neutral
`blockify_children` and update both call sites — impl's choice, surgical.)

**Out-of-flow children are NOT grid items.** Float/abs/fixed children are already

## 3. Track sizing algorithm (`grid.rs`, new module — `crates/layout/src/grid.rs`)

New module added to lib.rs `mod` list. Entry (§6). The container's
width/position are already resolved by `layout_block` before `layout_grid` is
called, so `content.x/y/width` are set and the container content width is
definite. The algorithm runs in three phases: **(A) resolve track lists +
container sizes → (B) place items → (C) size tracks → (D) lay out + position
items**. Placement (§4) actually runs before final track sizing because implicit
rows (added by placement) participate in row sizing; explicit-track resolution
and column sizing only need the explicit column list, which is known up front.
Concretely the entry does: resolve explicit columns; place all items (building
implicit rows); size columns; size rows; lay out + position items.

### 3.1 Data structures

```rust
/// A fully-resolved set of tracks on one axis: each track's used px size and its
/// start offset (absolute, in the container's content box, gaps already folded
/// into the offsets). `sizes.len()` == number of tracks; `offsets.len()` ==
/// `sizes.len() + 1` (offset of each line, including the trailing line).
struct Tracks {
    sizes: Vec<f32>,    // px size of each track (gaps NOT included here)
    offsets: Vec<f32>,  // px position of line i (line 0 = content start)
    gap: f32,           // gap between adjacent tracks on this axis
}

impl Tracks {
    fn count(&self) -> usize { self.sizes.len() }
    /// Sum of track sizes [start_track .. end_track) + interior gaps. Used for a
    /// cell/area extent spanning tracks `start..end` (0-based, end exclusive).
    fn span_extent(&self, start: usize, end: usize) -> f32 {
        let mut e = 0.0;
        for t in start..end { e += self.sizes[t]; }
        if end > start + 1 { e += self.gap * (end - start - 1) as f32; }
        e
    }
    /// Absolute offset (content-box-relative) of line `i`. offsets[i] already
    /// includes gaps before track i.
    fn line_offset(&self, i: usize) -> f32 { self.offsets[i] }
}
```

`offsets` are built from `sizes` + `gap` once sizing is done:
`offsets[0] = 0; offsets[i+1] = offsets[i] + sizes[i] + (i+1<count ? gap : 0)`.
The item's physical position is `content_origin + line_offset(track_start)`.

### 3.2 Resolve explicit tracks + container content sizes

- **Columns explicit list** = `self_style.grid_template_columns` (already
  expanded by parsing). **Container content width** =
  `b.dimensions.content.width` (definite, set by the block width algorithm).
- **Rows explicit list** = `self_style.grid_template_rows`. **Container content
  height** = `resolve(self_style.height, containing.content.height)` if definite
  (explicit `height`), else **indefinite** (auto — the grid's height is the sum
  of row sizes; `fr` rows then behave like `auto`, §3.4 note).
- Column/row gaps: `main`/`cross` are not relevant for grid (it's 2D).
  `column_gap` is the gap **between columns**; `row_gap` between rows:
  ```rust
  let col_gap = resolve_or_zero(self_style.column_gap, content_w);
  let row_gap = resolve_or_zero(self_style.row_gap, content_w);
  ```
  (Both resolve percentages against the container content width, matching the CSS
  rule that gap percentages resolve against the corresponding dimension; M1 uses
  width for both — a minor simplification for `row-gap: %`, noted §8.)

The **explicit grid** has `cols = grid_template_columns.len()` columns and
`rows = grid_template_rows.len()` explicit rows. If a template is empty
(`none`), the explicit count on that axis is 0; auto-placement still creates
**implicit** tracks (§3.5).

### 3.3 Column sizing (definite container width)

Columns are sized against the **definite** container content width
`W = content_w`, minus inter-column gaps `G_c = col_gap * (cols-1).max(0)`:

```
avail = W - G_c
```

Distribute `avail` across the column `TrackSize`s in one pass:

1. **Fixed (`Px`)**: size = the px value. Subtract from `avail`.
2. **Percent**: size = `pct/100 * W`. Subtract from `avail`.
3. **Auto**: size = the track's **max item content width** (§3.6). Subtract from
   `avail`. (Computed after item placement, since we must know which items fall in
   each auto column; see ordering note below.)
4. **Fr**: distribute the **remaining** `avail` (after fixed+percent+auto+gaps)
   proportionally to fr values: `size_i = remaining * (fr_i / sum_fr)`. If
   `sum_fr == 0` there are no fr tracks. Remaining is clamped ≥ 0 (overflowing
   fixed tracks → fr tracks get 0).

> **Ordering.** Auto column sizing (step 3) needs item placement (to know which
> items occupy each auto column) and an item content-size measurement. So the
> entry computes, in order: (a) explicit column **structure** (count + which are
> px/%/auto/fr) is known from the style; (b) **placement** runs (§4) using the
> column count; (c) auto column max-content is measured; (d) px/%/auto column
> sizes fixed, then fr distributes the remainder. Practically: a single
> `size_columns(explicit, W, col_gap, &placed_items, …)` pass that first lays
> out each item once at an unconstrained width to get its content width
> (`flex_base_main`-style: `layout_block` at `W`, read `content.width`), bucket
> by auto column, take the per-column max, then distribute fr.

```rust
fn size_columns(
    list: &[TrackSize],
    container_w: f32,
    gap: f32,
    items: &[PlacedItem],     // with resolved column spans
    item_min_content_w: &dyn Fn(usize) -> f32, // measured content width of item i
) -> Tracks;
```

**Auto column max-content (pragmatic).** For each auto column `c`, its size =
the max over single-column items placed in `c` of that item's measured content
width; items spanning multiple columns are **not** distributed into auto columns
for M1 (their extra width is absorbed by the columns they span; a spanning item
contributes nothing to an auto column's intrinsic size — pragmatic, noted §8). An
auto column with no single-column item → size 0. This is the pragmatic `auto` ≈
max-content approximation the roadmap permits.

### 3.4 Row sizing

Same structure on the row axis, but the container height may be **indefinite**:

- **Definite height** (explicit `height`): `H = explicit height`,
  `avail = H - row_gap*(rows-1)`. Px/Percent/Auto/Fr resolved exactly like
  columns: fr rows distribute the remainder of `H`.
- **Indefinite height** (auto): there is no free space to distribute. Px rows
  take their px size; Percent rows resolve against **0** (percentage of an
  indefinite height → treated as `auto`, §8); **Auto rows** = max item content
  height in that row (§3.6, measured by laying the item out at its already-sized
  column-span width); **Fr rows behave like Auto rows** (no definite size to
  flex against → each fr row sizes to its content). The container's resulting
  content height = sum of row sizes + row gaps (returned by `layout_grid`, §6).

> The asymmetry (columns always definite, rows possibly indefinite) mirrors block
> layout (width definite, height content-driven) and flex (row container: width
> definite, height auto). It is the expected, correct behavior.

### 3.5 Implicit tracks

- **Implicit rows**: auto-placement (§4) or an explicit placement past the last
  explicit row creates rows beyond `grid_template_rows.len()`. Each implicit row
  is **auto-sized** (`TrackSize::Auto`; M1 has no `grid-auto-rows`, so all
  implicit rows are `auto`). The row track list passed to `size_rows` is the
  explicit list **extended** with `Auto` entries up to `max_row_line - 1` tracks.
- **Implicit columns**: for **row-major** auto-flow we **clamp the column count
  to the explicit column count** — auto-placed items never create new columns
  (CSS: the auto-placement cursor wraps within the explicit columns). An item
  **explicitly** placed at a column line beyond the explicit grid (e.g.
  `grid-column: 5` with only 2 columns) would create implicit columns; for M1 we
  **clamp such explicit out-of-range column lines into the explicit grid** and
  note it (§8). So the column count is always `grid_template_columns.len()` (≥ 1;
  if the template is empty, see below).
- **Empty column template**: if `grid_template_columns` is empty, the grid has
  **one implicit column** spanning the full container width (so a grid with only
  `grid-template-rows` still lays items in a single column). `cols = max(1,
  grid_template_columns.len())`; the single implicit column is `auto` → it takes
  the full available width (one column, no fr, auto = remaining width since it's
  the only track). Practical rule: `if list.is_empty() { cols = 1; single auto
  column sized to container width }`.

### 3.6 Item content-size measurement (the `auto` approximation)

Auto track sizing and the final item layout reuse **`layout_block`** exactly like
flex:

- **Measured content width** of item `i` (for auto-column sizing): run
  `layout_block(item, cb{width=W}, …)` with a fresh `FloatContext`, read
  `content.width`. Re-pin specified margins (auto→0) like `layout_inline_block`
  so the margin box is tight. (Pragmatic max-content ≈ content extent at the
  container width — same caveat as flex §6.)
- **Measured content height** of item `i` in a row (for auto-row sizing): after
  the item's **column span width** is known, run `layout_block(item,
  cb{width = column_span_width}, …)`, read `content.height` (margin-box height
  for the row extent). This is the same two-pass pragmatic re-layout flex uses.

A grid item that is itself a grid/flex/block container recurses through
`layout_block` → grid/flex dispatch — **nested grid works for free**.

## 4. Item placement (`grid.rs`)

Resolve each item's column/row placement to concrete 0-based track ranges, build
an occupancy grid, then auto-place the rest row-major.

### 4.1 Resolved item

```rust
struct PlacedItem {
    idx: usize,           // index into container children
    col_start: usize,     // 0-based, inclusive
    col_end: usize,       // 0-based, exclusive (col_end > col_start)
    row_start: usize,
    row_end: usize,
    style: ComputedStyle,
}
```

### 4.2 Resolve one axis's lines → (start, end) tracks

CSS lines are 1-based; line `k` sits **before** track `k-1` (0-based). For an
axis with `n` explicit tracks there are `n+1` explicit lines (1..=n+1). Negative
lines count from the end: line `-1` = line `n+1` (the last line). The resolution
for one axis given `GridLine { start, end }` and the explicit track count `n`:

```
resolve_line(L: Line(k)) -> 0-based line index:
    if k > 0  => k - 1
    if k < 0  => (n + 1) + k        // -1 => n  (last line)
    (k == 0 already normalized to Auto at parse)

Cases:
  (Line a, Line b)   : s = min, e = max of the two resolved 0-based lines;
                        if s == e, e = s + 1 (a zero-width area → 1 track).
  (Line a, Span n)   : s = resolve(a);            e = s + n
  (Span n, Line b)   : e = resolve(b); s = e - n  (clamp s >= 0)
  (Line a, Auto)     : s = resolve(a);            e = s + 1   (1 track)
  (Auto,   Line b)   : e = resolve(b); s = e - 1
  (Span n, Auto) /
  (Auto, Span n)     : span n tracks, position chosen by auto-flow (definite
                        size n, indefinite position) — handled in §4.4
  (Auto,   Auto)     : fully auto — position+size chosen by auto-flow (1 track)
```

Clamp resolved track indices into `[0, n]` for the **column** axis (explicit
out-of-range column lines clamped, §3.5/§8). For the **row** axis, lines beyond
the explicit grid are allowed (they create implicit rows); `row_end` may exceed
`grid_template_rows.len()`, growing the implicit-row count.

### 4.3 Two-pass placement (CSS grid auto-placement, row-major sparse subset)

Mirrors the CSS auto-placement algorithm, restricted to the common cases:

**Pass 1 — place items with a definite position on both axes.** An item is
"definitely placed" when **both** its column and row resolve to concrete track
ranges (i.e. neither axis is fully `Auto`/`Span`-only — both have at least one
`Line`). Mark its cells occupied in the occupancy grid. The occupancy grid is a
`HashSet<(usize, usize)>` of `(row, col)` cells, or a growable `Vec<Vec<bool>>`
indexed `[row][col]` (rows grow on demand). Track `max_row_end` for implicit
rows.

**Pass 2 — auto-place the rest, row-major.** Maintain an auto-placement cursor
`(cur_row, cur_col)` starting at `(0, 0)`. For each remaining item in document
order:

- Determine the item's **column span** `cspan` and **row span** `rspan` from its
  placement (a `Span n` → n; a single `Line` fixing one axis → that axis is
  fixed, the other auto; fully auto → 1×1, or 1×cspan if `grid-column: span k`).
- **Item with a fixed column (definite column, auto row)**: keep the column
  range; scan rows downward from `cur_row` (CSS: from row 0 for sparse, but
  cursor monotonic is the common-case shortcut) for a row band where all
  `cspan` cells are free; place there; mark occupied.
- **Item with a fixed row (definite row, auto column)**: scan columns from
  `cur_col` in that row, wrapping/advancing rows, for `cspan` free cells.
- **Fully auto item**: from `(cur_row, cur_col)`, scan left-to-right; if the
  `cspan` cells starting at `cur_col` are free **and** fit within the column
  count (`cur_col + cspan <= cols`), place there; else advance `cur_col`; when
  `cur_col + cspan > cols`, wrap to `cur_row += 1, cur_col = 0` (adding an
  implicit row); skip occupied cells. After placing, advance the cursor past the
  placed item (`cur_col = col_end`; if `>= cols`, wrap).

This is **row-major sparse** (the default `grid-auto-flow: row`). `dense` is **not**
implemented (cursor only moves forward; no back-filling — §8). The occupancy grid
grows rows as needed; `implicit_rows = max(row_end over all items)`.

### 4.4 Span clamping

- `Span n` with `n > cols` on the column axis → clamp `cspan = cols` (an item
  cannot span more columns than exist for row-major; §8).
- A resolved `col_end > cols` → clamp to `cols` (overflowing explicit span).
- `Span 0` is impossible (parse forces `>= 1`).
- An item whose resolved start ≥ end after clamping → coerce to a 1-track span at
  `start.min(cols-1)`.

After placement, the **total row count** (explicit + implicit) is known →
`size_rows` (§3.4) runs over the extended row track list.

## 5. Item layout + positioning (`grid.rs`)

For each `PlacedItem`, compute its **cell/area rectangle** from the sized tracks
and lay the item out as a block into it, then translate to position. M1 default:
**stretch to fill the area** (the CSS initial `align-items`/`justify-items:
stretch`); precise align/justify is E5-M2.

```
col_off = cols_tracks.line_offset(col_start)             // content-box relative
row_off = rows_tracks.line_offset(row_start)
area_w  = cols_tracks.span_extent(col_start, col_end)    // spanned cols + interior gaps
area_h  = rows_tracks.span_extent(row_start, row_end)
abs_x   = content_x + col_off
abs_y   = content_y + row_off
```

Lay the item out as a block whose containing block is its grid area:

```rust
let cb = Dimensions {
    content: Rect { x: abs_x, y: abs_y, width: area_w, height: 0.0 },
    ..Dimensions::default()
};
let mut floats = FloatContext::default(); // each item establishes its own BFC
layout_block(item, cb, styled, doc, m, images, &mut floats);
// Stretch to the cell (M1 default = align/justify stretch):
item.dimensions.content.width = area_w
    - bpm_horizontal(&istyle, area_w);   // fill area minus the item's own h-bpm+margins
item.dimensions.content.height = (area_h
    - bpm_vertical(&istyle, area_w)).max(item.dimensions.content.height.min(area_h));
```

> **Stretch height nuance (M1).** Width stretch is unconditional (item content
> width = area width minus its horizontal border/padding/margin), matching how
> `layout_block` at `width = area_w` already fills width — so after layout we
> just pin `content.width`. For **height**, stretch sets the item's content
> height so its border-box fills `area_h`; but if the item's own content is taller
> than the cell (content overflows the area), keep the larger (overflow, like a
> too-tall block). The simplest M1 rule that the test plan asserts: **content
> height = area_h − vertical bpm/margins** (fill the cell exactly) for the common
> case where items fit; document that overflow is clamped to the cell in M1
> (alignment/overflow precision is M2). Recommended M1: pin
> `content.height = (area_h − vbpm).max(0.0)` (exact cell fill). Pick the exact-
> fill rule for deterministic tests.

Finally position via the existing helper (the item was laid out at `(abs_x,
abs_y)` content origin already, but margins shift the content origin inward, so
translate by the delta of the **margin-box** top-left to the target area
top-left, exactly as flex does):

```rust
let target_x = abs_x;  // area top-left (margin box should start here)
let target_y = abs_y;
let cur = item.dimensions.margin_box();
translate_box(item, target_x - cur.x, target_y - cur.y);
```

(For M1 stretch with the area as the CB, the margin box already starts near the
area; the translate corrects any residual from the block width algorithm's margin
handling. Re-pin specified margins auto→0 first, like flex's `layout_item`, so
the area is filled tightly.)

Out-of-flow children (skipped as non-items) are left untouched in `b.children`
and handled by the existing float/abs passes.

## 6. Entry + integration (`grid.rs` + `block.rs`)

### 6.1 Entry signature (mirrors `layout_flex`)

```rust
/// Lay out a grid container's in-flow children into a 2D track grid. The
/// container's width/position are already resolved by `layout_block`. Returns the
/// container's content-box height (sum of row sizes + row gaps, or the explicit
/// height). Items are positioned absolutely via `translate_box`.
pub(crate) fn layout_grid(
    b: &mut LayoutBox,
    containing: Dimensions,
    self_style: &ComputedStyle,
    styled: &StyledTree,
    doc: &Document,
    m: &dyn TextMeasurer,
    images: &dyn ImageSource,
) -> f32;
```

Signature matches `layout_flex` exactly (note: `flex::layout_flex` takes `doc`
and `images` in the current source — grid must too).

Body outline:

```rust
let content_x = b.dimensions.content.x;
let content_y = b.dimensions.content.y;
let content_w = b.dimensions.content.width;
let col_gap = resolve_or_zero(self_style.column_gap, content_w);
let row_gap = resolve_or_zero(self_style.row_gap, content_w);
let explicit_h = resolve(self_style.height, containing.content.height);

// take children out (so we can index styled/floats alongside), like flex
let mut children = std::mem::take(&mut b.children);

// 1. column structure: cols = max(1, grid_template_columns.len())
// 2. place items (§4) → Vec<PlacedItem> + implicit_rows count
// 3. size columns (§3.3) → Tracks (needs per-item content-width measure)
// 4. size rows (§3.4) over explicit+implicit list (needs per-item, per-row
//    content-height measure at the item's column-span width)
// 5. build offsets for both Tracks
// 6. for each PlacedItem: compute area rect, layout_block into it, stretch,
//    translate_box to area top-left (§5)

b.children = children;

// container content height
let total_rows_h = rows.sizes.iter().sum::<f32>()
    + row_gap * (rows.count().saturating_sub(1) as f32);
explicit_h.unwrap_or(total_rows_h)
```

### 6.2 Dispatch from `layout_block` (the hook)

Extend the existing flex dispatch in `block.rs` (lines 42-48) to also cover grid:

```rust
    if matches!(style.display, Display::Flex | Display::InlineFlex) {
        let h = crate::flex::layout_flex(b, containing, &style, styled, doc, m, images);
        b.dimensions.content.height = h;
    } else if matches!(style.display, Display::Grid | Display::InlineGrid) {
        let h = crate::grid::layout_grid(b, containing, &style, styled, doc, m, images);
        b.dimensions.content.height = h;
    } else {
        layout_block_children(b, &style, containing, styled, doc, m, images, floats);
    }
    calculate_block_height(b, &style); // explicit height still overrides
```

`InlineGrid` works for free: `layout_inline_block` → `layout_block` → this
dispatch picks grid. Nested grid (an item that is itself a grid) recurses through
`layout_block`'s item layout (§5) → this dispatch. **Mirrors flex exactly.**

Add `mod grid;` to `crates/layout/src/lib.rs`.

## 7. Paint (`starfish-paint`)

**No paint changes.** Grid items are ordinary `BlockContainer` / `InlineBlock` /
`AnonymousBlock` boxes with **absolute** content coordinates assigned by
`translate_box` (§5). `role()` (display.rs) reclassifies only
`BlockContainer|InlineBlock|InlineBox`: a block-level grid container is a
`BlockContainer`, inline-grid an `InlineBlock` — both paint in the in-flow pass;
their items (block-level boxes) likewise. Grid items are never out of flow
(out-of-flow children are excluded from being items, §2/§4), so no float/positioned
diversion interaction. **Confirmed: no change needed.**

## 8. Edge cases & explicit non-goals

Handled:
- `display:grid` (block-level) and `display:inline-grid` (atomic inline).
- Explicit tracks `grid-template-columns`/`-rows` with `px`/`%`/`fr`/`auto` and
  `repeat(<integer>, <tracklist>)` expansion.
- `gap`/`row-gap`/`column-gap` (reuses the flex M3 fields/parsing).
- Line-based placement `grid-column`/`grid-row` (`N`, `N / M`, `span N`) + the
  `grid-column-start/end`/`grid-row-start/end` longhands; negative line numbers
  (count from the end).
- Row-major sparse auto-placement of unplaced items, adding implicit (auto-sized)
  rows.
- Multi-track spans (`span N`, `A / B`): area = sum of spanned track sizes +
  interior gaps.
- Stretch-to-cell item sizing (M1 default).
- Nested grid / grid-in-flex / flex-in-grid via recursive `layout_block`.

Explicit **non-goals / simplifications** for M1:
- **`minmax()`/`min-content`/`max-content`/`fit-content()`** → not parsed (a
  track with these is dropped → declaration ignored); `auto` uses the pragmatic
  max-content-at-container-width approximation (same caveat as flex auto-basis).
- **Auto tracks + spanning items**: a multi-track-spanning item does **not**
  contribute to an `auto` track's intrinsic size (only single-track items do).
  Pragmatic; precise distribution deferred.
- **`auto-fill`/`auto-fit`** in `repeat()` → unsupported (non-integer count →
  declaration dropped).
- **`grid-auto-flow: column` / `dense`** → row-major sparse only (cursor moves
  forward, no back-filling).
- **`grid-auto-columns`/`grid-auto-rows`** → implicit tracks are always `auto`.
- **Named areas / `grid-template-areas` / `grid-area` / named lines** → E5-M2.
- **Alignment**: `justify-items`/`align-items`/`*-self` (start/end/center) and
  `justify-content`/`align-content` track distribution → E5-M2. M1 = stretch
  default; items overflowing their cell are clamped to the cell (overflow
  precision is M2).
- **Implicit columns from explicit out-of-range column lines** → clamped into the
  explicit grid (row-major never grows columns).
- **`row-gap: %`** resolves against the container **width** (not height) in M1 —
  a minor simplification (CSS: row-gap % resolves against the block size).
- **Subgrid, masonry, baseline** → out of scope.
- **Out-of-flow children of a grid container** (float/abs/fixed) are **not** grid
  items — they keep the existing float/abs behavior (the grid algorithm skips
  them). A loosely-supported uncommon combination.
- **Empty grid** (no children, or all out-of-flow) → 0 rows; content height = 0
  (or explicit height). No panic.
- **Percent rows against indefinite height** → treated as `auto` (resolve against
  0; auto-sized).

- `grid-template-columns: repeat(auto-fill, 100px)` → declaration ignored →
  initial `[]` (deferred).
- `grid-template-rows: none` → `[]`.
- `grid-column: 1 / 3` → `GridLine{start:Line(1), end:Line(3)}`.
- `grid-column: span 2` → `{start:Span(2), end:Auto}` (or per the shorthand
  split: start=Span(2), end=Auto).
- `grid-row: 2` → `{start:Line(2), end:Auto}`.
- `grid-column: -1` → `{start:Line(-1), end:Auto}`.
- `grid-column-start: 2; grid-column-end: 4` longhands → `{Line(2), Line(4)}`.
- none of the grid props inherit: a child of a `display:grid` parent computes
  `grid_template_columns == []`, `grid_column == AUTO`, `display != Grid`.

### layout — track sizing
- **Fixed 2×2.** `grid-template-columns: 100px 100px; grid-template-rows: 50px
  50px; gap:0`, 4 items → cells at (x,y): item0 (0,0), item1 (100,0), item2
  (0,50), item3 (100,50); each 100×50. (Auto-placement row-major.)
- **`1fr 1fr 1fr` thirds.** Container width 300, `gap:0` → three columns 100 each;
  items at x = 0, 100, 200. With `column-gap:30` → `(300-60)/3 = 80` each; x = 0,
  110, 220.
- **`repeat(3, 1fr)`** identical to `1fr 1fr 1fr` (proves expansion).
- **`100px 1fr`.** Container 300, `gap:0` → col0 100, col1 200; item in col1 at
  x=100 width 200.
- **auto column.** `grid-template-columns: auto 1fr`, container 300, an item in
  col0 with content width 60 (e.g. text "abcdef" at per=10) → col0 = 60, col1 =
  240; second item at x=60 width 240.

### layout — placement
- **explicit span two columns.** `grid-template-columns: 100px 100px 100px`, item
  `grid-column: 1 / 3` → x=0, width = 100+100+gap. With `column-gap:10`: width =
  210 (two tracks + one interior gap).
- **`grid-row: 2`** places an item in the second row → y = row0 height + row_gap.
- **`span 2` rows.** item `grid-row: span 2` in a `grid-template-rows: 40px 40px`
  grid → height = 80 + interior row_gap.
- **auto-placement fills row-major.** `grid-template-columns: repeat(2, 100px)`,
  3 items, none placed → item0 (0,0), item1 (100,0), item2 (0, row1_y) — wraps to
  a new (implicit) row.
- **mixed explicit + auto.** item A `grid-column: 2; grid-row: 1` (definite),
  items B,C auto → B fills (row0,col0) skipping A's occupied (row0,col1), C wraps.

### layout — gaps + height
- **gap adds spacing.** `grid-template-columns: 100px 100px; column-gap: 20;
  row-gap: 10; grid-template-rows: 50px 50px`, 4 items → item1 x=120, item2 y=60,
  item3 (120,60).
- **container auto height.** `grid-template-rows: 30px 30px; gap:0`, no explicit
  container height → `layout_grid` returns 60; with `row-gap:10` → 70.
- **implicit row height (auto).** `grid-template-columns: 100px` (1 col), 2 items
  each content height 25 → implicit rows auto-sized 25 each; container height 50.

### layout — nested
- **grid item is itself a grid.** Outer `grid-template-columns: 200px` with one
  item that is `display:grid; grid-template-columns: 1fr 1fr` containing two items
