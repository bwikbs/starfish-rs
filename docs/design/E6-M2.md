# E6-M2 — `@font-face` web fonts (design note)

Scope: capture `@font-face` rules in the CSS parser (currently *all* at-rules
are dropped), load the declared font file through the existing `ResourceLoader`
(file / http / data — all already supported), and register the loaded face into
the paint `FontDb` so that when an element's `font-family` matches the
author-declared family name, the loaded face is used — with the right
weight/style picked when several `@font-face` rules share a family.

Crates touched: `css` (capture `@font-face` + its descriptors), `paint`
(`FontDb` @font-face registry + load step + `resolve` order), wiring in
`render_document`. **No** `net` change — the loader already returns
`Resource { bytes }` for file/http/data URLs. **No** `layout` change —
`FontQuery`/`TextMeasurer` are unchanged; the registry hooks inside
`FontDb::resolve` which both layout (measure) and paint already call with an
identical `FontQuery`, so measure == paint is preserved automatically.

Guiding rule (Simplicity First): **add a small registry checked before the
fontdb query**, parse `@font-face` minimally as a declaration block, load via
the loader, parse once with fontdue. Defer WOFF/WOFF2, `unicode-range`,
`font-display`, `local()`-beyond-system, `font` shorthand `@font-face`.

---

## 0. The real APIs this builds on (verified)

- **CSS parser** (`crates/css/src/parser.rs`): at-rules go through
  `skip_at_rule()` (called from `parse_rule_list`). A `{…}` declaration block is
  already parsed by `parse_declaration_block()` → `Vec<Declaration>` (the same
  routine qualified rules use). `url(...)` and `format(...)` tokenize as
  `Token::Function(name)` and are classified by `classify_components` into
  `Component::Function { name, raw_args }` (name lowercased, `raw_args` the
  source between the parens, trimmed). A quoted family name is `Component::Str`,
  an unquoted one is `Component::Keyword`, commas are `Component::Comma`.
- **CSS model** (`crates/css/src/model.rs`): `Stylesheet { rules: Vec<Rule> }`,
  `Declaration { name, value: Value, important }`, `Value { raw, components }`.
- **FontDb** (`crates/paint/src/font.rs`): `fontdb::Database` + a
  `RefCell<HashMap<ID, Rc<FontdueFont>>>` cache + `default_id`. Resolution is
  `resolve(&FontQuery) -> Rc<FontdueFont>` = `face_by_id(resolve_id(q))`;
  `resolve_id` builds the borrowed `Family` list and calls `db.query`.
  `face_by_id` parses bytes via `db.with_face_data(id, |bytes, index| …)` and
  caches by `ID`.
- **FontQuery** (`crates/layout`): `{ family: &[String], style: FontStyle,
  weight: FontWeight, size: f32 }`. `FontWeight(pub u16)` (style crate),
  `FontStyle { Normal, Italic, Oblique }`.
- **ResourceLoader** (`crates/net`): `fetch(&Url) -> Result<Resource, LoadError>`,
  `Resource { bytes, content_type, final_url }`. `base.join(href) -> Result<Url>`
  resolves relative refs. `DataLoader`/`RouterLoader` already decode `data:` URLs
  (base64 ttf works); `LocalLoader` reads `file://`.
- **fontdb registration caveat (decision-driving):** `Database::load_font_data`
  indexes a face by the **file's own internal family names**, not by any author
  name. An `@font-face { font-family: "MyFont" }` name almost never equals the
  file's internal name, and even when it does the author name must *win* over a
  same-named system font. So we do **not** push @font-face data into the shared
  `fontdb::Database`; we keep a **separate registry** in `FontDb`, checked
  *before* the fontdb query (§3). This also keeps the vendored/system DB and its
  matcher untouched.

## 1. Capturing `@font-face` in the CSS parser

### 1.1 Model additions (`crates/css/src/model.rs`)

```rust
/// A captured `@font-face` rule. Only the descriptors we use are kept; unknown
/// descriptors (unicode-range, font-display, …) are ignored.
#[derive(Debug)]
pub struct FontFaceRule {
    /// The author-chosen family name (the `font-family` descriptor), unquoted.
    pub family: String,
    /// The `src` list in source order; the loader tries them front-to-back.
    pub src: Vec<FontSrc>,
    /// `font-weight` descriptor → numeric (single value; a range collapses to
    /// its low end). `None` ⇒ default 400 at match time.
    pub weight: Option<u16>,
    /// `font-style` descriptor. `None` ⇒ default Normal at match time.
    pub style: Option<FontFaceStyle>,
}

/// One `src` entry.
#[derive(Debug)]
pub enum FontSrc {
    /// `url("…") format("…")` — the URL string + optional format hint
    /// (lowercased, e.g. "truetype", "woff2"); used to skip unsupported formats.
    Url { url: String, format: Option<String> },
    /// `local("…")` — a system face name to look up in the system DB.
    Local(String),
}

/// `font-style` as it can appear in an `@font-face` descriptor.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FontFaceStyle { Normal, Italic, Oblique }
```

`Stylesheet` gains a parallel list (additive — existing `rules` semantics and
all current tests are untouched):

```rust
pub struct Stylesheet {
    pub rules: Vec<Rule>,
    pub font_faces: Vec<FontFaceRule>,   // NEW
}
```

> Decision: a separate `font_faces` field, **not** an enum over rule kinds.
> `style_tree` already takes `&[Stylesheet]` and iterates `.rules`; an enum
> would force every cascade call site to filter. A new `Vec` is the minimal,
> surgical change and keeps qualified-rule code byte-identical.

Re-export `FontFaceRule`, `FontSrc`, `FontFaceStyle` from `css/src/lib.rs`.

### 1.2 Parser change (`crates/css/src/parser.rs`)

The top-level loop currently calls `self.skip_at_rule()` for any
`Token::AtKeyword`. Change *only* that arm to special-case `@font-face`,
leaving every other at-rule on the existing skip path:

```rust
Token::AtKeyword(name) => {
    if name.eq_ignore_ascii_case("font-face") {
        if let Some(ff) = self.parse_font_face() {
            font_faces.push(ff);
        }
    } else {
        self.skip_at_rule();      // @media / @import / … unchanged
    }
}
```

`parse_rule_list` threads a second out-param (or `parse` owns both `Vec`s and
passes `&mut` to the loop). `parse` returns
`Stylesheet { rules, font_faces }`.

`parse_font_face` (new, ~25 lines): consume the `@font-face` keyword, skip
whitespace, and — if the next token is `{` — reuse the existing
`parse_declaration_block()` to get `Vec<Declaration>`; otherwise (no block,
malformed) fall back to `skip_at_rule()` and return `None`. Then fold the
declarations into a `FontFaceRule`:

```rust
fn parse_font_face(&mut self) -> Option<FontFaceRule> {
    self.bump();                 // @font-face
    self.skip_whitespace();
    if !matches!(self.peek(), Token::LeftBrace) {
        // statement form / malformed: behave like a skipped at-rule.
        // (cursor not on `{`; consume to `;`/`}`/EOF)
        return { self.recover_at_rule_tail(); None };
    }
    let decls = self.parse_declaration_block();   // leaves cursor past `}`
    fold_font_face(&decls)                         // None if no family/src
}
```

`fold_font_face` walks the `Declaration`s by lowercased `name`:

- `"font-family"`: take the family name from `value.components` — the first
  `Component::Str(s)` or `Component::Keyword(s)` (an unquoted multi-word name
  joins consecutive keywords with single spaces; simplest: use `value.raw`
  with surrounding quotes stripped). Required — no family ⇒ drop the rule.
- `"src"`: split `value.components` on `Component::Comma` into entries; per
  entry classify:
  - a `Component::Function { name: "url", raw_args }` → strip optional quotes
    from `raw_args` → `FontSrc::Url`. A following
    `Component::Function { name: "format", raw_args }` in the same entry sets
    `format` (lowercased, quotes stripped).
  - a `Component::Function { name: "local", raw_args }` → `FontSrc::Local`.
  - anything else in the entry → ignored.
  Required — empty `src` ⇒ drop the rule.
- `"font-weight"`: first `Component::Number(n)` → `n as u16`; or a keyword
  `bold` → 700, `normal` → 400. A two-number range (`400 700`) → take the first.
- `"font-style"`: keyword `italic`/`oblique`/`normal` → `FontFaceStyle::*`.
- any other descriptor (`unicode-range`, `font-display`, …) → ignored.

Return `None` (drop) if family or src is missing — a malformed `@font-face`
must not register anything (it just falls back to normal matching).

A small `recover_at_rule_tail()` helper (consume to top-level `;`/`}`/EOF) keeps
the malformed-statement path from desyncing the stream; it mirrors the loop
inside `skip_at_rule` after the keyword.

> The existing at-rule tests (`at_rule_block_skipped`, `at_rule_statement_skipped`,
> `smoke_small_stylesheet` with `@media`/`@import`) keep passing — only
> `@font-face` diverges from the skip path.

## 2. Loading `@font-face` fonts (in `render_document`)

A new free function in `crates/paint/src/lib.rs`, run **after**
`collect_author_sheets` and **after** building `FontDb`, **before** `layout`:

```rust
/// For each captured @font-face, pick the best src, fetch it via `loader`
/// (resolving relative URLs against `base`), parse with fontdue, and register
/// it into `fonts`' @font-face registry. Failures are skipped (no panic).
fn load_font_faces(
    sheets: &[Stylesheet],
    base: &Url,
    loader: &dyn ResourceLoader,
    fonts: &FontDb,
) {
    for sheet in sheets {
        for ff in &sheet.font_faces {
            for src in &ff.src {            // try in source order until one loads
                let bytes = match src {
                    FontSrc::Url { url, format } => {
                        if !format_supported(format.as_deref()) { continue; }   // skip woff2 etc.
                        let Ok(u) = base.join(url) else { continue; };
                        let Ok(res) = loader.fetch(&u) else { continue; };
                        res.bytes
                    }
                    FontSrc::Local(name) => {
                        // resolve via the system/vendored DB; on miss, next src.
                        match fonts.system_face_bytes(name) { Some(b) => b, None => continue }
                    }
                };
                if fonts.register_face(&ff.family, ff.weight, ff.style, bytes) {
                    break;                  // registered this family/weight/style → done
                }
                // parse failed → fall through to the next src.
            }
        }
    }
}
```

`format_supported`: `None` (no hint) ⇒ try it (let fontdue decide);
`Some("truetype" | "opentype" | "truetype-collection" | "opentype-collection")`
⇒ yes; `Some("woff" | "woff2" | "embedded-opentype" | "svg")` ⇒ no (deferred).
A `.woff2` URL with **no** format hint is attempted and fontdue parsing fails →
skipped gracefully (same end state). We also sniff nothing extra — fontdue's
`from_bytes` returning `Err` is the catch-all.

`register_face` (on `FontDb`, §3.2) parses the bytes with fontdue and, on
success, inserts into the registry and returns `true`; on a parse error returns
`false` (so the loader tries the next `src`).

`system_face_bytes(name)` queries the existing `db` for `Family::Name(name)`
(weight/style left to the registering rule's descriptors) and returns the raw
face bytes via `with_face_data` — reusing the matcher already in `FontDb`. On
miss (no such system face, or `vendored_only()`), returns `None` → the loader
moves to the next `src`. This is the whole of `local()` support for M2: a hook
into the system DB, no extra machinery.

## 3. The `FontDb` `@font-face` registry + resolve order

### 3.1 Registry type

Add to `FontDb`:

```rust
/// Author @font-face faces, keyed by (normalized family, style, weight).
/// Checked in `resolve` BEFORE the fontdb query, so an @font-face family
/// overrides any system/generic of the same name.
font_faces: RefCell<Vec<FaceEntry>>,

struct FaceEntry {
    family: String,        // normalized: lowercased, trimmed
    style: FontStyle,      // descriptor; default Normal
    weight: u16,           // descriptor; default 400
    font: Rc<FontdueFont>, // parsed once at registration
}
```

`Vec` (not `HashMap`) because the count is tiny (a handful of faces) and
weight/style matching is a nearest-search, not an exact-key lookup (§4).
`RefCell` matches the existing single-threaded interior-mutability pattern;
registration happens once up front, lookups are read-only.

### 3.2 Registration

```rust
impl FontDb {
    /// Parse `bytes` with fontdue and register under the author family/weight/
    /// style. Returns false (and registers nothing) if the bytes don't parse.
    pub fn register_face(
        &self, family: &str, weight: Option<u16>, style: Option<FontFaceStyle>, bytes: Vec<u8>,
    ) -> bool {
        let Ok(font) = FontdueFont::from_bytes(
            bytes, FontSettings { collection_index: 0, ..Default::default() }
        ) else { return false };
        self.font_faces.borrow_mut().push(FaceEntry {
            family: family.trim().to_ascii_lowercase(),
            style: match style {
                Some(FontFaceStyle::Italic)  => FontStyle::Italic,
                Some(FontFaceStyle::Oblique) => FontStyle::Oblique,
                _ => FontStyle::Normal,
            },
            weight: weight.unwrap_or(400),
            font: Rc::new(font),
        });
        true
    }
}
```

`collection_index: 0` — @font-face files are single faces (TTC selection by
@font-face is out of scope).

### 3.3 New resolve order

`resolve` (and the test-only `resolve_id` path) gains a registry pre-check.
Restructure so `resolve` is:

```rust
fn resolve(&self, q: &FontQuery) -> Rc<FontdueFont> {
    if let Some(f) = self.match_font_face(q) {   // NEW: @font-face wins
        return f;
    }
    self.face_by_id(self.resolve_id(q))          // existing: fontdb → vendored default
}
```

`match_font_face` walks `q.family` **in order** (the family list is honored: an
earlier family that is an @font-face name wins over a later one), and for each
name looks for registry entries whose normalized `family` equals the lowercased
requested name. Among the matching entries it picks the best by style+weight
(§4). Returns `None` if no requested family is an @font-face family — then
normal fontdb matching runs unchanged.

Lookup order, stated:
1. **@font-face registry** — by family name (list order) + best style/weight.
2. **fontdb query** — system + vendored (the existing E6-M1 matcher).
3. **vendored default** — `default_id`, when `query` returns `None`.

Generic keywords (`serif`, `monospace`, …) are *not* @font-face names, so they
skip the registry and fall straight to fontdb (unchanged).

> Cache note: the @font-face `Rc<FontdueFont>` is parsed once at registration
> and stored directly in `FaceEntry`; no `ID`-keyed cache entry is involved (the
> `faces` cache stays purely for fontdb-resolved ids). `resolve` is on the hot
> path but `match_font_face` is a short linear scan over a tiny `Vec` — cheap.

## 4. Weight/style matching among `@font-face` faces

Several `@font-face` rules can share a family (regular + bold + italic …). Given
a `FontQuery` whose requested `family[i]` matches registry entries, pick one:

1. Filter the entries for that family name.
2. **Style:** prefer an exact `style` match. If the query is `Italic`/`Oblique`
   and only `Normal` exists (or vice-versa), fall back across styles rather than
   miss — but exact match is strictly preferred. Concretely: partition into
   {exact-style} and {other-style}; if {exact-style} non-empty, choose from it,
   else from {other-style}.
3. **Weight:** within the chosen style set, pick the entry with the smallest
   `|entry.weight as i32 - query.weight as i32|`; ties broken by the
   first-registered (source order). This is a deliberately simple
   nearest-weight rule — *not* the full CSS weight ladder — which is adequate
   for the common regular/bold split and keeps M2 small.

Defaults at match time: an entry that omitted `font-weight` is 400; one that
omitted `font-style` is `Normal` (already applied in `register_face`).

Example: family `MyFont` with two faces (`weight 400 normal`, `weight 700
normal`). Query weight 700 → exact-style set is both; nearest weight to 700 is
the 700 face. Query weight 400 → the 400 face. Query weight 600 → nearest is 700
(|600-700|=100 < |600-400|=200).

## 5. Pipeline threading (`render_document`)

`render_document` already holds `base: &Url` and `loader: &dyn ResourceLoader`
and already builds `author` sheets + `FontDb`. Insert the load step between DB
creation and layout:

```rust
let js = starfish_js::run_scripts(&mut doc, base, loader);   // unchanged
report_console(&js);

let author = collect_author_sheets(&doc, base, loader);      // now also captures @font-face
let styled = style_tree(&doc, &author);
let fonts = FontDb::new();
load_font_faces(&author, base, loader, &fonts);              // NEW: fetch + register
// … images, layout, paint use `&fonts` exactly as before …
let root = layout(&doc, &styled, viewport_width, &FontMeasurer(&fonts), &images);
paint(&root, &styled, &fonts, &images, width, height)
```

Order rationale:
- **After CSS collection**: `@font-face` rules live in the author sheets, so
  they must be collected first.
- **After scripts**: scripts run before CSS collection in the current pipeline;
  a script that injects `@font-face` via CSSOM is **out of scope** (the engine
  does not re-collect sheets after scripting in M2) — note this. Static
  `@font-face` in `<style>`/`<link>` is the supported path.
- **Before layout**: layout's `FontMeasurer` calls `FontDb::resolve`, which now
  consults the registry; faces must be registered before the first measure so
  measure == paint (paint, later, uses the same warm registry).
- `style_tree(&doc, &author)` is unchanged — it ignores `font_faces`
  (it only reads `.rules`).

The two BACK-COMPAT shims (`render_html`, `render_html_cwd`) route through
`render_document`, so they pick up @font-face loading for free (against their
`file://` base). `render_url` likewise (http/https/data faces fetch over the
router).

## 6. Edge cases & non-goals

Handled / decided:
- **WOFF/WOFF2** — *deferred*. fontdue/ttf-parser read raw TTF/OTF only; WOFF is
  zlib-wrapped, WOFF2 is Brotli+transform. `format_supported` skips
  `woff`/`woff2`/`embedded-opentype`/`svg` hints; a hint-less woff URL is
  attempted and fontdue's `Err` skips it. (A `woff2`→ttf decoder crate is *not*
  cheap enough to justify in M2; note for a follow-up.)
- **`local()`** — resolved against the system/vendored DB via
  `system_face_bytes`; a miss falls through to the next `src`. Under
  `vendored_only()` only vendored family names resolve.
- **Multiple `src` fallback** — tried front-to-back; the first that fetches +
  parses wins; the rest are not fetched.
- **`format()` hints** — used only to skip clearly-unsupported formats; a
  supported/absent hint defers to fontdue.
- **`unicode-range`** — *deferred* (ignored): the @font-face face applies to the
  whole family, not a code-point subset.
- **`font-display`** — ignored (synchronous load; no FOUT/FOIT model).
- **Missing/failed `src`** — the whole rule registers nothing; the family falls
  back to normal fontdb matching (no panic, no blank text).
- **Family is both @font-face and a system font** — the @font-face registry is
  checked first → **author @font-face wins** (the spec behavior).
- **`data:` URL fonts** — supported: `base.join` keeps the absolute `data:` URL,
  and `DataLoader`/`RouterLoader` decode base64 ttf into bytes.
- **`@font-face` with no usable descriptor** (no family / no src) — dropped at
  parse time (`fold_font_face` → `None`).
- **TTC / `collection_index`** — fixed at 0 for @font-face (single-face files).
- **Faux bold / synthetic italic** — none; nearest declared face is used (a
  family with only a regular face renders bold as that regular face).
- **CSSOM-injected `@font-face`** (via script) — out of scope (sheets are not
  re-collected post-script in M2).

Otherwise the ROADMAP-epic6 deferral list stands.

## 7. Test plan

Use a **vendored .ttf as the served font file** for determinism: copy/reuse an
existing `crates/paint/assets/*.ttf` (e.g. `DejaVuSerif.ttf`) written into a
temp dir and served via `LocalLoader`, or embedded as a base64 `data:` URL via
`RouterLoader`. Tests use `FontDb::vendored_only()` plus explicit
`load_font_faces` / `register_face` so the host font set is irrelevant. Asserts
are *relative* (distinct advances, override behavior), never exact pixels.

### 7.1 `css/parser` — capture
- `@font-face { font-family: "MyFont"; src: url("a.ttf") format("truetype") }`
  parses to one `FontFaceRule { family: "MyFont", src: [Url{ url:"a.ttf",
  format:Some("truetype") }], weight:None, style:None }` and **zero** `rules`.
- `src: local("Arial"), url("a.woff2") format("woff2")` → two `FontSrc`
  (`Local`, then `Url` with `format Some("woff2")`), in order.
- `font-weight: 700; font-style: italic` descriptors captured.
- A `@font-face` with **no** `src` (or no `font-family`) → dropped, `font_faces`
  empty.
- Mixed sheet: `@media`/`@import` still skipped, a `@font-face` captured, normal
  rules still in `.rules` (existing at-rule tests unchanged).

### 7.2 `paint/font` — registry + match
- `register_face("MyFont", None, None, ttf_bytes)` then a `FontQuery` for
  `["MyFont"]` resolves to the registered face — its advances differ from the
  vendored default for the same string (distinct face drove resolution).
- **Override:** register `MyFont` from a face whose advances differ from
  `"DejaVu Sans"`; a query for `["DejaVu Sans"]` *unregistered* resolves to the
  vendored face, but after registering `@font-face font-family: "DejaVu Sans"`
  with the other face, `["DejaVu Sans"]` now resolves to the @font-face face
  (author wins over the same-named vendored family) — advances change.
- **Weight pick:** register `MyFont` twice (weight 400 from face A, weight 700
  from face B with different advances). Query weight 700 → face B advances;
  weight 400 → face A advances; weight 600 → face B (nearest).
- **Style pick:** register `MyFont` Normal and `MyFont` Italic (Liberation
  Regular vs Italic bytes). Query Italic → the italic face; query Normal → the
  regular; query Oblique with only Normal+Italic present → Italic (exact-miss
  falls back across styles, italic preferred over normal? — assert the chosen
  fallback is deterministic: nearest non-empty style set).
- **Bad bytes:** `register_face("X", .., b"not a font".to_vec())` returns
  `false` and registers nothing; a query for `["X"]` falls back to fontdb (no
  panic).
- **measure == paint** for an @font-face family: summed `rasterize_glyph(ch,&q)`
  advances equal `advance_width(text,&q)` (the registry face is used by both).

### 7.3 `render_document` — end-to-end
- **file url ttf:** write a vendored ttf to a temp dir as `myfont.ttf`; HTML
  with `<style>@font-face{font-family:"MyFont";src:url("myfont.ttf")} p{font-family:MyFont}</style>`
  + `<p>` → the text-run width (via the layout helper) differs from the same `<p>`
  with `font-family:sans-serif` (the loaded face drove layout); glyph pixels
  drawn.
- **data: url ttf:** base64 a vendored ttf into a `data:font/ttf;base64,…` `src`,
  rendered via `RouterLoader` → same assertion (loads + renders).
- **two faces (regular + bold):** two `@font-face` for `MyFont` (weight 400 ttf,
  weight 700 ttf with distinct metrics); `<p style="font-family:MyFont;
  font-weight:700">` measures with the bold face (width ≠ the weight-400 case).
- **failed src:** `@font-face{font-family:"MyFont";src:url("nope.ttf")}` +
  `font-family:MyFont,sans-serif` → no panic; renders with sans fallback (glyph
  pixels present).
- **unsupported format:** `src:url("x.woff2") format("woff2")` only → skipped;
  family falls back to the next family in the list / fontdb; no panic.
- **VISUAL (review artifact, not asserted pixel-exact):** a page using an
  @font-face family rendered to PNG, showing the loaded font's distinct shapes
  vs the default.
