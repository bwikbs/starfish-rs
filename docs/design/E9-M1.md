# E9-M1 — inline `<svg>` basic shapes + viewBox (DESIGN)

Make an inline `<svg>` render. Four moving parts, each surgical:

1. **HTML foreign-content** — an `in_svg` flag in the tree builder so SVG markup
   (self-closing shapes, `viewBox` case) survives parsing.
2. **DOM case** — SVG elements/attrs are stored case-preserved (so `viewBox` is
   readable); HTML stays lowercased and byte-identical.
3. **Layout** — `<svg>` becomes a replaced `BoxKind::Svg` box sized from
   `width`/`height`/`viewBox`; its DOM children are NOT turned into LayoutBoxes.
4. **Paint** — at display-list time we pre-flatten the svg subtree into
   self-contained `PaintCmd::SvgShape{…}` commands (the rasterizer stays
   DOM-free); a small SVG walker reads shape + presentation attributes and emits
   tiny-skia fills/strokes.

Scope: shapes `rect` (+`rx`/`ry`), `circle`, `ellipse`, `line`; presentation
attrs `fill`, `stroke`, `stroke-width`, `opacity`, `fill-opacity`,
`stroke-opacity` (attr + inline `style`). Deferred to M2/M3: `path`,
`polygon`/`polyline`, `text`, `<g>`/`transform`, gradients,
`preserveAspectRatio` variants, dasharray.

Crates touched: `html` (tokenizer + tree_builder), `dom`, `style`/`layout`
(box gen + sizing), `paint` (new PaintCmd + svg walker), reuse `css` color
parser.

## 1. HTML foreign-content (SVG mode)

### 1.1 The two problems, verified against the current parser

The tokenizer (`crates/html/src/tokenizer.rs`) **lowercases tag names**
(`tag_name`, line 120: `name.push(c.to_ascii_lowercase())`) and **attribute
names** (`attribute`, line 177). The tree builder (`tree_builder.rs`,
`in_body`, lines 287–299) pushes every non-void start tag onto the open stack
and ignores the `self_closing` flag entirely — so:

- `<rect … />` → `rect` is NOT a void element → pushed on the stack and never
  popped (the tokenizer DID parse `self_closing: true`, but `in_body` discards
  it). Subsequent shapes nest inside it. **Self-closing is broken for SVG.**
- `<svg viewBox="0 0 10 10">` → attribute name lowercased to `viewbox`. The SVG
  painter reads `viewBox` (case-sensitive per SVG) → miss. **Case is lost.**

`<circle>`/`<rect>`/etc. tag names are already lowercase in source, so for M1
shapes the *tag* case rarely matters — but `viewBox` (and M3's
`linearGradient`, `preserveAspectRatio`) need case preservation. We preserve
case for the whole SVG subtree (cleaner than a fix-up table, and forward-
compatible with M3).

### 1.2 Where to intercept case-lowercasing — the tokenizer

The tokenizer is stateless w.r.t. the tree. Rather than thread parser state
into it, **stop lowercasing at the source and let the tree builder decide**:

- Change `Token::StartTag` / `Token::EndTag` to also carry the **original-case**
  name. Minimal approach: keep `name` lowercased (HTML path unchanged) and add a
  sibling field `name_raw: String` with source case. The tree builder uses
  `name` for HTML dispatch (byte-identical) and `name_raw` only when in SVG mode.

```rust
// tokenizer.rs
pub enum Token {
    Doctype { name: String },
    StartTag { name: String, name_raw: String, attrs: Vec<Attr>, self_closing: bool },
    EndTag { name: String, name_raw: String },
    Character(char),
    Comment(String),
    Eof,
}
```

`tag_name` accumulates both: push `c` to `raw` and `c.to_ascii_lowercase()` to
`name` in the same loop. Likewise, `attribute` accumulates `Attr { name (raw),
name_lower }` — but `Attr` is a DOM type; instead the tokenizer keeps `attrs`
**raw-cased** and lowercases at *insert* time for HTML. Simpler and avoids a
second DOM field:

**Decision (minimal):** the tokenizer keeps attribute names **raw (source
case)**. HTML attribute case-insensitivity is preserved by lowercasing at DOM
insertion for the HTML path, and `get_attribute` already compares against a
lowercased query (§2). Tag names: add `name_raw` to the tokens as above; tag
`name` stays lowercased so all existing HTML dispatch is untouched.

> Why raw attrs in the tokenizer: HTML attribute *values* are already case-
> preserving; only attribute *names* are lowercased today. Lowercasing names is
> done once, at the point the element is created (`insert_element`), for HTML.
> For SVG we skip that lowercasing. This keeps the change in one place.

Concretely, the tokenizer change is: `tag_name`/`attribute` no longer call
`to_ascii_lowercase()`; they emit raw names. The **tree builder** lowercases for
HTML. (`Token` equality in tokenizer unit tests then expects raw names — those
tests assert lowercase input like `<DIV CLASS=X>` → adjust the two affected
tests `uppercase_normalization`, or keep them by having the tree-builder-facing
helper lowercase. To keep tokenizer tests stable, prefer the `name_raw` sibling-
field form and leave `name`/attr-name lowercasing in the tokenizer for HTML,
adding raw copies. Pick the sibling-field form — it is the least disruptive.)

**Chosen shape (least churn):**
- `StartTag`/`EndTag` gain `name_raw: String` (raw tag case).
- `Attr` gains nothing; the tokenizer keeps lowercasing attr names for the HTML
  path, AND the tree builder, when in SVG mode, re-derives raw attr names from a
  second raw list. To avoid duplicating attr storage, instead: the tokenizer
  stores attrs **raw**, and `insert_element` lowercases per-attr only when NOT
  in SVG mode.

Both are viable; the implementation agent should pick whichever yields the
smaller diff after spiking. The **invariant that matters**: in SVG mode, the
element name + attr names land in the DOM **case-preserved**; outside SVG mode,
HTML output is byte-identical to today.

### 1.3 The `in_svg` flag in the tree builder

```rust
struct TreeBuilder {
    doc: Document,
    open: Vec<NodeId>,
    mode: Mode,
    head: Option<NodeId>,
    svg_depth: u32,   // NEW: >0 ⇒ inside an <svg> subtree (foreign content)
}
```

`svg_depth` is a counter, not a bool, so nested `<svg>` (rare, allowed) and the
matching `</svg>` balance. Handled entirely inside `in_body` (SVG only appears
in body content for M1):

- On a **start tag** whose lowercased `name == "svg"`: enter SVG mode
  (`svg_depth += 1` *after* inserting the element so the `<svg>` element itself
  is created with case-preserved name `"svg"` — already lowercase — and its
  attrs case-preserved, giving us `viewBox`).
- While `svg_depth > 0`:
  - Insert the element with **case-preserved** name + attrs (`insert_element_svg`
    / a `case_preserve: bool` param).
  - **Honor `self_closing`**: if the start tag's `self_closing` is true, do NOT
    push it onto the open stack (it is a leaf) — this fixes `<rect/>`,
    `<circle/>`, etc. Also treat the SVG shape leaves as never-pushed even
    without the slash is NOT done (we honor the author's `/>`; a non-self-closed
    `<rect>…</rect>` is also fine because the matching `</rect>` pops it).
  - HTML auto-closing (`auto_close_for`) is **skipped** in SVG mode (no `<p>`
    auto-close etc. — foreign content has no such rules).
  - Void-element logic (`is_void`) is **skipped** in SVG mode (SVG has no HTML
    void elements; `<rect>` is not void).
- On the **end tag** `name == "svg"`: pop through the `svg` element on the open
  stack (like `close_element("svg")`), then `svg_depth -= 1`.
- Other end tags in SVG mode: `close_element(name_raw)` — pop the matching open
  element. (Case-sensitive match against the case-preserved open-stack names; in
  practice shape end tags are lowercase.)

`in_body` start-tag branch becomes:

```rust
Token::StartTag { name, name_raw, attrs, self_closing } => {
    let svg = self.svg_depth > 0 || name == "svg";
    if !svg { self.auto_close_for(&name); }
    let (insert_name, attrs) = if svg { (name_raw, attrs /*raw-cased*/) }
                               else  { (name, lowercase_attr_names(attrs)) };
    let el = self.insert_element(&insert_name, attrs);
    if name == "svg" { self.svg_depth += 1; }
    let leaf = if svg { self_closing } else { is_void(&name) };
    if !leaf { self.open.push(el); }
}
```

```rust
Token::EndTag { name, name_raw } => {
    if self.svg_depth > 0 {
        if name == "svg" { self.close_element("svg"); self.svg_depth -= 1; }
        else { self.close_element(&name_raw); }
        return;
    }
    // …existing HTML end-tag handling unchanged…
}
```

> Note: `name == "svg"` uses the lowercased name so `<SVG>` / `<svg>` both
> trigger SVG mode; the element is stored as the (lowercased-anyway) `"svg"`.

### 1.4 What stays byte-identical

Outside any `<svg>`, `svg_depth == 0`, so every branch above takes the existing
HTML path. The only structural change to HTML output is the extra `name_raw`
field plumbing — no behavioral change. The existing `html` test corpus
(`lib.rs`/`tokenizer.rs` tests) must pass unchanged (modulo the two tokenizer
case-normalization tests if the raw-token form is chosen — adjust them to assert
the tree-builder output, not the raw token).

## 2. DOM case handling

`crates/dom/src/lib.rs` currently lowercases in `create_element` (line 116:
`name.to_ascii_lowercase()`) and in `set_attribute`/`remove_attribute`. For SVG
we must store case-preserved names.

**Decision:** add a non-lowercasing element constructor and let the tree builder
choose:

```rust
/// Create an element with the name stored VERBATIM (no lowercasing). Used for
/// SVG foreign content where tag/attr case is significant (`viewBox`).
pub fn create_element_ns(&mut self, name: &str) -> NodeId {
    self.push(NodeKind::Element(Element { name: name.to_string(), attrs: Vec::new() }))
}
```

The tree builder's `insert_element` gains a `case_preserve: bool` (or a parallel
`insert_element_svg`) that (a) uses `create_element_ns` and (b) stores `attrs`
verbatim (skips per-attr lowercasing). HTML path keeps `create_element`
(lowercased) — byte-identical.

**`get_attribute` case-sensitivity.** `get_attribute(id, name)` (line 283)
compares `a.name == name` exactly. Today HTML attr names are pre-lowercased and
callers query lowercased keys, so it works. For SVG the painter queries with the
**exact author case**: `get_attribute(svg, "viewBox")`, `get_attribute(rect,
"x")`. Since SVG attrs are stored verbatim and the painter uses the canonical
SVG spelling, the exact-match `get_attribute` is correct as-is — **no DOM API
change needed**, just the verbatim storage.

> Edge: an author writing `<svg VIEWBOX=…>` (wrong case) won't match `viewBox`.
> That is per-spec for foreign content (SVG attrs are case-sensitive) and out of
> scope to "fix".

`tag_name` returns the stored name; for shapes (`"rect"`, `"circle"`, …) it is
lowercase and the painter matches lowercase. The `<svg>` tag is `"svg"`. M3's
`linearGradient` will arrive case-preserved for free.

## 3. `<svg>` layout (replaced box)

`<svg>` is a replaced element, sized like `<img>` but with no external resource.
Add a box kind:

```rust
// boxtree.rs
pub enum BoxKind {
    …,
    Image,
    /// An inline replaced `<svg>` root. Carries the svg element's NodeId in
    /// `style` (BoxStyleRef::Node); its used size is in `dimensions`. Its DOM
    /// children are NOT turned into LayoutBoxes — the SVG painter walks the DOM
    /// subtree directly (E9-M1).
    Svg,
}
```

`Svg` is inline-level (add to `is_inline_level`, like `Image`).

### 3.1 Box generation (`build_node`)

Mirror the `<img>` early-return in `build_node` (boxtree.rs line 209). Before
the generic element branch:

```rust
if doc.tag_name(id) == Some("svg") {
    let display = styled.get(id).map(|s| s.display).unwrap_or(Display::Inline);
    if display == Display::None { return None; }
    let b = LayoutBox::new(BoxKind::Svg, BoxStyleRef::Node(id));
    return Some(b);   // NO children built — painter walks the DOM
}
```

This stops box generation from descending into `<rect>`/`<circle>` (which have
no CSS box). `display:block` on the `<svg>` is honored at sizing time the same
way `<img>` blockifies (out-of-flow / block path); for M1 the default inline
atomic path is the focus, matching `<img>`.

### 3.2 Sizing (`inline.rs`, the `BoxKind::Image` sibling)

Add a `BoxKind::Svg` arm next to `BoxKind::Image` in `collect_items`
(inline.rs line 168). The svg's **intrinsic content size**:

```rust
fn svg_intrinsic_size(doc: &Document, id: NodeId) -> (f32, f32) {
    let w = attr_px(doc, id, "width");          // "100" or "100px" → px
    let h = attr_px(doc, id, "height");
    let vb = parse_view_box(doc.get_attribute(id, "viewBox"));
    match (w, h) {
        (Some(w), Some(h)) => (w, h),
        (Some(w), None) => (w, vb.map(|v| w * v.h / v.w).unwrap_or(150.0)),
        (None, Some(h)) => (vb.map(|v| h * v.w / v.h).unwrap_or(300.0), h),
        // no width/height → viewBox w/h if present, else CSS default 300×150
        (None, None) => vb.map(|v| (v.w, v.h)).unwrap_or((300.0, 150.0)),
    }
}
```

CSS `width`/`height` (definite) override the attrs, exactly as `<img>` does
(`resolve(style.width, cbw).or_else(|| attr_px(…))`). Reuse the existing
`attr_px` helper. The svg sub-box gets `content.width/height = (w,h)`, margins
resolved like `<img>`, pushed as an `Atomic`. **No child layout.** Width/height
percentages: `resolve(style.width, cbw)` already handles `%` for the CSS path;
attr-percentages are out of scope (HTML attr `width="50%"` → `attr_px` returns
`None` → falls to viewBox/default). Acceptable for M1; note it.

The grid/table intrinsic-width helpers (`grid.rs:592`, `table.rs:602`) currently
match `BoxKind::Image` for atomic-inline width; add `BoxKind::Svg` there too so
an svg inside a grid/table cell measures (one-line each; low priority but cheap).

## 4. viewBox → box mapping

`viewBox="minX minY w h"` defines the user coordinate system mapped onto the
svg's painted content box (`dest` = the svg box's absolute `content` rect,
`w_box × h_box`).

```rust
struct ViewBox { x: f32, y: f32, w: f32, h: f32 }

fn parse_view_box(s: Option<&str>) -> Option<ViewBox> {
    let s = s?;
    let n: Vec<f32> = s.split([',', ' ', '\t', '\n'])
        .filter(|t| !t.is_empty())
        .filter_map(|t| t.parse().ok())
        .collect();
    if n.len() == 4 && n[2] > 0.0 && n[3] > 0.0 {
        Some(ViewBox { x: n[0], y: n[1], w: n[2], h: n[3] })
    } else { None }
}
```

**Transform user→canvas** (default `preserveAspectRatio: xMidYMid meet` — for
M1 we implement **uniform `meet` + centering**, which is the spec default and
only ~6 lines more than non-uniform; recommend it):

```rust
// dest: svg content rect (absolute). vb: Some(viewBox) or None.
fn svg_transform(dest: Rect, vb: Option<ViewBox>) -> tiny_skia::Transform {
    let Some(vb) = vb else {
        // no viewBox: user units == px, origin at dest top-left.
        return Transform::from_translate(dest.x, dest.y);
    };
    let sx = dest.width / vb.w;
    let sy = dest.height / vb.h;
    let s = sx.min(sy);                       // "meet": fit, uniform
    let tx = dest.x + (dest.width  - vb.w * s) / 2.0 - vb.x * s;  // xMid
    let ty = dest.y + (dest.height - vb.h * s) / 2.0 - vb.y * s;  // yMid
    Transform::from_row(s, 0.0, 0.0, s, tx, ty)
}
```

This `Transform` is applied per shape at fill/stroke time (`fill_path(&path, …,
transform, None)` accepts a `Transform`). Coordinates are emitted in **user
space**; the transform does the scale + translate. (Alternative: bake the
transform into each coordinate at build time and pass `Transform::identity()`.
Applying the `Transform` in the rasterizer is cleaner for stroke-width scaling —
see §5.3 — and matches how the rest of paint uses tiny-skia Transforms.)

## 5. SVG painter — pre-flattened `SvgShape` paint commands

### 5.1 Where it runs + how paint reaches the DOM

`build_display_list` (display.rs:114) does **not** receive the `Document`; the
rasterizer (raster.rs) doesn't either. But `paint()`/`render_document`
(`lib.rs:282`/`179`) **do** hold the `doc`. Threading the `Document` all the way
into the rasterizer is invasive and would taint every signature.

**Decision (recommended):** pre-flatten the svg at **display-list build time**.
`build_display_list` already walks the box tree with the `StyledTree`; thread
the `&Document` into it (one new param on `build_display_list` /
`paint_subtree` / `emit_self`). When `emit_self` hits a `BoxKind::Svg`, walk the
svg's DOM subtree and append a list of **self-contained** shape commands. The
rasterizer then renders those commands with no DOM access — keeping raster.rs
DOM-free.

`paint()` in lib.rs already has `doc` in scope at the only call site
(`render_document`), and the display.rs unit tests build a `doc` (line 535) — so
threading `&Document` is a localized change.

```rust
// lib.rs paint()
let cmds = build_display_list(layout_root, styled, fonts, images, doc);
```

### 5.2 The new PaintCmd(s)

One command per shape primitive, fully resolved (canvas-space transform baked in
as a `[f32;6]`, colors resolved, geometry in user coords). The rasterizer builds
a tiny-skia `Path` from the geometry and fills/strokes through the transform.

```rust
// display.rs
#[derive(Debug, Clone, PartialEq)]
pub enum SvgGeom {
    Rect { x: f32, y: f32, w: f32, h: f32, rx: f32, ry: f32 },
    Ellipse { cx: f32, cy: f32, rx: f32, ry: f32 }, // circle ⇒ rx==ry==r
    Line { x1: f32, y1: f32, x2: f32, y2: f32 },     // stroke-only
}

pub enum PaintCmd {
    …,
    /// A single SVG shape, flattened from the svg subtree at build time
    /// (E9-M1). `transform` (a,b,c,d,e,f) is the user→canvas viewBox transform.
    /// `fill`/`stroke` are already alpha-folded (shape opacity × paint opacity).
    SvgShape {
        geom: SvgGeom,
        transform: [f32; 6],
        fill: Option<Rgba>,        // None ⇒ no fill (fill="none")
        stroke: Option<Rgba>,      // None ⇒ no stroke
        stroke_width: f32,         // in USER units (scaled by transform)
    },
}
```

> A `clip` to the svg box (so shapes outside the viewport are clipped) is M1-
> optional; the simplest correct-enough behavior is to NOT clip (matches `<img>`
> only when content fits). Spec says clip to the svg box. For M1 we **note** it
> and skip clipping unless a `clip` is trivially addable; the test corpus keeps
> shapes inside the box.

### 5.3 The build-time walk (in display.rs)

```rust
fn emit_svg(b: &LayoutBox, styled: &StyledTree, doc: &Document, out: &mut Vec<PaintCmd>) {
    let svg_id = b.style.node();
    let dest = b.dimensions().content;                  // absolute svg content rect
    let vb = parse_view_box(doc.get_attribute(svg_id, "viewBox"));
    let t = svg_transform(dest, vb);
    let m = [t.sx, t.ky, t.kx, t.sy, t.tx, t.ty];
    for child in doc.children(svg_id) {
        if let Some(cmd) = build_shape(doc, child, m) { out.push(cmd); }
    }
}
```

`build_shape` dispatches on `tag_name` (lowercase): `rect`/`circle`/`ellipse`/
`line`. It reads geometry + presentation attrs and produces an `SvgShape`. Unknown
tags (`defs`, `g`, `text`, `path`, …) → `None` (skipped in M1).

Per shape (numbers via `attr_f(doc, id, "x")` → parse f32, default 0):

- **rect**: `x,y,width,height` (0/0 default for x,y; require w>0,h>0 else skip),
  `rx`/`ry` (if only one given, the other equals it; clamp to half w/h). `rx==ry==0`
  → sharp rect.
- **circle**: `cx,cy,r` (skip if r≤0) → `Ellipse { cx, cy, rx:r, ry:r }`.
- **ellipse**: `cx,cy,rx,ry` (skip if rx≤0 or ry≤0).
- **line**: `x1,y1,x2,y2` → `Line`. Fill is ignored for lines (stroke only).

### 5.4 Presentation attributes (attr + inline `style`)

```rust
struct Paints { fill: Option<Rgba>, stroke: Option<Rgba>, stroke_width: f32 }

fn resolve_paints(doc: &Document, id: NodeId) -> Paints {
    // Lookup order per property: inline style declaration, else presentation attr,
    // else the SVG initial (fill = black, stroke = none, stroke-width = 1).
    let style = doc.get_attribute(id, "style");        // "fill:red;stroke:#00f"
    let prop = |name: &str| svg_style_prop(style, name).or_else(|| doc.get_attribute(id, name).map(str::to_string));

    let fill = parse_paint(prop("fill").as_deref(), default = Some(BLACK));
    let stroke = parse_paint(prop("stroke").as_deref(), default = None);
    let sw = prop("stroke-width").and_then(|s| parse_len(&s)).unwrap_or(1.0);

    // opacity folding: shape opacity × per-channel opacity into alpha.
    let op = prop("opacity").and_then(|s| s.parse().ok()).unwrap_or(1.0).clamp(0.0,1.0);
    let fo = prop("fill-opacity").and_then(parse_opacity).unwrap_or(1.0);
    let so = prop("stroke-opacity").and_then(parse_opacity).unwrap_or(1.0);
    Paints {
        fill:   fill.map(|c| with_alpha(c, op * fo)),
        stroke: stroke.map(|c| with_alpha(c, op * so)),
        stroke_width: sw,
    }
}
```

- `svg_style_prop(style, "fill")` is a trivial `;`/`:`-split lookup over the
  inline `style` string (no full CSS engine needed for M1; matches how SVG
  presentation defaults work). Inline `style` wins over the presentation attr.
- `parse_paint(s, default)`: `None`/absent → `default`; `"none"` → `None`;
  `"currentColor"` → the element's CSS `color` (`styled.get(id).color`, fall to
  black); else `starfish_css::parse_color(s)` (named/#hex/rgb()).
- `with_alpha(c, a)`: `Rgba { a: (c.a as f32 * a) as u8, ..c }`.

### 5.5 Rasterizer (raster.rs)

A new arm in `draw_into`:

```rust
PaintCmd::SvgShape { geom, transform, fill, stroke, stroke_width } =>
    draw_svg_shape(pixmap, geom, transform, *fill, *stroke, *stroke_width),
```

`draw_svg_shape` builds a `tiny_skia::Path` via `PathBuilder` in **user coords**:

- Rect (sharp): `pb.push_rect` or move/line/line/line/close. Rounded rect: reuse
  the existing `append_rounded_rect` style (cubic corners) — or a per-corner
  rx/ry arc. For M1 uniform `rx=ry` via `append_rounded_rect([rx;4])` is reused;
  asymmetric rx≠ry is a minor refinement (note).
- Ellipse/circle: 4 cubic-bezier arcs (κ≈0.5523) around `(cx,cy)` with radii
  `rx,ry`. (Circle = rx==ry.)
- Line: `move_to(x1,y1); line_to(x2,y2)` — only stroked.

Then:
```rust
let t = Transform::from_row(m[0],m[1],m[2],m[3],m[4],m[5]);
if let Some(fill) = fill {                 // not for Line
    let mut p = Paint { anti_alias: true, ..Default::default() };
    p.set_color_rgba8(fill.r, fill.g, fill.b, fill.a);
    pixmap.fill_path(&path, &p, FillRule::Winding, t, None);
}
if let Some(stroke) = stroke {
    let mut p = Paint { anti_alias: true, ..Default::default() };
    p.set_color_rgba8(stroke.r, stroke.g, stroke.b, stroke.a);
    let sk = tiny_skia::Stroke { width: stroke_width, ..Default::default() };
    pixmap.stroke_path(&path, &p, &sk, t, None);
}
```

`tiny_skia::Pixmap::stroke_path(path, paint, stroke, transform, mask)` and
`Stroke { width, line_cap, line_join, .. }` are confirmed available in
tiny-skia 0.11 (the ANALYSIS agent verifies the exact `Stroke` field set +
`LineCap`/`LineJoin` defaults — M1 uses defaults: butt cap, miter join). The
`transform` argument scales **both** geometry and stroke width uniformly under a
uniform `meet` transform, which is the correct SVG behavior (stroke-width is in
user units). Under a non-uniform scale stroke width would be anisotropic — a
known limitation we avoid by using uniform `meet`.

## 6. Color / paint parsing

Reuse `starfish_css::parse_color` (exported, `crates/css/src/color.rs:46`):
handles `#rgb/#rgba/#rrggbb/#rrggbbaa`, `rgb()/rgba()`, and the 16 named colors.
SVG-specific values handled in the svg painter wrapper:

- `"none"` (case-insensitive) → no paint (`None`).
- `"currentColor"` (case-insensitive) → the element's computed CSS `color`
  (`b.style(styled)`/`styled.get(id).color`), default black.
- everything else → `parse_color`. Unknown keyword → treat as no paint? No —
  SVG default `fill` is black; an unparseable value falls back to the default
  (black for fill, none for stroke) to stay lenient.

Named SVG colors beyond the 16 (e.g. `orange`, `dodgerblue`) are NOT in the css
named table — they parse to `None` → fall to default. Extending the named table
is out of scope but cheap if a test needs it (note); the test corpus uses
red/blue/green/#hex/rgb() which are covered.

## 7. Edge cases & non-goals

| Case | M1 behavior |
|---|---|
| `<svg>` no width/height, no viewBox | default 300×150 (CSS replaced default) |
| `<svg>` width/height only | that size; user units == px (no viewBox) |
| `<svg>` viewBox only | intrinsic = viewBox w×h |
| `display:none` on `<svg>` | no box (handled in `build_node`) |
| nested `<svg>` | `svg_depth` counter balances; inner svg's own box is M2+ — for M1 the inner svg element is parsed but not separately laid out (it's a DOM child of the outer svg; the outer painter skips unknown tags). Acceptable. |
| shape outside the viewBox | NOT clipped in M1 (note; spec clips to the svg box) |
| `fill="none"` + stroke | stroke only |
| `width="50%"` HTML attr | `attr_px` → None → falls to viewBox/default (CSS `%` width works) |
| `transform` on a shape | M3 |
| `path`/`polygon`/`polyline` | M2 |
| `text`/`tspan`, `<g>`, gradients, `<defs>` | M3 (skipped tags) |
| `stroke-dasharray`, `linecap`/`linejoin` | deferred (M2 does basic caps/joins) |
| `preserveAspectRatio` variants | default `xMidYMid meet` only |
| rx≠ry rounded rect | approximated (uniform) in M1; note |

## 8. Test plan

**Parsing (`html`):**
- `parse("<svg width=100 height=100><rect x=10 y=10 width=80 height=80 fill=\"red\"/></svg>")`
  → `svg` element with a single `rect` child element that is **self-closed**
  (not nesting following siblings); `rect` carries attrs `x/y/width/height/fill`.
- `<svg viewBox="0 0 10 10">…</svg>` → the svg element has an attribute named
  **`viewBox`** (exact case), value `"0 0 10 10"` (case preserved).
- HTML regression: the existing `html` corpus passes byte-identically (no `<svg>`
  in those inputs).
- `<svg><circle/></svg><p>after` → `circle` self-closes; `</svg>` exits SVG mode;
  `<p>` is a normal HTML sibling after the svg.

**Layout:**
- `<svg width=100 height=100>` → a `BoxKind::Svg` box with content 100×100,
  inline-level.
- no attrs → 300×150. viewBox-only `viewBox="0 0 40 20"` → 40×20.

**Display list / paint (display.rs unit + lib.rs pixel tests):**
- `<rect x=10 y=10 width=80 height=80 fill="red"/>` in a 100×100 svg → an
  `SvgShape{ geom: Rect, fill: red, transform: translate(svg.x,svg.y) }`; pixel
  at the rect interior is red, outside (e.g. (2,2)) is white.
- `<circle cx=50 cy=50 r=40 fill="blue"/>` → blue at center, white at corner.
- `<ellipse cx=50 cy=25 rx=40 ry=20 fill="green"/>` → green at center.
- `<line x1=0 y1=0 x2=100 y2=100 stroke="black" stroke-width=4/>` → dark pixels
  along the diagonal; no fill.
- **viewBox scaling**: `<svg width=100 height=100 viewBox="0 0 10 10">
  <rect x=1 y=1 width=8 height=8 fill="red"/></svg>` → the user-(1,1,8,8) rect
  paints at canvas (10,10)…(90,90); pixel (50,50) red, (5,5) white.
- `fill="none" stroke="black" stroke-width=2` rect → interior white, edge dark.
- colors: `fill="#00ff00"`, `fill="rgb(0,0,255)"`, `fill="blue"` all paint.
- `stroke-width` honored (a thicker stroke covers more pixels).
- opacity folding: `fill="red" fill-opacity="0.5"` → a half-alpha red (≈ pink
  over white).

**Visual (PNG, manual/review):** one svg with a red `rect`, a blue `circle`, and
a stroked `line` — the E9-M1 done-when artifact.
