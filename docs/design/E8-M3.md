# E8-M3 — Storage + misc JS APIs: `localStorage`/`sessionStorage`, `JSON` (confirm), `Element.dataset`, `URL`/`URLSearchParams`, console additions (design note)

Scope (per `docs/ROADMAP-epic8.md`, the final Epic-8 milestone): the storage + grab-bag
JS APIs real scripts reach for, all in **`crates/js`** (no pipeline change, no new crate dep):

- **`localStorage` / `sessionStorage`** — two independent in-memory `string → string` stores,
  exposing `getItem`/`setItem`/`removeItem`/`clear`/`length`/`key(i)`. **Per-render** (a fresh
  store each `run_scripts`; no persistence, no `storage` events, no quota).
- **`JSON`** — Boa's ECMAScript built-in. **Confirm + test only** (no implementation).
- **`Element.dataset`** — `el.dataset` returns an object exposing the element's `data-*`
  attributes with camelCase keys (read; write a small stretch).
- **`URL` / `URLSearchParams`** — `new URL(url[, base])` (href/protocol/host/hostname/port/
  pathname/search/hash/origin) + `URLSearchParams` (get/getAll/has/set/append/delete/toString/
  forEach), both over the `url` crate (re-exported by `starfish-net` as `Url`).
- **console additions** — `console.dir`/`console.table`/`console.assert` (trivial; reuse the
  existing capture sink).

Guiding rule (project CLAUDE.md "Simplicity First / Surgical Changes"): **method-based** Storage
over two `Rc<RefCell<HashMap>>` in `DomState` (mirrors how `DomState` already carries
`#[unsafe_ignore_trace]` plain-data fields); `JSON` is Boa's (zero code); `dataset` READ built
fresh per access (the exact `el.style`/`el.classList` precedent in `dom/style.rs`) with WRITE as a
thin accessor add; `URL`/`URLSearchParams` as native classes over `url::Url` / `Vec<(String,String)>`
(the `Xhr` class precedent in `dom/xhr.rs`); console methods reusing `console.rs`. **Defer:** Storage
bracket/property exotic access (methods-only), persistence/quota/events, `structuredClone`,
URLSearchParams iterator-protocol/`entries`/`keys`/`values`, full WHATWG URL edge cases. Non-goals §7.

The companion ANALYSIS agent is the authority on Boa 0.21.1 shapes; this note pins to the **real
current source** (quoted as read) for `starfish-{js,dom,net}`.

## 1. `localStorage` / `sessionStorage` — method-based in-memory Storage

### 1.1 Decision — a plain object whose methods close over a shared `Rc<RefCell<HashMap>>` (NOT a native class)

Two viable shapes (ANALYSIS confirms both work):

1. **Native `Storage` class** (`impl Class`, like `Xhr`) carrying a `HashMap` as instance data.
2. **A plain `JsObject`** (built with `ObjectInitializer`) whose method closures **capture** a shared
   `Rc<RefCell<HashMap<String,String>>>`, the map itself living in `DomState`.

**We pick (2).** Reasons (Simplicity First):
- The store is a **singleton per name** (`localStorage` is *the* store; there's no `new Storage()`).
  A class buys per-instance data we don't need and forces a JS-constructible ctor we don't want
  (`new Storage()` shouldn't be a thing).
- It mirrors **exactly** the existing `console` sink (a `Rc<RefCell<Vec<…>>>` captured by closures,
  `console.rs:20-55`) and the `el.classList` object (closures over a handle reading shared state,
  `style.rs:229`). One established pattern, reused.
- The `length`/`key(i)` ordering needs a stable insertion order → use **`indexmap::IndexMap`** if it
  is already a dep, else a plain `HashMap<String,String>` + a `Vec<String>` insertion-order key list,
  OR (simplest, no new dep) a `Vec<(String,String)>` used as an ordered map. **Decision: a
  `Vec<(String,String)>`** behind the `Rc<RefCell<…>>` — `length` = `vec.len()`, `key(i)` = the i-th
  key in insertion order, `getItem`/`setItem`/`removeItem` linear-scan by key (storage is tiny; O(n)
  is irrelevant). Avoids a new `indexmap` dep and gives spec-correct `key(index)` ordering for free.
  (If the implementer prefers `indexmap` and it is already in the tree, that is equivalent — but do
  **not** add a dep for this.)

### 1.2 Where the maps live — two `Rc<RefCell<…>>` in `DomState`

```rust
// crates/js/src/dom/mod.rs — extend DomState
#[derive(Trace, Finalize, JsData)]
pub(crate) struct DomState {
    // ... existing fields (doc, cache, listeners, timers, author_sheets, base, loader) ...

    /// E8-M3: the per-render in-memory `localStorage` backing store (insertion-
    /// ordered string→string). Plain data (no Gc pointers) → ignored by the GC
    /// trace. Born + dropped with this `DomState` (one per `run_scripts`), so it
    /// is naturally per-render: no persistence, cleared automatically each render.
    #[unsafe_ignore_trace]
    pub local_storage: Rc<RefCell<Vec<(String, String)>>>,
    /// E8-M3: the `sessionStorage` backing store — an INDEPENDENT map, identical
    /// implementation. (Per-render, both stores are equivalent in behavior; they
    /// differ only in identity — a key set on one is not visible on the other.)
    #[unsafe_ignore_trace]
    pub session_storage: Rc<RefCell<Vec<(String, String)>>>,
}
```

Seeded in `dom::install` (`mod.rs:237`) alongside the existing fields:
`local_storage: Rc::new(RefCell::new(Vec::new())), session_storage: Rc::new(RefCell::new(Vec::new()))`.

> The closures that implement `getItem`/etc. also need to reach the map. Two equivalent ways: (a)
> capture an `Rc` clone of the map directly into each method closure (like `console`'s `ConsoleSink`),
> or (b) read `DomState` inside each closure. **(a) is simpler** — the `build_storage_object` helper
> (§1.3) is handed the `Rc<RefCell<Vec<…>>>` and clones it into each method closure. The `DomState`
> field exists mainly so the same `Rc` is reachable if other code ever needs it; the closures own
> their own clones. (We still store it in `DomState` for symmetry + future-proofing — cheap.)

A `Trace`-able newtype wraps the `Rc` for capture (mirroring `ConsoleSink`, `console.rs:19-26`):

```rust
// crates/js/src/dom/storage.rs (new)
#[derive(Clone, Finalize)]
struct Store(Rc<RefCell<Vec<(String, String)>>>);
// SAFETY: holds only an Rc<RefCell<Vec<(String,String)>>> — no Boa Gc pointers — nothing to trace.
unsafe impl Trace for Store { boa_gc::empty_trace!(); }
```

### 1.3 The Storage object + its methods

`build_storage_object(map: Rc<RefCell<Vec<(String,String)>>>, ctx) -> JsObject` builds a plain object
with five methods + a `length` accessor, each capturing a `Store(map.clone())`:

```rust
// crates/js/src/dom/storage.rs (new)
pub(crate) fn build_storage_object(
    map: Rc<RefCell<Vec<(String, String)>>>,
    ctx: &mut Context,
) -> JsObject {
    let mut init = ObjectInitializer::new(ctx);

    // getItem(key) -> string | null
    init.function(getter(&map), js_string!("getItem"), 1);
    // setItem(key, value) -> undefined  (BOTH coerced to string per the IDL)
    init.function(setter(&map), js_string!("setItem"), 2);
    // removeItem(key) -> undefined
    init.function(remover(&map), js_string!("removeItem"), 1);
    // clear() -> undefined
    init.function(clearer(&map), js_string!("clear"), 0);
    // key(index) -> string | null  (the index-th key in insertion order)
    init.function(keyer(&map), js_string!("key"), 1);

    // length accessor (read-only): the number of stored entries.
    let len_get = NativeFunction::from_copy_closure_with_captures(
        |_t, _a, cap: &Store, _ctx| Ok(JsValue::from(cap.0.borrow().len() as u32)),
        Store(map.clone()),
    );
    let realm = init.context().realm().clone();
    let len_get = FunctionObjectBuilder::new(&realm, len_get).build();
    init.accessor(js_string!("length"), Some(len_get), None, Attribute::all());

    init.build()
}
```

Method semantics (each closure captures `Store(map.clone())`, borrows the `Vec`):

| method | behavior |
|---|---|
| `getItem(key)` | coerce `key` to string; linear-scan; `Some(v)` → `JsString`, else **`null`** (NOT `undefined` — the IDL returns `null` for a missing key). |
| `setItem(key, value)` | coerce **both** to string (via `arg_str` → uses `to_string(ctx)`); if key exists, replace value (keep position); else push `(key, value)` (insertion order preserved). |
| `removeItem(key)` | coerce key; `vec.retain(|(k,_)| k != &key)`. No-op if absent. |
| `clear()` | `vec.clear()`. |
| `key(index)` | coerce `index` to a `u32` (`to_number`/`to_u32`); return the index-th key's **name** as a string, or **`null`** if out of range. |
| `length` | accessor → `vec.len()` as a number. |

> **Coercion detail:** `setItem(1, true)` stores `"1" → "true"`; `getItem(1)` (number) coerces to
> `"1"` and finds it. `arg_str` (`node.rs:73`) already does `v.to_string(ctx)` coercion — reuse it.
> `key(index)` coerces a non-integer index per the IDL's `unsigned long` (`to_u32`); a fractional/NaN
> index → `0`/out-of-range → `null`.

### 1.4 Registration

`localStorage`/`sessionStorage` are **read-only global properties** (you can't reassign
`localStorage = …`), each holding a `build_storage_object` over the respective `DomState` map:

```rust
// in globals::install, after dom::install seeds the maps:
let (local_map, session_map) = crate::dom::storage::maps(ctx);   // clone the two Rc out of DomState
let local = crate::dom::storage::build_storage_object(local_map, ctx);
let session = crate::dom::storage::build_storage_object(session_map, ctx);
let _ = ctx.register_global_property(js_string!("localStorage"), local, Attribute::READONLY);
let _ = ctx.register_global_property(js_string!("sessionStorage"), session, Attribute::READONLY);
```

`storage::maps(ctx)` is a tiny helper that reads `DomState.{local_storage,session_storage}` and
returns the two `Rc` clones (so the objects share the *same* `Vec` the `DomState` holds).

### 1.5 Property / bracket access — DEFERRED (methods-only), documented

`localStorage.foo = "x"` / `localStorage["foo"]` / `delete localStorage.foo` are the *legacy
platform object* **named-property getter/setter/deleter** — exotic behavior requiring a custom
`[[Get]]`/`[[Set]]`/`[[Delete]]`/`[[OwnPropertyKeys]]` (a Boa `Proxy` or a custom exotic object). Per
the task brief and Simplicity First, **M3 supports the METHOD API fully** (`getItem`/`setItem`/…) and
treats bracket/dot access as a **non-goal** (§7). A plain object would let `localStorage.foo = "x"`
set an ordinary JS own-property that `getItem("foo")` would *not* see — inconsistent — so we **do not**
pretend to support it; scripts must use `getItem`/`setItem`. Note §7. (If a future milestone wants it,
a Boa `Proxy` wrapping the method object, trapping `get`/`set`/`deleteProperty`/`ownKeys` to route to
the same `Vec`, is the clean add — out of scope now.)

## 3. `Element.dataset` — read the `data-*` attributes (write a thin stretch)

### 3.1 Decision — a fresh object per `.dataset` access; READ full, WRITE supported via accessor

`el.dataset` returns a **plain `JsObject` built on each access** (the `el.style`/`el.classList`
precedent, `style.rs`), so it always reflects the element's *current* attributes. Two sub-decisions:

- **READ (required):** at build time, enumerate the element's `data-*` attributes and add each as a
  property keyed by its **camelCase** name (value = the attribute's string value). This is a snapshot
  of the attributes *at access time* — re-reading `el.dataset.foo` after `el.dataset` was captured in
  a variable reflects the value as of *that* `.dataset` call (standard caveat; `el.style` has the same
  per-access shape). A fresh `el.dataset` access re-enumerates.
- **WRITE (supported, low-cost):** we make each known `data-*` property an **accessor** (getter +
  setter) closing over the element `NodeHandle` + the kebab attribute name, reusing the existing
  `accessor_prop` shape (`style.rs:173`). The setter does `set_attribute(id, "data-foo-bar", v)`.
  **The only gap:** setting a *brand-new* key not present at `.dataset`-build time
  (`el.dataset.newKey = "v"`) won't have a pre-built accessor, so it'd land as an ordinary JS property
  and NOT write the attribute. **Decision:** support **write to existing `data-*` keys** via accessors
  (covers the common read-modify-write), and additionally expose a tiny **`set(name, value)` helper
  method** on the dataset object for setting *new* keys (`el.dataset.set('newKey','v')` →
  `data-new-key`) — a pragmatic non-standard escape hatch so a script *can* add a data attribute
  without exotic-setter machinery. Full standard "assign any new camelCase property writes the
  attribute" is the **exotic-named-property** case (same machinery as Storage §1.5) and is **deferred**
  (§7). (If the implementer finds even the existing-key accessor write awkward, READ-only + the `set`
  helper is the acceptable floor — but the existing-key accessor is cheap and recommended.)

### 3.2 The camelCase ↔ kebab mapping

The HTML `dataset` name conversion (the WHATWG subset we implement):

- **attribute → property (read):** strip the leading `data-`, then **camelCase**: each `-x`
  (a hyphen followed by an ASCII letter) becomes the uppercased letter; other characters pass through.
  - `data-foo-bar` → `fooBar`; `data-foo` → `foo`; `data-x` → `x`; `data-foo-bar-baz` → `fooBarBaz`.
  - `data-` with nothing after → property name `""` (degenerate; we skip empty names).
- **property → attribute (write):** prefix `data-`, then **kebab-case**: each ASCII uppercase letter
  `X` becomes `-x` (lowercased).
  - `fooBar` → `data-foo-bar`; `foo` → `data-foo`; `x` → `data-x`.
  - (The spec restricts/throws on a property name containing a `-` immediately followed by a letter, or
    a name producing an invalid attribute; we keep it simple — straight kebab transform, no validation.
    Note §7.)

```rust
// crates/js/src/dom/dataset.rs (new)
/// `data-foo-bar` (the part after `data-`) → `fooBar`.
fn attr_to_camel(rest: &str) -> String {
    let mut out = String::with_capacity(rest.len());
    let mut up = false;
    for c in rest.chars() {
        if c == '-' { up = true; }
        else if up { out.extend(c.to_uppercase()); up = false; }
        else { out.push(c); }
    }
    out
}
/// `fooBar` → `data-foo-bar`.
fn camel_to_attr(name: &str) -> String {
    let mut out = String::from("data-");
    for c in name.chars() {
        if c.is_ascii_uppercase() { out.push('-'); out.push(c.to_ascii_lowercase()); }
        else { out.push(c); }
    }
    out
}
```

### 3.3 The dataset object

```rust
// crates/js/src/dom/dataset.rs (new)
pub(crate) fn dataset_object(h: NodeHandle, ctx: &mut Context) -> JsResult<JsValue> {
    // 1. Snapshot the element's current data-* attributes (camelKey, kebabAttr) pairs.
    let pairs: Vec<(String, String)> = {                 // (camelProp, kebabAttrName)
        let doc = h.shared.borrow();
        match doc.kind(h.id) {
            NodeKind::Element(e) => e.attrs.iter()
                .filter(|a| a.name.starts_with("data-") && a.name.len() > 5)
                .map(|a| (attr_to_camel(&a.name[5..]), a.name.clone()))
                .filter(|(camel, _)| !camel.is_empty())
                .collect(),
            _ => Vec::new(),
        }
    };

    let mut init = ObjectInitializer::new(ctx);
    // 2. One accessor per existing data-* key: get reads, set writes the attribute.
    for (camel, attr) in pairs {
        accessor_data_prop(&mut init, &camel, h.clone(), attr);   // §3.3 helper, mirrors style::accessor_prop
    }
    // 3. A non-standard `set(name, value)` escape-hatch for adding NEW keys (§3.1).
    init.function(
        {
            let h = h.clone();
            NativeFunction::from_copy_closure_with_captures(
                move |_t, args, cap: &NodeHandle, ctx| {
                    let name = arg_str(args, 0, ctx)?;
                    let value = arg_str(args, 1, ctx)?;
                    cap.shared.borrow_mut().set_attribute(cap.id, &camel_to_attr(&name), &value);
                    Ok(JsValue::undefined())
                }, h)
        },
        js_string!("set"), 2,
    );
    Ok(init.build().into())
}
```

`accessor_data_prop` is the `style::accessor_prop` shape (`style.rs:173`): a getter closure reading
`doc.get_attribute(id, &attr)` (→ string, or `""`/absent) and a setter closure calling
`set_attribute(id, &attr, &v)`, both over the captured `NodeHandle` + the kebab `attr` string.

Wired on the `Node` class (`node.rs:13`, next to `classList`):

```rust
accessor(class, "dataset", get_dataset, None);   // read-only accessor → builds the dataset object
// get_dataset: let h = NodeHandle::from_this(this)?; super::dataset::dataset_object(h, ctx)
```

> On a non-element node `el.dataset` is an empty object (`pairs` empty) — harmless. A `data-` attr
> with an empty remainder (`data-`) is skipped (empty camel name). Numeric-leading remainders
> (`data-1`) camelCase straight through (`1`) — accessible via bracket `el.dataset["1"]` (a JS
> own-property; bracket *read* works on a plain object, it's only Storage's named-*setter* that needs
> exotic machinery — dataset read via bracket is fine since the props are real own-properties).

## 4. `URL` / `URLSearchParams` — native classes over the `url` crate

Two native classes (`impl Class`), registered in `dom::install` alongside `Xhr`
(`ctx.register_global_class::<UrlClass>()`, `…::<UrlSearchParams>()`). Both are **JS-constructible**
(`new URL(...)`, `new URLSearchParams(...)`), so each `data_constructor` parses its args into instance
data.

### 4.1 `URL` — `new URL(url[, base])`

```rust
// crates/js/src/dom/url.rs (new)
#[derive(Trace, Finalize, JsData)]
pub(crate) struct UrlClass {
    #[unsafe_ignore_trace] url: url::Url,   // the parsed WHATWG URL
}

impl Class for UrlClass {
    const NAME: &'static str = "URL";
    const LENGTH: usize = 1;
    fn data_constructor(_nt: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<Self> {
        let input = arg_str(args, 0, ctx)?;
        let parsed = match args.get(1) {
            Some(v) if !v.is_undefined() && !v.is_null() => {
                let base_str = v.to_string(ctx)?.to_std_string_escaped();
                let base = url::Url::parse(&base_str)
                    .map_err(|e| type_err(&format!("Invalid base URL: {e}")))?;
                base.join(&input)
            }
            _ => url::Url::parse(&input),
        };
        let url = parsed.map_err(|e| type_err(&format!("Invalid URL: {e}")))?;  // ctor THROWS on bad URL
        Ok(UrlClass { url })
    }
    fn init(class: &mut ClassBuilder<'_>) -> JsResult<()> {
        accessor(class, "href",         get_href,        None);  // (setters DEFERRED — read-only, §7)
        accessor(class, "protocol",     get_protocol,    None);  // "https:"
        accessor(class, "host",         get_host,        None);  // "a.com:8080"
        accessor(class, "hostname",     get_hostname,    None);  // "a.com"
        accessor(class, "port",         get_port,        None);  // "8080" or ""
        accessor(class, "pathname",     get_pathname,    None);  // "/p"
        accessor(class, "search",       get_search,      None);  // "?q=1" or ""
        accessor(class, "hash",         get_hash,        None);  // "#h" or ""
        accessor(class, "origin",       get_origin,      None);  // "https://a.com:8080"
        accessor(class, "searchParams", get_search_params, None);// a URLSearchParams over the query
        method(class, "toString", 0, url_to_string);             // === href
        Ok(())
    }
}
```

Accessor formatting (each: `with_url(this, |u| …)` downcast like `with_xhr`, then map the `url` crate
field to the WHATWG string form):

| property | `url` crate source | format |
|---|---|---|
| `href` | `u.as_str()` | the full serialization |
| `protocol` | `u.scheme()` | `format!("{}:", scheme)` (WHATWG includes the colon) |
| `host` | `u.host_str()` + `u.port()` | `host` + (`:port` if a non-default port present) else `""` |
| `hostname` | `u.host_str()` | host without port, or `""` |
| `port` | `u.port()` | the port number as a string, or `""` if absent/default |
| `pathname` | `u.path()` | `"/p"` |
| `search` | `u.query()` | `Some(q)` → `format!("?{q}")`, `None`/empty → `""` |
| `hash` | `u.fragment()` | `Some(f)` → `format!("#{f}")`, `None` → `""` |
| `origin` | `u.origin().ascii_serialization()` | `"https://a.com:8080"` (opaque origins → `"null"`) |
| `searchParams` | `u.query().unwrap_or("")` | a **new** `URLSearchParams` instance built from the query string (§4.2) |
| `toString()` | `u.as_str()` | === `href` |

> **`searchParams` caveat:** per spec it is a *live* object whose mutations write back to the URL's
> query. We build a **fresh `URLSearchParams` snapshot** of the query on each `.searchParams` access
> (the `el.style` per-access pattern again). Mutating it does **not** write back to the parent `URL`
> (no back-link). This is the pragmatic M3 choice; the common read (`url.searchParams.get('q')`)
> works. Note §7. (Round-trip editing via `URL.search =` setter is also deferred — `URL` is read-only
> in M3.)

### 4.2 `URLSearchParams`

```rust
// crates/js/src/dom/url.rs (new)
#[derive(Trace, Finalize, JsData, Default)]
pub(crate) struct UrlSearchParams {
    #[unsafe_ignore_trace] pairs: Vec<(String, String)>,   // ordered (name, value) pairs
}

impl Class for UrlSearchParams {
    const NAME: &'static str = "URLSearchParams";
    const LENGTH: usize = 0;
    fn data_constructor(_nt: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<Self> {
        // M3 accepts a STRING init ("a=1&b=2", optional leading "?"). A record/array/another
        // URLSearchParams init is DEFERRED (§7) — coerce to string for now.
        let init = arg_str(args, 0, ctx)?;
        Ok(UrlSearchParams { pairs: parse_query(&init) })
    }
    fn init(class: &mut ClassBuilder<'_>) -> JsResult<()> {
        method(class, "get",    1, usp_get);       // first value for name, or null
        method(class, "getAll", 1, usp_get_all);   // JS Array of all values for name
        method(class, "has",    1, usp_has);       // bool
        method(class, "set",    2, usp_set);       // replace all values for name with one
        method(class, "append", 2, usp_append);    // add a (name, value) pair
        method(class, "delete", 1, usp_delete);    // remove all pairs for name
        method(class, "toString", 0, usp_to_string);
        method(class, "forEach", 1, usp_for_each); // callback(value, name, this)
        Ok(())
    }
}

/// Parse "a=1&b=2" (optional leading '?') into ordered (name, value) pairs, with
/// percent-decoding + '+' → space. Reuse `url::Url`'s parser via a throwaway URL
/// so encoding matches the platform: `url::Url::parse(&format!("http://x/?{q}"))`
/// then `.query_pairs()`. (Or `form_urlencoded::parse` — but that needs the
/// `form_urlencoded` crate; the throwaway-URL trick needs NO new dep.)
fn parse_query(s: &str) -> Vec<(String, String)> {
    let q = s.strip_prefix('?').unwrap_or(s);
    if q.is_empty() { return Vec::new(); }
    match url::Url::parse(&format!("http://x/?{q}")) {
        Ok(u) => u.query_pairs().map(|(k, v)| (k.into_owned(), v.into_owned())).collect(),
        Err(_) => Vec::new(),
    }
}
```

Method semantics (each `with_usp`/`with_usp_mut` downcast like `with_xhr`):

| method | behavior |
|---|---|
| `get(name)` | first pair with that name → its value (`JsString`), else **`null`**. |
| `getAll(name)` | a JS `Array` (`JsArray::from_iter`) of all values for `name` (empty array if none). |
| `has(name)` | `true` if any pair has that name. |
| `set(name, value)` | remove all pairs named `name`, then push one `(name, value)`. (Spec: replaces in place at first occurrence; M3's remove-then-append at end is acceptable — note §7 ordering.) |
| `append(name, value)` | push `(name, value)` (duplicates allowed). |
| `delete(name)` | `pairs.retain(|(k,_)| k != name)`. |
| `toString()` | serialize back to `a=1&b=2` with proper `application/x-www-form-urlencoded` encoding — reuse the throwaway-URL trick: build `url::Url`, `query_pairs_mut().clear().extend_pairs(&pairs)`, take `.query()`. |
| `forEach(cb)` | call `cb(value, name, this)` for each pair in order (via `JsObject::call`). |

> **Encoding** is delegated to the `url` crate (parse + serialize), so `a=hello%20world` decodes to
> `"hello world"` and `toString` re-encodes — matching the platform without hand-rolling
> percent-encoding. The subtle differences between WHATWG `application/x-www-form-urlencoded` and the
> URL query encoding (space → `+` vs `%20`) are the `url` crate's `query_pairs_mut` behavior; we accept
> whatever it produces (note §7).

## 5. console additions — `dir` / `table` / `assert` (trivial)

Reuse `console::install`'s `make_logger` + `stringify_args` (`console.rs:46,61`). Add three methods to
the `ObjectInitializer` in `console.rs:32-38`:

- **`console.dir(obj)`** — for M3, **identical to `console.log`**: `stringify_args` the arg and push a
  `ConsoleLevel::Log` message. (Real `dir` shows an interactive object tree; we have no UI — log the
  coerced string. Note §7.) → `.function(make_logger(ConsoleLevel::Log, &sink), js_string!("dir"), 0)`.
- **`console.table(data)`** — **minimal**: same as `console.log` (stringify the arg). A real ASCII
  table is out of scope; logging the value is the trivial floor. Note §7. →
  `.function(make_logger(ConsoleLevel::Log, &sink), js_string!("table"), 0)`.
- **`console.assert(cond, ...msg)`** — if `args[0]` is **falsy** (`!args[0].to_boolean()`), push a
  message (`ConsoleLevel::Error`) prefixed `"Assertion failed:"` + `stringify_args(&args[1..])`; if
  truthy, do nothing. This needs a **dedicated small closure** (not `make_logger`, since it inspects
  `args[0]` + slices) capturing the sink:

```rust
// console.rs — a fourth helper alongside make_logger
fn make_assert(sink: &Rc<RefCell<Vec<ConsoleMessage>>>) -> NativeFunction {
    let captured = ConsoleSink(sink.clone());
    NativeFunction::from_copy_closure_with_captures(
        move |_this, args, captures: &ConsoleSink, ctx| {
            let cond = args.first().map(|v| v.to_boolean()).unwrap_or(false);
            if !cond {
                let rest = stringify_args(args.get(1..).unwrap_or(&[]), ctx);
                let text = if rest.is_empty() { "Assertion failed".to_string() }
                           else { format!("Assertion failed: {rest}") };
                captures.0.borrow_mut().push(ConsoleMessage { level: ConsoleLevel::Error, text });
            }
            Ok(JsValue::undefined())
        },
        captured,
    )
}
```

Wired:
```rust
.function(make_logger(ConsoleLevel::Log, &sink), js_string!("dir"), 0)
.function(make_logger(ConsoleLevel::Log, &sink), js_string!("table"), 0)
.function(make_assert(&sink), js_string!("assert"), 0)
```

`stringify_args`'s signature already takes `&[JsValue]`; `args.get(1..)` slicing works directly.

## 7. Edge cases & non-goals (deliberate)

**Delivered:** method-based `localStorage`/`sessionStorage` (getItem/setItem/removeItem/clear/length/
key, two independent per-render stores); `JSON` confirmed (Boa built-in, tested); `el.dataset` read
(camelCase data-* snapshot) + existing-key accessor write + a `set(name,value)` helper for new keys;
`new URL(url[,base])` (href/protocol/host/hostname/port/pathname/search/hash/origin/searchParams/
toString) + `URLSearchParams` (get/getAll/has/set/append/delete/toString/forEach); `console.dir`/
`table`/`assert`.

**Non-goals / documented limits:**
- **Storage bracket/property access** — `localStorage.foo`/`localStorage["foo"]`/`delete` (the legacy
  named-property exotic getter/setter/deleter) is **NOT** supported; use `getItem`/`setItem`/
  `removeItem`. (§1.5.) A `Proxy`-based exotic object is the future add.
- **Storage persistence / quota / `storage` events / cross-realm sharing** — none. Per-render in-memory
  only; both stores reset every `run_scripts` (a fresh `Context`). `sessionStorage` and `localStorage`
  are **identical in implementation**, differing only in identity (separate maps). No `QuotaExceededError`.
- **dataset full standard write** — assigning an *arbitrary new* camelCase property
  (`el.dataset.brandNew = "v"`) does NOT auto-write the attribute (that needs the exotic named-property
  machinery); use the `set(name, value)` helper or `setAttribute`. Existing-key write + read are full.
  No validation of property names (a name with an embedded `-`+letter is not rejected). dataset is a
  **per-access snapshot** (capturing `el.dataset` in a var then re-reading reflects access-time state).
- **`URL` setters** — `url.href = …`/`url.pathname = …`/`url.search = …` etc. are **read-only** in M3
  (no setters). `url.searchParams` is a **fresh snapshot**, not live — mutating it does not write back
  to the parent URL.
- **`URLSearchParams` non-string init** — only a string (or string-coercible) init; a record/2D-array/
  iterable/another `URLSearchParams` init is deferred. No iterator protocol (`entries`/`keys`/`values`/
  `for…of`/`Symbol.iterator`); `forEach` is provided. `set` ordering is remove-then-append (not
  in-place at first occurrence). `sort()` deferred. Encoding follows the `url` crate (space `+`/`%20`
  subtleties accepted as-is).
- **`URL` WHATWG edge cases** — whatever `url::Url::parse` does (it is a solid WHATWG impl, but a few
  spec corners — e.g. special-scheme normalization details — are the crate's behavior, not hand-tuned).
  An invalid URL throws a `TypeError` from the constructor (spec-correct).
- **`console.dir`/`table`** — both behave like `console.log` (stringify + capture); no object-tree
  inspector, no ASCII grid. `console.assert` logs an `Error`-level "Assertion failed[: msg]" on a falsy
  first arg, nothing on truthy.
- **`structuredClone`** — deferred (not in scope).
- **`JSON`** — Boa's intrinsic, untouched; no custom reviver/replacer handling beyond what Boa provides.

All native-fn errors are caught by `run_scripts` (a thrown ctor/method error lands in
`ScriptOutcome.errors`; the page always renders).

## 8. Test plan (concrete)

`js` unit tests drive `run_scripts` directly (the existing `run`/`log_of`/`lines_of`/`find_id`
helpers in `lib.rs` tests; `run` passes a loader + `Rc::new(Vec::new())` sheets). Most M3 tests are
**pure-JS via `console.log` probes** (no DOM/network needed) — assert the captured console lines.

**localStorage (methods):**
1. `localStorage.setItem('k','v'); console.log(localStorage.getItem('k'))` → `"v"`.
2. `console.log(localStorage.getItem('missing'))` → `"null"` (the IDL null, not undefined).
3. `localStorage.setItem('a','1'); localStorage.setItem('b','2'); console.log(localStorage.length)` → `"2"`;
   `console.log(localStorage.key(0), localStorage.key(1))` → `"a 1"`-style ordering (`"a b"`);
   `console.log(localStorage.key(5))` → `"null"` (out of range).
4. `localStorage.setItem('k','v'); localStorage.removeItem('k'); console.log(localStorage.getItem('k'), localStorage.length)`
   → `"null 0"`.
5. `localStorage.setItem('k','v'); localStorage.clear(); console.log(localStorage.length)` → `"0"`.
6. **coercion:** `localStorage.setItem(1, true); console.log(localStorage.getItem('1'))` → `"true"`.
7. **independence:** `localStorage.setItem('k','L'); sessionStorage.setItem('k','S');
   console.log(localStorage.getItem('k'), sessionStorage.getItem('k'))` → `"L S"` (separate stores).
8. **per-render reset:** a second `run_scripts` over a page with no setItem → `localStorage.length === 0`
   (the store did not persist across calls).

**JSON (confirm Boa built-in):**
9. `console.log(JSON.stringify({a:1}))` → `'{"a":1}'`.
10. `console.log(JSON.parse('{"a":1}').a)` → `"1"` (round-trip).
11. round-trip: `var o={x:[1,2],y:"s"}; console.log(JSON.stringify(JSON.parse(JSON.stringify(o))))`
    → the same JSON string.

**dataset (read + write):**
12. `<div id='d' data-foo-bar='hello' data-x='1'></div>`:
    `var d=document.getElementById('d'); console.log(d.dataset.fooBar, d.dataset.x)` → `"hello 1"`.
13. **write existing key:** `d.dataset.fooBar='changed'; console.log(d.getAttribute('data-foo-bar'))`

**URL:**
16. `var u=new URL('https://a.com:8080/p/q?x=1&y=2#h');

19. **invalid URL throws:** `try { new URL('not a url'); } catch(e){ console.log('caught') }` → `"caught"`.
20. `u.searchParams.get('x')` for the URL in §16 → `"1"`.

**URLSearchParams:**
21. `var p=new URLSearchParams('a=1&b=2&a=3');
    console.log(p.get('a'), p.has('b'), p.has('z'))` → `"1 true false"`.
22. `console.log(p.getAll('a').join(','))` → `"1,3"`.
