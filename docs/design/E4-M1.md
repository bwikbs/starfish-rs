# E4-M1 — Boa integration: run `<script>`s, capture `console`, shared-`Document` ownership (design note)

Scope (per `docs/ROADMAP-epic4.md`): integrate the **Boa** pure-Rust JS engine so
a page's `<script>` elements (inline + external via the existing
`ResourceLoader`) execute **in document order** before style/layout/paint;
`console.log/warn/error/info/debug` are captured; minimal `window`/`globalThis`
globals exist so common scripts don't `ReferenceError`; and the **shared-`Document`
ownership refactor** lands so E4-M2 can bind DOM mutation **without re-plumbing
style/layout/paint**. **No DOM bindings in M1** beyond a trivial read-only probe
(`document.title`/`document` existence). Script errors are **non-fatal** — the page
still renders.

This note is pinned to the **real** current APIs read from source (signatures
quoted inline). The exact Boa crate version + the exact `boa_engine` calls
(`Context`, `Source`, `eval`, registering native functions/globals, capturing
output) are confirmed by the companion **ANALYSIS** agent; where this note shows a
Boa call it shows the *shape* — the implementation uses the analysis agent's exact
signatures and pins the version from `Cargo.lock`.

Guiding rule (project CLAUDE.md "Simplicity First"): engine + script running +
console + minimal globals, nothing more. The ownership refactor must **not churn**
`style_tree`/`layout`/`paint` signatures. DOM bindings, events, and timers are
explicitly deferred (M2/M3). Deviations are called out in §7.

## 1. New `js` crate (`crates/js`)

A workspace crate owning the Boa `Context`, script collection/execution, the
`console` capture, and the minimal globals. It depends on `boa_engine`, on
`starfish-dom` (to walk the DOM for `<script>`s and the read-only `document`
probe), and on `starfish-net` (for the `ResourceLoader`/`Url` to fetch external
scripts). It does **not** depend on style/layout/paint (leaf-ish; paint depends
on it, not vice-versa — no cycle).

### 1.3 Public surface (`crates/js/src/lib.rs`)

The crate exposes **one entry point** plus its result/types:

```rust
use starfish_dom::Document;
use starfish_net::{ResourceLoader, Url};

/// One captured console call.
#[derive(Debug, Clone, PartialEq)]
pub struct ConsoleMessage {
    pub level: ConsoleLevel,
    pub text: String,          // already-stringified, space-joined args
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ConsoleLevel { Log, Info, Warn, Error, Debug }

/// One uncaught script error (a thrown value or a load failure), captured —
/// never propagated. `text` is the engine's display of the thrown value (or a
/// "failed to load <url>" message). Execution continues with the next script.
#[derive(Debug, Clone)]
pub struct ScriptError {
    pub text: String,
}

/// What `run_scripts` produces. Purely observational in M1 (the DOM is mutated
/// in place via `doc`); nothing here is fatal.
#[derive(Debug, Default)]
pub struct ScriptOutcome {
    pub console: Vec<ConsoleMessage>,
    pub errors: Vec<ScriptError>,
    /// Number of `<script>` elements actually executed (skipped modules / failed
    /// loads not counted) — handy for tests/diagnostics.
    pub executed: usize,
}

/// Execute every `<script>` in `doc` in document order against a single shared
/// Boa context, fetching external scripts (`<script src>`) against `base`
/// through `loader`. Mutates `doc` in place (M1: no DOM bindings, so the arena
/// is unchanged — the signature is shaped for M2, where bindings write here).
///
/// NEVER panics, NEVER returns `Err`: a script that throws or a `src` that fails
/// to load is captured into the returned `ScriptOutcome` and execution proceeds.
pub fn run_scripts(
    doc: &mut Document,
    base: &Url,
    loader: &dyn ResourceLoader,
) -> ScriptOutcome;
```

Why `&mut Document` (not `Rc<RefCell<Document>>`) in the public signature: §2
explains. The `&mut` is what lets M2 hand Boa a handle that writes into this same
arena, while M1 simply doesn't write. The caller (`render_document`) owns the
`Document` and lends it mutably for the JS phase, then continues to lend it
`&Document` to style/layout — **no ownership churn in paint**.

Internal modules:
```
crates/js/src/
  lib.rs        # public API above; orchestrates run_scripts
  collect.rs    # walk DOM → Vec<ScriptSource> in document order (§3)
  console.rs    # register the capturing `console` object (§4)
  globals.rs    # window/globalThis alias + navigator/location/document stubs (§4)
```

## 2. Shared `Document` ownership — THE decision

**Decision: the JS phase borrows the `Document` mutably (`&mut Document`) as a
distinct pipeline phase inside `render_document`; style/layout/paint keep
borrowing `&Document` unchanged. The `Rc<RefCell<…>>` sharing needed for Boa host
objects lives *entirely inside the `js` crate* and is built up + torn down within
`run_scripts`.** This is option **(c)** from the milestone brief, made minimal.

### 2.1 Why not thread `Rc<RefCell<Document>>` everywhere (option a)

`style_tree(&Document, …)` and `layout(&Document, …)` and the whole paint
pipeline take `&Document`. Switching the canonical type to
`Rc<RefCell<Document>>` would force every call site, every test
(`crates/{style,layout,paint}` have dozens), and every internal borrow to become
`doc.borrow()` — a large, churny diff that the milestone explicitly says to
avoid, and that buys nothing for M1 (no mutation yet). Rejected.

### 2.2 Why not "JS owns then returns by value" only (option b)

Taking `Document` by value into `run_scripts` and returning it works, but for M2
the Boa host objects must hold a **shared, `'static`-ish, clonable** handle to the
arena (Boa stores native objects in its GC heap, which outlives any single
`&mut` borrow frame). A bare owned `Document` moved in/out can't be co-held by GC
objects during a script. So the *internal* representation while scripts run must
be `Rc<RefCell<Document>>` regardless. We keep the **external** contract as a
plain borrow and convert at the boundary.

### 2.3 The chosen shape — convert at the `run_scripts` boundary

```rust
pub fn run_scripts(doc: &mut Document, base: &Url, loader: &dyn ResourceLoader)
    -> ScriptOutcome
{
    // 1. Collect script sources up front (immutable walk), so we don't hold a
    //    borrow of `doc` across the move into the Rc (and so document-order is
    //    fixed before any script could mutate the tree in M2).
    let scripts = collect::collect_scripts(doc, base, loader);   // Vec<ScriptSource>
    if scripts.is_empty() {
        return ScriptOutcome::default();                          // zero overhead (§7)
    }

    // 2. Move the Document into a shared cell for the duration of scripting.
    //    `std::mem::take` swaps in an empty Document (cheap: Document::default()
    //    is a 1-node arena), leaving `*doc` valid but empty while JS runs.
    let shared: Rc<RefCell<Document>> = Rc::new(RefCell::new(std::mem::take(doc)));

    // 3. Build the Boa context, register console + globals (+ in M2: the
    //    `document` host object holding `shared.clone()`).
    let mut ctx = Context::default();
    let console_sink = console::install(&mut ctx);                // Rc<RefCell<Vec<ConsoleMessage>>>
    globals::install(&mut ctx, &shared, base);                    // window/navigator/location/document

    // 4. Execute each script in order in the SHARED context (§3).
    let mut errors = Vec::new();
    let mut executed = 0;
    for src in scripts {
        match ctx.eval(Source::from_bytes(src.code.as_bytes())) {
            Ok(_) => executed += 1,
            Err(e) => errors.push(ScriptError { text: e.to_string() }),  // non-fatal
        }
    }

    // 5. Reclaim the Document. Drop the Boa context first so no GC object still
    //    holds a clone of `shared` (M2: the `document` host object). Then
    //    Rc::try_unwrap is guaranteed to succeed (strong count == 1).
    drop(ctx);
    let recovered = Rc::try_unwrap(shared)
        .map(RefCell::into_inner)
        .unwrap_or_else(|rc| rc.borrow().clone_arena());  // defensive; see note
    *doc = recovered;

    ScriptOutcome {
        console: console_sink.take(),     // move out the captured messages
        errors,
        executed,
    }
}
```

Key properties:
- **style/layout/paint signatures untouched.** They still receive `&Document`
  after `run_scripts` returns; the `*doc` they read is the post-script arena.
- **M1 is trivial:** no host object clones `shared`, so step 5's `try_unwrap`
  always hits strong-count 1. The `clone_arena` fallback (a tiny new
  `Document::clone_arena(&self) -> Document` deep-copy, or simply
  `unreachable!()`/`expect`) exists only to guarantee non-panic if a future M2
  bug leaks a clone; **M1 may use `.expect("no live JS handle to Document")`**
  and add the clone path in M2. *Simplicity First: M1 uses `expect`; the fallback
  is a one-line M2 addition, documented, not built now.*
- **`std::mem::take(doc)`** requires `Document: Default` — it already is
  (`impl Default for Document` exists). The temporary empty document is never
  observed (we overwrite `*doc` before returning).
- The internal `Rc<RefCell<Document>>` is the **exact type M2 hands to Boa host
  objects** (`Rc::clone(&shared)` stored in each `document`/`Element` wrapper).
  M1 builds it (step 2) and tears it down (step 5) even though no host object
  holds it — so M2 slots in by (a) cloning `shared` into the `document` host
  object in `globals::install`, and (b) keeping the `drop(ctx)`-before-unwrap
  ordering. **No re-plumbing.**

### 2.4 `NodeId` stability note (for M2, recorded now)

`NodeId` is an index into the arena `Vec`; `append_child` only ever pushes
(never removes/compacts), so ids stay valid across script mutation. M2's host
objects can safely store a `NodeId` + the `Rc<RefCell<Document>>` and re-resolve
on each access. (Recorded so the M1 ownership choice is known-compatible; no code
in M1.)

## 3. Script collection + execution order (`crates/js/src/collect.rs`)

### 3.1 Walk

A single document-order DFS (same shape as paint's `collect_author_sheets` /
`decode_images`: push children reversed, `pop()` yields document order). For each
`<script>` element, classify and produce a `ScriptSource`:

```rust
struct ScriptSource { code: String }   // fully-resolved source text, ready to eval

fn collect_scripts(doc: &Document, base: &Url, loader: &dyn ResourceLoader)
    -> Vec<ScriptSource>
{
    let mut out = Vec::new();
    let mut stack = vec![doc.root()];
    while let Some(id) = stack.pop() {
        if doc.tag_name(id) == Some("script") && is_runnable_type(doc.get_attribute(id, "type")) {
            match doc.get_attribute(id, "src") {
                // External: resolve + fetch; failure → skip (non-fatal, §3.4).
                Some(src) if !src.trim().is_empty() => {
                    if let Some(code) = fetch_external(src.trim(), base, loader) {
                        out.push(ScriptSource { code });
                    }
                    // NOTE: a <script src> ignores inline text (per HTML spec).
                }
                // Inline: concatenate child Text nodes.
                _ => {
                    let code = inline_text(doc, id);
                    if !code.trim().is_empty() {
                        out.push(ScriptSource { code });
                    }
                }
            }
        }
        for c in doc.children(id).into_iter().rev() { stack.push(c); }
    }
    out
}
```

`inline_text` joins child `NodeKind::Text(t)` payloads (a `<script>`'s content is
raw text — the HTML tokenizer already places it as a single/few Text nodes).

> Collection runs on `&Document` **before** the `mem::take` (§2.3 step 1), so the
> order is fixed up front. In M1 nothing mutates the DOM, so this is equivalent
> to walking during execution; doing it first keeps the borrow simple and is
> M2-safe (a script that appends a *later* `<script>` via DOM in M2 would not be
> re-scanned — matching the brief's "defer/async ignored, run what was parsed";
> dynamic-script execution is out of scope for this epic).

### 3.2 `type` attribute handling (`is_runnable_type`)

Run a script iff its `type` is **absent**, or (case-insensitively, trimmed) one
of the classic-script MIME types:

```rust
fn is_runnable_type(t: Option<&str>) -> bool {
    match t {
        None => true,
        Some(t) => {
            let t = t.trim().to_ascii_lowercase();
            matches!(t.as_str(),
                "" | "text/javascript" | "application/javascript"
                  | "application/ecmascript" | "text/ecmascript")
        }
    }
}
```

- `type="module"` → **skipped** (modules out of scope; noted §7). Not an error,
  just not executed.
- Any other `type` (e.g. `application/json`, `text/template`, a custom data
  block) → skipped (HTML treats non-JS `type` as data, never executed).

### 3.3 Execution order — single shared `Context`

All `ScriptSource`s execute **in order in one Boa `Context`** (§2.3 step 4), so
`var`/`function`/`globalThis.x` declared in an earlier script are visible to a
later one — exactly like a real page's classic scripts sharing one global
environment. `ctx.eval(Source::from_bytes(code))` runs a classic script in the
global scope (Boa's `eval` of a top-level `Source` evaluates in the realm's
global environment; the analysis agent confirms `Source`/`eval` signatures).

`defer`/`async` attributes are **ignored** — every runnable script runs
synchronously in document order (§7). For a one-shot renderer this matches
"run-to-quiescence then render"; ordering subtleties land with timers in M3.

### 3.4 Failure handling (non-fatal everywhere)

- `<script src>` fetch failure (`base.join(src)` errors, or `loader.fetch`
  returns any `LoadError`) → `fetch_external` returns `None` → the script is
  **skipped**; optionally a `ScriptError { text: "failed to load <url>" }` is
  pushed (recorded so tests can assert it). Execution continues.
- A script that **throws** (uncaught) → `ctx.eval` returns `Err(JsError)` → push
  `ScriptError { text: err.to_string() }` and continue to the next script.
- External script bytes → **UTF-8 lossy** (`String::from_utf8_lossy`), matching
  the CSS/HTML decoding policy (§7).

## 4. console + globals

### 4.1 Capturing `console` (`crates/js/src/console.rs`)

Register a `console` object on the global with `log`, `info`, `warn`, `error`,
`debug`. Each is a `NativeFunction` (a closure that captures a shared sink)
which **stringifies its arguments and pushes a `ConsoleMessage`** into a
`Rc<RefCell<Vec<ConsoleMessage>>>` returned to `run_scripts`. We do **not** use
`boa_runtime::Console` (which prints to stdout) — we capture so `ScriptOutcome`
carries the messages; the caller may also print them (§5.3).

```rust
/// Install `console` and return the shared sink the closures push into.
pub fn install(ctx: &mut Context) -> Rc<RefCell<Vec<ConsoleMessage>>> {
    let sink = Rc::new(RefCell::new(Vec::new()));
    let console = ObjectInitializer::new(ctx)
        .function(make_log(sink.clone(), ConsoleLevel::Log),   js_string!("log"),   0)
        .function(make_log(sink.clone(), ConsoleLevel::Info),  js_string!("info"),  0)
        .function(make_log(sink.clone(), ConsoleLevel::Warn),  js_string!("warn"),  0)
        .function(make_log(sink.clone(), ConsoleLevel::Error), js_string!("error"), 0)
        .function(make_log(sink.clone(), ConsoleLevel::Debug), js_string!("debug"), 0)
        .build();
    ctx.register_global_property(js_string!("console"), console, Attribute::all())
        .expect("register console");
    sink
}
```

(`ObjectInitializer`/`NativeFunction::from_copy_closure_with_captures`/
`register_global_property` are the Boa builders the ANALYSIS agent confirms;
the exact closure-capture API — `NativeFunction::from_fn_ptr` vs
`from_copy_closure_with_captures` — is taken from the analysis. The closure
shape is: receive `&[JsValue]` args, map each via `arg.display()` /
`arg.to_string(ctx)`, join with a single space, push `ConsoleMessage`.)

**Stringify rule:** join args with a single space; each arg via Boa's value
display (`JsValue::display` for a spec-ish `console.log` rendering, falling back
to `to_string(ctx)` for the primitive coercion). Objects render as Boa renders
them (`[object Object]`/inspected form — whatever the analysis confirms
`display` yields). Good enough for M1's "capture what scripts log".

`ScriptOutcome.console` preserves call order across all scripts (one shared
sink). `sink.take()` (i.e. `RefCell::take`) moves the `Vec` out at the end.

### 4.2 Minimal globals (`crates/js/src/globals.rs`)

Goal: **common scripts run without `ReferenceError`**, with zero DOM behaviour in
M1. `Context::default()` already provides ECMAScript built-ins (`Object`,
`Array`, `JSON`, `Math`, `Date`, `String`, etc.) and `globalThis`. We add:

- **`window`** → an alias to the global object: `window === globalThis === this`
  at top level. Implemented by setting a global property `window` whose value is
  the realm's global object (`ctx.global_object()`), so `window.foo = 1` and a
  bare `foo` reference the same global. (Exact "global object as a `JsValue`" call
  per analysis; conceptually `register_global_property("window",
  global_object, all)`.)
- **`navigator`** → an object with a single read-only string `userAgent` set to
  the **starfish UA string**. Use a single shared constant
  `pub const USER_AGENT: &str = "Mozilla/5.0 (compatible; starfish-rs/0.0)";`
  (placeholder; pick the real UA the project standardizes on — note it's the only
  UA literal so it's trivial to change). `navigator.userAgent` returns it.
- **`location`** → an object with `href`, `protocol`, `host`, `pathname`,
  `origin` filled from `base` (the document `Url`): `base.as_str()`,
  `base.scheme()+":"`, `base.host_str()`, `base.path()`,
  `base.origin().ascii_serialization()`. Read-only string props. (Just enough that
  `location.href` / `window.location` don't throw; navigation is a non-goal.)
- **`document`** → a **minimal read-only stub object** (NOT the DOM binding):
  - `document.title` → the text of the first `<title>` element (scan
    `doc.borrow()` for `title` → child Text), or `""`.
  - `document.URL` → `base.as_str()`.
  - That's it. No `getElementById`, no `createElement` (those are M2). This is the
    "trivial read-only probe" the milestone allows. In M2, `globals::install`
    replaces this stub with the real `document` host object holding
    `Rc::clone(&shared)` — the **same install seam**, so M1's stub and M2's real
    object are wired identically (`register_global_property("document", …)`).

```rust
pub fn install(ctx: &mut Context, shared: &Rc<RefCell<Document>>, base: &Url) {
    // window === globalThis
    let global = ctx.global_object();
    ctx.register_global_property(js_string!("window"), global, Attribute::all()).ok();

    // navigator.userAgent
    let navigator = ObjectInitializer::new(ctx)
        .property(js_string!("userAgent"), js_string!(USER_AGENT), Attribute::READONLY)
        .build();
    ctx.register_global_property(js_string!("navigator"), navigator, Attribute::all()).ok();

    // location.{href,protocol,host,pathname,origin}
    let location = build_location(ctx, base);
    ctx.register_global_property(js_string!("location"), location, Attribute::all()).ok();

    // document (M1: read-only stub: title, URL)
    let document = build_document_stub(ctx, shared, base);
    ctx.register_global_property(js_string!("document"), document, Attribute::all()).ok();
}
```

Anything else a script touches (e.g. `setTimeout`, `addEventListener`, `fetch`,
`localStorage`) is **not** provided in M1 → a real `ReferenceError`/`TypeError`
caught per §3.4 (non-fatal). M3 adds timers/events; the brief lists these as
non-goals for M1. We do **not** speculatively stub them (Simplicity First) — but
because errors are non-fatal, a page that *optionally* uses them still renders.

## 5. Pipeline integration (`crates/paint/src/lib.rs`)

### 5.1 Where the JS phase runs

`render_document` runs the JS phase **after `parse`, before
`collect_author_sheets`/`style_tree`**, so that in M2 (when scripts mutate the
DOM) the mutations are visible to CSS collection, styling, layout, and paint. M1
has no DOM effect, so the only observable effect is captured console/errors — but
the **order is designed for M2** (parse → run_scripts → collect CSS → style →
layout → paint).

```rust
pub fn render_document(
    html: &str,
    base: &Url,
    viewport_width: f32,
    loader: &dyn ResourceLoader,
) -> Pixmap {
    let mut doc = starfish_html::parse(html);          // was `let doc`

    // E4-M1: run <script>s against the (mutable) document BEFORE styling.
    // M1: no DOM mutation; M2: scripts edit `doc` here so styling sees the result.
    let js = starfish_js::run_scripts(&mut doc, base, loader);
    report_console(&js);                               // §5.3 (print captured output)

    // Unchanged below: everything still borrows &doc.
    let author = collect_author_sheets(&doc, base, loader);
    let styled = style_tree(&doc, &author);
    let fonts = FontDb::load().expect("embedded faces load");
    let mut images = ImageStore::new(base.clone(), loader);
    decode_images(&doc, &mut images);
    let root = layout(&doc, &styled, viewport_width, &FontMeasurer(&fonts), &images);
    let width = clamp_dimension(viewport_width);
    let height = clamp_dimension(root.dimensions().margin_box().height);
    paint(&root, &styled, &fonts, &images, width, height)
}
```

The **only** change to the body is `let doc` → `let mut doc` plus the two
`run_scripts` + `report_console` lines. `collect_author_sheets`, `style_tree`,
`decode_images`, `layout`, `paint` are **byte-identical** — they keep taking
`&doc`. The loader + base already in scope are passed straight to `run_scripts`.

### 5.2 Wrappers keep working

`render_path`, `render_url`, `render_html`, `render_html_cwd` all delegate to
`render_document`, so they pick up the JS phase **for free**. No signature
changes anywhere. The CLI (`crates/cli/src/main.rs`) is **untouched** (it calls
`render_document`).

### 5.3 Surfacing console output

`render_document` returns only a `Pixmap` (its signature must not change, or the
CLI/tests break). So captured console/errors are surfaced by **printing**:

```rust
fn report_console(js: &starfish_js::ScriptOutcome) {
    for m in &js.console {
        match m.level {
            ConsoleLevel::Error | ConsoleLevel::Warn => eprintln!("[console] {}", m.text),
            _ => println!("[console] {}", m.text),
        }
    }
    for e in &js.errors {
        eprintln!("[script error] {}", e.text);
    }
}
```

This keeps `render_document -> Pixmap` intact while making script output visible
on the CLI. Tests that need to **assert** console content call
`starfish_js::run_scripts` directly (it returns the `ScriptOutcome`); the
`render_document` path only needs to prove "no panic, page still renders" (§8).
(*If a structured outcome is wanted from `render_document` later, a sibling
`render_document_with_outcome -> (Pixmap, ScriptOutcome)` can be added without
touching the existing signature — deferred, not built.*)

## 6. `ScriptOutcome` / error model (recap)

- `run_scripts` **never panics and never returns `Result::Err`.** Every failure
  is a value:
  - thrown JS → `ScriptOutcome.errors[i].text` (engine display of the value),
  - failed external load → skipped (optionally an `errors` entry),
  - non-JS / module `type` → skipped silently.
- `ScriptOutcome { console: Vec<ConsoleMessage>, errors: Vec<ScriptError>,
  executed: usize }`. `console` is in global call order; `errors` in
  script-encounter order.
- The `Document` is mutated **in place** through the `&mut` borrow (M1: no
  mutation). Reclaimed losslessly via the `Rc::try_unwrap` boundary (§2.3).
- A page with **no `<script>`** → `collect_scripts` returns empty →
  `ScriptOutcome::default()` returned immediately; **no Boa `Context` is even
  constructed** → zero overhead, byte-identical render to pre-E4 (§7, §8).

## 7. Edge cases & non-goals (deliberate)

Handled:
- Inline + external scripts, document order, single shared global env.
- `type` absent / classic-JS MIME → run; `module` / other → skip (not error).
- External `src` resolved via `base.join` + fetched via the **existing** loader;
  any `LoadError` → skip, non-fatal.
- Thrown/uncaught script error → captured, next script still runs.
- External script bytes decoded **UTF-8 lossy**.
- `console.{log,info,warn,error,debug}` captured (+ printed by paint).
- `window`/`globalThis` alias; `navigator.userAgent`; `location.*`; read-only
  `document.{title,URL}` probe — no `ReferenceError` for these.
- **No scripts → zero overhead** (early return; no `Context`).

Explicit **non-goals** (deferred / documented limits):
- **No DOM bindings** (E4-M2) — `document` is a read-only stub; no
  `getElementById`/`createElement`/mutation. The `&mut Document` + internal
  `Rc<RefCell<Document>>` are the *seam* M2 fills, not used to mutate in M1.
- **No events / timers** (E4-M3) — no `addEventListener`, `setTimeout`,
  `DOMContentLoaded`/`load`. Touching them → caught `ReferenceError` (non-fatal).
- **No ES modules** (`type="module"`, `import`/`export`) — skipped.
- **No `document.write`** — not provided; a call is a caught `TypeError`.
- **`defer`/`async` ignored** — all runnable scripts run synchronously in order.
- **No network from JS** (`fetch`/`XHR`), no `localStorage`/cookies/history.
- **Dynamically-inserted `<script>`** (M2 DOM) is **not** re-scanned/executed —
  only parse-time scripts run (matches "run what was parsed").
- **Boa limits** (noted): tree-walking/bytecode interpreter, **no JIT** (fine for
  one-shot); a deeply-recursive script can hit Boa's stack limit → it throws,
  caught per §3.4; Boa's `Promise`/microtask queue is whatever Boa drains during
  `eval` — we do **not** add an explicit job-queue drain in M1 (timers/jobs land
  in M3).
- **Stringification fidelity** is Boa's display, not a full spec `console`
  formatter (no `%s`/`%d` format specifiers, no grouping/`console.table`). M1
  joins args with spaces — sufficient to capture intent.

## 8. Test plan (concrete)

### 8.1 `js` crate unit tests (`crates/js/src/lib.rs` tests) — drive `run_scripts` directly

Helpers: a `LocalLoader` over a temp dir, `file_url_from_path` for `base`, and
`starfish_html::parse` to build a `Document`.

1. **Inline `console.log` captured.**
   `parse("<script>console.log('hi')</script>")`; `run_scripts(&mut doc, base,
   &LocalLoader)` → `outcome.console == [ConsoleMessage{Log, "hi"}]`,
   `executed == 1`, `errors` empty.
2. **Levels mapped.** A script calling `console.warn('w'); console.error('e');
   console.info('i')` → three messages with levels `Warn/Error/Info` in order.
3. **Multi-arg stringify.** `console.log('x', 1, true)` → text `"x 1 true"`
   (space-joined; assert exact).
4. **Two scripts share state.** Two `<script>`s: first `var a = 41; window.b =
   1;`, second `console.log(a + b)` → captures `"42"` (proves single shared
   `Context` / global env across scripts).
5. **External `<script src>` runs.** Write `app.js` = `console.log('ext')` into a
   temp dir; HTML `<script src="app.js"></script>` with `base` = that dir's
   `index.html` file URL → `run_scripts` fetches via `LocalLoader`, captures
   `"ext"`, `executed == 1`.
6. **Failed external load is non-fatal.** `<script src="missing.js"></script>`
   followed by `<script>console.log('after')</script>` → the missing one is
   skipped (no panic), `"after"` still captured, `executed == 1`.
7. **A throwing script is non-fatal; later script runs.**
   `<script>throw new Error('boom')</script><script>console.log('later')</script>`
   → `errors.len() == 1` (text contains `"boom"`), `console == ["later"]`,
   `executed == 1`.
8. **Globals don't `ReferenceError`.** A script reading
   `console.log(typeof window, typeof globalThis, navigator.userAgent,
   location.href, document.URL)` → no entry in `errors`; the logged line contains
   `"object object"` (typeofs) and the UA + URL substrings. Assert
   `window === globalThis` via `console.log(window === globalThis)` → `"true"`.
9. **`document.title` read-only probe.**
   `parse("<title>Hello</title><script>console.log(document.title)</script>")` →
   captures `"Hello"`.
10. **`type` handling.** `<script type="module">console.log('m')</script>` and
    `<script type="application/json">{}</script>` are **skipped**
    (`executed == 0`, no `"m"`); `<script type="text/javascript">console.log('c')
    </script>` runs (`"c"` captured).
11. **No scripts → empty outcome.** `parse("<p>hi</p>")` → `run_scripts` returns
    `ScriptOutcome::default()` (`console`/`errors` empty, `executed == 0`).
12. **Document survives the round-trip.** After a no-op `<script>` run, assert
    `doc.serialize(doc.root())` is unchanged vs. the same parse without scripts
    (proves the `mem::take`/`try_unwrap` reclaim is lossless and the `&mut`
    leaves the arena intact). Also a `parse`-only baseline equality.

### 8.2 paint integration tests (`crates/paint` tests) — no regression, non-fatal

13. **Page with a script still renders, identically to no-script.** Two HTMLs
    differing only by an added `<script>console.log('x')</script>` in `<head>`
    render to the **same pixmap bytes** (the script has no DOM effect in M1) —
    proves the JS phase is render-transparent. Use an existing colored-block
    fixture + a `LocalLoader` over a temp dir.
14. **Throwing script doesn't break rendering.**
    `<head><script>throw 1</script></head><body><div style=…red…></div></body>`
    via `render_document` → the red block pixel still asserts red (no panic, no
    blank page).
15. **No-script regression guard.** An existing `render_html_cwd` colored-block
    test is unchanged and still passes (the early-return path means no `Context`
    is built when there are no scripts) — confirms zero overhead / zero behaviour
    change for the (common) script-free page.

`cargo test -p starfish-js` and the full `cargo test` are green; a manual smoke:
render a page with an inline `console.log` and confirm the `[console] …` line
prints and the PNG is produced.
