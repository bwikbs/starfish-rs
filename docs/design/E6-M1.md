# E6-M1 — Font matching & faces (design note)

Scope: replace the single embedded DejaVu Sans/Bold pair with **real font
selection**. Build a font database that discovers system fonts (via the
`fontdb` crate) with the vendored DejaVu faces as a guaranteed deterministic
fallback; resolve `font-family` (family lists + generic families
serif/sans-serif/monospace/cursive/fantasy); honor `font-style`
(normal/italic/oblique) and match `font-weight` to the nearest available face
via fontdb's CSS matcher; and feed **real per-face fontdue metrics + advances**
into both layout's `TextMeasurer` and paint's rasterizer so measure == paint.

Crates touched: `paint` (font DB + match + measurer + raster + display),
`style` (add `font-style`). No layout-algorithm change beyond a `TextMeasurer`
trait signature change. Deferred to later milestones: `@font-face` (E6-M2),
bidi/letter-spacing/white-space (E6-M3).

Guiding rule (project "Simplicity First"): **let `fontdb` do the CSS font
matching** — its `Database::query(&Query) -> Option<ID>` already implements the
family-list walk, generic-family mapping, the style match, and the standard
weight fallback ladder. We do **not** reimplement the weight ladder. Our code
only: (1) builds the DB once with the vendored faces guaranteed present, (2)
translates a `ComputedStyle`'s font fields into a `fontdb::Query`, (3) caches the
parsed fontdue `Font` per resolved face id, and (4) threads the same query into
both layout and paint.

## 0. The real APIs this builds on (verified)

### 0.1 `fontdb` 0.23 (new dependency)

Verified against docs.rs/fontdb/0.23.0. The relevant surface:

```rust
// Database
impl Database {
    pub fn new() -> Self;
    pub fn load_system_fonts(&mut self);
    pub fn load_font_data(&mut self, data: Vec<u8>);                 // owns the bytes
    pub fn load_font_file<P: AsRef<Path>>(&mut self, path: P) -> Result<(), Error>;
    pub fn query(&self, query: &Query<'_>) -> Option<ID>;           // CSS-like matcher
    pub fn face(&self, id: ID) -> Option<&FaceInfo>;
    pub fn faces(&self) -> impl Iterator<Item = &FaceInfo>;
    pub fn with_face_data<P, T>(&self, id: ID, p: P) -> Option<T>    // raw bytes + face index
        where P: FnOnce(&[u8], u32) -> T;
    // generic-family mapping used by query():
    pub fn set_serif_family<S: Into<String>>(&mut self, family: S);
    pub fn set_sans_serif_family<S: Into<String>>(&mut self, family: S);
    pub fn set_monospace_family<S: Into<String>>(&mut self, family: S);
    pub fn set_cursive_family<S: Into<String>>(&mut self, family: S);
    pub fn set_fantasy_family<S: Into<String>>(&mut self, family: S);
}

// Query — note BOTH `families` and `Family::Name` are BORROWED (lifetimes!)
pub struct Query<'a> {
    pub families: &'a [Family<'a>],
    pub weight: Weight,     // Weight(pub u16); Weight::NORMAL == 400, Weight::BOLD == 700
    pub stretch: Stretch,   // leave Default (Normal) — font-stretch is out of scope
    pub style: Style,       // Normal | Italic | Oblique
}
pub enum Family<'a> { Name(&'a str), Serif, SansSerif, Cursive, Fantasy, Monospace }
pub enum Style { Normal, Italic, Oblique }
pub struct ID(/* opaque, Copy + Hash + Eq */);
```

Two consequences of the borrowed `Query`/`Family`:
- The `Vec<Family>` and the `&[Family]` it slices must **outlive** the `query()`
  call. We build them locally per resolve and call `query()` in the same scope
  (see §2.2) — never store a `Query`.
- `query()` does the whole match (family list in order → generic fallback →
  weight ladder → style). It returns `None` only if the DB is empty; with the
  vendored fallback families always present and `set_*_family` pointing the
  generics at vendored names, a non-empty query effectively always resolves.
  Our wrapper still treats `None` as "use the hard default face id".

## 1. The font database

### 1.1 What we vendor (decision)

We need deterministic faces for the three common generics **and** a real italic,
independent of any system fonts (CI has unpredictable font sets). DejaVu has
**no italic face at all** (confirmed: no DejaVu*-Italic/-Oblique except DejaVu
Sans Mono's `-Oblique`). To support `font-style: italic` deterministically we
vendor a family that *has* a real italic.

Vendored set (all under free licenses, copied from `/usr/share/fonts`):

| File | Family (fontdb name) | Role |
|------|----------------------|------|
| `DejaVuSans.ttf` *(already)* | DejaVu Sans | sans-serif regular + the **hard default** |
| `DejaVuSans-Bold.ttf` *(already)* | DejaVu Sans | sans-serif bold |
| `DejaVuSerif.ttf` | DejaVu Serif | serif regular |
| `DejaVuSerif-Bold.ttf` | DejaVu Serif | serif bold |
| `DejaVuSansMono.ttf` | DejaVu Sans Mono | monospace regular |
| `DejaVuSansMono-Bold.ttf` | DejaVu Sans Mono | monospace bold |
| `LiberationSerif-Regular.ttf` | Liberation Serif | the **italic-capable serif** family |
| `LiberationSerif-Italic.ttf` | Liberation Serif | **real italic** (deterministic `font-style:italic`) |
| `LiberationSerif-Bold.ttf` | Liberation Serif | bold |
| `LiberationSerif-BoldItalic.ttf` | Liberation Serif | bold italic |

Rationale for Liberation Serif as the italic vehicle: it ships a genuine
`-Italic` and `-BoldItalic` (verified present in `/usr/share/fonts/truetype/liberation`),
it is free (SIL OFL / GPL-with-font-exception), and it gives a visibly distinct
italic for the golden/visual test. DejaVu alone cannot satisfy a deterministic
italic test, so a second vendored family is unavoidable; one serif family with
all four styles is the minimal addition.

Licenses: add `LICENSE-Liberation.txt` next to the existing
`LICENSE-DejaVu.txt`. (Roughly +2 MB of embedded font data; acceptable — the
binary stays self-contained and deterministic.)

> Note: `DejaVuSansMono-Oblique.ttf` is *not* vendored — italic is covered by
> Liberation Serif, and synthesizing/oblique-mapping mono italic is out of scope
> (§8). A `font-style: italic` request on a monospace family with no italic face
> falls back to the regular mono face (documented below).

### 1.2 Determinism strategy (decision)

Two needs pull in opposite directions: runtime should honor real system fonts;
tests/golden must be reproducible regardless of the host's font set. Resolution:

- **The vendored faces are ALWAYS loaded into the DB, in addition to system
  fonts.** They are loaded *after* `load_system_fonts()` but a query for a
  vendored family name (e.g. `"DejaVu Sans"`, `"Liberation Serif"`) always
  resolves to a vendored face because that exact family name is guaranteed
  present. So tests assert against vendored *family names* + the *generics*,
  never against an arbitrary system family.
- **The generic families are pointed at vendored names** via
  `set_serif_family("DejaVu Serif")`, `set_sans_serif_family("DejaVu Sans")`,
  `set_monospace_family("DejaVu Sans Mono")`,
  `set_cursive_family("Liberation Serif")`,
  `set_fantasy_family("DejaVu Sans")`. This makes `font-family: serif | sans-serif |
  monospace | cursive | fantasy` deterministic everywhere, even though system
  fonts are also present. (`cursive`/`fantasy` have no vendored script/display
  face; they map to the nearest vendored family — italic-capable serif for
  cursive, sans for fantasy — and this is the documented fallback.)
- **A construction flag selects whether system fonts are loaded at all.**
  `FontDb::new()` (runtime) loads system + vendored; `FontDb::vendored_only()`
  (tests, golden) loads **only** the vendored faces. Unit tests and the golden
  test use `vendored_only()` so output never depends on the host. The hard
  default face (the face id used when `query()` returns `None`) is the vendored
  DejaVu Sans regular in both modes.

This keeps "real system fonts at runtime" and "stable tests" both true, with no
test depending on a specific system font.

### 1.3 Types & construction

`crates/paint/src/font.rs` (rewrite of the current two-face struct):

```rust
use std::cell::RefCell;
use std::collections::HashMap;
use fontdb::{Database, Family, Query, Style as FdbStyle, Weight as FdbWeight, ID};
use fontdue::{Font as FontdueFont, FontSettings};
use starfish_layout::{FontStyle, LineMetrics, TextMeasurer};
use starfish_style::FontWeight;

// Vendored faces, embedded for determinism (no I/O for these).
const DEJAVU_SANS:        &[u8] = include_bytes!("../assets/DejaVuSans.ttf");
const DEJAVU_SANS_BOLD:   &[u8] = include_bytes!("../assets/DejaVuSans-Bold.ttf");
const DEJAVU_SERIF:       &[u8] = include_bytes!("../assets/DejaVuSerif.ttf");
const DEJAVU_SERIF_BOLD:  &[u8] = include_bytes!("../assets/DejaVuSerif-Bold.ttf");
const DEJAVU_MONO:        &[u8] = include_bytes!("../assets/DejaVuSansMono.ttf");
const DEJAVU_MONO_BOLD:   &[u8] = include_bytes!("../assets/DejaVuSansMono-Bold.ttf");
const LIB_SERIF:          &[u8] = include_bytes!("../assets/LiberationSerif-Regular.ttf");
const LIB_SERIF_IT:       &[u8] = include_bytes!("../assets/LiberationSerif-Italic.ttf");
const LIB_SERIF_BD:       &[u8] = include_bytes!("../assets/LiberationSerif-Bold.ttf");
const LIB_SERIF_BDIT:     &[u8] = include_bytes!("../assets/LiberationSerif-BoldItalic.ttf");

/// One rasterized glyph (unchanged from M5).
pub struct GlyphBitmap { /* width, height, left, top, advance, coverage — as today */ }

/// The font database: a `fontdb::Database` for matching + a lazily-populated
/// cache of parsed fontdue faces keyed by the resolved fontdb face id.
pub struct FontDb {
    db: Database,
    /// Resolved-face cache. RefCell because resolution happens behind the
    /// shared `&FontDb` that layout + paint both hold; interior mutability keeps
    /// the public API `&self`. Single-threaded render, so RefCell is enough.
    faces: RefCell<HashMap<ID, std::rc::Rc<FontdueFont>>>,
    /// The id of the vendored DejaVu Sans regular — the guaranteed default when
    /// a query yields None or a face fails to parse.
    default_id: ID,
}

impl FontDb {
    /// Runtime DB: system fonts + the vendored fallback faces, generics mapped
    /// to vendored families.
    pub fn new() -> FontDb {
        let mut db = Database::new();
        db.load_system_fonts();
        Self::finish(db)
    }

    /// Deterministic DB for tests/golden: ONLY the vendored faces.
    pub fn vendored_only() -> FontDb {
        Self::finish(Database::new())
    }

    /// BACK-COMPAT shim so existing call sites (`FontDb::load()`) keep compiling.
    /// Returns `new()` wrapped in Ok (it is infallible: embedded assets are
    /// validated at build time, system-font load failures are tolerated by fontdb).
    pub fn load() -> Result<FontDb, String> { Ok(FontDb::new()) }

    fn finish(mut db: Database) -> FontDb {
        // Always register the vendored faces (load_font_data owns the Vec).
        for bytes in [DEJAVU_SANS, DEJAVU_SANS_BOLD, DEJAVU_SERIF, DEJAVU_SERIF_BOLD,
                      DEJAVU_MONO, DEJAVU_MONO_BOLD, LIB_SERIF, LIB_SERIF_IT,
                      LIB_SERIF_BD, LIB_SERIF_BDIT] {
            db.load_font_data(bytes.to_vec());
        }
        // Map generics deterministically to vendored families.
        db.set_sans_serif_family("DejaVu Sans");
        db.set_serif_family("DejaVu Serif");
        db.set_monospace_family("DejaVu Sans Mono");
        db.set_cursive_family("Liberation Serif");
        db.set_fantasy_family("DejaVu Sans");
        // The hard default: query for our sans regular; it is guaranteed present.
        let default_id = db
            .query(&Query {
                families: &[Family::Name("DejaVu Sans")],
                weight: FdbWeight::NORMAL,
                stretch: Default::default(),
                style: FdbStyle::Normal,
            })
            .or_else(|| db.faces().next().map(|f| f.id))
            .expect("vendored DejaVu Sans always present");
        FontDb { db, faces: RefCell::new(HashMap::new()), default_id }
    }
}
```

## 2. Font matching

### 2.1 The query type threaded through the engine

A small owned struct carries the font selection from a `ComputedStyle` through
layout and paint. It lives in `layout` (where the `TextMeasurer` trait lives) so
both crates can name it without a paint→layout type cycle.

`crates/layout/src/measure.rs`:

```rust
/// `font-style` computed value. Mirrors the CSS keyword; `Oblique` is matched
/// like italic (we don't model an oblique angle).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FontStyle { Normal, Italic, Oblique }

/// Everything needed to resolve + measure with the right face. Borrows the
/// family list from the owning `ComputedStyle` (no clone on the hot path).
#[derive(Debug, Clone, Copy)]
pub struct FontQuery<'a> {
    pub family: &'a [String],   // the font-family list, in order; may be empty
    pub style: FontStyle,
    pub weight: FontWeight,
    pub size: f32,              // px
}
```

`FontStyle` is re-exported from `layout`'s `lib.rs` (alongside `LineMetrics`,
`TextMeasurer`) and from `style` (see §3), so call sites use one type.

### 2.2 Resolution + caching (`FontDb`)

```rust
impl FontDb {
    /// Resolve a (family-list, style, weight) selection to a parsed fontdue
    /// face, delegating the CSS match to fontdb. Caches the parsed face by id.
    /// Always returns a usable face (the vendored default on any miss).
    fn resolve(&self, q: &FontQuery) -> std::rc::Rc<FontdueFont> {
        // Build the borrowed Family list: each requested family name, then map a
        // generic keyword to its Family variant so fontdb's set_*_family applies.
        let families: Vec<Family> = q.family.iter().map(|name| match name.to_ascii_lowercase().as_str() {
            "serif"      => Family::Serif,
            "sans-serif" => Family::SansSerif,
            "monospace"  => Family::Monospace,
            "cursive"    => Family::Cursive,
            "fantasy"    => Family::Fantasy,
            _            => Family::Name(name.as_str()),
        }).collect();
        // If the list is empty (no font-family) fall back to the UA default sans.
        let fallback = [Family::SansSerif];
        let fam_slice = if families.is_empty() { &fallback[..] } else { &families[..] };

        let id = self.db.query(&Query {
            families: fam_slice,
            weight: FdbWeight(q.weight.0),     // pass the numeric weight straight through
            stretch: Default::default(),
            style: match q.style {
                FontStyle::Normal  => FdbStyle::Normal,
                FontStyle::Italic  => FdbStyle::Italic,
                FontStyle::Oblique => FdbStyle::Oblique,
            },
        }).unwrap_or(self.default_id);

        self.face_by_id(id)
    }

    /// Parse-and-cache the fontdue face for a resolved id. On a parse failure or
    /// a missing-data id, fall back to the default face (and cache that).
    fn face_by_id(&self, id: ID) -> std::rc::Rc<FontdueFont> {
        if let Some(f) = self.faces.borrow().get(&id) { return f.clone(); }
        let parsed = self.db.with_face_data(id, |bytes, index| {
            FontdueFont::from_bytes(bytes, FontSettings { collection_index: index, ..Default::default() }).ok()
        }).flatten();
        let face = match parsed {
            Some(f) => std::rc::Rc::new(f),
            None if id != self.default_id => return self.face_by_id(self.default_id),
            None => panic!("default face must parse"), // unreachable: vendored asset
        };
        self.faces.borrow_mut().insert(id, face.clone());
        face
    }
}
```

Notes:
- **fontdb owns the weight ladder + style match.** We pass the numeric
  `font-weight` (e.g. 350, 600) and the style straight into `Query`; fontdb
  picks the nearest available face per the CSS algorithm. No bespoke ladder.
- The family list resolves **in order**: fontdb tries each `Family` in turn and
  only falls to the next when no face in that family matches; generics resolve
  via the `set_*_family` mapping. This is exactly the spec walk.
- Caching is **per resolved face id**, not per query tuple — multiple style
  tuples that resolve to the same face share one parsed `FontdueFont`. fontdb's
  `query()` is cheap; fontdue parsing is the cost we cache.
- `Rc<FontdueFont>` so a resolved face can be handed back and held briefly for a
  measure/raster loop without re-borrowing the RefCell mid-iteration.

### 2.3 Public metric/raster API (face-aware)

The three M5 entry points gain a `&FontQuery` (replacing the bare
`font_size`/`weight`):

```rust
impl FontDb {
    /// Sum of per-glyph advances of `text` for the resolved face at q.size px.
    pub fn advance_width(&self, text: &str, q: &FontQuery) -> f32 {
        let f = self.resolve(q);
        text.chars().map(|c| f.metrics(c, q.size).advance_width).sum()
    }
    /// Ascent/descent from the resolved face's horizontal line metrics.
    pub fn line_metrics(&self, q: &FontQuery) -> LineMetrics { /* resolve(q) → horizontal_line_metrics */ }
    /// Rasterize one char with the resolved face.
    pub fn rasterize_glyph(&self, ch: char, q: &FontQuery) -> GlyphBitmap { /* resolve(q).rasterize(ch, q.size) */ }
}
```

The `line_metrics` body matches today's: `ascent = lm.ascent`, `descent =
-lm.descent` (fontdue descent is negative), with the `font_size*0.8/0.2`
fallback when a face has no horizontal metrics.

## 3. `ComputedStyle` — add `font-style`

`crates/style/src/computed.rs`:

- **New enum**, re-using layout's `FontStyle` shape but defined in `style`
  (to avoid a style→layout dep). Layout's `FontStyle` and style's `FontStyle`

  style). So: define `FontStyle { Normal, Italic, Oblique }` in `style`,
  `pub use starfish_style::FontStyle` from `layout`, and `FontQuery` uses it.

```rust

```

- **New field** on `ComputedStyle`, next to the other font fields:
  `pub font_style: FontStyle,`
- **Initial value** in `ComputedStyle::initial()`: `font_style: FontStyle::Normal`.
- **Inherited**: add `child.font_style = self.font_style;` to `inherit_from()`
  (font-* are inherited; confirmed `font_family`/`font_weight`/`font_size`
  already are).

`font_family: Vec<String>` and `font_weight: FontWeight` already exist

## 4. `TextMeasurer` signature change

The trait must measure with the *face*, so it takes a `&FontQuery` instead of
`(font_size, weight)`. `crates/layout/src/measure.rs`:

```rust
pub trait TextMeasurer {
    /// Advance width in px of `text` for the queried face/size.
    fn measure(&self, text: &str, font: &FontQuery) -> f32;

    /// Ascent/descent for one line of the queried face. Default keeps the crude
    /// 0.8/0.2 split (used by DefaultMeasurer / image-only layout).
    fn line_metrics(&self, font: &FontQuery) -> LineMetrics {
        LineMetrics { ascent: font.size * 0.8, descent: font.size * 0.2 }
    }
}
```

`line_metrics` now also takes the query (so the real measurer uses the *resolved
face's* ascent/descent rather than the regular-sans face — a face-correct line
box). `DefaultMeasurer` becomes:

```rust
impl TextMeasurer for DefaultMeasurer {
    fn measure(&self, text: &str, font: &FontQuery) -> f32 {
        text.chars().count() as f32 * 0.5 * font.size   // family/style/weight ignored
    }
}
```

`FontMeasurer` (paint) becomes face-backed:

```rust
impl TextMeasurer for FontMeasurer<'_> {
    fn measure(&self, text: &str, font: &FontQuery) -> f32 { self.0.advance_width(text, font) }
    fn line_metrics(&self, font: &FontQuery) -> LineMetrics { self.0.line_metrics(font) }
}
```

### 4.1 Call sites in `inline.rs` (surgical)

`layout_inline` already resolves each word's `ComputedStyle` to read
`font_weight`/`font_size`. It now also reads `font_family`/`font_style` and
builds a `FontQuery`. The two measure call sites + the marker measure change:

- Word measure (currently `m.measure(word, *font_size, weight)`): collect the
  word's family/style alongside size/weight in `CollectedItem::Word`, then build
  a `FontQuery { family: &style.font_family, style: style.font_style, weight,
  size: *font_size }` and call `m.measure(word, &q)`. The space measure
  (`m.measure(" ", ..)`) uses the same `q`.
  - The borrow: build `q` from the resolved `&ComputedStyle` (via
    `styled.get(id)`) inside the per-item match arm so the `&[String]` borrow is
    live across the `measure` call. The container's style is the fallback when a
    word has no node style (rare; markers/anonymous).
- Marker measure (`m.measure(&pm.text, font_size, weight)`): same — build a
  `FontQuery` from the marker's style and call `m.measure(&pm.text, &q)`.
- Line height is still `used_line_height(font_size, lh)` (unchanged);
  `line_metrics` is consumed in paint, not here.

`CollectedItem::Word` gains nothing structural if we keep `style_ref` and
re-resolve the style at measure time (it already stores `style_ref`); simplest
is to read `font_family`/`font_style` off the already-resolved `style` in the
collect loop and store them, OR re-`styled.get` in the measure loop (already
done for `weight`). **Decision:** re-use the existing `styled.get(id)` lookup in
the measure loop (it already fetches `weight` there) and read `font_family` +
`font_style` from the same `&ComputedStyle` — zero new fields on
`CollectedItem`, the change is just building `q` from that style. Keeps it
surgical.

`layout_default` / any `DefaultMeasurer` or `NoImages` test callers compile
unchanged except for the trait method shape (size moved into the query).

### 5.1 `PaintCmd::GlyphRun` carries family + style

`crates/paint/src/display.rs` — extend the variant so the rasterizer resolves
the **same** face the measurer used:

### 5.2 Rasterizer face selection

`crates/paint/src/raster.rs` `draw_glyph_run` rebuilds the **same** `FontQuery`
from the run's fields and resolves the face once per run:

```rust
let PaintCmd::GlyphRun { origin, text, font_size, weight, style, family, color, ascent } = cmd else { return };
let q = FontQuery { family, style: *style, weight: *weight, size: *font_size };
let baseline = origin.1 + ascent;
let mut pen_x = origin.0;
for ch in text.chars() {
    let g = fonts.rasterize_glyph(ch, &q);   // resolves the same face the measurer used
    /* blit unchanged */
    pen_x += g.advance;
}
```

Because both the measurer (layout) and `rasterize_glyph` (paint) call
`FontDb::resolve` with an identical `FontQuery`, they hit the same cached face →
identical advances → **measure == paint** (the M5 invariant, preserved).

---

## 6. Consistency — one shared DB

The DB is created **once** in `render_document` and shared by both layout (as
the `FontMeasurer`) and paint:

```rust
let fonts = FontDb::new();                                  // was FontDb::load().expect(..)
let root  = layout(&doc, &styled, vw, &FontMeasurer(&fonts), &images);
// ...
paint(&root, &styled, &fonts, &images, width, height)       // same &fonts
```

`FontMeasurer<'a>(pub &'a FontDb)` is unchanged in shape; `paint`/`build_display_list`/
`rasterize` already thread `&FontDb`. The resolved-face cache (`RefCell`) is
populated during layout's measure pass and reused during paint — same `&FontDb`,
so paint mostly hits warm cache entries. Single render = single thread, so
`RefCell` interior mutability is sound (no `Send`/`Sync` needed; the DB is not
shared across threads).

`FontDb::load()` is kept as an infallible shim returning `Ok(FontDb::new())` so
the many test/`paint` call sites compiling against `FontDb::load().unwrap()`
keep working without edits; new tests use `FontDb::vendored_only()`.

---

## 7. Determinism & fallback

- **Vendored faces always in the DB** → a page with no system fonts (CI, minimal
  containers) still renders text with DejaVu/Liberation. `query()` returning
  `None` is treated as the vendored DejaVu Sans default.
- **Generics mapped to vendored families** → `serif`/`sans-serif`/`monospace`/
  `cursive`/`fantasy` are reproducible on any host.
- **Tests use `vendored_only()`** so the system font set is irrelevant; they
  assert against vendored family **names** (`"DejaVu Sans"`, `"DejaVu Serif"`,
  `"DejaVu Sans Mono"`, `"Liberation Serif"`) and the generics, never an
  arbitrary system family.
- **No test asserts exact glyph pixels or exact advances** (font-version
  brittle) — assert *relative* facts: mono advances differ from sans; the serif
  face's metrics differ from sans; italic resolves to the italic face;
  weight 700 resolves to a different face than 400; consistency
  (measure-width == paint-pen-advance).

---

## 8. Edge cases & non-goals

Handled / decided:
- **No matching family at all** → `query()` falls through generics to a present
  family; if still `None`, the vendored DejaVu Sans default (never blank text).
- **`font-style: italic` on a family with no italic face** → fontdb returns the
  nearest face it has (regular). We do **not** synthesize a slant. Documented:
  italic is real only for families that ship an italic (Liberation Serif among
  the vendored set; DejaVu has none → DejaVu requests render upright). This is
  the deliberate reason Liberation Serif is vendored.
- **`oblique <angle>`** → treated as `Oblique` (queried like italic); the angle
  is ignored.
- **Synthetic bold** → none; fontdb picks the nearest real weight face. A family
  with only a regular face renders bold as that regular face (no faux-bold).
- **`cursive`/`fantasy`** → mapped to vendored families (serif-italic-capable /
  sans); no script/display face is vendored.
- **Missing glyph** → fontdue's `.notdef` (empty mask, real advance) — unchanged.
- **No kerning** (sum of advances), **no OpenType features**, **no font-stretch /
  variable-font axes**, **no `@font-face`** (E6-M2), **no `font` shorthand**
  (only `font-style`/`font-family`/`font-weight`/`font-size` longhands).
- **Variable fonts**: fontdb exposes them as faces with a default instance;
  fontdue rasterizes the default instance. We do not select named instances or
  set axes. Acceptable for M1 (system variable fonts still render).

Non-goals are otherwise the ROADMAP-epic6 deferral list.

## 9. Test plan

`vendored_only()` DB throughout (deterministic). Unit tests in `font.rs`,
`display.rs`; integration via `render_document`/`paint`.

### 9.1 `font.rs` — matching & metrics
- **mono ≠ sans**: build a `FontQuery` for `["DejaVu Sans Mono"]` and one for
  `["DejaVu Sans"]`; `advance_width("Hello", ..)` differs (mono is fixed-width).
  Also `monospace` generic resolves to the mono face → same advance as the
  explicit `"DejaVu Sans Mono"` query.
- **serif**: `["DejaVu Serif", "serif"]` resolves to the serif face; its
  `line_metrics` ascent/descent differ from sans (face metrics come from the
  resolved face, not a fixed regular face).
- **italic → italic face**: `["Liberation Serif"]` with `style: Italic` resolves
  to a *different* face id than `style: Normal` (assert the two resolve to
  distinct fontdue faces, e.g. distinct advances for an italicizable glyph, or
  expose the resolved `ID` from a test-only helper and assert inequality).
  Also `["DejaVu Serif"]` with `Italic` resolves to the regular DejaVu Serif
  (documented no-italic fallback) — assert it equals the `Normal` resolution.
- **weight 700 → bold face**: `["DejaVu Sans"]` weight 700 vs 400 resolve to
  different faces (advances differ for "Mmm"), and weight 600/599 boundary
  follows fontdb's ladder (assert 700≠400; don't hard-code the 600 boundary —
  fontdb owns it).
- **unknown family falls back**: `["No Such Font 12345"]` resolves without panic
  and yields the same advances as `sans-serif` (→ vendored DejaVu Sans).
- **generics deterministic**: `serif`/`sans-serif`/`monospace` each resolve to
  their mapped vendored family (advances match the explicit-name query).
- **empty family list** → behaves as `sans-serif`.
- **rasterize**: `rasterize_glyph('x', &q)` non-empty mask; `' '` empty mask but
  advance > 0 (per face).

### 9.2 `display.rs` — GlyphRun carries family/style
- A `<p style="font-family: monospace; font-style: italic">` emits a `GlyphRun`
  whose `family == ["monospace"]` and `style == FontStyle::Italic`.
- Inherited: a child with no `font-family` inherits the parent's list into its
  `GlyphRun`.

### 9.3 Consistency (measure == paint)
- For a text run, sum the per-glyph advances the rasterizer would walk
  (`rasterize_glyph(ch,&q).advance`) and assert it equals
  `advance_width(text,&q)` for the same `FontQuery` (mono, serif, sans, italic,
  bold). This is the invariant guaranteeing text fits its measured box.

### 9.4 style — `font-style` parsing & inheritance
- `font-style: italic|oblique|normal` → the right `FontStyle`.
- `oblique 14deg` → `Oblique`.
- `font_style` inherits from parent (a child `<span>` with no `font-style` under
  an italic `<p>` is `Italic`).

### 9.5 Pipeline / visual (golden, font-independent assertions)
- A fixture page with five lines —
  `font-family: sans-serif`, `serif`, `monospace`, `font-weight: 700`,
  `font-style: italic` (on Liberation Serif) — rendered via `render_document`
  with `vendored_only()`.
  - Assert each line's text region has non-white pixels (glyphs drew).
  - Assert the monospace line's measured width (from layout, via the line box /
    text-run content width) differs from the sans line for the same string —
    proving distinct faces drove layout.
  - **No full-image PNG golden** (font-version brittle); sample regions + assert
    relative widths only.
- VISUAL artifact: render the fixture to a PNG (manually, for review) showing the
  five visibly distinct faces; not asserted pixel-exact.
