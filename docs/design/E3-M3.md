# E3-M3 — `data:` URLs + in-memory resource cache + robustness (design note)

Scope (per `docs/ROADMAP-epic3.md`, E3-M3 row): close out Epic 3 with

1. **`data:` URLs** — render `data:image/...;base64,…` images and
   `data:text/css,…` / `;base64,…` stylesheets, plus `data:,hello` plain text.
2. **An in-memory resource cache** — dedupe `fetch` by URL so a repeated
   document/CSS/image URL hits the underlying loader once per render.
3. **Robustness / content-type / charset basics** — never panic on invalid
   UTF-8 (lossy decode, already done), degrade gracefully on any failed
   sub-resource, confirm we're robust to wrong/missing `Content-Type`.

This is **purely additive** in the `net` crate plus a one-line wire-up in
paint/CLI. **The `ResourceLoader` trait is unchanged** (`fetch(&self, url:
&Url) -> Result<Resource, LoadError>`), exactly as E3-M1/M2 designed it. No
paint pipeline change below the loader; no new charset/streaming machinery.

Guiding rule (project CLAUDE.md "Simplicity First"): a tiny `DataLoader`, a
tiny `CachingLoader` wrapper, and the already-present `from_utf8_lossy`
robustness — nothing speculative. Deviations/non-goals are called out in §6.

This note is pinned to the **real** current APIs, read and verified from source
(and a throwaway probe against the `url` crate, results quoted in §1.3). The
trait, `Resource`, `LoadError`, `RouterLoader`, `render_document`/`render_url`,
`collect_author_sheets`, and `ImageStore` are all quoted from the live tree.

## 1. `data:` URL support — `DataLoader`

### 1.1 Crate: `base64` 0.22

Add to **`crates/net/Cargo.toml`** (the loader is the only thing that decodes a
`data:` payload; everything above sees `&dyn ResourceLoader`):

```toml
[dependencies]
url = "2"
ureq = "3"
base64 = "0.22"   # RFC 4648 base64 decode for data:…;base64 payloads
```

- `base64` 0.22 is the current line; its API is the `Engine` trait +
  pre-built engine constants. The exact call we use:

  ```rust
  use base64::Engine as _;
  use base64::engine::general_purpose::STANDARD;
  let bytes = STANDARD.decode(payload_str)?;   // -> Result<Vec<u8>, DecodeError>
  ```

  `STANDARD` is the standard alphabet **with** `=` padding (what
  `data:…;base64,` uses). It tolerates correct padding; malformed input →
  `DecodeError` → we map to `LoadError::BadDataUrl` (§5). (We do **not** need
  the URL-safe alphabet for `data:`.) Percent-decoding of the *non*-base64
  text path uses the `percent-encoding` crate, which is already a transitive
  dep of `url`; rather than add it as a direct dep we re-implement the trivial
  `%XX` decode inline (§1.3) or pull `percent-encoding` as a direct dep — the
  implementation agent picks; inline is ~15 lines and avoids a new manifest
  entry, so **prefer inline** (Simplicity First).

### 1.2 RFC 2397 grammar we handle

```
data:[<mediatype>][;base64],<data>
<mediatype> := <mimetype>[;<param>=<value>]*   (we keep only the mimetype;
                                                params like charset are ignored)
```

- Everything before the **first comma** is the *header*; everything after is
  the *payload*.
- If the header **ends with `;base64`** (case-insensitive), the payload is
  base64; otherwise the payload is percent-encoded text whose bytes are the
  resource bytes.
- The media type is the header with any trailing `;base64` and any `;param`
  segments stripped — i.e. the part up to the first `;` (or the whole header if
  no `;`). Empty media type → default per RFC is `text/plain;charset=US-ASCII`;
  we set `content_type = None` and let the element type drive parsing (§3b).
- **No comma at all** → malformed → `LoadError::BadDataUrl` (§5).

### 1.3 Extracting the payload from `url::Url` (verified)

A throwaway probe (`crates/net/tests/`, since removed) against `url` 2.x
confirmed how `data:` URLs surface:

| input | `url.scheme()` | `url.path()` |
|-------|----------------|--------------|
| `data:text/css,p%7Bcolor%3Ared%7D` | `data` | `text/css,p%7Bcolor%3Ared%7D` |
| `data:,hello%20world` | `data` | `,hello%20world` |
| `data:image/png;base64,iVBORw0KG` | `data` | `image/png;base64,iVBORw0KG` |
| `data:text/css;base64,cHt9` | `data` | `text/css;base64,cHt9` |
| `data:;base64,SGk=` | `data` | `;base64,SGk=` |

**Key result:** for `data:` URLs `url::Url` does **not** percent-decode the
path — `%7B` stays literal. So `url.path()` returns exactly the substring after
`data:` (header + comma + payload), un-decoded. That is precisely what we need
(we must do our own percent-decode for the text path). To be robust against any
`url`-version quirk, we extract the same substring **deterministically from
`url.as_str()`** rather than trust `path()`:

```rust
// `url.as_str()` is "data:<everything>"; strip the scheme+':' prefix.
let after = url.as_str().strip_prefix("data:")
    .ok_or_else(|| LoadError::BadDataUrl(url.clone()))?;   // not a data: URL
// split header from payload at the FIRST comma.
let (header, payload) = after.split_once(',')
    .ok_or_else(|| LoadError::BadDataUrl(url.clone()))?;   // no comma → malformed
```

(`strip_prefix("data:")` can't fail when the router routed a `data` scheme
here, but we handle it as `BadDataUrl` rather than `unwrap`.) Using `as_str()`
+ `strip_prefix("data:")` + `split_once(',')` is the **exact, defined
extraction** — independent of `path()` decoding behavior.

### 1.4 `DataLoader`

`crates/net/src/data.rs` (new module; `lib.rs` adds `mod data; pub use
data::DataLoader;`).

```rust
use base64::Engine as _;
use base64::engine::general_purpose::STANDARD;
use url::Url;

use crate::loader::{LoadError, Resource, ResourceLoader};

/// Hard cap on decoded `data:` payload size (anti-OOM, mirrors the HTTP body
/// cap). A base64 image inline can be large but not unbounded.
const MAX_DATA_BYTES: usize = 10 * 1024 * 1024; // 10 MiB

/// Decodes `data:` URLs (RFC 2397) into in-memory bytes. Stateless, never
/// panics — every malformed input is a `LoadError::BadDataUrl`.
pub struct DataLoader;

impl ResourceLoader for DataLoader {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        if url.scheme() != "data" {
            return Err(LoadError::UnsupportedScheme(url.scheme().to_string()));
        }
        // 1. Split "data:<header>,<payload>" (§1.3).
        let after = url
            .as_str()
            .strip_prefix("data:")
            .ok_or_else(|| LoadError::BadDataUrl(url.clone()))?;
        let (header, payload) = after
            .split_once(',')
            .ok_or_else(|| LoadError::BadDataUrl(url.clone()))?;

        // 2. ;base64 flag (case-insensitive) + media type.
        let is_base64 = header
            .rsplit(';')
            .next()
            .is_some_and(|t| t.eq_ignore_ascii_case("base64"));
        let media = media_type(header, is_base64); // -> Option<String>

        // 3. Decode payload → bytes.
        let bytes = if is_base64 {
            // base64 may legally contain %XX-encoded whitespace/newlines from
            // the URL; percent-decode first, then base64-decode. (Most inputs
            // have no %; percent_decode is a no-op then.)
            let cleaned = percent_decode_str(payload);
            STANDARD
                .decode(cleaned)
                .map_err(|_| LoadError::BadDataUrl(url.clone()))?
        } else {
            // Plain text path: the payload bytes ARE percent-decoded text.
            percent_decode_bytes(payload)
        };

        // 4. Size cap (anti-OOM).
        if bytes.len() > MAX_DATA_BYTES {
            return Err(LoadError::BadDataUrl(url.clone()));
        }

        Ok(Resource {
            bytes,
            content_type: media,
            final_url: Some(url.clone()), // data: is self-contained, no redirect
        })
    }
}

/// Media type = header up to the first ';' (or whole header). Empty → None
/// (let the element type drive parsing, §3b). The `;base64` suffix and any
/// `;charset=…`/params are dropped.
fn media_type(header: &str, _is_base64: bool) -> Option<String> {
    let mime = header.split(';').next().unwrap_or("").trim();
    if mime.is_empty() { None } else { Some(mime.to_string()) }
}
```

`percent_decode_str` / `percent_decode_bytes`: a ~15-line inline helper that
walks the string, turning `%XX` (hex) into the byte and leaving everything else
(including `+`, which in `data:` is a literal plus, **not** a space) as-is.
Invalid `%` sequences (`%`, `%G1`) are passed through literally rather than
erroring — matching browser leniency and avoiding a hard failure on a
slightly-off URL. (Alternatively use `percent_encoding::percent_decode_str`
from the already-transitive crate; implementation agent's call, but keep the
"`+` is literal, bad `%` passes through" semantics.)

### 1.5 Wire into `RouterLoader`

`crates/net/src/router.rs` — add the `data` arm and a `DataLoader` field
(zero-size, so essentially free):

```rust
pub struct RouterLoader {
    local: LocalLoader,
    http: HttpLoader,
    data: DataLoader,            // NEW (ZST)
}

// in both ::new() and ::with_timeout(): `data: DataLoader,`

impl ResourceLoader for RouterLoader {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        match url.scheme() {
            "file" => self.local.fetch(url),
            "http" | "https" => self.http.fetch(url),
            "data" => self.data.fetch(url),        // NEW (replaces the M2 TODO)
            other => Err(LoadError::UnsupportedScheme(other.to_string())),
        }
    }
}
```

### 1.6 `data:` and base resolution (verified)

`data:` is a **"cannot-be-a-base" URL**. The probe confirmed:

```
Url::parse("data:text/plain,hi").join("x.css")   = Err(RelativeUrlWithCannotBeABaseBase)
Url::parse("data:text/plain,hi").join("data:,other") = Ok("data:,other")
```

Consequences for the existing pipeline (no special-casing needed):

- An **absolute `data:` URL as a sub-resource** — `<img
  src="data:image/png;base64,…">` or `<link href="data:text/css,…">` — joins
  fine because `base.join("data:…")` returns the absolute data URL unchanged.
  So `ImageStore`/`collect_author_sheets` resolve it and route it to
  `DataLoader`. **This is the common case and works with no code change in
  paint.**
- A **`data:` URL as the *document* base** with a **relative** sub-resource
  (`base.join("theme.css")`) → `Err`. In `collect_author_sheets`/`ImageStore`
  that `Err` is already handled by `?`/`.ok()?` → the sub-resource is skipped.
  This is correct: a `data:` document has no base to resolve relatives against.
  No panic, graceful skip. (Rendering a `data:text/html` *document* itself is
  not a milestone goal, but `render_url`/CLI would still work for it: fetch via
  `DataLoader` → `from_utf8_lossy` → render; only its *relative* sub-resources
  drop.)

So **no special-case join logic is required** — the `url` crate's
cannot-be-a-base behavior already produces exactly the right graceful outcome.

## 2. In-memory resource cache — `CachingLoader<L>`

### 2.1 Shape: a wrapper around any `ResourceLoader`

`crates/net/src/cache.rs` (new; `lib.rs` adds `mod cache; pub use
cache::CachingLoader;`). A generic wrapper that memoizes `fetch` by `Url`:

```rust
use std::cell::RefCell;
use std::collections::HashMap;
use std::rc::Rc;

use url::Url;

use crate::loader::{LoadError, Resource, ResourceLoader};

/// Wraps any `ResourceLoader` and dedupes `fetch` by URL within one render: the
/// first fetch of a URL hits the inner loader; the outcome (success OR error)
/// is memoized and returned to every later fetch of the same URL. Single-render
/// scoped (built fresh per render, dropped after), so `RefCell`/`Rc` are sound:
/// the whole pipeline is single-threaded (fetch-then-render).
pub struct CachingLoader<L: ResourceLoader> {
    inner: L,
    cache: RefCell<HashMap<Url, Rc<Result<Resource, LoadError>>>>,
}

impl<L: ResourceLoader> CachingLoader<L> {
    pub fn new(inner: L) -> Self {
        CachingLoader { inner, cache: RefCell::new(HashMap::new()) }
    }
}
```

### 2.2 The `Clone` problem — `Resource` clones, `LoadError` does not

The trait returns `Result<Resource, LoadError>` **by value**, so the cache must
hand back an *owned* result on every call. Two facts shape the design:

- `Resource { bytes: Vec<u8>, content_type: Option<String>, final_url:
  Option<Url> }` — all `Clone`. We add `#[derive(Clone)]` to `Resource` (it has
  none today; this is a trivial, safe addition — every field is `Clone`).
- `LoadError` is **not** `Clone` (`Io(std::io::Error)` and
  `BadUrl(url::ParseError)` aren't cheaply/derivably `Clone`). We do **not**
  want to force `LoadError: Clone`.

Resolution: store **`Rc<Result<Resource, LoadError>>`** in the map, and on a hit
**re-materialize** an owned `Result` for the caller:

```rust
impl<L: ResourceLoader> ResourceLoader for CachingLoader<L> {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        // Hit?
        if let Some(slot) = self.cache.borrow().get(url) {
            return rematerialize(slot);
        }
        // Miss: fetch once, store the Rc, return a fresh owned copy.
        let result = self.inner.fetch(url);
        let slot = Rc::new(result);
        self.cache.borrow_mut().insert(url.clone(), Rc::clone(&slot));
        rematerialize(&slot)
    }
}

/// Produce an owned `Result` from a cached slot. `Ok` clones the `Resource`
/// (cheap-ish: Vec<u8> clone). `Err` is reconstructed as a *summary* error so
/// callers still get an `Err` without requiring `LoadError: Clone`.
fn rematerialize(slot: &Rc<Result<Resource, LoadError>>) -> Result<Resource, LoadError> {
    match &**slot {
        Ok(res) => Ok(res.clone()),
        Err(e) => Err(LoadError::Network(format!("{e}"))),  // see note
    }
}
```

**Caching errors (recommended) without `LoadError: Clone`.** We cache the
outcome including failures so a 404'd or unreachable URL isn't re-hit on every
reference. Because `LoadError` isn't `Clone`, the cached error is returned to
later callers as a **flattened `LoadError::Network(Display-of-original)`**. This
is acceptable because **every sub-resource caller treats any `Err` identically
(skip the resource)** — they never match on the variant. The CLI only matches
the variant for the *document* fetch, which is the **first** fetch of that URL
(a cache miss → the original, un-flattened error is returned). So variant
fidelity is preserved exactly where it's consumed (the first/top-level fetch)
and lossily-but-harmlessly collapsed only on *repeat* fetches of an
already-failed URL.

> Simpler alternative the implementation agent may take if the flattening feels
> impure: **cache successes only** (store `Rc<Resource>`; on a miss that errored,
> return the error straight through and don't insert). Failures then re-hit the
> inner loader on every reference. For `data:`/`file:` that's free; for HTTP a
> repeated 404 re-requests. Given Simplicity First and that repeated-failed-URL
> is rare, *cache-successes-only* is a legitimate MVP. **Recommendation: cache
> both** (the flatten-on-repeat above) — it's ~5 extra lines and avoids
> re-hitting a dead URL. Either is acceptable; pick one and note it in code.

### 2.3 Where the cache lives — layering vs `ImageStore`

```
render_url / CLI
        │ builds
        ▼
CachingLoader<RouterLoader>          ← NEW: dedupes at the BYTES/fetch level
        │  fetch(url)                   (one entry per Url, success or error)
        ▼
RouterLoader { local, http, data }   ← scheme dispatch (E3-M2 + §1.5)
```

And **above** the loader, unchanged:

```
ImageStore (in paint)  ← caches DECODED images (Option<DecodedImage>) by Url
```

Two distinct caches at two levels, **no conflict, no wasteful double-caching**:

- **`ImageStore`** already dedupes **decoded** images per `<img src>` Url, so a
  given image URL is fetched-and-decoded once *within the image pre-pass*.
- **`CachingLoader`** dedupes at the **bytes/fetch** level across *all* callers:
  the **document** fetch, every **linked CSS** fetch, and every **image** fetch.
  It helps where `ImageStore` can't: the same `<link href>` appearing twice (CSS
  is re-fetched today — `collect_author_sheets` has no cache), a CSS file and an
  image at the same URL (rare), or the document URL also referenced as a
  sub-resource. It also means the bytes for an image are cached even if (future)
  some other subsystem fetched the same URL.
- **No double-caching of image bytes wastefully:** `ImageStore` decodes
  immediately and keeps only the *decoded* `DecodedImage`, dropping the raw
  bytes; `CachingLoader` keeps the raw bytes once. They store different things.
  The only overlap is that an image fetched once lives as raw bytes in
  `CachingLoader` *and* decoded in `ImageStore` — but `ImageStore` fetches each
  image URL exactly once anyway (its own `Option<DecodedImage>` cache), so the
  `CachingLoader` entry for an image is populated once and re-read only if that
  same URL is *also* a `<link href>` (the cross-type case). Net: each URL is
  fetched over the wire/disk **at most once per render**; decoded at most once.

This is the minimal, non-overlapping layering: keep `ImageStore` exactly as-is
(it's a *decode* cache), add `CachingLoader` as the *fetch* cache underneath.

### 2.4 Scope & thread-safety

- **Per-render**, not persistent: `render_url`/CLI build a fresh
  `CachingLoader` for each render and drop it after. No cross-render or on-disk
  cache (a non-goal, §6).
- **Single-threaded**: the entire fetch-then-render pipeline runs on one thread,
  so `RefCell<HashMap>` + `Rc` are sound and lock-free. We deliberately do
  **not** use `Mutex`/`Arc` (no concurrency to protect against). A doc comment
  states this invariant. (If a future epic parallelizes fetching, this wrapper
  is swapped for an `RwLock`/`DashMap` variant; not now.)

## 3. Robustness / content-type / charset

Most of this already exists; M3's job is to *confirm* and fill the one gap.

**(a) Charset — assume UTF-8, lossy.** CSS and HTML bytes are decoded with
`String::from_utf8_lossy` (already in `collect_author_sheets`'
`load_link_sheet`, in `render_url`, and in the CLI). Invalid UTF-8 → U+FFFD
replacement chars, **never a panic**. The `Content-Type` `charset=` parameter is
**ignored** (non-UTF-8 charset transcoding deferred, §6). *No code change
needed* — this is already the behavior; M3 documents it as the intended final
policy and adds a test (§7) proving invalid-UTF-8 CSS doesn't panic.

**(b) Wrong/missing `Content-Type` is fine.** We parse a resource by the
**element that references it** (`<link rel=stylesheet>` → CSS parser; `<img>` →
`image::load_from_memory`, which sniffs PNG/JPEG magic bytes), **not** by
`Content-Type`. So a CSS served as `text/plain` or with no header still parses
as CSS; an image served as `application/octet-stream` still decodes (magic-byte
sniff). `Resource.content_type` is captured (HTTP header; `data:` media type)
but **not currently used to gate parsing** — and that's the robust choice. *No
code change.* (We keep the field populated for future use / debugging.)

**(c) Redirects.** Already handled in `HttpLoader` (E3-M2): ureq follows ≤10
redirects, `final_url` carries the post-redirect URL, relative sub-resources
resolve against it. **Nothing new in M3.** `data:`/`file:` have no redirects
(`final_url = the requested URL`).

**(d) Graceful degradation.** Any failed sub-resource — a malformed `data:`
URL, a 404, a `BadDataUrl`, a cache-stored error — surfaces as `Err` and is
**skipped** by `collect_author_sheets` (`?`/`.ok()?`) and `ImageStore`
(`fetch(...).ok()?` → cached `None`, broken-image placeholder). The page still
renders with the rest. The **document** fetch failing → clean CLI error +
non-zero exit (existing `main` path). **No panics anywhere.** This is the
existing M1/M2 posture; M3 only adds `BadDataUrl` to the set of `Err`s that flow
through it (and a `data:` image that's malformed renders the same grey
broken-image placeholder as a 404 image).

## 4. Integration (minimal churn)

### 4.1 `render_url` and CLI build a `CachingLoader<RouterLoader>`

`crates/paint/src/lib.rs` — `render_url` is the one spot that constructs the
loader for the network path. Wrap the router in a caching loader:

```rust
pub fn render_url(url: &Url, viewport_width: f32) -> Result<Pixmap, LoadError> {
    let loader = CachingLoader::new(RouterLoader::new());   // was: RouterLoader::new()
    let res = loader.fetch(url)?;
    let html = String::from_utf8_lossy(&res.bytes);         // lossy UTF-8 (§3a)
    let base = res.final_url.as_ref().unwrap_or(url);
    Ok(render_document(&html, base, viewport_width, &loader))
}
```

`render_document` takes `&dyn ResourceLoader`, so passing `&loader`
(a `&CachingLoader<RouterLoader>`) just works — `collect_author_sheets` and
`ImageStore` see the caching layer transparently. Re-export `CachingLoader` (and
`DataLoader`) from paint's `lib.rs` alongside the existing net re-exports.

`render_path` (local file) **may** also wrap in `CachingLoader::new(LocalLoader)`
for symmetry/dedup, but the benefit is marginal (local reads are cheap, and a
file rarely linked twice) — optional; **recommend leaving `render_path`
unchanged** (Simplicity First) and only caching the network path. The
implementation agent may add it if a test wants it.

### 4.2 CLI

`crates/cli/src/main.rs` builds the loader inline (it needs the
`UnsupportedScheme` → friendly-message mapping for the *document* fetch). Wrap
the router the same way:

```rust
let router = match timeout {
    Some(t) => RouterLoader::with_timeout(t),
    None => RouterLoader::new(),
};
let loader = CachingLoader::new(router);
// ...fetch(&base) as today (the UnsupportedScheme arm still works: a cache miss
//    returns the inner RouterLoader's original error variant — §2.2)...
let pixmap = starfish_paint::render_document(&html, render_base, width as f32, &loader);
```

`base_url_from_input` already passes an absolute `data:` URL through unchanged
(it's parseable by `Url::parse`), so `starfish render 'data:text/html,<p>hi'`
routes to `DataLoader` for the document — works for free (its relative
sub-resources, if any, are dropped per §1.6). The CLI manifest is unchanged.

### 4.3 Trait unchanged

No change to `trait ResourceLoader`. `DataLoader` and `CachingLoader<L>` both
`impl ResourceLoader`. `Resource` gains `#[derive(Clone)]` (additive, §2.2).
`LoadError` gains one variant (§5).

## 5. `LoadError` extension (minimal — one variant)

Add a single variant to `crates/net/src/loader.rs` and one `Display` arm.

```rust
#[derive(Debug)]
pub enum LoadError {
    // ...existing (NotFound, Io, UnsupportedScheme, BadPath, BadUrl,
    //              Http, Timeout, Network)...
    /// A malformed `data:` URL — no comma, bad base64, or over the size cap.
    BadDataUrl(Url),
}
```

```rust
// Display arm (add):
LoadError::BadDataUrl(u) => write!(f, "malformed data: URL: {u}"),
// Error::source: no nested std::error::Error → falls in the existing `_ => None`.
```

One variant covers all `data:` failures (no comma / bad base64 / over-cap); the
CLI/callers don't need finer granularity — a malformed `data:` sub-resource is
skipped like any other `Err`, and a malformed `data:` *document* prints this
message. **No `Clone` derive on `LoadError`** (the cache works around it, §2.2).

(Why not reuse `Network`? A `data:` failure isn't a network failure; a distinct
variant gives a correct CLI message and keeps the meaning honest. It's the
minimum — one variant.)

## 6. Edge cases & non-goals (deliberate)

**Handled:**
- `data:image/<x>;base64,…` images (`<img src>`), `data:text/css,…` and
  `data:text/css;base64,…` stylesheets (`<link href>`), `data:,plain` text,
  `data:;base64,…` (empty media type). Media type → `content_type`; `;base64`
  detection; base64 decode (`base64 0.22`) or percent-decoded text bytes.
- Malformed `data:` (no comma, invalid base64, over 10 MiB) → `BadDataUrl`,
  skipped (sub-resource) or clean error (document). **No panic.**
- `data:` cannot-be-a-base join behavior verified — absolute `data:`
  sub-resources resolve; relative-against-`data:`-document gracefully skipped.
- Per-render fetch cache (`CachingLoader`) dedupes document/CSS/image fetches by
  URL; caches outcome incl. errors (flattened-on-repeat, §2.2). Layered under
  `ImageStore`'s decode cache without overlap (§2.3).
- Invalid-UTF-8 CSS/HTML → lossy decode, no panic. Wrong/missing `Content-Type`
  tolerated (parse by element type). Redirects via M2 unchanged.

**Explicit non-goals (documented):**
- **No charset transcoding** — UTF-8 assumed, `from_utf8_lossy`; `charset=`
  param ignored. Non-UTF-8 (Shift-JIS, etc.) deferred.
- **No `blob:` / `about:` / `filesystem:` schemes** — `UnsupportedScheme`
  (deferred). Only `data` is added in M3.
- **No `data:` charset/param semantics beyond ignoring them** — we keep only the
  mimetype; `charset`, `name=`, etc. are dropped. `+` in a `data:` payload is a
  **literal** `+` (not a space — `data:` is RFC 2397, not form-encoding).
- **No persistent / on-disk cache, no cross-render cache** — `CachingLoader` is
  built fresh per render and dropped. No `Cache-Control`/`ETag`/conditional
  requests / cache invalidation (Epic-3 non-goal; M2 §8).
- **No streaming** — `data:` decoded fully into memory (capped); fetch-then-
  render unchanged.
- **`data:` size cap = 10 MiB** (`MAX_DATA_BYTES`, mirrors the HTTP body cap) —
  over-cap → `BadDataUrl` (anti-OOM for a hostile huge base64 blob).
- **Cache thread-safety: single-threaded only** (`RefCell`/`Rc`); not safe to
  share across threads (no concurrency in the pipeline).
- **Cached errors are flattened to `Network(msg)` on repeat fetches** (§2.2) —
  variant fidelity kept only on the first/top-level fetch (where it's consumed).

## 7. Test plan (concrete, deterministic)

All in `crates/net` unit tests (`data.rs`, `cache.rs`) + a couple of paint
integration tests. No real network (data:/file: are offline; HTTP cache test
uses the existing `tiny_http` harness or a counting mock).

### 7.1 `DataLoader` (in `data.rs` `#[cfg(test)]`)

1. **base64 image round-trips** — encode a 2×2 PNG (the existing fixture
   bytes) to base64, build `data:image/png;base64,<b64>`,
   `DataLoader.fetch(url)` → `Ok(Resource)` with `content_type ==
   Some("image/png")` and bytes byte-equal to the PNG; feed to
   `image::load_from_memory` → decodes 2×2.
2. **`data:text/css,…` plain** — `data:text/css,p%7Bcolor%3Ared%7D` →
   bytes == `b"p{color:red}"` (percent-decoded), `content_type ==
   Some("text/css")`.
3. **`data:text/css;base64,…`** — base64 of `p{color:red}` → same bytes,
   `content_type == Some("text/css")`, `is_base64` path.
4. **`data:,hello`** — bytes == `b"hello"`, `content_type == None`.
5. **`data:,hello%20world`** — percent-decode → `b"hello world"`.
6. **empty media type `data:;base64,SGk=`** → bytes `b"Hi"`, `content_type ==
   None`.
7. **malformed — no comma** `data:text/plain` → `Err(BadDataUrl)`, no panic.
8. **malformed — bad base64** `data:image/png;base64,@@@notb64@@@` →
   `Err(BadDataUrl)`, no panic.
9. **over-cap** — a `data:` with a payload decoding to > a small test cap
   (use a `MAX_DATA_BYTES` test knob, or assert with a deliberately tiny cap
   ctor) → `Err(BadDataUrl)`, no OOM.
10. **`+` is literal** — `data:,a+b` → bytes `b"a+b"` (not `b"a b"`).

### 7.2 `RouterLoader` routes `data` (in `router.rs`)

11. `RouterLoader::new().fetch("data:,hi")` → `Ok` with bytes `b"hi"` (proves
    the `data` arm replaced the M2 `UnsupportedScheme("data")`).

### 7.3 `CachingLoader` (in `cache.rs` `#[cfg(test)]`, counting mock)

```rust
struct Counting { hits: std::cell::Cell<u32>, body: &'static [u8] }
impl ResourceLoader for Counting {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        self.hits.set(self.hits.get() + 1);
        Ok(Resource { bytes: self.body.to_vec(), content_type: None,
                      final_url: Some(url.clone()) })
    }
}
```

12. **success dedupe** — wrap `Counting`; `fetch(u)` twice for the **same** URL
    → both `Ok` with the body; **`hits == 1`** (inner hit exactly once). A
    different URL bumps to 2.
13. **error cached (recommended path)** — a mock that returns
    `Err(LoadError::Http{status:404,..})` and counts; `fetch(u)` twice →
    **`hits == 1`**, both calls `Err`. (If implementing *cache-successes-only*,
    this test asserts `hits == 2` instead — pick per §2.2 and write the matching
    assertion. **Recommended: cache errors → `hits == 1`.**)
14. **owned result** — confirm a cached `Ok` returns the bytes again (Resource
    cloned), independent of the first caller's value.

### 7.4 paint integration (end-to-end, in `paint` `#[cfg(test)]`)

15. **`data:` image renders** — `<img src="data:image/png;base64,<2x2 png>"
    width=4 height=4>` via `render_document` with `RouterLoader`/`CachingLoader`
    → the 4×4 pixmap quadrants match the PNG (TL red, TR green, BL blue, BR
    white), reusing the existing `px()`/`write_e3_png` assert pattern.
16. **`data:` linked CSS applies** — both `<link rel=stylesheet
    href="data:text/css,p{color:blue}">` and a `;base64` variant → rendered text
    is blue (reuse `has_color`). Proves `collect_author_sheets` →
    `base.join(data-url)` → `DataLoader` → parse.
17. **malformed `data:` sub-resource skipped** — `<img
    src="data:image/png;base64,@@@">` and `<link
    href="data:text/css,@@@bad">` (bad CSS still parses leniently; for the test
    use a bad base64 image) → renders without panic; broken-image placeholder
    for the bad image, page otherwise intact.
18. **invalid-UTF-8 CSS is lossy, no panic** — a `file://` (or counting-mock)
    CSS resource whose bytes are invalid UTF-8 (e.g. `b"p{}\xFF\xFE"`) →
    `collect_author_sheets` `from_utf8_lossy` → parses what it can, **no panic**;
    render completes.
19. **repeated linked CSS fetched once** — a document with the **same**
    `<link href="…theme.css">` twice, rendered through a
    `CachingLoader<Counting>` (or a `tiny_http` server counting requests) →
    the CSS URL is fetched **once** (assert the counter), and the style still
    applies. Proves the fetch-level dedupe `ImageStore` can't provide for CSS.
20. **end-to-end combined** — one page using a `data:` image **and** a repeated
    cached linked CSS over the counting loader: image renders, CSS applies,
    inner loader hit counts match expectations (data: image decoded once via
    `ImageStore`; CSS fetched once via `CachingLoader`).

### 7.5 Not tested
- Non-UTF-8 charset transcoding (deferred). `blob:`/`about:` (deferred). HTTPS
  cache behavior over the real network (loopback `tiny_http` counting suffices).
