# E3-M1 — URL model + `ResourceLoader` + linked stylesheets (design note)

Scope (per `docs/ROADMAP-epic3.md`): turn "render an HTML string with a base
*dir*" into "render a document identified by a *base URL*, fetching its linked
resources through a `ResourceLoader`." This milestone:

1. A new **`net` crate** holding a `Url` model (over the `url` crate) and the
   `ResourceLoader` trait + a `LocalLoader` for `file://` / local paths.
2. **Relative-URL resolution** against a base URL (`base.join(href)`).
3. Load **`<link rel="stylesheet">`** external CSS and merge it with inline
   `<style>` **in document order** into the author `Vec<Stylesheet>`.
4. Refactor E2-M4's **`ImageStore`** so `<img src>` is resolved as a URL against
   the base and fetched via the loader (instead of a `base_dir` filesystem join).

**No HTTP** (E3-M2), **no `data:`** (E3-M3), no `@import`, no media queries, no
charset detection. The loader trait is designed so an `HttpLoader` (M2) is just
another impl behind the same `fetch` call and a composite loader dispatches by
scheme.

Guiding rule (project CLAUDE.md "Simplicity First"): the smallest loader
abstraction that lets M2 slot HTTP in cleanly. Bytes-in/bytes-out, errors as
values, never panic. Deviations from real browsers are called out in §8.

This note is pinned to the **real** current APIs read from source (signatures
quoted inline), not an idealized model.

## 1. New `net` crate (`crates/net`)

A small workspace crate that owns the URL model and the loader abstraction. It
has **no dependency on dom/style/paint** — it's a leaf utility crate, so paint
and cli (and later html-fetching in M2) can depend on it without cycles.

### 1.1 Manifest

```toml
# crates/net/Cargo.toml

version.workspace = true
edition.workspace = true
license.workspace = true
repository.workspace = true

                    # Exact version pinned in the committed Cargo.lock.

`url` is the standard, well-maintained WHATWG URL implementation; it gives

## 2. Url model

### 2.1 Re-export `url::Url`, don't wrap

`url::Url` already does everything the milestone lists: absolute parse
(`Url::parse`), relative resolution (`base.join(href)`), scheme detection
(`.scheme()`), and `file://` ↔ path conversion (`from_file_path`/`to_file_path`).
A newtype would only re-expose those by hand. Per Simplicity First we **re-export
`url::Url` as `starfish_net::Url`** and add *free functions* for the two
operations `url` does NOT spell directly: building a base URL from a user input
(path or `file://`) and getting a readable filesystem path back out. No newtype.

### 2.2 Building the document base URL from a CLI input (`resolve.rs`)

A user supplies either a `file://`/`http(s)` URL or a bare filesystem path
(`page.html`, `./sub/page.html`, `/abs/page.html`). Rule:

```rust
use std::path::Path;
use url::Url;

/// Turn a user-supplied input (a URL string OR a filesystem path) into the
/// document's absolute base `Url`.
///
/// - If `input` parses as an absolute URL (`file://…`, `http://…`, …) it is
///   used as-is.
/// - Otherwise `input` is treated as a filesystem path and converted to a
///   `file://` URL: relative paths are first made absolute by joining the
///   current working directory (so relative `href`/`src` later resolve the way
///   a user expects when running `starfish render page.html`).
pub fn base_url_from_input(input: &str) -> Result<Url, LoadError> {
    if let Ok(u) = Url::parse(input) {
        // `Url::parse` succeeds only for an absolute URL with a scheme; a bare
        // path like "page.html" or "C:foo" fails here and falls through.
        return Ok(u);
    }
    file_url_from_path(Path::new(input))
}

/// Convert a filesystem path to an absolute `file://` URL. Relative paths join
/// the current working directory. The path need not exist (resolution is
/// lexical; the loader reports a missing file at fetch time).
pub fn file_url_from_path(path: &Path) -> Result<Url, LoadError> {
    let abs = if path.is_absolute() {
        path.to_path_buf()
    } else {
        std::env::current_dir()
            .map_err(LoadError::Io)?
            .join(path)
    };
    Url::from_file_path(&abs).map_err(|()| LoadError::BadPath(abs))
}
```

Notes:
- `Url::parse` only accepts an absolute URL (one with a scheme), so a single
  bare segment `"page.html"` returns `Err` and is correctly treated as a path.
  (A Windows drive path `C:\…` also fails `parse` — handled as a path. Fine for
  this Linux-targeted tool; noted §8.)
- For a **directory base** (rare), callers pass a path ending in `/`; for a file
  base (the normal HTML document), the file's own URL is the base — relative
  `href` resolves against the *file*, which is what `Url::join` does
  (`file:///a/b/page.html`.join(`theme.css`) = `file:///a/b/theme.css`). This
  replaces E2-M4's "input.parent() as base dir": the base is now the document's
  full URL, and `join` handles the "drop the last path segment" automatically.

### 2.3 Getting a readable path back (used by `LocalLoader`)

```rust
/// The filesystem path a `file://` URL refers to, or `None` if `url` is not a
/// `file:` URL (or has a host / is otherwise not a local path).
fn file_path_of(url: &Url) -> Option<std::path::PathBuf> {
    if url.scheme() != "file" { return None; }
    url.to_file_path().ok()
}
```

(`to_file_path` already strips the scheme, percent-decodes, and rejects URLs
with a non-empty host on Unix.)

### 2.4 Relative resolution — the one call everyone uses

```rust
// caller side (paint §5/§6): resolve an href/src against the document base.
let resolved: Url = base.join(href).map_err(LoadError::BadUrl)?;
```

`Url::join` implements WHATWG relative resolution: absolute `href`
(`http://…`, `file:///…`) replaces the base; relative `href` resolves against
the base's path; `#frag`/`?query`-only refs keep the path. Exactly the cascade
of cases the milestone needs, for free.

## 3. `ResourceLoader` trait + `LocalLoader` + `LoadError` (`net/src/loader.rs`)

### 3.1 Error type — values, never panics

```rust
use std::path::PathBuf;

#[derive(Debug)]
pub enum LoadError {
    /// The resource does not exist (e.g. `file://` path not found).
    NotFound(Url),
    /// An I/O error while reading (permissions, mid-read failure, cwd lookup).
    Io(std::io::Error),
    /// A scheme no loader handles yet (e.g. `http`/`https` in M1, `data:` in M1/M2).
    UnsupportedScheme(String),
    /// A `file://` URL that doesn't map to a local path (host present, etc.).
    BadPath(PathBuf),
    /// A relative `href` that failed to resolve against the base.
    BadUrl(url::ParseError),
}

impl std::fmt::Display for LoadError { /* human messages; "http not yet supported" etc. */ }
impl std::error::Error for LoadError {}
```

Callers (CSS/image collection) treat **any** `Err` as "skip this resource, keep
rendering" (§5, §6). The CLI surfaces a clean message for the *document* fetch
failing (§7). No `unwrap`/`panic` anywhere in the loader.

### 3.2 The loader trait — bytes in, bytes out

```rust
/// A fetched resource: the raw bytes plus an optional content type. M1 fills
/// `content_type` only when the loader knows it cheaply (LocalLoader leaves it
/// `None` — it sniffs by magic bytes / context). Kept on the struct so M2's
/// HttpLoader can populate it from the `Content-Type` header without changing
/// the trait.
pub struct Resource {
    pub bytes: Vec<u8>,
    pub content_type: Option<String>,
}

/// Fetches the bytes of a resource named by an absolute `Url`. Implementations
/// MUST NOT panic — every failure is a `LoadError`. The `&self` receiver lets a
/// loader hold config/cache (M3) and be shared as `&dyn ResourceLoader`.
pub trait ResourceLoader {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError>;
}
```

Bytes (not `String`) because images are binary; CSS callers do
`String::from_utf8_lossy(&res.bytes)` (assume UTF-8, §8). `content_type` is
carried now but unused in M1 — it costs one field and saves a trait change in
M2/M3.

### 3.3 `LocalLoader` — `file://` + local paths

```rust
/// Reads `file://` URLs from the local filesystem. The only loader in M1.
pub struct LocalLoader;

impl ResourceLoader for LocalLoader {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        match url.scheme() {
            "file" => {
                let path = file_path_of(url).ok_or_else(|| LoadError::BadPath(/*…*/))?;
                match std::fs::read(&path) {
                    Ok(bytes) => Ok(Resource { bytes, content_type: None }),
                    Err(e) if e.kind() == std::io::ErrorKind::NotFound =>
                        Err(LoadError::NotFound(url.clone())),
                    Err(e) => Err(LoadError::Io(e)),
                }
            }
            other => Err(LoadError::UnsupportedScheme(other.to_string())),
        }
    }
}
```

### 3.4 Designing for M2/M3 (composite dispatch) — documented, not built

M1 ships only `LocalLoader`. M2 adds `HttpLoader` (same trait). Dispatch by
scheme is then a trivial composite that needs **no trait change**:

```rust
// Sketch for M2 — NOT implemented in M1, shown to prove the trait is sufficient.
pub struct SchemeRouter { local: LocalLoader, http: HttpLoader }
impl ResourceLoader for SchemeRouter {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        match url.scheme() {
            "file" => self.local.fetch(url),
            "http" | "https" => self.http.fetch(url),
            "data" => /* M3 */ Err(LoadError::UnsupportedScheme("data".into())),
            s => Err(LoadError::UnsupportedScheme(s.into())),
        }
    }
}
```

Because every consumer takes `&dyn ResourceLoader`, swapping `LocalLoader` for a
`SchemeRouter` in M2 is a one-line change at the call sites in cli/paint.

## 4. Pipeline integration — `render_document` (`crates/paint/src/lib.rs`)

### 4.1 New URL/loader entry point

```rust
use starfish_net::{ResourceLoader, Url};

/// End-to-end: HTML string → rendered pixmap, resolving and fetching the
/// document's external resources (linked CSS, images) against `base` through
/// `loader`. `base` is the document's own URL.
pub fn render_document(
    html: &str,
    base: &Url,
    viewport_width: f32,
    loader: &dyn ResourceLoader,
) -> Pixmap {
    let doc = starfish_html::parse(html);

    // §5: author sheets in document order (inline <style> + linked <link>).
    let author = collect_author_sheets(&doc, base, loader);
    let styled = style_tree(&doc, &author);

    let fonts = FontDb::load().expect("embedded faces load");

    // §6: ImageStore now resolves <img src> against `base` and fetches via loader.
    let mut images = ImageStore::new(base.clone(), loader);
    decode_images(&doc, &mut images);

    let root = layout(&doc, &styled, viewport_width, &FontMeasurer(&fonts), &images);

    let width = clamp_dimension(viewport_width);
    let height = clamp_dimension(root.dimensions().margin_box().height);
    paint(&root, &styled, &fonts, &images, width, height)
}
```

`paint`, `build_display_list`, `rasterize`, `layout`, `clamp_dimension`,
`decode_images` are **unchanged** — they only ever saw the raw `src` string and
`&ImageStore`/`&dyn ImageSource`, which still hold.

### 4.2 Convenience: `render_path` + keep the old entries as shims

```rust
/// Render a local HTML file by path: builds a `file://` base URL and a
/// `LocalLoader`. The CLI's normal path.
pub fn render_path(path: &Path, viewport_width: f32) -> Result<Pixmap, LoadError> {
    let base = starfish_net::file_url_from_path(path)?;
    let html = std::fs::read_to_string(path).map_err(LoadError::Io)?;
    Ok(render_document(&html, &base, viewport_width, &LocalLoader))
}

/// BACK-COMPAT shim: render an HTML string with a base *directory* (E2-M4 API).
/// Builds a `file://` base from `base_dir` + a synthetic document name and a
/// `LocalLoader`, then delegates to `render_document`. Keeps existing callers /
/// the many paint unit tests compiling unchanged.
pub fn render_html(html: &str, viewport_width: f32, base_dir: &Path) -> Pixmap {
    // base = file://<base_dir>/  — a trailing-slash dir URL so relative src/href
    // join against the directory (matching the old base_dir-join semantics).
    let dir = if base_dir.is_absolute() { base_dir.to_path_buf() }
              else { std::env::current_dir().unwrap_or_default().join(base_dir) };
    let base = Url::from_directory_path(&dir)
        .unwrap_or_else(|()| Url::parse("file:///").unwrap());
    render_document(html, &base, viewport_width, &LocalLoader)
}

/// BACK-COMPAT shim (E2-M4): base = current working directory.
pub fn render_html_cwd(html: &str, viewport_width: f32) -> Pixmap {
    let cwd = std::env::current_dir().unwrap_or_else(|_| PathBuf::from("."));
    render_html(html, viewport_width, &cwd)
}
```

`Url::from_directory_path` appends the trailing `/`, so
`file:///dir/`.join("px.png") = `file:///dir/px.png` — **byte-identical
resolution to the old `base_dir.join("px.png")`**, which is why every E2-M4
paint test (which calls `render_html(html, w, &dir)`) keeps passing without
edits. This is the migration safety net: behavior is preserved, only the
plumbing moves to URLs+loader.

Re-exports added to `lib.rs`: `pub use starfish_net::{Url, ResourceLoader,
LocalLoader, LoadError};`.

## 5. Author CSS collection in document order (`crates/paint/src/lib.rs`)

Replace `extract_css(doc) -> String` (which only gathered `<style>` text into one
string and parsed once) with a DOM walk that builds the author **`Vec<Stylesheet>`
in document order**, interleaving inline and linked sheets. This stays in
**paint** (which already orchestrates the pipeline) as a private helper — no new
crate/module needed; minimal churn.

```rust
use starfish_dom::{Document, NodeKind};
use starfish_css::Stylesheet;
use starfish_net::{ResourceLoader, Url};

/// Walk the DOM in document order; for each `<style>` parse its text, for each
/// `<link rel="stylesheet" href>` resolve `href` against `base`, fetch via
/// `loader`, and parse the bytes as UTF-8 CSS. Returns the author sheets in the
/// order encountered → correct cascade order (later sheet wins ties).
///
/// A `<link>` with no/empty `href`, a bad URL, or a failed fetch is skipped
/// (no panic, no sheet added) — the page still renders with the rest.
fn collect_author_sheets(
    doc: &Document,
    base: &Url,
    loader: &dyn ResourceLoader,
) -> Vec<Stylesheet> {
    let mut sheets = Vec::new();
    // Same document-order DFS shape as the old extract_css / decode_images:
    // children pushed reversed so pop() yields document order.
    let mut stack = vec![doc.root()];
    while let Some(id) = stack.pop() {
        match doc.tag_name(id) {
            Some("style") => {
                let mut css = String::new();
                for c in doc.children(id) {
                    if let NodeKind::Text(t) = doc.kind(c) { css.push_str(t); css.push('\n'); }
                }
                sheets.push(starfish_css::parse_stylesheet(&css));
            }
            Some("link") if rel_is_stylesheet(doc.get_attribute(id, "rel")) => {
                if let Some(sheet) = load_link_sheet(doc, id, base, loader) {
                    sheets.push(sheet);
                }
            }
            _ => {}
        }
        for c in doc.children(id).into_iter().rev() { stack.push(c); }
    }
    sheets
}

/// `rel` is a space-separated token list; match the `stylesheet` keyword
/// case-insensitively (e.g. `rel="stylesheet"`, `rel="StyleSheet"`).
fn rel_is_stylesheet(rel: Option<&str>) -> bool {
    rel.map_or(false, |r| r.split_ascii_whitespace().any(|t| t.eq_ignore_ascii_case("stylesheet")))
}

/// Resolve + fetch + parse one linked stylesheet. `None` on any failure (skip).
fn load_link_sheet(
    doc: &Document, id: NodeId, base: &Url, loader: &dyn ResourceLoader,
) -> Option<Stylesheet> {
    let href = doc.get_attribute(id, "href")?.trim();
    if href.is_empty() { return None; }
    let url = base.join(href).ok()?;                 // BadUrl → skip
    let res = loader.fetch(&url).ok()?;              // NotFound/Io/Unsupported → skip
    let css = String::from_utf8_lossy(&res.bytes);   // assume UTF-8 (§8)
    Some(starfish_css::parse_stylesheet(&css))
}
```

Why one `Stylesheet` per source (not concatenate then parse): cascade ties break
by **later sheet wins**, which `style_tree` already implements across the slice.
Keeping each `<style>`/`<link>` as its own ordered element makes "linked sheet
sets `color`, later inline `<style>` overrides it" fall out naturally (test
§9). (Concatenating text would also work for *parse*, but mixing fetched and
inline text into one string is more error-prone around `@import`/error recovery;
one sheet per node is cleaner and is what real engines model.)

`render_document` calls `collect_author_sheets` and passes the `Vec` straight to
`style_tree(&doc, &author)`. The old `extract_css` and its
`extract_css_collects_style_text` test are replaced by `collect_author_sheets` +
a document-order test (§9).

## 6. Image loading via the loader (`crates/paint/src/image_store.rs`)

E2-M4's `ImageStore` joined a `base_dir` to the raw `src` and called
`image::open(path)`. Re-back it with **base URL + `&dyn ResourceLoader`**, keying
the cache by the **resolved `Url`**. Its *public* API (`get`/`peek` by raw `src`,
the `ImageSource` impl, `DecodedImage`) is unchanged, so layout/display/raster
need no edits.

```rust
use std::collections::HashMap;
use starfish_net::{ResourceLoader, Url};

#[derive(Clone)]
pub struct DecodedImage { pub width: u32, pub height: u32, pub rgba: Vec<u8> }

/// Cache of decoded images keyed by **resolved URL**. Each `src` decodes at most
/// once; layout (intrinsic size) and paint (pixels) both read here. A failed
/// resolve / fetch / decode caches `None` (a broken image) — never panics.
pub struct ImageStore<'a> {
    base: Url,
    loader: &'a dyn ResourceLoader,
    cache: HashMap<Url, Option<DecodedImage>>,
}

impl<'a> ImageStore<'a> {
    /// Resolve relative `src` against `base`, fetching through `loader`.
    pub fn new(base: Url, loader: &'a dyn ResourceLoader) -> Self {
        ImageStore { base, loader, cache: HashMap::new() }
    }

    /// Resolve a raw `src` to the absolute `Url` we key on. `None` if `src` is an
    /// unresolvable reference (cached as a broken image by the caller).
    fn resolve(&self, src: &str) -> Option<Url> { self.base.join(src).ok() }

    /// Load + decode (or hit cache) the image at `src`. `None` for an
    /// unresolvable / missing / undecodable image (cached). Never panics.
    pub fn get(&mut self, src: &str) -> Option<&DecodedImage> {
        let Some(key) = self.resolve(src) else { return None; };
        let loader = self.loader;
        self.cache.entry(key.clone())
            .or_insert_with(|| fetch_and_decode(loader, &key));
        self.cache.get(&key).and_then(|o| o.as_ref())
    }

    /// Read-only lookup used by paint after the pre-pass/layout populated the
    /// cache. `None` (broken image) if absent or unresolvable.
    pub fn peek(&self, src: &str) -> Option<&DecodedImage> {
        self.resolve(src).and_then(|k| self.cache.get(&k)).and_then(|o| o.as_ref())
    }
}

impl starfish_layout::ImageSource for ImageStore<'_> {
    fn intrinsic_size(&self, src: &str) -> Option<(f32, f32)> {
        self.peek(src).map(|d| (d.width as f32, d.height as f32))
    }
}

/// Fetch bytes via the loader, decode to RGBA8. `None` on any fetch/decode error.
fn fetch_and_decode(loader: &dyn ResourceLoader, url: &Url) -> Option<DecodedImage> {
    let res = loader.fetch(url).ok()?;                   // NotFound/Io/Unsupported → broken
    let img = image::load_from_memory(&res.bytes).ok()?; // sniffs PNG/JPEG (was image::open)
    let rgba = img.to_rgba8();
    let (w, h) = rgba.dimensions();
    Some(DecodedImage { width: w, height: h, rgba: rgba.into_raw() })
}
```

Key changes from E2-M4:
- `image::open(path)` → `image::load_from_memory(&bytes)` (decode in-memory bytes
  the loader returned; same magic-byte sniffing).
- Cache key `PathBuf` → `Url`; `resolve` joins the base **URL** instead of a
  base **dir**. (For a `file://` base this is the same file, so M1 behavior is
  equivalent — only the plumbing moved.)
- Adds a `loader: &'a dyn ResourceLoader` field, so `ImageStore` gains a lifetime
  `'a`. The pre-pass `decode_images` and paint's `&ImageStore` borrows are within
  `render_document`'s scope, so the lifetime threads cleanly. `build_display_list`
  / `rasterize` take `&ImageStore<'_>` (elided — no signature text change needed
  beyond the elided lifetime).
- The pre-pass `decode_images(&doc, &mut images)` is **unchanged** — still one
  DFS calling `images.get(src)` per `<img src>`, so every image is decoded up
  front and `peek` during paint is read-only.

`#[derive(Default)]` is dropped (a loader ref has no default); nothing used it.
E2-M4's `image_store.rs` unit tests are updated to construct
`ImageStore::new(file_url_for(dir), &LocalLoader)` and write a PNG that the
`file://` base resolves to (mechanical edits; same assertions).

## 7. CLI (`crates/cli/src/main.rs`)

Accept a path OR a `file://` URL; build the base URL + `LocalLoader`; fetch the
document through the loader so the same path that loads CSS/images also loads the
top-level HTML.

```rust
use starfish_net::{base_url_from_input, LoadError, LocalLoader, ResourceLoader};

// …arg parsing unchanged (render / -o / --width / positional `input`)…

let base = base_url_from_input(&input).map_err(|e| format!("bad input '{input}': {e}"))?;

// Fetch the document itself through the loader (file:// only in M1).
let loader = LocalLoader;
let bytes = match loader.fetch(&base) {
    Ok(res) => res.bytes,
    Err(LoadError::UnsupportedScheme(s)) =>
        return Err(format!("{s}:// URLs are not supported yet (HTTP lands in E3-M2)")),
    Err(e) => return Err(format!("reading {input}: {e}")),
};
let html = String::from_utf8_lossy(&bytes);

let pixmap = starfish_paint::render_document(&html, &base, width as f32, &loader);
pixmap.save_png(&output).map_err(|e| format!("writing {output}: {e}"))?;
println!("wrote {output} ({}x{})", pixmap.width(), pixmap.height());
```

- A bare path → `file://` base (cwd-joined if relative) → `LocalLoader` reads it.
- A `file://` URL input → used directly.
- An `http(s)://` input → `base_url_from_input` returns the URL fine, but
  `loader.fetch` returns `UnsupportedScheme("http")` → the CLI prints the clean
  "not supported yet (E3-M2)" message and exits non-zero. (No `--width`/`-o`
  changes.)

`crates/cli/Cargo.toml` adds `starfish-net = { workspace = true }`. The old
`render_html(&html, .., &base_dir)` call is replaced by `render_document`; the
`std::fs::read_to_string` + `input.parent()` block is removed (now the loader
fetch + URL base).

## 8. Edge cases & non-goals (deliberate deviations)

Handled:
- Path input (relative → cwd-joined, absolute) and `file://` URL input → base URL.
- Relative `href`/`src` resolved against the base via `Url::join` (WHATWG).
- `<link rel>` matched case-insensitively over the space-separated token list.
- `<link>` with missing/empty `href`, bad URL, or failed fetch → **skipped**, no
  panic, page renders with remaining sheets. Same for a failed `<img>` fetch →
  broken image (existing placeholder behavior).
- Author cascade order: inline `<style>` and linked `<link>` interleaved in
  **document order**; later wins same-specificity ties (relies on `style_tree`'s
  existing slice-order semantics).
- Same URL fetched/decoded once (URL-keyed image cache; CSS isn't deduped in M1 —
  rare and cheap, M3 adds a shared cache).
- E2-M4 behavior preserved via the `render_html`/`render_html_cwd` shims
  (`file://` dir base joins exactly like the old `base_dir`).

Explicit **non-goals** (documented limitations):
- **No HTTP(S)** — `http`/`https` → `UnsupportedScheme` (E3-M2). The loader trait
  + scheme-router sketch (§3.4) show M2 is a drop-in.
- **No `data:` URLs** (E3-M3) — `UnsupportedScheme`.
- **No `@import`** — the CSS parser already skips `@import` statements
  (`at_rule_statement_skipped` test); not fetched in M1.
- **No `<base>` element** — the document base comes solely from the input
  URL/path. (Cheap to add later: scan `<head>` for `<base href>` and `join` it
  onto the input base before resolving anything. Deferred — not requested,
  Simplicity First.)
- **No media queries / `media` attr / `disabled` on `<link>`** — every
  `rel=stylesheet` link is loaded and applied.
- **No charset detection** — CSS/HTML bytes are decoded as UTF-8
  (`from_utf8_lossy`). M3 may add basic charset handling.
- **No resource cache across CSS** / no redirect handling (M2/M3); image cache is
  per-render only.
- **No CORS / mixed-content / TLS** (no network in M1).
- **Path traversal allowed** — `file://` `..` segments resolve normally (this is
  a local rendering tool, not a sandbox). Noted.
- **Windows drive-letter paths** aren't specially handled (Linux-targeted build);
  a `C:\…` input that fails `Url::parse` is treated as a relative path. Acceptable.

## 9. Test plan (concrete)

### 9.1 `net` crate — URL model (`crates/net/src/{resolve,lib}.rs` tests)
- `base_url_from_input("page.html")` → a `file://` URL ending `/page.html` whose
  path is `cwd/page.html` (assert `.scheme()=="file"` and the path tail).
- `base_url_from_input("/abs/page.html")` → `file:///abs/page.html`.
- `base_url_from_input("file:///x/y.html")` → returned unchanged.
- `base_url_from_input("http://example.com/")` → parses to the http URL (scheme
  `http`) — proves a URL input passes through (even though M1 won't fetch it).
- **`join` resolution:** `Url::parse("file:///a/b/page.html").join("theme.css")`
  → `file:///a/b/theme.css`; `.join("sub/i.png")` → `file:///a/b/sub/i.png`;
  `.join("/abs.css")` → `file:///abs.css`; `.join("http://h/x.css")` →
  `http://h/x.css` (absolute replaces base).

### 9.2 `net` crate — `LocalLoader` / `LoadError` (`loader.rs` tests)
- Write a temp file; `LocalLoader.fetch(&file_url_for(temp))` → `Ok(Resource)`
  with the exact bytes, `content_type == None`.
- `fetch` a `file://` URL for a missing path → `Err(LoadError::NotFound(_))`
  (matches, no panic).
- `fetch` an `http://…` URL → `Err(LoadError::UnsupportedScheme("http"))`.

### 9.3 paint — document-order author CSS (`crates/paint` tests)
Using `LocalLoader` over a temp dir:
- Write `theme.css` = `p{color:red}`; HTML =
  `<head><link rel="stylesheet" href="theme.css"><style>p{color:blue}</style></head>
   <body><p>hi</p></body>`. `collect_author_sheets` yields **2** sheets,
  `[link(red), style(blue)]` in that order; after `style_tree`, `<p>`'s computed
  `color` is **blue** (later inline `<style>` wins the tie) — proving document
  order. Swap the order (inline `<style>` before `<link>`) → computed `color`
  **red** (the link, now later, wins). Two cases, both directions.
- `<link rel="stylesheet" href="missing.css">` + `<style>p{color:green}</style>`
  → 1 sheet (the missing link skipped), `<p>` is green, **no panic**.
- `<link rel="stylesheet">` (no href) and `<link rel="icon" href="x">` → neither
  added (no href / not a stylesheet rel); only `<style>` sheets collected.

### 9.4 paint — image via loader (`crates/paint` / `render_document` tests)
Reuse E2-M4's 2×2 PNG fixture, but resolve through a `file://` base:
- Write `px.png` into a temp dir; `base = file://<dir>/index.html`. HTML
  `<img src="px.png" width="4" height="4">`. `render_document(html, &base, 50.0,
  &LocalLoader)` → top-left pixel red, top-right green, bottom-left blue,
  bottom-right white (nearest-neighbour upscale) — proving relative-`src`
  URL resolution + loader fetch + decode end-to-end.
- Relative subdir `src="img/px.png"` with the PNG in `<dir>/img/` → resolves and
  renders (proves `join` of a multi-segment relative ref).
- Broken `<img src="nope.png" width="10" height="10">` → render does not panic;
  image region stays white + grey placeholder border (existing E2-M4 assertion).

### 9.5 paint — back-compat shims (`crates/paint` tests, unchanged assertions)
- All existing E2-M4/M5 `render_html(html, w, &dir)` and `render_html_cwd`
  tests pass **byte-identically** (the shim's `file://` dir base joins like the
  old base_dir). This is the regression guard for the URL/loader migration.

### 9.6 CLI / pipeline smoke (optional, `crates/cli` or an integration test)
- Temp dir with `index.html` (`<link rel=stylesheet href=theme.css>` +
  `<img src=px.png>`), `theme.css`, `px.png`; run `base_url_from_input(path)` →
  `render_document` → assert non-trivial pixmap (width = `--width`, height ≥ img
  height) and a sampled colored pixel — proving the whole path → base URL →
  loader → CSS+image flow.
- CLI with an `http://…` input → exits non-zero with the
  "not supported yet (E3-M2)" message (proves clean error, no panic).
