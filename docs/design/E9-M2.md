# E9-M2 — SVG `<path>` + `<polygon>`/`<polyline>` (DESIGN)

Extends the E9-M1 SVG painter. M1 gave us a self-contained shape pipeline:
`emit_svg` (display.rs) walks the `<svg>` DOM subtree at display-list-build time
and emits one `PaintCmd::SvgShape { geom: SvgGeom, transform:[f32;6], fill,
stroke, stroke_width }` per recognized basic shape; `draw_svg_shape` (raster.rs)
builds a `tiny_skia::Path` from the `SvgGeom` and fills/strokes it through the
viewBox transform. M2 extends **only** `SvgGeom`, `build_shape`, the
`SvgShape` command, and `svg_path`/`draw_svg_shape` — no parser/layout/HTML
changes (foreign-content + case preservation already land `<path d="…">`,
`<polygon points="…">` with attrs intact from M1).

**M2 scope:** parse `d` (M/m L/l H/h V/v C/c S/s Q/q T/t A/a Z/z) into an
absolute path-op list; fill with the correct `fill-rule` (nonzero/evenodd) +
stroke; `polygon`/`polyline` from a points list; `stroke-linecap`/`linejoin`
(basic); `stroke-dasharray` (optional, designed but deferrable). No new crates;
a new `crates/paint/src/svg_path.rs` module holds the path-data + points
parsers and arc-to-cubic.

> **Dependency on the ANALYSIS agent (E9-M2 analysis note).** This design
> references its findings for: (a) the exact tiny-skia 0.11 `PathBuilder`
> cubic/quad/close API, (b) the endpoint→center arc parameterization +
> ≤90°-segment cubic approximation constants, (c) the SVG path-data number
> micro-grammar. I verified these directly against the source in this repo's
> vendored crate (`tiny-skia-path-0.11.4`) and the tracked `display.rs`/
> `raster.rs`; signatures below are real.

## 1. SVG path-data parser

New module `crates/paint/src/svg_path.rs`. Two layers:

1. A **tokenizer** over the number micro-grammar (the hard part).
2. A **command interpreter** that turns command-letter + numbers into a flat
   list of **absolute** `PathOp`s — relative→absolute, H/V→Line, S/T→full
   C/Q via reflection, A→cubic Béziers. The output is the intermediate
   representation consumed by `SvgGeom::Path`.

### 1.1 The output IR

```rust
/// One absolute path op (the IR fed to a tiny-skia PathBuilder). All coords are
/// absolute user-space; H/V are already LineTo, S/T already Cubic/Quad, A already
/// a run of CubicTo.
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum PathOp {
    MoveTo(f32, f32),
    LineTo(f32, f32),
    QuadTo(f32, f32, f32, f32),                  // cx,cy, x,y
    CubicTo(f32, f32, f32, f32, f32, f32),       // c1x,c1y, c2x,c2y, x,y
    Close,
}
```

`PathOp` must be `Copy + PartialEq` so `SvgGeom` (which is `#[derive(Clone,
Copy, PartialEq)]`) stays `Clone + PartialEq` — **but** `SvgGeom::Path` carries
a `Vec<PathOp>`, so **`SvgGeom` loses `Copy`** (a Vec isn't Copy). See §3.1 for
the consequence (one `*geom` → `geom.clone()` / `match geom` borrow fix in two
call sites). That is the only ripple.

### 1.2 Public entry points

```rust
/// Parse the `d` attribute into a flat absolute op list. LENIENT: parses every
/// valid prefix and stops at the first malformed token (never panics, never
/// errors). An empty/whitespace `d` → empty Vec. (§7 edge cases.)
pub fn parse_path_data(d: &str) -> Vec<PathOp>;

/// Parse a `points` list ("x1,y1 x2,y2 …") into pairs. Lenient: stops at the
/// first unpaired/invalid number. Odd trailing number is dropped (§7).
pub fn parse_points(s: &str) -> Vec<(f32, f32)>;
```

### 1.3 The number micro-grammar

SVG path numbers are whitespace/comma separated, but with quirks that a plain
`split` cannot handle. A cursor-based number scanner over `&[u8]`/`char_indices`
handles all of them:

- **commas & whitespace** (`,` ` ` `\t` `\n` `\r`) are separators, any run is
  one separator (and a comma may stand between two numbers with no spaces).
- **sign as separator**: `1-2` = `1`, `-2`; `1+2` = `1`, `+2`. A `+`/`-` that
  is not the first char of the current number AND not part of an exponent
  starts a new number.
- **multiple decimals**: `.5.5` = `0.5`, `0.5`. A second `.` ends the current
  number and begins a new one.
- **exponents**: `1e3`, `1.5E-2`, `1e+3` — an `e`/`E` is consumed as part of
  the number, and the sign immediately after `e`/`E` is the exponent sign (NOT
  a separator). `1e3-4` = `1000`, `-4`.

```rust
struct Lexer<'a> { s: &'a [u8], i: usize }

impl Lexer<'_> {
    fn skip_sep(&mut self);                 // skip ws + at most that run; commas too
    fn next_cmd(&mut self) -> Option<u8>;   // a command letter MmLlHhVvCcSsQqTtAaZz
    /// Scan one number per the micro-grammar; None at end / on a non-number byte.
    fn next_number(&mut self) -> Option<f32>;
    /// A flag is a single '0' or '1' (the A command's large-arc/sweep flags can
    /// abut the next number with NO separator: "A1 1 0 0 1 …" but also "…0014 …"
    /// where "00" are two flags). next_flag reads exactly one '0'/'1' char.
    fn next_flag(&mut self) -> Option<bool>;
}
```

> The **flag quirk** is real and a common parser bug: in `A`/`a`, large-arc and
> sweep are single-digit flags that may not be space-separated from each other
> or from the following coordinate (`a25 25 -30 0 1 50 -25` is well-spaced, but
> `a25,25,-30,0,1,50,-25` and `…0150-25` are also legal). Use `next_flag` (one
> char) for those two operands, `next_number` for the rest. The test corpus
> includes both spaced and abutted forms.

`next_number` algorithm (one pass, no allocation): record start `i`; optional
leading `+`/`-`; consume digits; optional `.` + digits; optional `e`/`E` +
optional sign + digits — stopping at the first byte that violates the running
state (a second `.`, a non-exponent sign, any separator/letter). `parse::<f32>`
the slice; on parse failure return `None` (caller stops — lenient).

### 1.4 Command interpretation (relative→absolute, reflection, implicit repeat)

State carried while interpreting:

```rust
struct PathState {
    cur: (f32, f32),          // current point
    start: (f32, f32),        // current subpath start (for Z)
    prev_cubic_ctrl: Option<(f32,f32)>,  // 2nd ctrl of the last C/S (for S reflect)
    prev_quad_ctrl:  Option<(f32,f32)>,  // ctrl of the last Q/T (for T reflect)
    ops: Vec<PathOp>,
}
```

Loop: read a command letter; then read its operand groups **repeatedly** until
the next token is a command letter or end. After the first group of an `M`/`m`,
the **implicit command becomes `L`/`l`** (same case) per spec. Per command
(`abs` = uppercase; lowercase adds `cur`):

| cmd | operands (per group) | emits | post |
|---|---|---|---|
| M/m | x y | `MoveTo` | `start = cur`; implicit→L/l; reset both prev ctrls to None |
| L/l | x y | `LineTo` | reset prev ctrls |
| H/h | x | `LineTo(x, cur.y)` | reset prev ctrls |
| V/v | y | `LineTo(cur.x, y)` | reset prev ctrls |
| C/c | x1 y1 x2 y2 x y | `CubicTo(c1,c2,p)` | `prev_cubic_ctrl = (x2,y2)`; prev_quad=None |
| S/s | x2 y2 x y | `CubicTo(refl,c2,p)` | c1 = reflect(prev_cubic_ctrl about cur) or cur if last wasn't C/S; `prev_cubic_ctrl=(x2,y2)`; prev_quad=None |
| Q/q | x1 y1 x y | `QuadTo(c,p)` | `prev_quad_ctrl=(x1,y1)`; prev_cubic=None |
| T/t | x y | `QuadTo(refl,p)` | c = reflect(prev_quad_ctrl about cur) or cur if last wasn't Q/T; `prev_quad_ctrl=c`; prev_cubic=None |
| A/a | rx ry φ large sweep x y | run of `CubicTo` (§2) | reset prev ctrls |
| Z/z | — | `Close` | `cur = start`; reset prev ctrls |

- **Relative**: for lowercase, every coordinate adds the *current* `cur` (and
  for multi-point commands `cur` advances per group). H/h uses `cur.x`; V/v
  uses `cur.y`. For `A/a` the endpoint `x y` is relative; `rx ry φ` are not.
- **Reflection** (S/T): the reflected control point is `2*cur - prev_ctrl`.
  Only valid if the *immediately preceding* command was the matching family
  (C/S for S, Q/T for T); otherwise the control point equals `cur`. The
  `prev_*_ctrl: Option` fields encode this — set on C/S (resp. Q/T), cleared on
  every other command.
- **Z**: closes the current subpath and sets `cur = start`. A following
  `M` opens a new subpath. A `Z` with no preceding draw op is harmless (emit
  `Close` only if the current subpath has ≥1 op since the last MoveTo — to
  avoid a stray `Close` at the very start; simplest: only emit `Close` if
  `ops` non-empty and the last op isn't `MoveTo`/`Close`).
- **Leading non-M**: per spec a path should start with M; if it starts with a
  draw command, treat the first implicit point as `(0,0)` start — but simplest
  lenient rule: if the first command isn't M/m, **drop ops until the first
  MoveTo** is unnecessary; instead synthesize `MoveTo(0,0)` lazily on the first
  draw op when `ops` is empty. Keep it minimal: track an `started: bool`; the
  first draw op with no preceding MoveTo prepends `MoveTo(cur)` (cur starts
  (0,0)).
- **Malformed**: if `next_number`/`next_flag` returns `None` mid-group, stop
  the whole parse and return the ops accumulated so far (lenient, no panic).

### 1.5 Bound

Cap total ops at a constant (e.g. `MAX_PATH_OPS = 1 << 16`) to bound a
pathological `d`; on overflow stop appending and return. Cheap guard, noted in
§7.

## 2. Arc (A) → cubic Béziers

`A rx ry φ large-arc sweep x y` from the current point `(x1,y1)` to the
endpoint `(x2,y2)`. tiny-skia has **no arc helper**, so convert to ≤90° cubic
segments via the W3C SVG endpoint→center parameterization (SVG impl-notes
§F.6). Signature:

```rust
/// Append an SVG elliptical arc (absolute endpoints) as a run of CubicTo ops.
/// Degenerate cases fall back to a single LineTo (or nothing). Never panics.
fn arc_to_cubics(
    x1: f32, y1: f32,         // current point
    rx: f32, ry: f32,
    x_axis_rotation_deg: f32, // φ
    large_arc: bool, sweep: bool,
    x2: f32, y2: f32,         // endpoint
    ops: &mut Vec<PathOp>,
);
```

### 2.1 Degenerate guards (do these first)

- `(x1,y1) == (x2,y2)` (same start/end): per spec the arc is omitted entirely →
  return (emit nothing).
- `rx == 0 || ry == 0`: treat as a straight line → `ops.push(LineTo(x2,y2))`,
  return.
- Use absolute radii: `rx = rx.abs(); ry = ry.abs()`.

### 2.2 Endpoint → center (F.6.5 + F.6.6)

```
φ      = x_axis_rotation_deg.to_radians()
cosφ, sinφ = φ.cos(), φ.sin()

// Step 1: midpoint, rotated into ellipse frame (F.6.5.1)
dx = (x1 - x2) / 2;  dy = (y1 - y2) / 2
x1p =  cosφ*dx + sinφ*dy
y1p = -sinφ*dx + cosφ*dy

// Step 2 — radii correction (F.6.6.2): scale radii up if too small to span
Λ = x1p²/rx² + y1p²/ry²
if Λ > 1 { let k = Λ.sqrt(); rx *= k; ry *= k; }   // recompute rx², ry²

// Step 3 — center in the ellipse frame (F.6.5.2)
num   = rx²*ry² - rx²*y1p² - ry²*x1p²
den   = rx²*y1p² + ry²*x1p²
sign  = if large_arc == sweep { -1.0 } else { 1.0 }
coef  = sign * (num.max(0.0) / den).sqrt()        // max(0.0): clamp fp negatives
cxp =  coef * rx * y1p / ry
cyp = -coef * ry * x1p / rx

// Step 4 — center back to user space (F.6.5.3)
cx = cosφ*cxp - sinφ*cyp + (x1 + x2)/2
cy = sinφ*cxp + cosφ*cyp + (y1 + y2)/2

// Step 5 — start angle θ1 and sweep Δθ (F.6.5.5/6)
let ang = |ux:f32, uy:f32, vx:f32, vy:f32| -> f32 {
    let dot = ux*vx + uy*vy;
    let len = ((ux*ux+uy*uy)*(vx*vx+vy*vy)).sqrt();
    let mut a = (dot/len).clamp(-1.0, 1.0).acos();
    if ux*vy - uy*vx < 0.0 { a = -a; }
    a
};
θ1 = ang(1.0, 0.0, (x1p-cxp)/rx, (y1p-cyp)/ry);
mut Δθ = ang((x1p-cxp)/rx, (y1p-cyp)/ry, (-x1p-cxp)/rx, (-y1p-cyp)/ry);
if !sweep && Δθ > 0.0 { Δθ -= 2π; }
if  sweep && Δθ < 0.0 { Δθ += 2π; }
```

### 2.3 Split into ≤90° cubic segments (F.6.4 approximation)

```
n = (Δθ.abs() / (π/2)).ceil() as usize;        // number of segments, ≥1
dθ = Δθ / n;
t  = (4/3) * tan(dθ/4);                          // tangent length factor (κ for dθ)
```

For each segment `k = 0..n`, with `θa = θ1 + k*dθ`, `θb = θa + dθ`, define the
unit-ellipse point + derivative, then map through `(rx,ry,φ,cx,cy)`:

```
let e = |θ:f32| -> (f32,f32) {           // point on the rotated ellipse
    let (c,s) = (θ.cos(), θ.sin());
    ( cx + rx*c*cosφ - ry*s*sinφ,
      cy + rx*c*sinφ + ry*s*cosφ )
};
let d = |θ:f32| -> (f32,f32) {           // derivative direction (unnormalized)
    let (c,s) = (θ.cos(), θ.sin());
    ( -rx*s*cosφ - ry*c*sinφ,
      -rx*s*sinφ + ry*c*cosφ )
};
let (p0x,p0y) = e(θa); let (p3x,p3y) = e(θb);
let (d0x,d0y) = d(θa); let (d3x,d3y) = d(θb);
let c1 = (p0x + t*d0x, p0y + t*d0y);
let c2 = (p3x - t*d3x, p3y - t*d3y);
ops.push(PathOp::CubicTo(c1.0, c1.1, c2.0, c2.1, p3x, p3y));
```

The very first segment's `p0` equals the current point `(x1,y1)` (up to fp), so
no MoveTo is needed — the cubics chain from `cur`. After the loop the
interpreter sets `cur = (x2,y2)`.

> A quarter-circle test (`A r r 0 0 1 …` spanning exactly 90°) yields **one**
> cubic with `t = (4/3)·tan(π/8) ≈ 0.5523` — the familiar circle κ. This is
> the analysis-agent-confirmed constant and the test in §8 checks the endpoint
> lands within ~0.5px of the geometric target.

## 3. Path geometry in `SvgGeom`

### 3.1 Extend the enum

```rust
// display.rs
#[derive(Debug, Clone, PartialEq)]        // NOTE: drop `Copy` (Vec inside)
pub enum SvgGeom {
    Rect { x: f32, y: f32, w: f32, h: f32, rx: f32, ry: f32 },
    Ellipse { cx: f32, cy: f32, rx: f32, ry: f32 },
    Line { x1: f32, y1: f32, x2: f32, y2: f32 },
    /// A `<path>` (or polygon/polyline, §4) as an absolute op list.
    Path(Vec<crate::svg_path::PathOp>),
}
```

**Ripple of dropping `Copy`:** two existing sites use `*geom`:
- `display.rs` `build_shape` ends with `Some(PaintCmd::SvgShape { geom, … })` —
  already a move, fine.
- `display.rs` `build_shape` does `matches!(geom, SvgGeom::Line { .. })` on a
  by-value `geom` after constructing it — still fine (it's owned, used once).
- `raster.rs` `svg_path(geom: &SvgGeom)` already takes `&SvgGeom` and does
  `match *geom { … }` with `Copy` field destructuring. Change to `match geom {
  … }` borrowing (`SvgGeom::Rect { x, y, .. } => { let (x,y)=(*x,*y); … }`) OR
  keep `match geom` and add the `Path(ops) => { … &ops }` arm. The Rect/Ellipse/
  Line arms keep working under a borrow; only the new `Path` arm needs the slice
  by reference. This is a 1-line-per-arm mechanical change, no logic change.

`PaintCmd` derives `Clone, PartialEq` (not `Copy`) already, so it tolerates the
`Vec`. `#[derive(Debug)]` unaffected.

### 3.2 `build_shape` — `path`/`polygon`/`polyline` arms

In `display.rs build_shape`, add arms to the `match tag`:

```rust
"path" => {
    let d = doc.get_attribute(id, "d").unwrap_or("");
    let ops = crate::svg_path::parse_path_data(d);
    if ops.is_empty() { return None; }            // empty/missing d → nothing
    SvgGeom::Path(ops)
}
"polygon" | "polyline" => {
    let pts = crate::svg_path::parse_points(doc.get_attribute(id, "points").unwrap_or(""));
    if pts.len() < 2 { return None; }
    let closed = tag == "polygon";
    SvgGeom::Path(points_to_ops(&pts, closed))    // §4
}
```

The fill/stroke resolution at the end of `build_shape` is **reused verbatim** —
but the `fill` suppression currently special-cases only `Line`. A `<polyline>`
in SVG *does* fill by default (a polyline is a filled shape per spec, just an
open one). So **do not** suppress fill for Path. Keep the existing
`matches!(geom, SvgGeom::Line{..})` fill-none rule unchanged; Path always
honors `p.fill`. (A polyline with the default black fill will fill its implied
closed region — that is spec-correct; authors set `fill="none"` for the open-
stroke look, which the corpus test does.)

### 3.3 `svg_path` — build the tiny-skia Path for `SvgGeom::Path`

In `raster.rs svg_path`, add the arm:

```rust
SvgGeom::Path(ops) => {
    for op in ops {
        match *op {
            PathOp::MoveTo(x,y)               => pb.move_to(x,y),
            PathOp::LineTo(x,y)               => pb.line_to(x,y),
            PathOp::QuadTo(cx,cy,x,y)         => pb.quad_to(cx,cy,x,y),
            PathOp::CubicTo(a,b,c,d,x,y)      => pb.cubic_to(a,b,c,d,x,y),
            PathOp::Close                     => pb.close(),
        }
    }
}
```

`pb.finish()` returns `None` if the path is empty or invalid (e.g. a lone
MoveTo produces no drawable subpath) — `svg_path` already returns `Option`, so a
move-only path → `None` → `draw_svg_shape` early-returns and paints nothing.
Spec says a move-only path paints nothing for fill and (a zero-length subpath)
only paints with round/square caps; we accept "paints nothing" for M2 (note).

## 4. polygon / polyline

Reuse `SvgGeom::Path` (no separate variant — a polygon is just a path of
LineTos). `parse_points` (§1.2) yields `Vec<(f32,f32)>`; convert:

```rust
fn points_to_ops(pts: &[(f32,f32)], closed: bool) -> Vec<PathOp> {
    let mut ops = Vec::with_capacity(pts.len() + 1);
    ops.push(PathOp::MoveTo(pts[0].0, pts[0].1));
    for &(x,y) in &pts[1..] { ops.push(PathOp::LineTo(x,y)); }
    if closed { ops.push(PathOp::Close); }   // polygon closes; polyline doesn't
    ops
}
```

- `parse_points` parses whitespace/comma-separated numbers in **pairs** using
  the same `Lexer::next_number` (the sign-as-separator/decimal quirks apply to
  `points` too: `points="0,0 1-2"` → `(0,0),(1,-2)`).
- **Odd point count**: an unpaired trailing number is dropped (`points="0,0 5"`
  → just `(0,0)` → `<2` points → skipped). Per spec an odd coordinate list is
  an error; dropping the dangling value is the lenient behavior.
- A `polyline` does NOT close (`closed=false`); its default black `fill` fills
  the region between the path and the implied closing edge (spec-correct), and
  `fill="none"` gives the open-stroke look.

## 5. fill-rule + stroke style

### 5.1 Extend the `SvgShape` command + the painter

`fill-rule` and the stroke linecap/linejoin (and optional dash) must flow from
`build_shape` → the command → `draw_svg_shape`. Extend the command:

```rust
// display.rs PaintCmd::SvgShape
SvgShape {
    geom: SvgGeom,
    transform: [f32; 6],
    fill: Option<Rgba>,
    fill_rule: SvgFillRule,        // NEW
    stroke: Option<Rgba>,
    stroke_width: f32,
    stroke_cap: SvgLineCap,        // NEW
    stroke_join: SvgLineJoin,      // NEW
    // dash: optional (§5.4) — defer; if done, Vec<f32> + offset, or None.
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SvgFillRule { NonZero, EvenOdd }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SvgLineCap  { Butt, Round, Square }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SvgLineJoin { Miter, Round, Bevel }
```

> Small `paint`-local enums (not raw `tiny_skia::*`) keep `display.rs` free of a
> tiny-skia dependency in its public command type, matching how M1 used a
> `[f32;6]` transform rather than `tiny_skia::Transform`. raster.rs maps them.

All existing `SvgShape { … }` constructions (one in `build_shape`, the test
asserts in display.rs) get the three new fields. The M1 tests pattern-match with
`..` (`PaintCmd::SvgShape { geom, transform, fill, stroke, .. }`), so they keep
compiling — only `build_shape` (the constructor) and `draw_svg_shape` (the
consumer signature) need the new fields. Good: the new fields are additive.

### 5.2 Resolve in `build_shape` / extend `resolve_paints`

`fill-rule`, `stroke-linecap`, `stroke-linejoin` are presentation attrs /
inline-style props read with the existing `prop(name)` helper (inline `style`
wins over attr — already implemented in `resolve_paints`). Add to `Paints`:

```rust
struct Paints {
    fill: Option<Rgba>, stroke: Option<Rgba>, stroke_width: f32,
    fill_rule: SvgFillRule, cap: SvgLineCap, join: SvgLineJoin,
}

// inside resolve_paints, using the same `prop` closure:
let fill_rule = match prop("fill-rule").as_deref().map(str::trim) {
    Some("evenodd") => SvgFillRule::EvenOdd,
    _ => SvgFillRule::NonZero,            // default + unknown
};
let cap = match prop("stroke-linecap").as_deref().map(str::trim) {
    Some("round")  => SvgLineCap::Round,
    Some("square") => SvgLineCap::Square,
    _ => SvgLineCap::Butt,
};
let join = match prop("stroke-linejoin").as_deref().map(str::trim) {
    Some("round") => SvgLineJoin::Round,
    Some("bevel") => SvgLineJoin::Bevel,
    _ => SvgLineJoin::Miter,
};
```

(Case-insensitive compare is nicer — `eq_ignore_ascii_case` — but SVG keyword
values are lowercase by spec; `trim`+exact is enough and matches the corpus.)

`build_shape` passes these into the new `SvgShape` fields. The Rect/Ellipse/
Line M1 shapes also gain these fields — they default to NonZero/Butt/Miter
(which is what M1 already did implicitly), so behavior is unchanged.

### 5.3 raster.rs mapping

```rust
fn draw_svg_shape(pixmap, geom, transform, fill, fill_rule, stroke, stroke_width,
                  cap, join /*, dash */) {
    let Some(path) = svg_path(geom) else { return };
    let t = Transform::from_row(m[0],…,m[5]);

    if let Some(c) = fill {
        if c.a != 0 {
            let mut paint = Paint { anti_alias: true, ..Default::default() };
            paint.set_color_rgba8(c.r, c.g, c.b, c.a);
            let fr = match fill_rule {
                SvgFillRule::NonZero => FillRule::Winding,
                SvgFillRule::EvenOdd => FillRule::EvenOdd,
            };
            pixmap.fill_path(&path, &paint, fr, t, None);
        }
    }
    if let Some(c) = stroke {
        if c.a != 0 && stroke_width > 0.0 {
            let mut paint = Paint { anti_alias: true, ..Default::default() };
            paint.set_color_rgba8(c.r, c.g, c.b, c.a);
            let sk = tiny_skia::Stroke {
                width: stroke_width,
                line_cap:  match cap  { SvgLineCap::Butt=>LineCap::Butt,
                                        SvgLineCap::Round=>LineCap::Round,
                                        SvgLineCap::Square=>LineCap::Square },
                line_join: match join { SvgLineJoin::Miter=>LineJoin::Miter,
                                        SvgLineJoin::Round=>LineJoin::Round,
                                        SvgLineJoin::Bevel=>LineJoin::Bevel },
                // dash: §5.4
                ..Default::default()                 // keeps miter_limit 4.0
            };
            pixmap.stroke_path(&path, &paint, &sk, t, None);
        }
    }
}
```

Add `LineCap, LineJoin` to the `tiny_skia::{…}` import in raster.rs (and
`FillRule` is already imported).

### 5.4 `stroke-dasharray` — optional, deferrable

Designed but **may be deferred**. If done:
- Parse `stroke-dasharray` (comma/space list of lengths; `none` → no dash;
  negative or all-zero → no dash) via the same number lexer into `Vec<f32>`;
  parse `stroke-dashoffset` (a single length, default 0).
- An **odd-length** dash list is doubled (SVG: `[a,b,c]` → `[a,b,c,a,b,c]`).
- Carry `dash: Option<(Vec<f32>, f32)>` on the command; in raster.rs build
  `StrokeDash::new(arr, offset)` → assign to `sk.dash` (it's `Option<StrokeDash>`
  already, so `sk.dash = StrokeDash::new(arr, offset);` directly).
- `StrokeDash::new` returns `None` for a degenerate array → no dash (lenient).

**Recommendation:** ship caps/joins + fill-rule (the milestone "done-when"); add
dasharray only if time remains. Keep the `dash` field out of the command until
implemented to avoid carrying an unused `Vec` — add it in the same edit as the
parse if done.

## 7. Edge cases & non-goals

| Case | M2 behavior |
|---|---|
| malformed `d` | lenient: parse the valid prefix, stop at first bad token, no panic |
| empty / missing `d` | `parse_path_data` → empty Vec → `build_shape` returns None (no command) |
| path = only a MoveTo | `pb.finish()` → None → paints nothing (note: spec paints a point only with round/square caps; deferred) |
| leading non-M command | synthesize `MoveTo(cur)` (cur starts (0,0)) on first draw op |
| `Z` with no subpath | only emit `Close` if last op isn't MoveTo/Close (no stray close) |
| implicit repeated commands | supported; after `M`/`m` the implicit cmd is `L`/`l` |
| number micro-syntax `1-2`, `.5.5`, `1e3`, `1e-2` | handled by `Lexer::next_number` |
| arc flag abutment `0014` | `Lexer::next_flag` reads one '0'/'1' char |
| arc rx=0 or ry=0 | → LineTo(endpoint) |
| arc start==end | omitted (emit nothing) |
| arc radii too small | scaled up per F.6.6.2 |
| `S`/`T` with no preceding C/Q | reflected control = current point |
| polygon/polyline odd point count | drop the dangling trailing number; `<2` pts → skipped |
| polyline default fill | fills the implied-closed region (spec-correct); `fill="none"` for open look |
| very long `d` | bounded at `MAX_PATH_OPS`; stop appending |
| `fill-rule` unknown value | NonZero (default) |
| `stroke-dasharray` | optional/deferrable (§5.4) |
| markers (`marker-start/mid/end`) | DEFER (M3+/non-goal) |
| `pathLength` | DEFER (non-goal) |
| `transform` on `<path>` | DEFER (M3) |
| non-scaling-stroke, miter-limit attr | DEFER |

## 8. Test plan

Unit tests live in `svg_path.rs` (parser) + `display.rs` (build_shape) +
`lib.rs`/raster pixel tests (paint), mirroring M1's structure.

### 8.1 Parser (`svg_path.rs` unit tests)

- `parse_path_data("M10 10 L90 10 L90 90 Z")` →
  `[MoveTo(10,10), LineTo(90,10), LineTo(90,90), Close]` (triangle).
- **H/V**: `"M0 0 H10 V10 H0 Z"` →
  `[MoveTo(0,0), LineTo(10,0), LineTo(10,10), LineTo(0,10), Close]`.
- **C**: `"M0 0 C0 10 10 10 10 0"` → `[MoveTo, CubicTo(0,10, 10,10, 10,0)]`.
- **S reflection**: `"M0 0 C0 5 5 5 10 0 S15 -5 20 0"` → the 2nd cubic's c1 =
  reflect (5,5) about (10,0) = `(15,-5)`; assert the emitted c1 ≈ (15,-5).
- **S with no preceding C**: `"M0 0 S5 5 10 0"` → c1 = current point (0,0).
- **Q / T**: `"M0 0 Q5 5 10 0 T20 0"` → 2nd quad ctrl = reflect (5,5) about
  (10,0) = (15,-5).
- **relative**: `"m10 10 l5 0 l0 5"` →
  `[MoveTo(10,10), LineTo(15,10), LineTo(15,15)]`.
- **implicit repeat + M→L**: `"M0 0 10 0 10 10"` →
  `[MoveTo(0,0), LineTo(10,0), LineTo(10,10)]`.
- **number quirks**: `"M1-2"` → `[MoveTo(1,-2)]`; `"M.5.5"` →
  `[MoveTo(0.5,0.5)]`; `"M1e1 2e1"` → `[MoveTo(10,20)]`.
- **arc quarter circle**: `"M10 0 A10 10 0 0 1 0 10"` (center (0,0), from
  (10,0) to (0,10), sweep) → exactly one `CubicTo`; assert the final endpoint ≈
  (0,10) within 1e-3 and the control points ≈ `(10, 5.523)` / `(5.523, 10)`
  within ~0.05.
- **arc degenerate**: `"M0 0 A0 5 0 0 1 10 0"` → `[MoveTo, LineTo(10,0)]`
  (rx=0 → line); `"M0 0 A5 5 0 0 1 0 0"` (start==end) → `[MoveTo]` only.
- **malformed**: `"M10 10 Lfoo"` → `[MoveTo(10,10)]` (stops at `foo`), no panic.
- `parse_points("50,5 90,90 10,90")` → `[(50,5),(90,90),(10,90)]`;
  `parse_points("0,0 1-2")` → `[(0,0),(1,-2)]`; odd: `parse_points("0,0 5")`
  → `[(0,0)]`.

### 8.2 build_shape (`display.rs` unit tests, like M1's `svg_shapes`)

- `<path d="M10 10 L90 10 L90 90 Z" fill="red"/>` → one `SvgShape` with
  `geom == SvgGeom::Path([MoveTo,LineTo,LineTo,Close])`, fill = red,
  `fill_rule == NonZero`.
- `<path d="…" fill-rule="evenodd"/>` → `fill_rule == EvenOdd`.
- `<polygon points="50,5 90,90 10,90"/>` → `SvgGeom::Path` ending in `Close`.
- `<polyline points="0,0 10,0 10,10"/>` → `SvgGeom::Path` with **no** `Close`.
- `<path d=""/>` and `<path/>` → no command emitted.
- `stroke-linecap="round" stroke-linejoin="bevel"` → `stroke_cap == Round`,
  `stroke_join == Bevel`.

### 8.3 Paint / pixel (lib.rs)

- triangle `<path d="M10 10 L90 10 L50 90 Z" fill="red"/>` in a 100×100 svg →
  red at the centroid (~(50,40)), white at a corner outside the triangle.
- **fill-rule evenodd star**: a 5-point self-intersecting star path with
  `fill-rule="evenodd"` → the center pixel is the **hole** (background),
  whereas with `fill-rule="nonzero"` the center is filled. Assert both.
- `<polyline points="10,10 50,50 90,10" fill="none" stroke="black"
  stroke-width="4"/>` → dark pixels along both legs, white between/below.
- `stroke-linecap="round"` on a single open segment → rounded end pixels
  beyond the endpoint (vs butt: none) — a coarse check (a pixel just past the
  endpoint is dark for round, white for butt).
- arc `<path d="M90 50 A40 40 0 0 1 50 90" stroke="black" fill="none"/>` → dark
  pixels tracing the quarter-circle from (90,50) to (50,90).

### 8.4 Visual (PNG, review)

- A filled `<path>` **star** (evenodd hole) + a filled **heart**
  (`M…C…C…Z` cubics) + a stroked `<polyline>` with round caps/joins, one inline
  `<svg>` — the E9-M2 done-when artifact.
