# M4 — Layout design note

Scope: the `starfish-layout` crate. Given a `Document` (from `starfish-dom`), a
`StyledTree` (from `starfish-style`), and a **viewport width**, build a **box
tree** and compute geometry — content `Rect{x, y, width, height}` plus
`margin`/`border`/`padding` edge sizes — for every box, via **block** and
**inline** flow layout. The output is a walkable box tree consumed by M5
(paint).

This is the layout stage of "render a static HTML page to PNG". No JS, no
incremental reflow.

Guiding rule (project "Simplicity First"): implement the **minimum correct**
block + inline flow layout. No floats, no positioning, no flex/grid, no margin
collapsing, no real font metrics. Every type/field below has a consumer in M4
geometry or M5 paint. See §7 for the explicit non-goals.

---

## 0. Inputs M4 actually receives (recap of the real M1/M3 API)

Pinned to the exact types, not an idealized API.

From `starfish-dom` (`crates/dom/src/lib.rs`):

- `NodeId` — `Copy + Eq + Hash`, 4-byte index. Only valid for its `Document`.
- `Document::kind(id) -> &NodeKind`, `NodeKind::{Document, Doctype, Element,
  Text(String), Comment(String)}`.
- `Document::children(id) -> Vec<NodeId>` (document order; allocates — fine),
  `first_child` / `next_sibling` / `parent`, `root()`.
- `Document::tag_name(id) -> Option<&str>` (lowercased; `None` for non-elements).
- Text content lives **in the node**: `NodeKind::Text(String)`. M4 reads the
  string by matching `doc.kind(id)`.

From `starfish-style` (`crates/style/src/{lib,computed}.rs`):

- `StyledTree::computed(id) -> &ComputedStyle` (panics if unstyled),
  `StyledTree::get(id) -> Option<&ComputedStyle>`.
- **Text nodes have NO entry** (M3 contract): `get(text_id)` is `None`. A
  text node's font/color comes from its **parent element's** `ComputedStyle`.
  M4 must carry the parent style down when generating `TextRun` boxes.
- `ComputedStyle` fields used by M4: `display`, `width`, `height`,
  `margin_*`, `padding_*`, `border_*_width`, `font_size`, `line_height`,
  `text_align`, `font_weight`. (Colors/border style/family are passed through
  to M5, not consumed by geometry.)
- `Display::{Block, Inline, InlineBlock, None}`. **`InlineBlock` is treated as
  `Inline` for M4** (laid as an inline-level atomic box would be too much; we
  fold it to inline flow — noted §7).
- `Length::{Px(f32), Percent(f32), Auto}`. `Percent` resolves against the
  containing block in M4; `Auto` is the layout-driven case.
- `LineHeight::{Normal, Number(f32), Px(f32)}` — resolved to px against the
  element's own `font_size` in M4 (M3 left the final number to us).
- `TextAlign::{Left, Right, Center, Justify}` — M4 honors **Left** only;
  others noted optional (§4.6).

Consequence: **percentages and `auto` survive to M4 and are resolved here**
with the containing block's content width. M4 owns all layout-context math.

## 1. Box tree model

A box tree built **fresh on each `layout()` call** — so a simple **owned tree**
(`Vec<LayoutBox>` children, no arena, no `Rc`) is the right call. No
cross-references, no mutation after build except the geometry fill done in the
same pass. This avoids arena/index bookkeeping entirely.

### 1.1 Geometry primitives

```rust
#[derive(Debug, Clone, Copy, Default, PartialEq)]
pub struct Rect {
    pub x: f32,
    pub y: f32,
    pub width: f32,
    pub height: f32,
}

#[derive(Debug, Clone, Copy, Default, PartialEq)]
pub struct EdgeSizes {
    pub top: f32,
    pub right: f32,
    pub bottom: f32,
    pub left: f32,
}

/// Geometry of one box. `content` is the absolute (page-space) content rect;
/// the surrounding edges grow outward from it.
#[derive(Debug, Clone, Copy, Default, PartialEq)]
pub struct Dimensions {
    pub content: Rect,
    pub padding: EdgeSizes,
    pub border: EdgeSizes,
    pub margin: EdgeSizes,
}

impl Dimensions {
    /// content + padding (the background-painting box).
    pub fn padding_box(&self) -> Rect { /* content expanded by padding */ }
    /// padding box + border (the border-painting box).
    pub fn border_box(&self) -> Rect { /* padding_box expanded by border */ }
    /// border box + margin (the space the box occupies among siblings).
    pub fn margin_box(&self) -> Rect { /* border_box expanded by margin */ }
}
```

`Rect` helpers `expanded_by(&EdgeSizes) -> Rect` back the three box accessors.
All coordinates are **absolute page space** (root content box starts at `(0,0)`
offset by nothing; the viewport is the initial containing block). M5 paints
directly from these — no transform stack.

### 1.2 Box kind and node

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum BoxKind {
    /// Block-level box establishing a block formatting context for its block
    /// children (or holding inline children via line boxes).
    BlockContainer,
    /// Inline-level box generated by `display:inline` elements (e.g. <span>,
    /// <a>). Carries style for paint; its geometry is the union of the fragments
    /// it produced on line boxes (M4 records a bounding rect, §4.7).
    InlineBox,
    /// Synthesized block wrapping a run of inline-level siblings that share a
    /// parent with block-level siblings (§2.3).
    AnonymousBlock,
    /// A run of text. Carries the string + the font-bearing ComputedStyle.
    TextRun,
    /// A single line produced by inline layout inside a BlockContainer /
    /// AnonymousBlock. Children are the TextRun/InlineBox fragments on that line.
    LineBox,
}

/// Back-reference to style. Elements point at their styled NodeId; anonymous and
/// line boxes inherit the containing block's style for font/color defaults.
#[derive(Debug, Clone)]
pub enum BoxStyleRef {
    /// A styled element: look up `styled.computed(node)`.
    Node(NodeId),
    /// Anonymous box: no DOM node. Inherit font/color from this element's style.
    Anonymous(NodeId),
}

#[derive(Debug, Clone)]
pub struct LayoutBox {
    pub kind: BoxKind,
    pub style: BoxStyleRef,
    /// Text payload — `Some` iff `kind == TextRun`.
    pub text: Option<String>,
    pub dimensions: Dimensions,
    pub children: Vec<LayoutBox>,
}
```

Design choices:

- **`BoxStyleRef` over a borrowed `&ComputedStyle`:** keeping a `NodeId` (not a
  reference) lets `LayoutBox` be `'static`-free and `Clone` without tangling
  lifetimes with `StyledTree`. M5 is handed the `&StyledTree` alongside the box
  tree (§5) and resolves `Node(id)`/`Anonymous(id)` → `&ComputedStyle`.
- **`text: Option<String>` on the box** rather than a separate enum payload —
  one field, only meaningful for `TextRun`. Simplest representation.
- **Anonymous boxes reference their generating element's `NodeId`** so font/
  color resolution still works (text inside an anonymous block uses the block
  container's style for defaults; the `TextRun`'s own style ref carries the real
  parent element).
- `InlineBlock` is not its own `BoxKind` — folded to `InlineBox` (§7).

`LayoutBox` exposes a constructor `LayoutBox::new(kind, style)` and helpers for
walking (§5).

## 2. Box generation

Walk the styled DOM and produce the box tree (geometry left zeroed; filled in
the layout pass §3/§4). Entry: `build_box_tree(doc, styled, root_element) ->
Option<LayoutBox>`.

### 2.1 Display dispatch

For a DOM node `id`:

- Non-element (`Document`/`Doctype`/`Comment`) other than `Text` → produce no
  box; recurse is not applicable (only the element subtree is walked from the
  root element, see §6).
- **`Text`** → a `TextRun` box (subject to whitespace handling §2.4), styled by
  the **parent element**'s `NodeId` (`BoxStyleRef::Node(parent_id)`).
- **Element**, by `styled.computed(id).display`:
  - `None` → **skip entirely** (no box, no recursion into the subtree).
  - `Block` → a `BlockContainer` box.
  - `Inline` / `InlineBlock` → an `InlineBox` box.

### 2.2 Child generation

For a generated `BlockContainer` / `InlineBox`, generate child boxes from the
DOM children **in order**, recursing per §2.1. `display:none` children vanish;
text children become `TextRun`s.

### 2.3 The anonymous block box rule

A `BlockContainer` whose generated children are **a mix of block-level
(`BlockContainer`) and inline-level (`InlineBox` / `TextRun`)** must not place
inline boxes as direct siblings of block boxes. Rule:

- If **all** children are inline-level → keep them as direct children; this
  block does **inline layout** (§4). (Flagged implicitly: a `BlockContainer`
  with no `BlockContainer` child runs inline layout over its inline children.)
- If **all** children are block-level → block layout (§3).
- If **mixed** → wrap each **maximal run of consecutive inline-level children**
  in a synthesized `AnonymousBlock` box (`BoxStyleRef::Anonymous(container_id)`).
  After wrapping, the container's children are all block-level
  (`BlockContainer` + `AnonymousBlock`), so it does block layout; each
  `AnonymousBlock` does inline layout over the inline run it wraps.

This is the classic anonymous-block rule and the only anonymous box M4
generates. `AnonymousBlock` has zero margin/border/padding and `Auto` width
(fills its parent's content width).

### 2.4 Whitespace handling (`white-space: normal`, the only mode)

Text comes from `NodeKind::Text(String)` raw. For M4:

- **Collapse** runs of ASCII whitespace (` `, `\t`, `\n`, `\r`, `\x0C`) within a
  text node to a single U+0020 space.
- A text node that is **entirely whitespace** between two block-level boxes
  produces **no box** (drop it). Between inline content it collapses to a single
  space.
- Leading/trailing space of the collapsed string is **kept** at generation time;
  inline layout (§4.2) drops a leading space at the start of a line and a
  trailing space at the end of a line. (Minimal, good-enough collapsing — full
  CSS bidi/segment-break rules are out.)

Concretely: `fn collapse_ws(s: &str) -> String` collapses internal runs; box
generation skips the resulting `TextRun` if the collapsed string is empty or a
lone space adjacent only to block boxes.

## 3. Block layout

The classic block flow (Brubeck's "Let's build a browser engine", corrected for
the real `ComputedStyle`). A `BlockContainer` / `AnonymousBlock` lays out within
its **containing block** (the parent's already-computed content geometry passed
as a `Dimensions`-derived value).

Method on the box:

```rust
impl LayoutBox {
    /// Lay out this box and its subtree. `containing` is the *content* geometry
    /// of the containing block (x, y of its content origin, and its content
    /// width). Mutates `self.dimensions`. `m` measures text (§4.1).
    fn layout(&mut self, containing: Dimensions, styled: &StyledTree, m: &dyn TextMeasurer);
}
```

`layout` dispatches on `self.kind`:
- `BlockContainer` / `AnonymousBlock` → `layout_block` (§3).
- inline content inside them → `layout_inline` (§4), driven from the block.

### 3.1 `layout_block(containing)`

Order matters (width before children, height after):

1. **`calculate_block_width(containing)`** — §3.2. Sets `content.width` and the
   left/right `margin`, `border`, `padding` edges.
2. **`calculate_block_position(containing)`** — §3.3. Sets `content.x`,
   `content.y` and top/bottom edges.
3. **`layout_block_children()`** — §3.4. Recurse; track running y; accumulate
   children's total height.
4. **`calculate_block_height()`** — §3.5. `Auto` → accumulated content height;
   explicit `Px`/`%` → used value.

### 3.2 Width (`content-box`, no `box-sizing` support)

Inputs from `style` (the box's `ComputedStyle`, or zeros for anonymous):
`width`, `margin_left/right`, `border_left/right_width`,
`padding_left/right`. Let `cb = containing.content.width`.

- Resolve each `Length` against `cb`:
  `Px(v)→v`, `Percent(p)→ p/100 * cb`, `Auto`→ a marker (see below).
- Sum the **non-auto** parts: `total = margin_l + border_l + padding_l + width +
  padding_r + border_r + margin_r` (treating `auto` margins/width as 0 for the
  sum).
- **Auto resolution** (CSS §10.3.3, simplified, content-box):
  - If `width` is not `auto` and `total > cb` (overconstrained): treat `auto`
    margins as 0 (no negative-margin trick beyond this).
  - `underflow = cb - total`.
  - **width auto:** width becomes `max(0, underflow)`; any `auto` margins → 0.
    (Auto width fills the available space.)
  - **width fixed, both margins auto:** split `underflow` evenly → centered.
  - **width fixed, one margin auto:** that margin absorbs `underflow`.
  - **width fixed, no auto margin:** push the **right** margin by `underflow`
    (so the box stays left-aligned; underflow may be negative → overflow, not
    clamped, §7).
- Write resolved `content.width`, `margin.left/right`, `border.left/right`,
  `padding.left/right` into `self.dimensions`.

`border-*-width` is already an `f32` in `ComputedStyle` (no `Length`), used
directly.

### 3.3 Position

```
self.dimensions.margin.top    = resolve(margin_top, cb)        // % of cb width per CSS
self.dimensions.margin.bottom = resolve(margin_bottom, cb)
self.dimensions.padding.top    = resolve(padding_top, cb)
self.dimensions.padding.bottom = resolve(padding_bottom, cb)
self.dimensions.border.top     = border_top_width
self.dimensions.border.bottom  = border_bottom_width

content.x = containing.content.x + margin.left + border.left + padding.left
content.y = containing.content.y + containing.content.height          // running bottom
          + margin.top + border.top + padding.top
```

`containing.content.height` is **used as the running y-cursor**: the block layout
loop (§3.4) grows `containing.content.height` by each child's full margin-box
height before laying out the next child, so the next child stacks below. This is
the Brubeck trick and it works because each block sets its own y from the
parent's current accumulated height.

**No margin collapsing** for M4 (§7). Adjacent vertical margins simply add.
(Optional follow-up: collapse adjacent top/bottom margins; explicitly out for
now.)

### 3.4 Children

```rust
fn layout_block_children(&mut self, styled, m) {
    let mut d = self.dimensions;          // copy: content origin known, height starts 0
    d.content.height = 0.0;
    for child in &mut self.children {
        child.layout(d, styled, m);       // child reads d.content.{x,y,width,height}
        // grow the running height by the child's full margin box
        d.content.height += child.dimensions.margin_box().height;
    }
    self.dimensions.content.height_accumulated = d.content.height; // see §3.5
}
```

The block passes a `Dimensions` whose `content.height` is the running cursor.
Each child positions itself below the prior using §3.3. After the loop the
accumulated height is the sum of child margin-boxes.

If the children are **inline-level** (no block child; §2.3 "all inline" case),
the block instead calls `layout_inline` (§4) which builds `LineBox` children and
returns the total inline content height.

### 3.5 Height

- `height: Auto` → content height = the accumulated child height from §3.4
  (block children) or the summed line-box heights (inline content).
- `height: Px(v)` → `v`.
- `height: Percent(p)` → `p/100 * containing.content.height` **only if** the
  containing block has a definite height; otherwise treat as `Auto` (CSS rule;
  for M4 the root has the viewport — but the viewport height grows with content,
  so percent-height is effectively `Auto` and that's acceptable, noted §7).

Result written to `self.dimensions.content.height`.

## 4. Inline layout

Runs inside a `BlockContainer`/`AnonymousBlock` that has only inline-level
children (`InlineBox` / `TextRun`). It flows fragments left-to-right and breaks
into `LineBox` children when the current line would exceed the available width.

Entry: `fn layout_inline(&mut self, containing, styled, m) -> f32` (returns total
height of all line boxes; the block uses it as its content height when `Auto`).

### 4.1 Text measurement abstraction

M4 must measure text. Define a trait so M5 can inject real font metrics later:

```rust
/// Measures the advance width of a text string at a given font.
/// M5 will provide a real implementation backed by font metrics; M4 ships a
/// crude default so layout is deterministic and testable now.
pub trait TextMeasurer {
    /// Advance width in px of `text` rendered at `font_size` px and `weight`.
    fn measure(&self, text: &str, font_size: f32, weight: FontWeight) -> f32;
    /// Ascent/used line-box height contribution for one line at this font.
    /// Default provided in terms of font_size; M5 may override.
    fn line_metrics(&self, font_size: f32) -> LineMetrics {
        LineMetrics { ascent: font_size * 0.8, descent: font_size * 0.2 }
    }
}

#[derive(Debug, Clone, Copy)]
pub struct LineMetrics { pub ascent: f32, pub descent: f32 }

/// Crude monospace-ish default: every char (incl. space) advances
/// `0.5 * font_size`; bold is unchanged. Good enough for wrapping tests.
pub struct DefaultMeasurer;

impl TextMeasurer for DefaultMeasurer {
    fn measure(&self, text: &str, font_size: f32, _w: FontWeight) -> f32 {
        text.chars().count() as f32 * 0.5 * font_size
    }
}
```

`FontWeight` is re-exported from `starfish-style`. The default's `0.5 *
font_size` per char (space included) makes word widths predictable for tests.

### 4.2 Line breaking

Available width = the inline container's `content.width` (already set by block
width §3.2). Algorithm:

1. Maintain a `cursor_x` (relative to content origin), a current `LineBox`
   accumulator, and `line_y` (relative content y, starts 0).
2. Walk inline-level children in order. For an `InlineBox`, recurse into its
   inline children (its `TextRun`s / nested inline boxes) — inline boxes are
   **flattened into the line flow**; M4 records the inline box's bounding rect
   afterward (§4.7). Padding/border/margin on inline boxes are **ignored for
   M4** (noted §7) except they may be added as left/right spacing if trivial —
   for simplicity, ignored.
3. For each `TextRun`, **split on spaces into words**. For each word:
   - `w = m.measure(word, font_size, weight)`; `space_w = m.measure(" ", …)`.
   - If `cursor_x == 0` (line start): place the word (drop any leading space).
   - Else if `cursor_x + space_w + w <= avail_width`: add a space then the word.
   - Else: **break** — finish the current line (§4.3), start a new `LineBox`,
     reset `cursor_x = 0`, place the word at line start.
   - Each placed word becomes (or extends) a `TextRun` fragment positioned at
     `(content.x + cursor_x, content.y + line_y)`; advance `cursor_x`.
4. A single word wider than `avail_width` is placed alone on its own line
   (overflows to the right; no mid-word break for M4, §7).

Words are the break opportunities; we break at collapsed spaces only.

### 4.3 Line box height and vertical advance

Each `LineBox`'s height = max over its fragments of the **used line-height**:

```
used_lh(style) = match style.line_height {
    LineHeight::Px(v)     => v,
    LineHeight::Number(n) => n * style.font_size,
    LineHeight::Normal    => 1.2 * style.font_size,   // M4 picks 1.2
}
```

`line_box.dimensions.content.height = max used_lh of fragments` (empty line →
the container style's used_lh). After finishing a line: `line_y +=
line_box.height`; the next line starts there. Total inline height returned =
final `line_y`.

Each `LineBox` is pushed as a child of the block; each fragment (`TextRun` /
`InlineBox`) is a child of the `LineBox`. So the tree is:
`BlockContainer → [LineBox → [TextRun, TextRun, …], LineBox → […]]`.

### 4.4 Fragment vertical position (baseline-ish)

Within a line box, fragments are top-aligned for M4 (a reasonable approximation;
true baseline alignment is §7). A `TextRun`'s `content.y` = the line's
`content.y`; its `content.height` = its own `used_lh`. Painting draws the glyph
run inside that rect (M5 owns baseline placement from `LineMetrics`).

### 4.5 Text run geometry recorded for paint

Each placed `TextRun` fragment stores:
- `text`: the word(s) it covers (a fragment may hold one word or a run of words
  with single spaces — implementation may coalesce consecutive same-style words
  on a line into one `TextRun` for fewer boxes; either is fine).
- `content`: absolute `Rect{x, y, width = measured advance, height = used_lh}`.
- `style`: `BoxStyleRef::Node(parent_element_id)` → M5 gets font_size, weight,
  color, family.

### 4.6 `text-align`

M4 implements **Left** only: fragments laid from `content.x` rightward. For
`Center` / `Right` (optional follow-up): after a line is finished, compute
`slack = avail_width - line_used_width` and shift every fragment's `content.x`
by `slack/2` (center) or `slack` (right). `Justify` → treat as Left. Noted §7.

### 4.7 Inline box geometry

An `InlineBox` (e.g. `<span>` with a background) may span multiple line
fragments. For M4 we record **one bounding rect** = the union of the fragment
rects its descendants produced on the line(s). This is enough for M5 to paint a
background/color span approximately. (Full per-line inline-box fragment boxes
are out, §7.) The `InlineBox`'s `dimensions.content` = that union; its style ref
gives the background/border to paint.

## 5. Geometry output (what M5 consumes)

M5 receives the **root `LayoutBox`** plus the **`&StyledTree`** (to resolve
`BoxStyleRef` → `&ComputedStyle` for colors/borders/font). The box tree is
walkable; every box carries absolute geometry.

Accessors on `LayoutBox`:

```rust
impl LayoutBox {
    pub fn kind(&self) -> BoxKind;
    pub fn children(&self) -> &[LayoutBox];
    pub fn dimensions(&self) -> &Dimensions;
    /// Some(&str) iff this is a TextRun.
    pub fn text(&self) -> Option<&str>;
    /// Resolve this box's ComputedStyle via the styled tree (None for the rare
    /// box whose ref node isn't styled — shouldn't happen for elements).
    pub fn style<'a>(&self, styled: &'a StyledTree) -> Option<&'a ComputedStyle>;
    /// Pre-order walk helper for painters.
    pub fn walk(&self, f: &mut dyn FnMut(&LayoutBox));
}
```

M5 paint order per box (pre-order): background (`padding_box()`), border
(`border_box()` minus `padding_box()`), then children; `TextRun`s draw glyphs in
`content`. `Dimensions::{padding_box, border_box, margin_box}` give the rects.

The viewport **height grows with content**: the root box's `border_box().height`
(or `margin_box`) is the page height M5 rasterizes; width = `viewport_width`.

## 6. Entry point

```rust
/// Build the box tree and lay it out against a viewport of the given width.
/// The viewport is the initial containing block: content origin (0,0), content
/// width = `viewport_width`, height = grows with content. Returns the root
/// LayoutBox (a BlockContainer for the root element, e.g. <html>).
///
/// `measurer` abstracts text metrics; pass `&DefaultMeasurer` in M4, a real
/// font-backed measurer in M5.
pub fn layout(
    doc: &Document,
    styled: &StyledTree,
    viewport_width: f32,
    measurer: &dyn TextMeasurer,
) -> LayoutBox;
```

Steps:

1. Find the **root element** to lay out: the first element child of
   `doc.root()` (typically `<html>`; the M3 walk styles from there). If none →
   return an empty `BlockContainer` of zero size.
2. `build_box_tree(doc, styled, root_element)` → root `LayoutBox` (§2). The root
   element is forced to `BlockContainer` even if its `display` were inline
   (the initial containing block is block).
3. Construct the **initial containing block** `Dimensions`:
   `content = Rect{ x: 0, y: 0, width: viewport_width, height: 0 }`, all edges 0.
4. `root.layout(initial_cb, styled, measurer)` (§3).
5. Return `root`. Its `dimensions.content.height` (plus root margins/border) is
   the page height.

A thin convenience may also expose `pub fn layout_default(doc, styled,
viewport_width) -> LayoutBox` using `DefaultMeasurer`, but the trait-taking form
is the primary API.

## 7. Edge cases & explicit non-goals

Handled:

- `display:none` subtree removed (no box, no recursion).
- Mixed block+inline children → anonymous block wrapping (§2.3).
- Whitespace collapsing (`normal`), whitespace-only text between blocks dropped
  (§2.4).
- `width:auto` fills containing block; `auto` margins center / absorb underflow
  (§3.2).
- Percent width/margin/padding resolved against containing block **width**
  (§3.2/§3.3).
- `Auto` height = sum of children / line boxes (§3.5).
- Inline text wraps into multiple line boxes at word boundaries (§4.2).
- Single overlong word overflows on its own line (§4.2).

Explicit **non-goals** for M4 (documented limitations):

- **No margin collapsing** — adjacent vertical margins add. (Optional follow-up.)
- **No floats, no `clear`.**
- **No positioning** — `position` is not in `ComputedStyle`; everything is
  static normal flow.
- **No flexbox / grid / table layout.**
- **No `box-sizing`** — content-box only.
- **No min/max-width/height, no overflow handling/clipping** — overflow simply
  draws outside (M5's concern, unclamped here).
- **No real font metrics** — `DefaultMeasurer` (0.5·font_size per char). M5
  injects real metrics via `TextMeasurer`.
- **`display:inline-block` folded to `inline`** — no atomic inline sizing.
- **Inline box padding/border/margin ignored**; inline box geometry is a
  bounding-rect approximation across line fragments (§4.7).
- **`text-align`: Left only** (Center/Right/Justify optional, §4.6).
- **No baseline alignment** — fragments top-aligned within a line (§4.4);
  baseline placement of glyphs is M5's via `LineMetrics`.
- **Percent height** with an indefinite containing block → treated as `Auto`.
- **No bidi / no line-break beyond ASCII spaces / no hyphenation / no `tab`
  expansion.**

## 8. Crate boundary & module layout

`starfish-layout` depends on `starfish-dom` and `starfish-style`.

`crates/layout/Cargo.toml`:

```toml
[dependencies]
starfish-dom   = { workspace = true }
```

## 9. Test plan

Unit tests in `crates/layout/src/…`. A helper builds a `Document` (via
`starfish_html::parse`), a `StyledTree` (via `starfish_style::style_tree`), runs
`layout(doc, &styled, width, &DefaultMeasurer)`, and asserts geometry. With the
`DefaultMeasurer` (0.5·font_size/char) all text widths are exact and
deterministic.

### 9.1 Block stacking

1. `<body><div>a</div><div>b</div></body>` → second `div`'s `content.y` ==
   first `div`'s `margin_box().bottom` (stacked, margins added).
2. Nested blocks: child `content.x/y` offset from parent by parent's
   margin+border+padding-left/top.

### 9.2 Width resolution

1. `div { }` (auto width) inside 800px viewport with `body{margin:8px}` →
   `div.content.width == 800 - 16` (fills container minus body margins);
   adjust for any div margins.
2. `div { width: 50% }` in an 800px containing block → `content.width == 400`.
3. `div { width: 200px; padding: 10px; border: 5px }` → content.width 200,
   padding/border edges set; margin-right absorbs the underflow.
4. (Optional) `div { width: 100px; margin: 0 auto }` in 300px → `margin.left ==
   margin.right == 100` (centered).

### 9.3 Height

1. `Auto` height block with two 50px-tall children (explicit heights) → parent
   `content.height == 100` (+ child margins if any).
2. `div { height: 120px }` → `content.height == 120` regardless of children.

### 9.4 Box generation / anonymous block

1. `<div><p>a</p>text<p>b</p></div>` (mixed block + inline) → the `div`'s
   children are `[BlockContainer(p), AnonymousBlock([TextRun]),
   BlockContainer(p)]`; the anonymous block wraps the stray text.
2. `<div><span>a</span> <span>b</span></div>` (all inline) → `div` is a
   `BlockContainer` with `LineBox` children (no anonymous block needed).
3. `display:none`: `<div><p style-none>x</p><p>y</p></div>` → only one `p` box;
   the none subtree is absent. (Use CSS `p.hidden{display:none}`.)
4. Whitespace-only text between two block `<p>`s produces no box.

### 9.5 Inline wrapping

1. Container width chosen so 3 words fit per line; a 7-word paragraph → 3 line
   boxes (3+3+1). With `DefaultMeasurer`, word widths are exact, so the line
   count is deterministic — assert `count of LineBox children == 3` and each
   line's fragment x positions.
2. Line box height: `font-size:20px; line-height:normal` → line height ==
   `24` (1.2·20). `line-height: 30px` → 30.
3. A single word wider than the container → its own line, width == measured
   advance (overflow allowed).
4. Two stacked lines: second `LineBox.content.y == first.content.y +
   first.height`.

### 9.6 End-to-end smoke

A representative small page (heading, paragraph with wrapping text, nested divs,
a list) at viewport 800px → assert: root height > 0; the heading block sits
above the paragraph (`y` ordering); paragraph text wrapped into the expected
number of lines; total page height == root `border_box().height`. This is the
milestone's "done-when" check.
