# E6-M3 — Bidirectional + spaced text (design note)

Scope: the final Epic-6 milestone. Add the **text-shaping-adjacent** CSS that
does not need a real shaper:

- **`direction`** (`ltr`/`rtl`) + **`unicode-bidi`** (`normal`/`embed`/
  `bidi-override`/`isolate` — minimal) and **RTL reordering** of a laid-out line
  via the **`unicode-bidi`** crate (Arabic/Hebrew runs reorder; mixed LTR+RTL
  ordered per the bidi algorithm). `direction:rtl` also sets the **inline base
  direction** so a line starts at the right.
- **`letter-spacing`** (extra px after each char) + **`word-spacing`** (extra px
  at each U+0020).
- **`text-transform`** (`uppercase`/`lowercase`/`capitalize`).
- **`white-space`** (`normal`/`pre`/`nowrap`/`pre-wrap`/`pre-line`) — controls
  whitespace collapsing + line wrapping + newline preservation.

Crates touched: `style` (six new fields + parsing), `layout` (`boxtree.rs`
whitespace + text-transform at text collection, `inline.rs` line breaking +
letter/word-spacing + bidi reorder), `paint` (`display.rs` GlyphRun additions +
emit, `raster.rs` spacing-aware advance + visual-ordered text). One new
dependency: `unicode-bidi` in `layout`.

Guiding rule (project "Simplicity First"): **let the `unicode-bidi` crate do the
bidi algorithm**; we only feed it a line's string + the base level and read back
the visual order. text-transform is a `String` transform applied **once at text
collection** (so measure == paint). letter/word-spacing is **additive on top of
the existing advances-sum** in both the measurer and the rasterizer. **Complex-
script shaping (Arabic joining/ligatures) stays OUT** (advances-sum + reorder
only; documented limit §7). No vertical writing modes, no locale tailoring.

## 0. The real APIs this builds on (verified)

### 0.1 `unicode-bidi` (new dependency for `layout`)

Verified against docs.rs/unicode-bidi (1.0.x). The minimal surface we use:

```rust
use unicode_bidi::{BidiInfo, Level, ParagraphInfo};

// Run the algorithm over a whole text (may be multiple paragraphs). For our
// per-line use we feed ONE line's string and force the base level.
let bidi = BidiInfo::new(text: &str, default_para_level: Option<Level>);
//   default_para_level = Some(Level::ltr()) | Some(Level::rtl()) forces the
//   paragraph base direction (from CSS `direction`); None = auto-detect (P2/P3).

// One paragraph (a line for us — line has no embedded hard breaks):
let para: &ParagraphInfo = &bidi.paragraphs[0];

// Reorder a byte range into VISUAL order. Returns:
//   levels:  Vec<Level> per byte (resolved embedding levels), and
//   runs:    Vec<Range<usize>> of byte ranges in VISUAL (left-to-right) order.
let (levels, runs) = bidi.visual_runs(para, para.range.clone());
// Each run is a maximal same-level slice; `levels[run.start].is_rtl()` tells
// whether that run's characters are themselves laid right-to-left.

// Level helpers:
Level::ltr()  // 0
Level::rtl()  // 1
level.is_rtl() -> bool
level.is_ltr() -> bool
```

Key facts we rely on:

- `BidiInfo::new(line, Some(base))` runs rules P2–L1 for that string with the
  forced base paragraph level. For a single line (no `\n`), `paragraphs[0]`
  covers the whole string.
- `visual_runs` already returns the runs **in visual left-to-right order**, and
  marks each run's level. **An RTL run's characters must be emitted
  right-to-left within the run** (the crate gives the run's *logical* byte range;
  we reverse character iteration when `level.is_rtl()`). This is the standard
  consumer pattern.
- We treat **one laid-out line as one paragraph**. Hard line breaks (`\n`) are
  already split into separate lines *before* bidi runs (white-space/pre handling,
  §2), so a line never contains a paragraph separator.
- `unicode-bidi` does NOT shape glyphs (no Arabic joining) — exactly our scope.

> If the analysis agent pins a different crate version whose `visual_runs`
> signature differs, adapt the call but keep the contract: *in → a line string +
> base level; out → visual-ordered (byte-range, is_rtl) runs.*

### 0.2 Rust case mapping (std, for text-transform)

`str::to_uppercase()` / `str::to_lowercase()` return **`String`** (Unicode case
mapping can change length, e.g. `ß`→`SS`, `İ`). We transform the **whole word/
string**, never char-by-char swap. `capitalize` uppercases the first cased char
of each whitespace-separated word and lowercases nothing else (per CSS:
capitalize only touches the first letter; the rest is left as authored).

### 0.3 What exists today (recap)

- `ComputedStyle` (style/computed.rs): has `font_*`, `text_align`, `line_height`,
  `color`, etc. Inherited set in `inherit_from()`: color, font-size/weight/style,
  line-height, text-align, font-family, list-style-*.
- `collapse_ws(&str) -> String` (layout/boxtree.rs): the **only** whitespace
  handler today — collapses ASCII ws runs to one space, keeps one leading/trailing
  space. Called from `build_node` (TextRun creation) and `build_children` (drop
  ws-only between blocks). Newlines become spaces.
- `inline.rs`: collects items, splits TextRun text **on `' '`** into words
  (`text.split(' ')`), greedy-wraps with `m.measure(word, &q)` + `m.measure(" ",
  &q)`, places `PlacedItem::Word { text, x, width, .. }` per fragment, builds
  `LineBox` children. text-align Left/Center/Right shifts the whole line.
- `measure.rs`: `TextMeasurer::measure(&str, &FontQuery) -> f32`; the real impl
  (`FontMeasurer`, paint/font.rs) sums per-char `metrics(c,size).advance_width`.
- `display.rs` `PaintCmd::GlyphRun { origin, text, font_size, weight, style,
  family, color, ascent }`; `emit_text` builds it from the TextRun's style.
- `raster.rs` `draw_glyph_run`: `pen_x = origin.0`, loops `text.chars()`,
  `pen_x += g.advance`. **This is where measure == paint lives.**

## 1. `ComputedStyle` additions (`style/computed.rs`)

Six new fields. All inherited except `unicode_bidi` (CSS says `unicode-bidi` is
*not* inherited; but per the prompt "keep simple" we treat it as **not
inherited** to match spec — it is a per-element reset).

```rust
/// `direction`. Initial `Ltr`; INHERITED. Sets the inline base direction.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Direction { Ltr, Rtl }

/// `unicode-bidi` (minimal subset). Initial `Normal`; NOT inherited.
/// `Embed`/`Override`/`Isolate` are modelled but, given no nested-element bidi
/// (§7), only `BidiOverride` meaningfully changes behaviour in M3 (forces the
/// run's direction = `direction`, ignoring character types). `Embed`/`Isolate`
/// behave like `Normal` for a single run (documented limit).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum UnicodeBidi { Normal, Embed, BidiOverride, Isolate }

/// `text-transform`. Initial `None`; INHERITED.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TextTransform { None, Uppercase, Lowercase, Capitalize }

/// `white-space`. Initial `Normal`; INHERITED.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum WhiteSpace { Normal, Pre, Nowrap, PreWrap, PreLine }

impl WhiteSpace {
    /// Whitespace runs (incl. newlines, except a preserved `\n`) collapse to one
    /// space. True for normal / nowrap / pre-line.
    pub fn collapses(self) -> bool {
        matches!(self, WhiteSpace::Normal | WhiteSpace::Nowrap | WhiteSpace::PreLine)
    }
    /// Segment breaks (`\n`) are preserved as forced line breaks (not collapsed
    /// into a space). True for pre / pre-wrap / pre-line.
    pub fn preserves_newlines(self) -> bool {
        matches!(self, WhiteSpace::Pre | WhiteSpace::PreWrap | WhiteSpace::PreLine)
    }
    /// The line may wrap at soft break opportunities (spaces). True for
    /// normal / pre-wrap / pre-line. (pre / nowrap → one long line / overflow.)
    pub fn wraps(self) -> bool {
        matches!(self, WhiteSpace::Normal | WhiteSpace::PreWrap | WhiteSpace::PreLine)
    }
}
```

## 2. `white-space` behaviour (the trickiest part)

`white-space` is **inherited**, so it is available on the text node's parent
element (the same place `collapse_ws` is called) and on the inline container.
Two concerns: **(A) whitespace collapsing + newline handling at text collection**
(boxtree), and **(B) wrapping at line breaking** (inline.rs).

### 2.1 The collapsing / breaking matrix (precise)

| value     | collapse ws runs | keep `\n` as break | wrap at spaces | keep leading/trailing ws |
|-----------|------------------|--------------------|----------------|--------------------------|
| `normal`  | yes → 1 space    | no (`\n`→space)    | yes            | edge spaces dropped per line |
| `nowrap`  | yes → 1 space    | no (`\n`→space)    | **no**         | edge dropped |
| `pre`     | **no**           | **yes**            | **no**         | **kept** (all ws preserved) |
| `pre-wrap`| **no**           | **yes**            | **yes**        | **kept** |
| `pre-line`| yes → 1 space    | **yes**            | yes            | edge dropped (but `\n` kept) |

Encoded by the three `WhiteSpace` predicates (§1): `collapses()`,
`preserves_newlines()`, `wraps()`. Tab: treated as an ordinary collapsible space
in collapsing modes; in `pre`/`pre-wrap` a tab is preserved **as a single space
advance** (no 8-column tab stops — documented limit §7).

### 2.2 Collapsing at text collection (`boxtree.rs`)

`collapse_ws` stays the default path. Add a **white-space-aware** variant and
route `build_node`'s `Text` arm through it using the **parent element's
`white-space`** (text nodes inherit it):

```rust
/// Transform raw text-node content per `white-space` (E6-M3 §2).
/// Returns the string to store on the TextRun. A preserved `\n` is kept LITERAL
/// in the string; inline.rs splits on it for forced breaks. For collapsing modes
/// this is exactly the old `collapse_ws` plus newline-as-space (already the case).
fn process_text(raw: &str, ws: WhiteSpace) -> String {
    match ws {
        WhiteSpace::Normal | WhiteSpace::Nowrap => collapse_ws(raw), // unchanged
        WhiteSpace::Pre | WhiteSpace::PreWrap => preserve_ws(raw),   // keep all, keep \n
        WhiteSpace::PreLine => collapse_ws_keep_newlines(raw),       // collapse spaces, keep \n
    }
}
```

- `collapse_ws` is unchanged (it already turns `\n` into a collapsed space and
  drops nothing but consecutive ws). Used for `normal`/`nowrap`.
- `preserve_ws(raw)`: return `raw` **verbatim** except normalize `\r\n`/`\r` →
  `\n` and `\t` → `" "` (single-space tab, §7). No collapsing.
- `collapse_ws_keep_newlines(raw)`: like `collapse_ws` but a `\n` is **not**
  folded into the surrounding space run — instead it is emitted as a literal
  `\n`, and spaces around it still collapse. (Implement as: split on `\n`,
  `collapse_ws` each segment, rejoin with `\n`.)

The TextRun's stored string therefore carries literal `\n` only for the three
`preserves_newlines()` modes. **text-transform is applied here too** (§3), after
`process_text`, on the same string.

`build_children`'s "drop ws-only text between block siblings" rule stays for
collapsing modes; for `pre*` modes a ws-only text node is **kept** (it has
visible/structural whitespace). Guard: only drop when `ws.collapses() &&
collapsed == " "` and the previous box is not inline-level (current logic, gated
on `collapses()`).

### 2.3 Line breaking on white-space (`inline.rs`)

Two changes to the collect + break loop, both keyed off the container/word
style's `white_space`:

**(a) Word splitting + preserved spaces (collect_items).** Today TextRun text is
split on `' '` and empty pieces skipped, so runs of spaces vanish and edge
spaces become the `pending_space` flag. For `preserves_newlines()` modes the
string may contain literal `\n`, and for `pre`/`pre-wrap` literal multiple
spaces must each advance. Revised collection per TextRun:

- Determine `ws` from the run's style (text node parent).
- **Split the text on `\n` into segments** (each segment is one *line piece*; a
  `\n` boundary emits a `ForcedBreak` item between segments — see (b)). Only
  `preserves_newlines()` modes will ever have >1 segment; for collapsing modes
  the string has no literal `\n`, so one segment.
- Within a segment:
  - **collapsing modes** (`normal`/`nowrap`/`pre-line`): keep the current
    behaviour — split on `' '`, skip empties, set `space_before` from collapsed
    spaces.
  - **preserving modes** (`pre`/`pre-wrap`): do **not** collapse. Emit each
    maximal **non-space run** as a `Word` and carry the **count of preceding
    spaces** so their width (incl. `word-spacing` ×count) is added as the gap.
    Leading/trailing spaces in the segment are preserved (an empty leading word
    with `space_before` = the space count). Simplest concrete encoding: keep
    `space_before` as today but generalize it to a small `spaces_before: u16`
    count on `CollectedItem::Word` (0 in collapsing modes ⇒ `bool`-equivalent;
    pre modes ⇒ the real run length). The gap width = `spaces_before *
    (space_advance + word_spacing) + (if spaces_before>0 || word_count>0:
    letter_spacing accounting per §4)`.

**(b) Forced break + soft-wrap gating.** Introduce `CollectedItem::ForcedBreak`
emitted at each preserved `\n`. In the break loop:

- On `ForcedBreak`: commit the current line unconditionally (advance `line_y`,
  recompute band), even if empty (an empty line for a blank `\n` — `pre` shows
  blank lines). Reset `cursor_x`.
- **Soft wrap** (the existing `cursor_x + space_w + width > avail` test) only
  fires when **`ws.wraps()`** is true. For `pre`/`nowrap` (`!wraps()`) never
  break on width — keep appending to the current line (it overflows the band; no
  clamping, §7). The single-overlong-word case (already its own line) also only
  applies under `wraps()`.

`white_space` for the wrap decision is read from the **inline container's**
style (it is inherited, so the container and its text agree in the common case;
a per-run override is rare and we use the container value for the line policy,
which is the pragmatic subset).

This keeps `normal` byte-for-byte identical (one segment, no ForcedBreak,
`wraps()`=true, `spaces_before`∈{0,1}).

## 3. `text-transform`

**Applied once, at text collection, on the stored string** — so layout (measure)
and paint (the GlyphRun text) both see the transformed text and stay consistent.
Application point: in `boxtree.rs build_node`'s `Text` arm, **after**
`process_text`, using the parent element's `ComputedStyle.text_transform`:

```rust
NodeKind::Text(raw) => {
    let ps = styled.get(parent_elem);            // parent element style (text inherits)
    let ws = ps.map(|s| s.white_space).unwrap_or(WhiteSpace::Normal);
    let tt = ps.map(|s| s.text_transform).unwrap_or(TextTransform::None);
    let text = transform_text(&process_text(raw, ws), tt);
    if text.is_empty() && ws.collapses() { return None; }
    // (pre* keeps an all-whitespace TextRun)
    let mut b = LayoutBox::new(BoxKind::TextRun, BoxStyleRef::Node(parent_elem));
    b.text = Some(text);
    Some(b)
}
```

```rust
/// Apply `text-transform` to a whole string (Unicode-correct; length may change).
fn transform_text(s: &str, tt: TextTransform) -> String {
    match tt {
        TextTransform::None => s.to_string(),
        TextTransform::Uppercase => s.to_uppercase(),
        TextTransform::Lowercase => s.to_lowercase(),
        TextTransform::Capitalize => capitalize(s),
    }
}

/// Uppercase the first cased char of each whitespace-delimited word; leave the
/// rest as authored (CSS `capitalize` does not lowercase the tail).
fn capitalize(s: &str) -> String {
    let mut out = String::with_capacity(s.len());
    let mut at_word_start = true;
    for ch in s.chars() {
        if ch.is_whitespace() {
            at_word_start = true;
            out.push(ch);
        } else if at_word_start {
            out.extend(ch.to_uppercase());
            at_word_start = false;
        } else {
            out.push(ch);
        }
    }
    out
}
```

Markers/`<img>`/inline-block text are untouched (transform is a text property of
text content; markers are UA-generated, §7). Because the transform is baked into
the TextRun string, **no GlyphRun/raster change is needed** for text-transform —
measure == paint follows automatically. (Note: `to_uppercase` can split a char
into several; storing the `String` handles this. CSS `text-transform` is locale-
sensitive for Turkish `i`/`İ`; we use Rust's default Unicode mapping — §7.)

## 4. `letter-spacing` / `word-spacing`

Both are **additive** on top of the existing advances-sum, applied identically in
the measurer and the rasterizer (measure == paint). Definitions used (the common
browser behaviour):

- **letter-spacing**: add `letter_spacing` px **after every character** of the
  run, *including* after spaces. (Edge nuance — the spacing after the very last
  glyph of a line — is kept simple: we add it after every char; the last char's
  trailing spacing is part of the measured width. This matches our advances-sum
  model and keeps measure == paint; §7.)
- **word-spacing**: add `word_spacing` px **at each U+0020 space** (in addition to
  the space glyph's own advance + its letter-spacing).

### 4.1 Thread spacing through `FontQuery`

`FontQuery` is the one struct both crates share for a run. Add two px fields:

```rust
pub struct FontQuery<'a> {
    pub family: &'a [String],
    pub style: FontStyle,
    pub weight: FontWeight,
    pub size: f32,
    pub letter_spacing: f32,  // NEW (px, default 0)
    pub word_spacing: f32,    // NEW (px, default 0)
}
```

All construction sites (inline.rs word/marker measure, display.rs `emit_text`)
fill the two new fields from the run's `ComputedStyle`. `DefaultMeasurer` and the
unit-test `q(...)` helpers set them to 0.

### 4.2 Measurement (`measure.rs` + paint/font.rs)

The advance of a run becomes:

```
advance(text, q) = Σ_chars [ glyph_advance(c) + q.letter_spacing
                             + (if c == ' ' { q.word_spacing } else { 0 }) ]
```

- `DefaultMeasurer::measure`: `chars*0.5*size + chars*letter_spacing +
  spaces*word_spacing`.
- `FontMeasurer`/`FontDb::advance_width` (paint/font.rs): the existing
  `text.chars().map(|c| metrics(c,size).advance_width).sum()` gains the same two
  additive terms. Add a small helper `extra_spacing(text, q)` shared so the
  formula lives once. **This is the layout-side number that drives wrapping.**

### 4.3 Rasterization (`raster.rs draw_glyph_run`)

`pen_x` advance must match exactly:

```rust
let mut pen_x = origin.0;
for ch in text.chars() {
    let g = fonts.rasterize_glyph(ch, &q);   // q now carries spacing (unused by raster of one glyph)
    // ...blit at pen_x...
    pen_x += g.advance + q.letter_spacing
           + if ch == ' ' { q.word_spacing } else { 0.0 };
}
```

The per-glyph advance is identical to the measurer's per-char term ⇒ the run's
painted width equals its measured width ⇒ **measure == paint** preserved for
spacing.

> Important interaction with bidi (§5): when the run is reordered for RTL, the
> per-glyph spacing is applied to the **visual-ordered** character stream the
> same way (after each visual char), so the painted width still equals the
> measured (logical) width — spacing is order-independent (it is a per-char and
> per-space sum). So bidi reordering and spacing compose cleanly.

## 5. bidi / RTL reordering (the core)

### 5.1 Where it runs

Bidi reordering happens **at the line level, after line breaking, per LineBox**,
in `inline.rs` — once each line's fragments are known. We keep the **pragmatic
subset** the prompt asks for:

- **One logical text string per line.** In M3 a line's reorderable text is the
  concatenation of its `PlacedItem::Word` fragments **in logical order** with
  single spaces between (the words were split from a single TextRun; for the
  common single-run line this reconstructs the original logical line text).
  Atomic inlines (`<img>`/inline-block) on a line are treated as **neutral
  objects** that do not reorder relative to each other in M3 — bidi applies to
  the text words; an atom keeps its logical slot (documented subset, §7).
- **Base direction** = the inline container's `direction` (→ `Level::ltr()` /
  `Level::rtl()`), with `unicode-bidi: bidi-override` forcing the run's level to
  the base (we pass an override by mapping all chars to the base level — see
  §5.3).

### 5.2 The reorder algorithm (per line)

After the existing greedy break produces a line's ordered `Vec<PlacedItem>` (with
each word's logical `x`/`width` already measured), but **before** emitting the
`LineBox` fragments with absolute geometry:

1. Build the line's **logical string** `L` = words joined by single spaces
   (record each word's char range in `L` and its measured `width`).
2. `let base = if dir == Rtl { Level::rtl() } else { Level::ltr() };`
3. `let bidi = BidiInfo::new(&L, Some(base));`
4. `let para = &bidi.paragraphs[0];`
5. `let (levels, runs) = bidi.visual_runs(para, para.range.clone());` →
   `runs` are byte ranges in **visual left-to-right** order.
6. **Re-place fragments in visual order.** Walk `runs` left-to-right; for each
   run, gather the words whose char range falls in the run; if `levels[start]`
   is RTL, reverse the words' order within the run; lay the fragments out
   left-to-right starting at the line's left edge, advancing by each fragment's
   `width` (+ the inter-word space advance incl. word-spacing). This produces a
   new visual `x` for every fragment. **Within an RTL word**, the fragment's
   **stored text is reversed to visual order** so the rasterizer (which paints
   left-to-right) draws the characters in the correct visual sequence (§5.4).

   For `direction:rtl` the base is RTL, so a pure-RTL line's single run is laid
   from the left edge but its words are reversed ⇒ the logically-first word ends
   up at the **right**, i.e. the line reads right-to-left. Embedded LTR
   sub-runs (latin/numbers) are themselves left-to-right runs placed among the
   RTL runs by `visual_runs` per the algorithm.

7. text-align then composes on top (§5.5): the recomputed visual fragment
   x-positions are relative to the line's left; the existing align offset shifts
   the whole line.

This is the standard "logical positions → visual runs → re-x" pass and needs no
change to the *vertical* line model. It is gated: when `dir == Ltr` **and** the
line contains no strong-RTL characters, the reorder is a no-op (we can skip
`BidiInfo` entirely via `unicode_bidi::level::has_rtl(&L)` fast check, or just
detect that `runs.len()==1 && levels[0].is_ltr()` and keep the existing
positions). So pure-LTR pages are unchanged.

### 5.3 `unicode-bidi` minimal subset mapping

- `direction: ltr|rtl` → `default_para_level = Some(ltr|rtl)`. This is the
  meaningful knob.
- `unicode-bidi: bidi-override` → after computing, **force every char's level to
  the base level** (override character types) by emitting a single run at the
  base level (i.e. skip `visual_runs` and reverse-or-keep the whole line by the
  base direction). Concretely: if base is RTL, reverse the whole logical line to
  visual; if LTR, keep as-is.
- `unicode-bidi: normal | embed | isolate` → behave as `normal` for a single
  run (we do not model nested isolating runs across inline elements in M3 — §7).

### 5.4 Per-character visual reversal for RTL runs

A fragment in an RTL run must have its **stored text reversed** (by `char`, not
byte) so `draw_glyph_run` (left-to-right pen) paints the visually-correct order:

```rust
fn to_visual(text: &str, rtl: bool) -> String {
    if rtl { text.chars().rev().collect() } else { text.to_string() }
}
```

This reverses *only* code points (no shaping/joining). For Hebrew (non-joining)
this is correct; for Arabic the letters appear in correct order but **unjoined**
(isolated forms) — the documented complex-script limit (§7). The fragment's
`width` is unchanged by reversal (advances-sum is order-independent), so
measure == paint holds.

> Implementation note: doing the reversal at fragment level requires that a
> fragment lie entirely within one bidi run. Because we feed *words* (no internal
> direction change inside a single space-delimited word in practice for the M3
> subset), each word maps to one run. A word that itself mixes scripts is split
> by `visual_runs` into multiple runs; in that rare case, split the word's text
> at the run boundaries (the byte ranges from `visual_runs`) into sub-fragments,
> each reversed per its level. Keep this path minimal.

### 5.5 text-align interaction

CSS: the **initial `text-align` for `direction:rtl` is `right`** (start edge).
Our `TextAlign` initial is `Left`. To keep the spec-correct default without a new
"start/end" model, map at line-alignment time:

```rust
let effective_align = match (align, dir) {
    (TextAlign::Left,  Direction::Rtl) => /* start = right */ TextAlign::Right,
    (TextAlign::Left,  Direction::Ltr) => TextAlign::Left,
    (other, _) => other, // explicit left/right/center/justify honored verbatim
};
```

(We only remap the *initial/`Left`* case under RTL; an explicit `text-align:left`
under RTL would also map to Right here — acceptable for M3 since we don't model
`start`/`end` vs `left`/`right` distinctly. Documented §7.) The existing slack
offset logic then right-aligns the visual line for the RTL base.

### 5.6 Threading `direction` into `inline.rs`

`layout_inline` already reads `container_style` (`style_of(styled, b)`). Read
`container_style.direction` and `container_style.unicode_bidi` there; pass them
into the per-line reorder step. No new function parameters needed.

## 6. measure == paint consistency + GlyphRun additions

Decision (per the prompt's recommendation): **pass the already-ordered visual
text + the spacing into the GlyphRun, and let raster advance by the same
formula.** We do **not** pass per-glyph x arrays — the advances-sum + spacing
formula is deterministic and identical on both sides, and bidi reversal is baked
into the fragment's stored `text` (§5.4), so raster's left-to-right pen reproduces
the measured layout exactly.

Concretely:

- After §5, each `TextRun` fragment's `text` is the **visual-ordered** string
  (reversed for RTL runs) and its `content.x/width` is the visual position/width.
- `display.rs emit_text` reads the fragment's (already visual) `text` and the
  run style's `letter_spacing`/`word_spacing`, and adds them to the `GlyphRun`:

```rust
GlyphRun {
    origin, text, font_size, weight, style, family, color, ascent,
    letter_spacing: style.letter_spacing,   // NEW
    word_spacing: style.word_spacing,        // NEW
}
```

- `raster.rs draw_glyph_run` rebuilds `FontQuery` including the two spacings and
  advances `pen_x` per §4.3.

Because (a) text-transform is baked into the string at collection, (b) bidi
visual order is baked into the fragment string, and (c) letter/word-spacing use
the **same additive formula** in `FontDb::advance_width` (layout measure) and
`draw_glyph_run` (paint), the painted run width equals the measured fragment
width for every case. The M5/E6-M1 measure == paint invariant is preserved.

> Alternative considered (per-glyph x array in GlyphRun): more robust for future
> shaping/kerning, but heavier and unnecessary for advances-sum + reorder. Reject
> for M3 (Simplicity First); revisit if a real shaper lands.

## 7. Edge cases & non-goals

Handled / decided:

- **Complex-script shaping is OUT.** Arabic contextual joining/ligatures, Indic
  reordering, mark positioning — none. RTL is **reorder + per-char reversal +
  advances-sum** only; Arabic renders as **unjoined isolated forms**. Hebrew
  (non-joining) renders correctly. Documented limit.
- **Vertical writing modes / `text-orientation` / `text-combine`** — OUT.
- **`unicode-bidi` nuance** — only `bidi-override` changes behaviour in M3;
  `embed`/`isolate`/`plaintext`/`isolate-override` collapse to `normal`/override.
  No nested isolating runs across inline elements.
- **bidi across multiple inline elements / multiple levels** — pragmatic subset:
  reorder the line's **text words** (typically one TextRun). Atomic inlines hold
  their logical slot; deeply nested mixed-direction inline trees are not modelled.
- **letter-spacing at line edges** — applied after every char incl. the last; the
  trailing spacing is part of the measured width (no edge-trim). Acceptable.
- **text-transform locale** — Rust default Unicode mapping (no Turkish-`i`
  tailoring). `capitalize` only uppercases word-initials, doesn't lowercase tails.
- **white-space `pre` tab** — a `\t` is normalized to **one space advance** (no
  8-column tab stops).
- **`pre`/`nowrap` overflow** — no soft wrap ⇒ a long line may exceed the band /
  canvas; it is drawn unclamped (clipping is the rasterizer's existing concern,
  unchanged). No `text-overflow`/ellipsis.
- **`pre`/`pre-wrap` blank lines** — a `\n` with no content emits an empty
  LineBox advancing by the container line-height (blank line shown).
- **`%` letter/word-spacing** — not supported (ignored).
- **Mixed direction + atomic inline ordering** — atoms are neutral, kept in
  logical slots (no full L1/bidi for replaced elements).

## 8. Test plan

Unit + pipeline tests; deterministic via `vendored_only()` font DB / literal
unicode. **No pixel-exact goldens** (font-brittle) — assert relative facts.

### 8.1 `style` — parsing & inheritance
- `direction:rtl` → `Direction::Rtl`; child inherits.
- `unicode-bidi:bidi-override` → `BidiOverride`; **not** inherited (child stays
  `Normal`).
- `letter-spacing:5px` → `5.0`; `letter-spacing:normal` → `0.0`; `2em` (16px
  font) → `32.0`; inherited.
- `word-spacing:3px` → `3.0`; inherited.
- `text-transform:uppercase|lowercase|capitalize|none` → right enum; inherited.
- `white-space:pre|nowrap|pre-wrap|pre-line|normal` → right enum; inherited.

### 8.2 `boxtree` — white-space + text-transform at collection
- `white-space:pre` text `"a\n b"` → stored TextRun string keeps `\n` and the
  leading space (assert `text.contains('\n')` and `" b"`).
- `white-space:normal` `"a\n b"` → `"a b"` (collapsed, no `\n`).
- `white-space:pre-line` `"a   \n  b"` → `"a\nb"` (spaces collapsed, `\n` kept).
- `text-transform:uppercase` `"héllo"` → `"HÉLLO"` (Unicode); `capitalize`
  `"two words"` → `"Two Words"`; `lowercase` `"ABC"` → `"abc"`.
- ws-only text node between blocks: dropped under `normal`, **kept** under `pre`.

### 8.3 `inline` — wrapping matrix
- `nowrap`: a long string that would wrap under `normal` → **one** LineBox (assert
  `LineBox` count == 1; width may exceed avail).
- `pre`: `"a\nb"` → **two** LineBoxes; no soft wrap even when long.
- `pre-wrap`: a long preserved string with spaces → multiple LineBoxes **and**
  preserved leading spaces (first fragment x reflects the kept spaces).
- `pre-line`: `"a   \n   b longlong..."` → `\n` makes ≥2 lines and the long part
  still soft-wraps.

### 8.4 letter/word-spacing — measure == paint
- `letter-spacing:5px` on `"abc"` (3 chars): measured width ==
  `base("abc") + 3*5`; and the painted pen advance (sum of `g.advance +
  letter_spacing`) equals the measured width.
- `word-spacing:10px` on `"a b"`: measured width == `base("a b") + 1*10`
  (+letter-spacing terms if also set).
- Consistency test (like E6-M1 §9.3): for `FontMeasurer`, assert
  `advance_width(text,&q)` == Σ `draw_glyph_run` pen increments for `q` with
  non-zero letter/word-spacing.

### 8.5 text-transform end-to-end
- `text-transform:uppercase` on `<p>hi</p>` → the `GlyphRun.text == "HI"`
  (transform baked in; measure used the same string).

### 8.6 bidi / RTL
- **direction:rtl renders from the right**: a single LTR word in a `direction:rtl`
  block → its fragment's visual `x` is at the **right** edge (assert the
  fragment's content.x is near `container.right - width`, via the RTL text-align
  remap).
- **Hebrew reorders**: a literal Hebrew string `"אבג"` (RTL) in an LTR block →
  the line's single run is RTL; the stored fragment text is reversed to visual
  order (assert the GlyphRun text == reversed code points) and the visual order
  reads right-to-left. (Assert via the visual run levels: `runs.len()==1 &&
  levels rtl`.)
- **mixed**: `"abc אבג 123"` with base LTR → `visual_runs` yields LTR("abc ")
  then the Hebrew run (reversed) then LTR(" 123"); assert the visual fragment
  order places `abc` left, Hebrew middle (reversed), `123` right. (Assert run
  count/levels rather than exact px.)
- **bidi-override**: `direction:rtl; unicode-bidi:bidi-override` on `"abc"` →
  whole line reversed (visual text == `"cba"`).
- **measure == paint for bidi**: the reversed fragment's measured width equals
  the painted width (reversal is order-independent).
