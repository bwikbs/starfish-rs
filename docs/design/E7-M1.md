# E7-M1 — CSS selector expansion (design note)

Scope: extend the **shared** selector subset (currently tag / id / class /
compound / descendant / child) with **attribute selectors**, **structural
pseudo-classes**, and the **sibling combinators** `+` / `~`, wired into BOTH
consumers of the parsed selector model:

- the cascade matcher — `crates/style/src/matching.rs`
- `querySelector` — `crates/js/src/dom/select.rs`

The two matchers must stay at **byte-for-byte parity**. §6 picks the
least-duplication way to guarantee that.

Pinned to the **real** current API (verified against the source, June 2026):

- `starfish_css::{Selector, SelectorPart, Compound, Combinator, Specificity}`
  with `Compound { tag: Option<String>, universal: bool, ids: Vec<String>,
  classes: Vec<String> }` and `Combinator::{Descendant, Child}`.
- The selector parser (`crates/css/src/parser.rs`) currently parses the prelude
  in `parse_complex_selector`, handling `Whitespace / Ident / Hash / Delim('*')
  / Delim('>') / Delim('.')+Ident` and `invalidate()`-ing on **anything else**
  (`:`, `[`, `+`, `~`, `Function`, …). Today an unsupported token drops the
  whole rule (cascade) / returns `null` (querySelector).
- The tokenizer (`crates/css/src/tokenizer.rs`) **already** emits every token we
  need: `LeftBracket`/`RightBracket`, `Colon`, `Function(name)` (an ident
  directly followed by `(`), `Str(String)`, `Ident`, `Hash`, `Number`, and
  `Delim('+'|'~'|'='|'^'|'$'|'*'|'|'|'-')`. **No tokenizer change is needed.**
- `parse_qualified_rule` already balances `[`…`]` and `Function(`…`)` while
  scanning the prelude for the rule's `{`, so `input[type=text]` and
  `li:nth-child(2)` preludes are already delimited correctly — only
  `parse_complex_selector` rejects their tokens. We replace that rejection with
  real parsing.
- `starfish_dom::Document` exposes `parent / first_child / next_sibling /
  prev_sibling / last_child / children / kind / tag_name / get_attribute`.
  Everything needed for sibling/index/empty/root is reachable; we add a few
  thin element-only helpers (§5) so both matchers share identical logic.

Guiding rule (project "Simplicity First"): add exactly the listed selectors.
Defer `:is`/`:where`/`:has`/`:nth-last-child`, pseudo-elements (E7-M2),
attribute namespaces, and `:not()` argument lists. See §7.

## 1. Selector model extension (`crates/css/src/selector.rs`)

`Compound` grows two vectors. Tag/universal/ids/classes are unchanged so the M3
matcher and all existing tests keep working; attrs/pseudos default to empty.

```rust
#[derive(Debug)]
pub struct Compound {
    pub tag: Option<String>,
    pub universal: bool,
    pub ids: Vec<String>,
    pub classes: Vec<String>,
    pub attrs: Vec<AttrSelector>,     // NEW
    pub pseudos: Vec<PseudoClass>,    // NEW
}

/// `[name op value flag]`. `value` is `None` only for `Exists` (`[name]`).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct AttrSelector {
    pub name: String,                 // lowercased (HTML attrs are ASCII-CI; §7)
    pub op: AttrOp,
    pub value: Option<String>,        // raw value (NOT lowercased; flag governs)
    pub case_insensitive: bool,       // the trailing `i` flag
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AttrOp {
    Exists,     // [a]
    Equals,     // [a=v]
    Includes,   // [a~=v]  whitespace-separated word match
    DashMatch,  // [a|=v]  v or v-...
    Prefix,     // [a^=v]
    Suffix,     // [a$=v]
    Substring,  // [a*=v]
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PseudoClass {
    FirstChild,
    LastChild,
    OnlyChild,
    NthChild(Nth),       // :nth-child(An+B)
    NthOfType(Nth),      // :nth-of-type(An+B)
    Root,                // :root
    Empty,               // :empty
    Not(Box<Compound>),  // :not(<single simple/compound selector>)
    /// A recognized-but-never-matching pseudo: `:hover`, `:focus`, `:active`,
    /// and any unknown `:foo`. Parsed (so the rule survives) but `false` always.
    NeverMatch,
}

/// `An+B`, e.g. `2n+1` → {a:2, b:1}; `odd` → {a:2, b:1}; `even` → {a:2, b:0};
/// `3` → {a:0, b:3}; `-n+3` → {a:-1, b:3}. Signed because `a`/`b` may be < 0.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Nth { pub a: i32, pub b: i32 }
```

`Combinator` grows two variants:

```rust
#[derive(Debug, PartialEq, Eq)]
pub enum Combinator {
    Descendant,
    Child,
    NextSibling,        // `+`  (adjacent)
    SubsequentSibling,  // `~`  (general)
}
```

`Compound::new` initializes the two new vecs empty; `Compound::is_empty` is
extended to also require `attrs.is_empty() && pseudos.is_empty()` so a bare
`[a]` or `:first-child` compound is **not** treated as empty (it's a valid
subject, equivalent to `*[a]` / `*:first-child`).

### 1.1 Specificity contributions

Per CSS Selectors §16, computed at parse time in `Selector::from_parts`:

- attribute selector → `b += 1` (class-level), one per `AttrSelector`.
- pseudo-class → `b += 1` (class-level), one per `PseudoClass`, **except**:
  - `Not(inner)` adds **nothing for the `:not` itself**; instead it folds the
    **specificity of its argument** in: `spec += specificity_of_compound(inner)`
    (so `:not(.x)` → `b+=1`, `:not(div)` → `c+=1`, `:not(#id)` → `a+=1`).
  - `NeverMatch` (`:hover`, unknown) still counts as a normal pseudo-class →
    `b += 1` (matches real CSS; it just never matches an element).

`from_parts` therefore changes from the current
```rust
spec.b += c.classes.len() as u32;
```
to a helper `add_compound_specificity(&mut spec, c)` that sums tag/ids/classes
**plus** `attrs.len()`, the non-`Not` pseudos, and recursively the inner
compound of each `Not`. (Universal and combinators contribute nothing, as
today.) `Specificity` stays `{a,b,c}: u32` — `:not` arguments only ever add, so
no overflow/negative concerns.

## 2. Parsing (`crates/css/src/parser.rs` + `selector.rs` builder)

All parsing stays in `parse_complex_selector` / `SelectorBuilder`; the lenient,
no-panic contract is preserved. We **replace** the catch-all `_ => b.invalidate()`
arm with handlers for `[`, `:`, `+`, `~`, and tighten `+`/`~` so they only act as
combinators (the tokenizer already classifies `+N`/`-N` as numbers, so a bare
`+`/`~` delim here is unambiguously a combinator).

### 2.1 Combinators `+` / `~`

In the `parse_complex_selector` token loop, alongside the existing
`Delim('>') => push_combinator(Child)`:

```rust
Token::Delim('+') => b.push_combinator(Combinator::NextSibling),
Token::Delim('~') => b.push_combinator(Combinator::SubsequentSibling),
```

`SelectorBuilder::push_combinator` already merges a pending `Descendant`
(whitespace) when an explicit combinator follows; extend the same merge logic so
`+`/`~` (like `>`) **override** an adjacent pending `Descendant`, and two
explicit combinators in a row (`+ +`, `> ~`, …) → `invalidate()`. Concretely the
match arms generalize from the `Child`-specific ones to: "explicit overrides
pending Descendant; explicit-then-explicit is invalid." A trailing `+`/`~`
(nothing to its right) never materializes — same as the current `>` handling, so
`finish()` already drops `div +` as malformed.

### 2.2 Attribute selectors `[ … ]`

The prelude scanner already keeps the bracketed tokens together. In
`parse_complex_selector`, on `Token::LeftBracket`, hand the sub-slice
`(i_open+1 .. matching_close)` to a small `parse_attr(tokens) -> Option<AttrSelector>`
and advance `i` past the `]`. Grammar (whitespace-tolerant, per Selectors L3):

```
'[' S* <ident:name> S*
      ( ( '~=' | '|=' | '^=' | '$=' | '*=' | '=' ) S*
        ( <ident> | <string> ) S*
        ( ('i'|'I') S* )?                 // case-insensitive flag
      )?
']'
```

Token mapping (no multi-char operator token exists; operators are
`Delim(op)` **immediately** followed by `Delim('=')`, except `=` itself):

| Source | Tokens                                  | `AttrOp`   |
|--------|-----------------------------------------|------------|
| `a`    | `Ident("a")`                            | `Exists`   |
| `a=v`  | `Ident, Delim('='), <val>`              | `Equals`   |
| `a~=v` | `Ident, Delim('~'), Delim('='), <val>`  | `Includes` |
| `a\|=v`| `Ident, Delim('\|'), Delim('='), <val>` | `DashMatch`|
| `a^=v` | `Ident, Delim('^'), Delim('='), <val>`  | `Prefix`   |
| `a$=v` | `Ident, Delim('$'), Delim('='), <val>`  | `Suffix`   |
| `a*=v` | `Ident, Delim('*'), Delim('='), <val>`  | `Substring`|

- `<val>` is either a `Str(s)` (already unquoted/unescaped by the tokenizer) or
  an `Ident(s)` (unquoted value like `text`). A bare number/dimension value
  (`[tabindex=0]`) is **out of M1 scope** → the attr fails to parse → the whole
  selector invalidates (lenient: rule drops, page unaffected). Noted in §7.
- The trailing `i` flag: an `Ident("i")` (case-insensitively) after the value →
  `case_insensitive = true`. Anything else after the value, or a malformed
  operator, or an empty/missing name → `parse_attr` returns `None` →
  `b.invalidate()`.
- `name` is lowercased (HTML matching is ASCII-case-insensitive on attr names).
- `value` is stored verbatim (case preserved); the matcher lowercases at compare
  time only when `case_insensitive`.

`Exists` with no operator is the `[a]` form. `[a=]` (operator, empty value) →
`value = Some("")` (valid; matches the empty-string attribute).

### 2.3 Pseudo-classes `:name` and `:name( … )`

On `Token::Colon`, look at the next token:

- `Token::Ident(name)` → a bare pseudo-class. Match `name` (ASCII-CI):
  - `first-child` → `FirstChild`, `last-child` → `LastChild`,
    `only-child` → `OnlyChild`, `root` → `Root`, `empty` → `Empty`.
  - `hover` / `focus` / `active` / `link` / `visited` / **anything else** →
    `NeverMatch` (parsed, rule survives, never matches). Advance past the ident.
- `Token::Function(name)` (ident immediately followed by `(`) → a functional
  pseudo-class. The matching `)` is found the same way the attr/prelude scanner
  finds its delimiter (balanced). Match `name` (ASCII-CI):
  - `nth-child` → `NthChild(parse_nth(args)?)`
  - `nth-of-type` → `NthOfType(parse_nth(args)?)`
  - `not` → `Not(Box::new(parse_simple_compound(args)?))`
  - unknown functional pseudo (`:is(`, `:where(`, `:has(`, `:nth-last-child(`)
    → **invalidate** the selector (drop the rule). Rationale: unlike a bare
    unknown `:foo` (cheap to treat as never-match), a functional one carries a
    sub-selector we don't model; dropping the rule is the conservative,
    spec-defensible choice and keeps `Not(Box<Compound>)` the only nested case.
    (A second `Delim('::')`-style colon, i.e. a pseudo-**element** `::before`,
    also invalidates here — that's E7-M2.)
- `Token::Colon` after the first colon (`::`) → pseudo-element → invalidate
  (E7-M2).

#### `parse_nth(tokens) -> Option<Nth>`

Accept (whitespace-tolerant, ASCII-CI), returning `Nth { a, b }`:

| Input        | a   | b   |
|--------------|-----|-----|
| `odd`        | 2   | 1   |
| `even`       | 2   | 0   |
| `<int>`      | 0   | int |
| `n`          | 1   | 0   |
| `-n`         | -1  | 0   |
| `<a>n`       | a   | 0   |
| `n+<b>`      | 1   | b   |
| `n-<b>`      | 1   | -b  |
| `<a>n+<b>`   | a   | b   |
| `<a>n-<b>`   | a   | -b  |
| `-n+<b>`     | -1  | b   |

The tokenizer's number rules make this fiddly — note these realities and parse
on the token sequence, not by re-lexing a string:

- `2n` lexes as `Dimension { value: 2, unit: "n" }` (digit run + ident-start).
- `n` / `-n` lex as `Ident("n")` / `Ident("-n")`.
- `2n+1` → `Dimension{2,"n"}, Delim('+'), Number(1)` (the `+1` is a separate
  number only when not part of `2n`; here `+1` after `n` lexes as `Number(1)`
  because `is_number_start` sees `+`digit). `2n-1` → `Dimension{2,"n"},
  Number(-1)` (the `-1` lexes as a signed `Number`).
- `n+2` → `Ident("n"), Delim('+'), Number(2)`. `-n+2` → `Ident("-n"),
  Delim('+'), Number(2)`.
- a plain `3` → `Number(3.0)`; `odd`/`even`/`n` → `Ident`.

So `parse_nth` is a tiny hand-written matcher over ≤3 significant tokens
(skipping whitespace): recognize a leading `Ident("n"|"-n")` or
`Dimension{_, "n"}` or signed `Number`, then an optional `± <int>` tail.
Anything outside the table → `None` → the `:nth-child(…)` invalidates the
selector. Non-integer values (`2.5`) → `None`.

#### `parse_simple_compound(tokens) -> Option<Compound>` (for `:not`)

M1 restricts `:not()` to **one simple/compound selector, no combinators, no
nested `:not`, no comma list**. Reuse the *same* token-loop logic as
`parse_complex_selector` but feeding a fresh `Compound` directly (no
`SelectorBuilder` combinator machinery): accept `Ident`(tag) / `Hash`(id) /
`Delim('*')` / `.`+`Ident`(class) / `[…]`(attr) / a **bare** structural
pseudo (`:first-child`, etc.). Reject (return `None`) on any `Whitespace`,
`>`/`+`/`~`, `,`, nested `:not`, or `::`. Returns the built `Compound`
(reusing the §3 compound matcher unchanged for the inner test). Refactor the
existing compound-building arms into a shared `fn apply_simple(&mut Compound, …)`
so `parse_complex_selector` and `parse_simple_compound` can't diverge.

### 2.4 Leniency invariant

Every new path returns `Option`/calls `invalidate()` on malformed input; none
panic. A whole rule is dropped only when a selector is structurally
unparseable; a *recognized-but-non-matching* construct (`:hover`, unknown
`:foo`) is preserved as `NeverMatch` so e.g. `a:hover { color: red }` no longer
discards the stylesheet — it just contributes a rule that matches nothing. This
is the key behavior change from M2 (where `a:hover` dropped) and **updates the
existing tests** `sel_pseudo_invalid_drops_rule`, `sel_attr_invalid_drops_rule`,
`sel_one_bad_in_list_drops_whole_rule` (the first two now parse to a 1-rule
sheet whose selector is non-matching / a real attr selector; the third: `a,
b:hover` now yields a 2-selector rule where `b:hover` never matches).

## 3. Matcher extension (`crates/style/src/matching.rs`, mirrored — see §6)

### 3.1 `compound_matches`

After the existing tag/id/class checks, add (all AND-combined; short-circuit on
first failure):

```rust
// attributes
for a in &c.attrs {
    if !attr_matches(doc, element, a) { return false; }
}
// pseudo-classes
for p in &c.pseudos {
    if !pseudo_matches(doc, element, p) { return false; }
}
```

`attr_matches`:

```rust
fn attr_matches(doc: &Document, el: NodeId, a: &AttrSelector) -> bool {
    let Some(have) = doc.get_attribute(el, &a.name) else { return false }; // missing → only nothing matches; Exists needs presence
    let want = a.value.as_deref();
    match a.op {
        AttrOp::Exists => true,                       // attribute present
        AttrOp::Equals => eqv(have, want.unwrap(), a.case_insensitive),
        AttrOp::Prefix => { let w = want.unwrap(); !w.is_empty() && starts(have, w, ci) }
        AttrOp::Suffix => { let w = want.unwrap(); !w.is_empty() && ends(have, w, ci) }
        AttrOp::Substring => { let w = want.unwrap(); !w.is_empty() && contains(have, w, ci) }
        AttrOp::Includes => {  // ~= : whitespace-separated word equals w
            let w = want.unwrap();
            !w.is_empty() && !w.contains(char::is_whitespace)
                && have.split_ascii_whitespace().any(|t| eqv(t, w, ci))
        }
        AttrOp::DashMatch => {  // |= : equals w, or starts with "w-"
            let w = want.unwrap();
            eqv(have, w, ci) || starts(have, &format!("{w}-"), ci)
        }
    }
}
```

`eqv/starts/ends/contains` apply ASCII-lowercase to both sides when
`case_insensitive`, else compare as-is. Per spec, `^=`/`$=`/`*=` with an **empty**
value never match (the `!w.is_empty()` guards); `~=` with empty/whitespace-only
value never matches.

`pseudo_matches`:

```rust
fn pseudo_matches(doc, el, p) -> bool {
    match p {
        FirstChild  => element_index(doc, el) == 1,
        LastChild   => element_index_from_end(doc, el) == 1,
        OnlyChild   => element_sibling_count(doc, el) == 1,
        NthChild(nth)  => nth_matches(nth, element_index(doc, el)),
        NthOfType(nth) => nth_matches(nth, type_index(doc, el)),
        Root  => is_root_element(doc, el),
        Empty => is_empty_element(doc, el),
        Not(inner)  => !compound_matches(doc, el, inner),
        NeverMatch  => false,
    }
}
```

### 3.2 The `An+B` test

An element at **1-based** element-sibling index `i` (`i ≥ 1`) matches `Nth{a,b}`
iff `∃ n ≥ 0 : i = a·n + b`:

```rust
fn nth_matches(nth: Nth, i: i32) -> bool {
    let Nth { a, b } = nth;
    if a == 0 { return i == b; }            // fixed position
    let diff = i - b;                        // need diff = a·n, n ≥ 0
    diff % a == 0 && diff / a >= 0
}
```

(`diff % a == 0 && (diff / a) >= 0` — `diff/a ≥ 0` captures `n ≥ 0` for either
sign of `a`. E.g. `-n+3` (a=-1,b=3): i=1→diff=-2,/a=2 ✓; i=4→diff=1,/a=-1 ✗.)

### 3.3 Combinator traversal

Extend `match_from`'s `match comb { … }` (the right-to-left walk) with the two
sibling cases, alongside the existing `Child`/`Descendant`:

```rust
Combinator::NextSibling => prev_element_sibling(doc, node)
    .is_some_and(|s| match_from(doc, s, parts, left)),
Combinator::SubsequentSibling => {
    let mut s = prev_element_sibling(doc, node);
    while let Some(p) = s {
        if match_from(doc, p, parts, left) { return true; }
        s = prev_element_sibling(doc, p);
    }
    false
}
```

We match right-to-left, so `h1 + p` (subject `p`) checks the **previous**
element sibling for `h1`; `h1 ~ p` walks **all** previous element siblings. This
mirrors the existing Descendant/Child structure exactly (recursion = automatic
backtracking, which is needed for `~` just as for descendant).

The `Document::parent(node).filter(tag_name.is_some())` guard already used for
`Child` matters for `:root` (a root element's parent is the Document node, not
an element) — handled in `is_root_element`.

## 4. dom helpers (`crates/dom/src/lib.rs`)

`Document` already has `parent/first_child/next_sibling/prev_sibling/last_child/
children/kind/tag_name/get_attribute`. We add the minimal element-only helpers so
**both** matchers compute indices identically (no ad-hoc loops in each matcher).
Arena-consistent, no new state:

```rust
impl Document {
    /// Nearest previous sibling that is an Element (skips text/comment). `None`
    /// if none.
    pub fn prev_element_sibling(&self, id: NodeId) -> Option<NodeId>;

    /// Nearest following sibling that is an Element.
    pub fn next_element_sibling(&self, id: NodeId) -> Option<NodeId>;

    /// 1-based index of `id` among its **element** siblings (text/comment
    /// ignored). Element `id` itself is counted. Returns 1 for a first/only
    /// element child. (Caller guarantees `id` is an Element.)
    pub fn element_index(&self, id: NodeId) -> u32;

    /// 1-based index counting from the end (for `:last-child`/symmetry).
    pub fn element_index_from_end(&self, id: NodeId) -> u32;

    /// Total number of element children of `id`'s parent (for `:only-child`:
    /// true iff this == 1). 0 if no parent.
    pub fn element_sibling_count(&self, id: NodeId) -> u32;

    /// 1-based index of `id` among its **same-tag** element siblings (for
    /// `:nth-of-type`). (Caller guarantees `id` is an Element.)
    pub fn element_type_index(&self, id: NodeId) -> u32;

    /// `:empty` — `id` has no element children and no Text child containing a
    /// non-whitespace character. Comments are ignored (per spec, comments don't
    /// affect `:empty`). (Caller guarantees `id` is an Element.)
    pub fn is_empty_element(&self, id: NodeId) -> bool;

    /// `:root` — `id` is an Element whose parent is the Document node (i.e. the
    /// document element, `<html>`). True iff `parent`'s kind is `Document`.
    pub fn is_root_element(&self, id: NodeId) -> bool;
}
```

All are simple sibling-link walks over the existing `prev_sibling/next_sibling/
parent/first_child` fields + `tag_name`/`kind` filters; each is a few lines. They
live in dom (not the matcher) precisely so style and js can't compute indices
differently. Unit-tested in dom (mixed text+element children, comment-only
children for `:empty`, single child for `:only-child`, root detection).

`element_index` is `prev_element_sibling`-walk length + 1; `element_type_index`
the same but counting only same-`tag_name` predecessors; `is_empty_element`
iterates `children` checking `Element` ⇒ false, `Text(s)` with any
`!c.is_whitespace()` ⇒ false.

## 6. js / querySelector parity — chosen approach

### 6.1 The dependency graph (verified)

```
starfish-dom   (leaf)
starfish-css   → (no deps on dom)        ← owns the Selector model + parser
starfish-style → dom, css                ← owns the matcher today
starfish-js    → dom, css, net           ← owns a *ported copy* of the matcher
```

`css` does **not** depend on `dom`, so the matcher can't live in `css` without
adding a `css → dom` edge. The matcher is ~40 lines today and would roughly
double with attrs/pseudos/siblings + the `nth`/attr-op helpers — exactly the
kind of logic that silently diverges if copied. Three options:

- **(a)** Keep two copies, extend both, add a shared cross-test corpus. Rejected:
  the new logic (nth arithmetic, attr operator edge cases, `:not` recursion) is
  the *most* divergence-prone part; copy-paste parity is a maintenance trap.
- **(b)** Add a `css → dom` edge and move the matcher into `css`
  (`css::matching`). Clean re-use, but `css` was deliberately DOM-free ("pure
  data, no DOM coupling" — `selector.rs` line 1), and this drags `dom` into the
  parser crate.
- **(c) CHOSEN — `js` depends on `style`; the matcher lives once in
  `starfish-style` and is made `pub`.** `style` already depends on `dom`+`css`
  and already owns the matcher; we only flip the current "ported, not depended
  on" note. `js` adds one Cargo edge (`starfish-style = { workspace = true }`),
  deletes its 4 duplicated functions (`match_from`/`compound_matches`/
  `last_compound_index`/`combinator_at`/`compound_at`), and calls the single
  shared implementation.

This is the **least new coupling** (`js → style` is one edge; `style` is not a
heavy crate and pulls in nothing `js` doesn't already transitively get via
`css`+`dom`) and the **only** option with zero matcher duplication. There's no
cycle: `style` does not depend on `js`.

### 6.2 What `style` exposes

`crates/style/src/matching.rs` makes the entry point public and `lib.rs`
re-exports it:

```rust
// matching.rs
pub fn matches(doc: &Document, element: NodeId, selector: &Selector) -> bool
// lib.rs
pub use matching::matches;
```

`crates/js/src/dom/select.rs` shrinks to: keep `parse_selector_list` (the
`"{sel}{{}}"` throwaway-stylesheet trick, unchanged) and replace the whole ported
matcher with `starfish_style::matches(doc, el, sel)`. querySelector/All iterate
the document in tree order and return the first / all elements for which any
selector in the list matches — that traversal stays in `js`; only the per-element
predicate is now shared, so parity is **structural**, not test-enforced.

`js`'s `Cargo.toml`: add `starfish-style = { workspace = true }` under
`[dependencies]`.

(If a future milestone wants `js` to *not* link `style`, factor the matcher into
a new tiny `starfish-select` crate depending on `dom`+`css`; not needed for M1 —
"Simplicity First".)

## 7. Edge cases & non-goals

In scope, handled:

- `:hover` / `:focus` / `:active` / `:link` / `:visited` and any unknown bare
  `:foo` → parse as `NeverMatch` (rule survives, matches nothing). One-shot
  renderer has no live input, so this is correct, not a stub.
- Attribute **name** matching is ASCII-case-insensitive (HTML): names lowercased
  at parse time; `get_attribute` already stores/looks up lowercased names.
- `[a=v i]` case-insensitive **value** flag → both sides ASCII-lowercased at
  compare.
- `^=`/`$=`/`*=` with empty value, `~=` with whitespace/empty value → never
  match (spec).
- `:empty` ignores comments; whitespace-only text still counts as empty.
- `:root` = the document element (parent is the Document node).
- `:nth-child` with negative `a` (`-n+3` = "first three") handled by the
  `diff/a ≥ 0` test.

Out of scope (deferred / documented limitations):

- `:is()` / `:where()` / `:has()` / `:nth-last-child()` / `:nth-last-of-type()`
  → functional unknown pseudo ⇒ **rule dropped** (conservative; §2.3).
- `:not()` takes **one** simple/compound selector only — no combinators, no
  comma list, no nested `:not` (Selectors L4 allows lists; M1 doesn't).
- Pseudo-**elements** (`::before`/`::after`/`::first-line`) → invalidate here;
  they're **E7-M2**.
- Attribute **namespaces** (`[ns|attr]`) ignored — `|` is only the `|=`
  dash-match operator in M1; a namespace-prefixed attr name → parse failure →
  rule drops.
- Non-string/ident attribute values (`[tabindex=0]`, numbers/dimensions) → out;
  selector invalidates. (Quote them to match in M1.)
- `:not` specificity uses its argument's specificity; `:nth-*` and attr selectors
  are class-level `(0,1,0)`; pseudo-elements would be type-level — N/A in M1.

### 8.5 VISUAL (the milestone "done-when")

A small page styling a list with `:nth-child(even)` striping plus an
attribute-selected element, e.g.:

```html
<ul>
  <li>one</li><li>two</li><li>three</li><li>four</li>
</ul>
<input type="text" value="hi">
<style>
  li:nth-child(even) { background: #eee }
  li:first-child     { font-weight: bold }

```

Render via the normal pipeline (html → dom → style_tree → layout → paint) and
eyeball: alternating row backgrounds, bold first row, blue-bordered text input,
and (with an `h1`+`p`) the adjacent paragraph green. This is the visual proof
that the cascade matcher honors the new selectors end-to-end.
