# E5-M2 — CSS Grid alignment + named areas design note

Scope: extend the **E5-M1 grid core** with (1) box alignment within cells
(`justify-items`/`align-items` container defaults + `justify-self`/`align-self`
per-item), (2) track/content distribution (`justify-content`/`align-content`
incl. the `space-*` set), (3) named areas (`grid-template-areas` +
`grid-area`), and (4) the E5-M1 review fix: a fixed-row item with no free column
span must **advance** instead of overlapping at column 0. Touches
`starfish-style` (a few new `ComputedStyle` fields + parsing) and
`starfish-layout` (changes confined to `grid.rs`). **Paint needs no changes**
(items are still ordinary absolutely-positioned boxes).

Guiding rule (project CLAUDE.md "Simplicity First"): the **minimum correct**
value subset. We **reuse the flex `AlignItems`/`AlignSelf`/`JustifyContent`
enums** (mapping `FlexStart`↔`start`, `FlexEnd`↔`end`) rather than adding a
parallel grid enum, add the two `justify-*` fields flex lacked
(`justify_items`/`justify_self`) and the missing `align_content`. Named areas
parse into a `Vec<Vec<String>>` name grid. Defer baseline, safe/unsafe,
legacy values, subgrid, named lines, and alignment of the grid container itself
(§7).

This note is pinned to the **real** current APIs read from the source (E5-M1
landed). Verified shapes the design relies on:

- `starfish-style` (`computed.rs`): `ComputedStyle` is a plain public-field
  struct built by `ComputedStyle::initial()` and mutated by `apply_declaration`
  (the big `match decl.name.as_str()` in `properties.rs`). The flex enums
  already exist and are exported from `lib.rs`:
  `JustifyContent {FlexStart, FlexEnd, Center, SpaceBetween, SpaceAround,
  SpaceEvenly}`, `AlignItems {Stretch, FlexStart, FlexEnd, Center, Baseline}`,
  `AlignSelf {Auto, Stretch, FlexStart, FlexEnd, Center, Baseline}`. Grid props
  `grid_template_columns/-rows: Vec<TrackSize>`, `grid_column/grid_row:
  GridLine` exist. `align_items` and `align_self` fields **already exist** (flex
  M3) — grid reuses them. `justify_content` field already exists (flex). There
  is **no** `justify_items`, `justify_self`, or `align_content` field yet.
- `properties.rs` already has `align_items_of`, `align_self_of`,
  `justify_content_of` keyword parsers (they already accept `start`/`end` →
  `FlexStart`/`FlexEnd`, and `left`/`right` for justify-content). `placement_of`
  parses one grid-line side. `Component::Str(String)` carries a quoted string
  token; the css parser emits **one `Component::Str` per quoted string**, so
  `grid-template-areas: "a a" "b c"` arrives as `[Str("a a"), Str("b c")]`
  (verified: tokenizer `consume_string`, parser `classify_components` line 424).
- `starfish-layout` (`grid.rs`): `Tracks { sizes: Vec<f32>, offsets: Vec<f32>,
  gap: f32 }` with `build_offsets()`, `span_extent(start,end)`,
  `line_offset(i)`, `count()`. `PlacedItem { idx, col_start, col_end, row_start,
  row_end, style }`. `layout_grid(b, containing, self_style, styled, doc, m,
  images) -> f32`. `place_items(children, styled, self_style, cols) ->
  Vec<PlacedItem>`. `resolve_axis(line, n, clamp_to_n) -> Option<(usize,usize)>`,
  `axis_span(line) -> usize`. `size_columns`/`size_rows` return `Tracks`. The
  per-item layout loop in `layout_grid` (lines 137-175) currently **always
  stretches**: it lays the item out at `area_w`, then pins `content.width =
  area_w - hbpm`, `content.height = area_h - vbpm`, then `translate_box` to the
  area top-left. The **fixed-row branch** in `place_items` (lines 356-376)
  currently does `c = 0; break;` on no-room — the bug to fix (§5).
- `block.rs` dispatch (lines 42-49) already routes `Grid|InlineGrid` to
  `layout_grid`. **No dispatch change.** `boxtree.rs` `flexify_children` already
  covers `Grid|InlineGrid` (line 176). **No box-generation change.**
- `starfish-paint`: items are ordinary boxes with absolute coords. **No change.**

All M2 layout changes are inside `grid.rs`; the only `block.rs`/`boxtree.rs`
touch is none. Style changes are additive fields + parser arms.

## 1. Style additions (`starfish-style`)

### 1.1 Reuse vs new fields (`computed.rs`)

**Decision: reuse the flex enums, do not add a grid `GridAlign` enum.** Grid's
value set is `start | end | center | stretch` for items, plus the `space-*` set
for content distribution. The flex `AlignItems`/`AlignSelf` already model
`Stretch/FlexStart/FlexEnd/Center` (`FlexStart` == grid `start`, `FlexEnd` ==
grid `end`); `JustifyContent` models the `space-*` set. Reuse them with that
mapping. This avoids a parallel enum and lets the existing keyword parsers be
reused almost verbatim.

`ComputedStyle` field set after this milestone (the **bold** four are NEW; the
rest already exist and are reused):

| Field | Type | Used by | Status |
|-------|------|---------|--------|
| `align_items` | `AlignItems` | flex + **grid container default (block axis)** | exists (reuse) |
| `align_self` | `AlignSelf` | flex + **grid item (block axis)** | exists (reuse) |
| `justify_content` | `JustifyContent` | flex + **grid column-track distribution** | exists (reuse) |
| **`justify_items`** | `AlignItems` | **grid container default (inline axis)** | NEW |
| **`justify_self`** | `AlignSelf` | **grid item (inline axis)** | NEW |
| **`align_content`** | `JustifyContent` | **grid row-track distribution** | NEW |
| **`grid_template_areas`** | `Vec<Vec<String>>` | **named areas (rows of cell names)** | NEW |

> `justify_items`/`justify_self` reuse the **`AlignItems`/`AlignSelf`** types
> (same value subset start/end/center/stretch + Auto for self). `align_content`
> reuses **`JustifyContent`** (the `space-*` set). No new enum types.

`grid-area` does **not** get a dedicated field. CSS `grid-area` is a shorthand:
either a single `<custom-ident>` (a named-area reference) **or** the 4-line form
`row-start / col-start / row-end / col-end`. We model it as:

- The **4-line form** writes straight into the existing `grid_row` and
  `grid_column` `GridLine` fields (no new storage). `grid-area: 1 / 2 / 3 / 4` ≡
  `grid-row: 1 / 3; grid-column: 2 / 4`.
- The **named form** (`grid-area: header`) needs the name available at layout
  time. We add **one** field:

```rust
    // grid item named-area placement (E5-M2). Empty = none. Lowercased ident.
    pub grid_area_name: Option<String>,
```

(Total NEW fields: `justify_items`, `justify_self`, `align_content`,
`grid_template_areas`, `grid_area_name` — five.)

Full additions to the struct, in a new "grid alignment + areas (E5-M2)" section
after the existing grid item block:

```rust
    // grid alignment (E5-M2) — reuse the flex enums.
    pub justify_items: AlignItems,   // inline-axis default; grid initial Stretch
    pub justify_self: AlignSelf,     // inline-axis per-item; Auto → justify_items
    pub align_content: JustifyContent, // row-track distribution; initial FlexStart(=start)

    // grid named areas (E5-M2)
    pub grid_template_areas: Vec<Vec<String>>, // rows of cell names; "." = empty cell
    pub grid_area_name: Option<String>,        // grid-area: <name> (else None)
```

### 1.2 Initial values (`ComputedStyle::initial()`)

Per CSS, the grid `justify-items`/`align-items` initial is **`normal`**, which
for grid items behaves as **`stretch`** — matching the E5-M1 "always stretch"
default, so default behavior is unchanged. `align_items` already initializes to
`AlignItems::Stretch` (flex initial) — reuse. Add:

```rust
    justify_items: AlignItems::Stretch,
    justify_self: AlignSelf::Auto,
    align_content: JustifyContent::FlexStart, // = grid `start` (no distribution)
    grid_template_areas: Vec::new(),
    grid_area_name: None,
```

> Note: `justify_content` already initializes to `JustifyContent::FlexStart`
> (flex), which grid reads as `start` — no distribution by default. No change to
> its initial.

### 1.3 Inheritance (`inherit_from`)

**None of these inherit** (CSS: all are non-inherited). `inherit_from` is
**unchanged** — children start from `initial()`. Explicitly noted so the impl
agent adds no copies. (`Vec<Vec<String>>` and `Option<String>` are fine for the
derived `Clone`/`PartialEq` on `ComputedStyle`.)

### 1.4 Property parsing (`properties.rs`)

The flex keyword parsers already accept the grid keyword spellings
(`start`/`end` map to `FlexStart`/`FlexEnd`). For the new container/item axes we
**reuse** `align_items_of` and `align_self_of`, and add three small additions to
the big `match`:

```rust
        "justify-items" => {
            if let Some(a) = align_items_of(comps) { style.justify_items = a; }
        }
        "justify-self" => {
            if let Some(a) = align_self_of(comps) { style.justify_self = a; }
        }
        "align-content" => {
            if let Some(j) = justify_content_of(comps) { style.align_content = j; }
        }
        "grid-template-areas" => {
            if let Some(a) = grid_template_areas_of(comps) {
                style.grid_template_areas = a;
            }
        }
        "grid-area" => apply_grid_area(style, comps),
```

> `align-content` reuses `justify_content_of`, which already maps
> `start/flex-start` → `FlexStart`, `end/flex-end` → `FlexEnd`, plus `center`
> and the three `space-*`. For grid these read as start/end/center/space-*.
> `justify-items`/`justify-self` reuse `align_items_of`/`align_self_of`, which
> map `start`→`FlexStart`, `end`→`FlexEnd`, plus `center`/`stretch` (and `auto`
> for self). `left`/`right` for justify-items/self → not in `align_items_of`
> today; **add `"left" => FlexStart` and `"right" => FlexEnd`** arms to
> `align_items_of`/`align_self_of` (these are harmless for flex's `align-items`,
> which never sees left/right, and give grid the spec's left→start / right→end
> mapping). One-line additions; noted so the impl doesn't fork the parser.

**`grid-template-areas` parsing.** Each row is a quoted string of
whitespace-separated cell names; `.` (one or more dots) means an empty cell.
Each quoted string arrives as a separate `Component::Str`. We split each string
on whitespace into a `Vec<String>` of (lowercased) names, with `.`-runs
normalized to a single `"."`. Rectangularity is validated **leniently**: rows of
differing lengths are kept as-is (the layout name lookup tolerates ragged grids
— §4). `none` → empty.

```rust
/// Parse `grid-template-areas`: a list of quoted row strings → a 2D name grid.
/// `none` or no string components → `Some(Vec::new())` (clears the grid).
/// Each name lowercased; a run of `.` becomes the empty marker `"."`.
fn grid_template_areas_of(comps: &[Component]) -> Option<Vec<Vec<String>>> {
    if let [Component::Keyword(k)] = comps {
        if k.eq_ignore_ascii_case("none") {
            return Some(Vec::new());
        }
    }
    let mut rows: Vec<Vec<String>> = Vec::new();
    for c in comps {
        if let Component::Str(s) = c {
            let row: Vec<String> = s
                .split_ascii_whitespace()
                .map(|tok| {
                    if tok.chars().all(|ch| ch == '.') {
                        ".".to_string()
                    } else {
                        tok.to_ascii_lowercase()
                    }
                })
                .collect();
            rows.push(row);
        }
    }
    if rows.is_empty() {
        return None; // no recognizable rows → leave the declaration's effect off
    }
    Some(rows)
}
```

**`grid-area` parsing.** `grid-area` is one of two forms:

1. A single `<custom-ident>` keyword (not `auto`, not `span`) → a named-area
   reference. Store in `grid_area_name` (lowercased). Also **clear**
   `grid_row`/`grid_column` to `AUTO` is **not** needed (named area resolution
   wins over them at placement, §4); but per CSS the named form also sets the
   four longhands to the named lines — we don't model named lines (deferred), so
   we leave `grid_row`/`grid_column` as `AUTO` and rely on `grid_area_name`.
2. The 4-value `/`-separated line form: `row-start / col-start / row-end /
   col-end`. Each side is parsed by the existing `placement_of`. Maps to
   `grid_row = {row-start, row-end}`, `grid_column = {col-start, col-end}`.
   (CSS omitted-trailing-value rules: with 1 line value it's the row-start and
   everything else auto; with 2 it's row-start/col-start; with 3 add row-end.
   We handle the common 4-value case fully and degrade omitted sides to `Auto`.)

```rust
/// `grid-area` shorthand. Either `<name>` (a named-area ref → `grid_area_name`)
/// or `r-start / c-start / r-end / c-end` (→ grid_row + grid_column). A bare
/// single ident that is not `auto`/`span` is treated as the name form.
fn apply_grid_area(style: &mut ComputedStyle, comps: &[Component]) {
    let has_slash = comps.iter().any(|c| matches!(c, Component::Raw(s) if s == "/"));
    if !has_slash {
        // Name form: a single non-auto/non-span ident.
        if let [Component::Keyword(k)] = comps {
            let lk = k.to_ascii_lowercase();
            if lk != "auto" && lk != "span" {
                style.grid_area_name = Some(lk);
                return;
            }
        }
        return; // unrecognized → ignore (lenient)
    }
    // 4-line form: split on `/` into up to four sides.
    let mut sides = comps.split(|c| matches!(c, Component::Raw(s) if s == "/"));
    let rs = placement_of(sides.next().unwrap_or(&[]));
    let cs = placement_of(sides.next().unwrap_or(&[]));
    let re = placement_of(sides.next().unwrap_or(&[]));
    let ce = placement_of(sides.next().unwrap_or(&[]));
    style.grid_row = GridLine { start: rs, end: re };
    style.grid_column = GridLine { start: cs, end: ce };
    style.grid_area_name = None; // line form wins; clear any prior name
}
```

Export from `lib.rs`: no new types to export (reusing `AlignItems`/`AlignSelf`/
`JustifyContent`, already exported). The new struct fields are public; the
new `Vec<Vec<String>>`/`Option<String>` types need no export.

## 2. Content distribution (`justify-content` / `align-content`) — `grid.rs`

After `size_columns`/`size_rows` compute the track `sizes`, the tracks may not
fill the container. Content distribution distributes the **extra** space by
shifting track offsets. `justify-content` distributes along the **inline axis**
(column track x offsets); `align-content` along the **block axis** (row track y
offsets).

This is applied **inside `Tracks::build_offsets`'s caller**, by a new function
that rebuilds `offsets` with a leading offset + extra between-track spacing —
exactly mirroring flex's `justify_offsets` math (`flex.rs` `justify_offsets`).

### 2.1 The distribution math

Given a `Tracks` (sizes + gap) and a definite **container extent** along that
axis (`content_w` for columns; the explicit container height for rows, **only
when definite**), compute:

```text
n          = tracks.count()
used       = sum(sizes) + gap * (n - 1)        // tracks + interior gaps
extra      = container_extent - used           // free space (clamped >= 0)
```

If `extra <= 0` or `n == 0` → no distribution (default start; offsets as E5-M1).
Else distribute per the keyword into a **leading offset `lead`** and an
**extra between-track gap `between`** (added on top of the existing `gap`):

```text
start        (FlexStart)   : lead = 0;              between = 0
end          (FlexEnd)     : lead = extra;          between = 0
center       (Center)      : lead = extra / 2;      between = 0
space-between(SpaceBetween): lead = 0;              between = extra / (n - 1)   (n>1 else lead handling)
space-around (SpaceAround) : between = extra / n;   lead = between / 2
space-evenly (SpaceEvenly) : between = extra/(n+1); lead = between
stretch                    : treated as start for M2 (no auto-track growth, §7)
```

This is **identical** to flex's `justify_offsets(justify, leftover, n)`
(`flex.rs` lines 560-582) — reuse a shared helper. Edge case: `space-between`
with `n == 1` → `lead = 0`, `between = 0` (one track, no distribution); same as
flex.

### 2.2 Modifying track offsets

`Tracks::build_offsets` currently builds `offsets[0]=0; offsets[i+1] =
offsets[i] + sizes[i] + (i+1<n ? gap : 0)`. We add a variant that folds the
distribution:

```rust
impl Tracks {
    /// Build line offsets, distributing `extra` content space per `dist` into a
    /// leading offset + between-track spacing. `extra <= 0` ⇒ plain start.
    fn build_offsets_distributed(&mut self, dist: JustifyContent, extra: f32) {
        let n = self.sizes.len();
        self.offsets = Vec::with_capacity(n + 1);
        if n == 0 {
            self.offsets.push(0.0);
            return;
        }
        let (lead, between) = content_offsets(dist, extra.max(0.0), n);
        let mut off = lead;
        self.offsets.push(off);
        for (i, sz) in self.sizes.iter().enumerate() {
            off += sz;
            if i + 1 < n {
                off += self.gap + between;
            }
            self.offsets.push(off);
        }
    }
}

/// Shared with flex's justify math: (leading offset, extra between-track gap).
fn content_offsets(dist: JustifyContent, extra: f32, n: usize) -> (f32, f32) {
    let nf = n as f32;
    match dist {
        JustifyContent::FlexStart => (0.0, 0.0),
        JustifyContent::FlexEnd => (extra, 0.0),
        JustifyContent::Center => (extra / 2.0, 0.0),
        JustifyContent::SpaceBetween => {
            if n > 1 { (0.0, extra / (nf - 1.0)) } else { (0.0, 0.0) }
        }
        JustifyContent::SpaceAround => {
            let b = extra / nf;
            (b / 2.0, b)
        }
        JustifyContent::SpaceEvenly => {
            let b = extra / (nf + 1.0);
            (b, b)
        }
    }
}
```

> `span_extent(start, end)` is unaffected: it sums `sizes` + interior `gap`
> (the per-track sizes don't change, only their offsets). An item spanning
> multiple tracks where `between > 0` got inserted between them would have a
> slightly larger visual extent than `span_extent` reports, but for M2 we keep
> `span_extent` as-is (the item is positioned by `line_offset(start)` and sized
> by `span_extent`, so a multi-track item under `space-*` is positioned at its
> start line and sized to the un-distributed extent — acceptable, noted §7).

### 2.3 Where it hooks into `layout_grid`

In `size_columns`, after `sizes` are computed but before `build_offsets`,
compute `used` and `extra = (container_w - used)` and call
`build_offsets_distributed(self_style.justify_content, extra)` instead of
`build_offsets`. **But only when there is leftover space** — i.e. there are no
`fr` tracks consuming all free space. With `fr` tracks present, `extra` is ~0
(fr already ate the remainder), so distribution is a no-op naturally. (No
special guard needed; `extra.max(0.0)` handles it.)

For `size_rows`: distribution applies along the row axis using `align_content`,
but **only when the container height is definite** (`explicit_h.is_some()`) —
with an indefinite (auto) height the rows exactly fill the content (height = sum
of rows), so `extra == 0` and there is nothing to distribute. So:

```rust
// columns: after sizes computed
let used = sizes.iter().sum::<f32>() + gap * (cols.saturating_sub(1) as f32);
let extra = container_w - used;
let mut t = Tracks { sizes, offsets: Vec::new(), gap };
t.build_offsets_distributed(self_style.justify_content, extra);

// rows: after sizes computed
let used = sizes.iter().sum::<f32>() + gap * (rows.saturating_sub(1) as f32);
let extra = explicit_h.map(|h| h - used).unwrap_or(0.0);
let mut t = Tracks { sizes, offsets: Vec::new(), gap };
t.build_offsets_distributed(self_style.align_content, extra);
```

`build_offsets` (the plain version) can stay for callers that pass no
distribution, or be expressed as `build_offsets_distributed(FlexStart, 0.0)`.
**Recommendation:** keep `build_offsets` and add the distributed variant; the
empty-template single-column path and the `rows==0` early return keep calling
`build_offsets` (no distribution needed there).

`size_columns` and `size_rows` need access to `self_style.justify_content` /
`self_style.align_content`. `self_style` is already a parameter of both — no
signature change.

## 3. Item alignment within cell (`justify-self` / `align-self` → items) — `grid.rs`

E5-M1's per-item loop (lines 137-175) **always stretches** the item to fill its
area. M2 replaces the unconditional pin with axis-resolved alignment:

- **inline axis** (horizontal) ← `justify-self` (Auto → container
  `justify-items`).
- **block axis** (vertical) ← `align-self` (Auto → container `align-items`).

Each axis independently does one of: `stretch` (E5-M1 behavior — fill the area
minus bpm/margins), `start` (top/left of the area at the item's content size),
`end` (bottom/right), `center` (centered).

### 3.1 Resolving the effective alignment per item

```rust
/// Resolve an item's effective inline/block alignment, folding Auto → container
/// default. Returns (justify = inline axis, align = block axis) as `AlignItems`.
fn item_alignment(item_style: &ComputedStyle, container: &ComputedStyle)
    -> (AlignItems, AlignItems)
{
    let resolve = |sf: AlignSelf, def: AlignItems| match sf {
        AlignSelf::Auto => def,
        AlignSelf::Stretch => AlignItems::Stretch,
        AlignSelf::FlexStart => AlignItems::FlexStart,
        AlignSelf::FlexEnd => AlignItems::FlexEnd,
        AlignSelf::Center => AlignItems::Center,
        AlignSelf::Baseline => AlignItems::FlexStart, // baseline → start (M2, §7)
    };
    let justify = resolve(item_style.justify_self, container.justify_items);
    let align = resolve(item_style.align_self, container.align_items);
    (justify, align)
}
```

(`item_style` is `p.style` — already cloned into each `PlacedItem`. `container`
is `self_style`.)

### 3.2 Getting the non-stretched item size

When an axis is **not** `stretch`, the item is sized to its **content size**
(not the area), then placed within the area. We reuse E5-M1's existing
measurement helpers:

- **Inline (width) non-stretch size**: `measure_item_width(item, area_w, …)` —
  already in `grid.rs` (returns the item's explicit width, or its pragmatic
  max-content width laid out at `area_w`). Clamp to `area_w` (don't exceed the
  cell content box: `min(measured, area_w - hbpm)`; overflow precision is M2 §7
  — we clamp).
- **Block (height) non-stretch size**: `measure_item_height(item, used_w, …)` —
  already in `grid.rs` (lays the item out at a given width, returns content
  height). The width passed is the item's **used inline content width** (the
  stretched area width if justify==stretch, else the measured width). Clamp to
  `area_h - vbpm`.

So the per-item flow becomes: resolve the inline width first (stretch → area
fill; else measured), lay the item out at that width to get its natural height,
then resolve the block height (stretch → area fill; else the laid-out height),
then position within the area per the two offsets.

### 3.3 The rewritten per-item loop

Replace lines 145-174 of `layout_grid` with:

```rust
let item = &mut children[p.idx];
let s = &p.style;
let (justify, align) = item_alignment(s, self_style);

// Margins (resolved against the area width, auto → 0), and bpm per axis.
let ml = resolve_or_zero(s.margin_left, area_w);
let mr = resolve_or_zero(s.margin_right, area_w);
let mt = resolve_or_zero(s.margin_top, area_w);
let mb = resolve_or_zero(s.margin_bottom, area_w);

// Lay the item out once at the area width to populate border/padding + content.
let cb = Dimensions {
    content: Rect { x: abs_x, y: abs_y, width: area_w, height: 0.0 },
    ..Dimensions::default()
};
let mut floats = FloatContext::default();
layout_block(item, cb, styled, doc, m, images, &mut floats);
item.dimensions.margin.left = ml;
item.dimensions.margin.right = mr;
item.dimensions.margin.top = mt;
item.dimensions.margin.bottom = mb;

let hbpm = item.dimensions.border.left + item.dimensions.border.right
    + item.dimensions.padding.left + item.dimensions.padding.right + ml + mr;
let vbpm = item.dimensions.border.top + item.dimensions.border.bottom
    + item.dimensions.padding.top + item.dimensions.padding.bottom + mt + mb;

// --- Inline axis (width) ---
let content_w = if justify == AlignItems::Stretch {
    (area_w - hbpm).max(0.0)
} else {
    // Non-stretch: the item's intrinsic/explicit width, clamped to the cell.
    let intrinsic = measure_item_width(item, area_w, styled, doc, m, images);
    intrinsic.min((area_w - hbpm).max(0.0))
};
item.dimensions.content.width = content_w;

// --- Block axis (height): measure natural height at the chosen width ---
let natural_h = measure_item_height(item, content_w, styled, doc, m, images);
let content_h = if align == AlignItems::Stretch {
    (area_h - vbpm).max(0.0)
} else {
    natural_h.min((area_h - vbpm).max(0.0))
};
item.dimensions.content.height = content_h;

// --- Offsets within the area (outer/margin-box sizes) ---
let outer_w = content_w + hbpm;
let outer_h = content_h + vbpm;
let off_x = axis_offset(justify, area_w, outer_w);
let off_y = axis_offset(align, area_h, outer_h);

// Position the item's margin box at area top-left + offset.
let cur = item.dimensions.margin_box();
translate_box(item, (abs_x + off_x) - cur.x, (abs_y + off_y) - cur.y);
```

with the offset helper (mirrors flex `align_cross`, `flex.rs` line 585):

```rust
/// Position offset of an item of outer size `outer` within an `area` extent.
fn axis_offset(align: AlignItems, area: f32, outer: f32) -> f32 {
    let free = (area - outer).max(0.0);
    match align {
        AlignItems::Stretch | AlignItems::FlexStart => 0.0,
        AlignItems::FlexEnd => free,
        AlignItems::Center => free / 2.0,
        AlignItems::Baseline => 0.0, // → start (M2)
    }
}
```

> **Cost.** Stretch (the default) keeps essentially the E5-M1 cost (one
> `layout_block`, plus one cheap `measure_item_height` re-layout for the natural
> height — only needed when not stretching, so guard it: skip
> `measure_item_height` when `align == Stretch`). Optimization: compute
> `natural_h` lazily only when `align != Stretch`. The common all-stretch grid
> stays one layout pass per item (no regression on E5-M1 tests).

**Lazy `natural_h` guard** (to keep the default cheap):

```rust
let content_h = if align == AlignItems::Stretch {
    (area_h - vbpm).max(0.0)
} else {
    let natural_h = measure_item_height(item, content_w, styled, doc, m, images);
    natural_h.min((area_h - vbpm).max(0.0))
};
```

Likewise `measure_item_width` is only called when `justify != Stretch`.

## 4. Named areas (`grid-template-areas` + `grid-area`) — `grid.rs`

Named-area placement runs **before** the existing line-based resolution in
`place_items`, so an item with `grid-area: <name>` whose name exists in the
container's area grid gets a concrete `(col, row)` range from the area's
bounding rectangle.

### 4.1 The area grid

`self_style.grid_template_areas` is a `Vec<Vec<String>>` (rows of cell names,
`"."` = empty). The container's column count for areas is the **max row length**
(but E5-M1 already clamps columns to `grid_template_columns.len().max(1)`; for
M2 the **explicit column count** still governs track sizing). The area grid is
used only to look up name → rectangle; it does **not** change the track count
(if a name's columns exceed the explicit grid, the item's resolved columns are
clamped by the existing `clamp_to_n` path, §4.3).

### 4.2 Name → bounding rectangle

```rust
/// Find the bounding rectangle (0-based col/row ranges, end-exclusive) of a
/// named area in the area grid. `None` if the name is absent. Non-rectangular
/// occurrences are tolerated: we take the min/max row and column over all cells
/// bearing the name (the bounding box), which for a valid rectangular area is
/// exact and for a malformed one is a lenient superset (no panic).
fn named_area_rect(areas: &[Vec<String>], name: &str) -> Option<(usize, usize, usize, usize)> {
    let (mut r0, mut c0) = (usize::MAX, usize::MAX);
    let (mut r1, mut c1) = (0usize, 0usize);
    let mut found = false;
    for (r, row) in areas.iter().enumerate() {
        for (c, cell) in row.iter().enumerate() {
            if cell.eq_ignore_ascii_case(name) {
                found = true;
                r0 = r0.min(r);
                c0 = c0.min(c);
                r1 = r1.max(r + 1);
                c1 = c1.max(c + 1);
            }
        }
    }
    if found { Some((c0, c1, r0, r1)) } else { None }
}
```

Returns `(col_start, col_end, row_start, row_end)`.

### 4.3 Integration into `place_items`

In the per-child loop where pendings are collected, before resolving
`grid_column`/`grid_row` via `resolve_axis`, check for a named-area match:

```rust
let mut col = resolve_axis(cstyle.grid_column, n_cols_explicit, true);
let mut row = resolve_axis(cstyle.grid_row, n_rows_explicit, false);

// Named area wins (E5-M2). A name present + found in the area grid sets BOTH
// axes to the area rectangle (clamped to the explicit column count).
if let Some(name) = &cstyle.grid_area_name {
    if let Some((mut cs, mut ce, rs, re)) = named_area_rect(&self_style.grid_template_areas, name) {
        // clamp columns into the explicit grid (cols never grow implicitly).
        cs = cs.min(cols.saturating_sub(1));
        ce = ce.min(cols).max(cs + 1);
        col = Some((cs, ce));
        row = Some((rs, re));
    }
    // name absent / no areas → leave col/row as-is (auto-place, no panic).
}
```

The rest of `place_items` is unchanged: a named item now has both axes
`Some(..)`, so it is treated as **definitely placed** (pass 1) and marks its
cells occupied; auto items flow around it. A named item whose name is missing
falls through to whatever its `grid_column`/`grid_row` resolved to (usually
`AUTO` → auto-placement).

> **Named lines** (`<name>-start`/`<name>-end` implicit lines from the area
> grid) are **deferred** (§7). Only the `grid-area: <name>` whole-area
> reference is supported. `span <name>` is not supported (parser yields no name
> → auto). Noted.

> **Implicit rows from areas.** If the area grid has more rows than
> `grid_template_rows.len()`, a named item placed in those rows produces
> `row_end > grid_template_rows.len()`, and the existing implicit-row machinery
> (`implicit_rows = max(row_end)`, `size_rows` extends with `Auto`) sizes them.
> No change needed.

## 5. The fixed-row overlap fix — `grid.rs`

**The E5-M1 bug** (review RISK): in `place_items`, the *fixed-row, auto-column*
branch (lines 356-376) does, on no free column span:

```rust
            loop {
                if c + cspan > cols {
                    // No room: overflow at column 0 (clamp).
                    c = 0;
                    break;            // ← BUG: places at col 0, overlapping occupied cells
                }
                ...
                if fits { break; }
                c += 1;
            }
```

When the fixed row has no free `cspan`-wide column band, it falls off the right
edge (`c + cspan > cols`), then **resets to column 0 and places anyway**,
overlapping whatever already occupies columns `0..cspan` of that row.

**The fix.** Per CSS grid auto-placement, an item locked to a specific row whose
columns don't fit must **advance to the next row** (extending into implicit
rows) and retry there, rather than overlap. Because the row is *fixed*, "the
next row" means we keep the item's `rspan` but slide the **whole row band**
downward until a free column band exists. (CSS technically keeps the explicit
row for the *primary* axis; but a fixed-row item that can't fit is an
overlap-or-overflow situation — the least-surprising, non-overlapping behavior
is to advance the band. We adopt advance-the-band: deterministic, no overlap.)

Corrected branch:

```rust
        } else if let Some((frs, fre)) = p.row {
            // Fixed row, auto column: scan columns; if no band fits in this row
            // band, advance the band downward (into implicit rows) and retry —
            // never overlap (E5-M2 fix).
            let rspan = fre - frs;
            let mut rs = frs;
            let (mut cc, mut placed_ok) = (0usize, false);
            'bands: loop {
                let re = rs + rspan;
                ensure_row(&mut occupied, re.saturating_sub(1));
                let mut c = 0usize;
                while c + cspan <= cols {
                    let fits = (rs..re)
                        .all(|rr| (c..c + cspan).all(|col| cell_free(&occupied, rr, col)));
                    if fits {
                        cc = c;
                        placed_ok = true;
                        break 'bands;
                    }
                    c += 1;
                }
                // No free band in this row band → advance to the next row band.
                rs += 1;
                // Safety: bound the search so a fully-occupied/`cspan>cols` case
                // terminates. cspan was already clamped to cols by axis_span.
                if rs > occupied.len() + cols + 1 {
                    cc = 0; // pathological: cspan can't fit at all → col 0, top band
                    rs = frs;
                    break;
                }
            }
            let _ = placed_ok;
            cs = cc;
            ce = (cc + cspan).min(cols);
            rs_out = rs;          // (renamed for clarity; assign to rs/re below)
            re_out = rs + rspan;
        }
```

> **Note on the fixed-row semantics deviation.** Strictly, CSS does not move a
> fixed-row item off its row; it would create implicit columns or overlap is
> resolved by the cursor for the *other* axis. Since E5-M1 clamps columns (no
> implicit columns) and the item is genuinely larger than the row's free space,
> advancing the band is the simplest non-overlapping resolution and matches the
> milestone's "clamp/advance instead of overlap" directive. The common case
> (the row has room) is unchanged — `rs == frs` on the first iteration.
> `cspan > cols` is already clamped by `axis_span(...).min(cols)` upstream, so
> the inner `while c + cspan <= cols` always has at least the `c == 0` slot to
> test; the pathological break only triggers if that slot is permanently
> occupied across all advanced bands (it won't be, since advancing into fresh
> implicit rows always finds an empty band).

Keep the variable names consistent with the surrounding code (`cs/ce/rs/re` are
assigned at the bottom of each branch in the current source — the snippet above
uses `rs_out`/`re_out` only for exposition; in the real edit, assign the
branch's `cs, ce, rs, re` locals directly as the other branches do).

> Simplification accepted: because advancing into fresh implicit rows always
> finds an empty band, the loop terminates after at most a few iterations in
> practice; the explicit safety bound prevents any infinite loop on a
> contrived fully-occupied grid.

## 7. Edge cases & explicit non-goals

Handled:
- `justify-items`/`align-items` (container defaults) + `justify-self`/
  `align-self` (per-item): `start`/`end`/`center`/`stretch` (+ `left`→start,
  `right`→end for justify), with `self: auto` → the container default.
- `justify-content`/`align-content`: `start`/`end`/`center`/`stretch`(→start)/
  `space-between`/`space-around`/`space-evenly`, distributing extra space by
  shifting track offsets (inline = columns, block = rows-when-definite-height).
- `grid-template-areas` (quoted row strings → 2D name grid, `.` = empty,
  lenient ragged rows) + `grid-area: <name>` whole-area placement and the
  `grid-area: r/c/r/c` 4-line shorthand.
- The fixed-row overlap fix: a fixed-row item with no free column band advances
  the row band downward (into implicit rows) instead of overlapping at col 0.
- Default stretch (E5-M1 behavior) preserved when no alignment is specified —
  no regression.

Explicit **non-goals / simplifications** for M2:
- **`stretch` for content distribution** (`justify-content:stretch`/
  `align-content:stretch`) is treated as **start** (no auto-track growth). True
  stretch would grow `auto` tracks to fill; deferred. The common `fr`-based fill
  already covers most "fill the container" cases.
- **Baseline alignment** (`*-items: baseline`, `*-self: baseline`,
  `*-content: baseline`) → treated as **start** (cross-start). No real baseline
  participation (same simplification as flex M3).
- **safe/unsafe** alignment modifiers (`safe center`, `unsafe end`) → not
  parsed; the bare keyword is used (overflow is clamped to the cell anyway).
- **Legacy values** (`legacy left`/`right` for `justify-items`) → not supported;
  bare `left`/`right` map to start/end.
- **Named lines** (`<name>-start`/`<name>-end` implicit lines from the area
  grid; `span <name>`) → deferred. Only the whole-area `grid-area: <name>`
  reference is honored.
- **`grid-template` shorthand** (areas + rows + columns in one declaration) →
  not parsed; authors use `grid-template-areas` + `grid-template-columns/-rows`
  separately. (Cheap to add later; out of M2 scope.)
- **Subgrid, masonry** → out of scope.
- **Alignment of the grid container itself** within its parent (e.g. a grid that
  is a flex item, or `place-self` on the container) → that is the parent layout's
  job, unchanged.
- **`space-*` with a single track** → `lead = 0, between = 0` (no distribution),
  matching flex.
- **Multi-track item under `space-*` distribution**: the item is positioned at
  its start line's distributed offset and sized by the un-distributed
  `span_extent` (it does not absorb the inter-track inserted space). A minor
  visual simplification; noted.
- **Overflow when content > cell** (non-stretch item larger than its area): the
  item content size is **clamped to the cell** (`min(measured, area - bpm)`).
  Precise overflow (item overflowing its cell) is not modeled in M2.
- **`place-items`/`place-self`/`place-content` shorthands** → not parsed
  (authors use the longhands). Cheap to add; out of scope.
- **Paint** → unchanged: items remain absolutely-positioned boxes.
