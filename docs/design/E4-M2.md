# E4-M2 — DOM bindings: `document` / `Element` / `Node` host objects over the real arena (design note)

Scope (per `docs/ROADMAP-epic4.md` + the M2 brief): expose `document`, `Element`/`Node`
host objects to JS (Boa 0.21.1) **backed by the real `starfish-dom` arena**, so scripts can
read AND mutate the DOM; the post-script DOM is then styled / laid-out / painted. This is the
headline JS milestone — a script that creates/moves/edits nodes and sets inline styles changes
the rendered PNG.

This note is pinned to the **real** current source (signatures quoted from
`crates/{js,dom,css,style}` as read), and to the **exact Boa 0.21.1 API** verified against the
crate source in `~/.cargo/registry/.../boa_engine-0.21.1` (see §2.1 — `from_proto_and_data`,
`downcast_ref`, `JsData`/`Trace`, `ObjectInitializer::{function,accessor,property}`,
`FunctionObjectBuilder`). The companion ANALYSIS agent's findings are the authority for any Boa
call; where this note shows a call it shows the **exact** 0.21.1 shape.

Guiding rule (project CLAUDE.md "Simplicity First / Surgical Changes"): a **pragmatic subset**
of DOM. Defer `innerHTML` write, live NodeLists, MutationObserver, events (M3), CSSOM beyond
inline `style` set. Keep the arena invariants (parent/first/last/prev/next consistent). Add
arena mutation methods **minimally**. The cascade gains exactly **one** hook (inline `style`
attribute), nothing more. Deviations / non-goals are §9.

## 0. Inputs (the real APIs touched)

`starfish-dom` (`crates/dom/src/lib.rs`) — the arena we bind to:
- `struct Document { nodes: Vec<Node>, root: NodeId }`; `NodeId(u32)` is `Copy` and a plain
  `Vec` index. **`Document` is NOT `Clone` today** (it has `#[derive]`-less manual impls) — §1
  adds `#[derive(Clone)]` to `Document`, `Node`, `NodeKind`, `Element`, `Doctype` (all fields
  are `Clone`: `Vec<Node>`, `String`, `Option<NodeId>`, `Vec<Attr>`; `Attr` already derives
  `Clone`).
- Present read/create API: `root`, `node`/`node_mut`, `kind`, `parent`, `first_child`,
  `next_sibling`, `children(id)->Vec<NodeId>`, `tag_name(id)->Option<&str>`,
  `get_attribute(id,name)->Option<&str>`, `create_element/text/comment/doctype` (all return a
  **detached** node), `append_child(parent,child)` (`debug_assert!(child detached)`),
  `append_text`, `serialize`.
- **Missing for M2** (added in §4): `set_attribute`, `remove_attribute`, `last_child`,
  `prev_sibling`, `remove_child` / `detach`, `insert_before`, and (helper) reading text content.
  `append_child` today only pushes; it must reject (or detach) a non-detached child — §4.3.

`starfish-css` (`crates/css/src/{lib,selector,parser}.rs`):
- `parse_stylesheet(&str)->Stylesheet`. **Selectors are only parsed inside a stylesheet** —
  there is no public "parse a bare selector list" entry. The parser builds `Selector` via the
  private `SelectorBuilder`. `Selector`/`Compound`/`SelectorPart`/`Combinator`/`Specificity`
  are public (`pub use selector::{…}`). For `querySelector` we reuse the selector model by
  **parsing a throwaway stylesheet** `"<sel>{}"` and lifting out `rules[0].selectors` (§5.1) —
  no new css API, no parser surgery.

`starfish-style` (`crates/style/src/{lib,matching,cascade}.rs`):
- `style_tree(&Document, &[Stylesheet]) -> StyledTree`. **Borrows `&Document`; must stay
  byte-identical.**
- `matching::matches(doc, element, &Selector) -> bool` is `pub(crate)` (used by the cascade).
  It is the exact subset matcher we want for `querySelector` (tag/id/class/compound/descendant/
  child, right-to-left with backtracking). §5.2 decides: **do NOT add a `starfish-style` dep to
  `js`** (that pulls the whole style crate + would need `matches` made `pub`); instead **port a
  ~40-line tiny matcher into `js`** mirroring `matching.rs` exactly (same selector subset, same
  semantics). Rationale + tradeoff in §5.2.
- `cascade::cascade(...)` builds `Vec<MatchedDecl>` from UA+author sheets. §6 adds **one** step:
  after author/UA declarations, apply the element's inline `style=""` attribute as the
  highest-precedence normal declarations.

`starfish-js` (`crates/js/src/{lib,collect,console,globals}.rs`) — extended, not rewritten:
- `run_scripts(doc:&mut Document, base:&Url, loader:&dyn ResourceLoader) -> ScriptOutcome`. The
  M1 ownership seam (`mem::take` → `Rc<RefCell<Document>>` → `try_unwrap`) is **replaced** by a
  deep-copy/clone-out fallback (§1) because host objects now retain `Rc` clones.
- `globals::install(ctx, &shared, base)` currently installs a read-only `document` **stub** —
  §3 **replaces** the stub with the real `document` host object at the same seam.

`starfish-paint` (`crates/paint/src/lib.rs`): `render_document` already runs `run_scripts`
after `parse`, before `collect_author_sheets`/`style_tree` (M1 §5). M2 changes **nothing** in
paint's ordering — the post-script (cloned-out) `doc` feeds the rest unchanged (§7).

Boa 0.21.1 — exact API surface used (verified against crate source):
- `JsObject::from_proto_and_data(prototype, data) -> JsObject` — build a wrapper carrying
  native data with a chosen prototype. **No constructor / `new` needed** — DOM nodes are not
  JS-constructible; we mint wrappers directly. (`crates/.../boa_engine-0.21.1/src/object/jsobject.rs:164`.)
- `obj.downcast_ref::<T>() -> Option<&T>` / `downcast_mut::<T>()` on a borrowed object — get
  `this`'s native data. (`.../object/mod.rs:114,128`.)
- `trait NativeObject: Any + Trace + JsData` is **auto-implemented** for any `Any + Trace +
  JsData`. So `NodeHandle` derives/impls `Trace` (empty trace — holds an `Rc`, no `Gc`) +
  `Finalize` + `JsData`. (`.../object/mod.rs:66`, `.../object/datatypes.rs`.)
- `ObjectInitializer::{new(ctx), function(NativeFunction, key, len), property(key,val,attr),
  accessor(key, Option<JsFunction>, Option<JsFunction>, attr), build() -> JsObject}` — build
  prototypes with methods + getter/setter accessors. (`.../object/mod.rs:502,529,552,571,595`.)
- A getter/setter is a `JsFunction`, built from a `NativeFunction` via
  `FunctionObjectBuilder::new(ctx.realm(), native).build() -> JsFunction`. (`.../object/mod.rs:445`.)
- `NativeFunction::from_copy_closure_with_captures(closure, captures)` — already used in
  `console.rs`; the closure is `move |this:&JsValue, args:&[JsValue], cap:&C, ctx:&mut Context|
  -> JsResult<JsValue>`.
- Errors: `JsNativeError::typ()/range()...with_message(...).into()` → a `JsError` to return
  `Err(...)` (becomes a JS `TypeError`/etc., caught non-fatally by `run_scripts`).

## 1. Ownership change — replace `try_unwrap` with clone-out

**M1 today** (`lib.rs` step 5): `drop(ctx)` then `Rc::try_unwrap(shared)` and panic on failure.
That is sound only while **no GC object holds a clone of `shared`**. In M2 the `document` host
object (and every `Node`/`Element` wrapper, and the wrapper cache, §2.3) holds `Rc::clone(&shared)`
inside Boa's GC heap. `drop(ctx)` *should* drop all of them, but Boa's GC is **not guaranteed to
run finalizers synchronously on `drop`** — a cycle or a deferred sweep can leave a live `Rc`
clone, making `try_unwrap` fail → panic. The brief mandates the **robust** path: clone the arena
out regardless of leaked handles.

**Decision — clone-out, never `try_unwrap`:**

```rust
// after the eval loop, in run_scripts:
drop(ctx);                          // drop the Context → drops most/all GC handles
let recovered: Document = match Rc::try_unwrap(shared) {
    Ok(cell) => cell.into_inner(),          // fast path: sole owner, move out
    Err(rc)  => rc.borrow().clone(),        // robust path: deep-copy the arena out
};
*doc = recovered;
```

- `Document: Clone` is **added in §0/§4** (`#[derive(Clone)]` on `Document`+`Node`+`NodeKind`+
  `Element`+`Doctype`). All fields are `Clone` (`Vec<Node>`, `String`, `Option<NodeId>`,
  `Vec<Attr>`). The clone is a flat `Vec` copy — O(nodes), cheap for one-shot rendering, and
  `NodeId` values stay valid because the clone preserves indices 1:1.
- The fast path (`try_unwrap` Ok) is kept as an optimization; the `Err` arm is the guarantee.
  Either way `*doc` ends up with the **post-script arena** (all mutations included).
- The leaked `Rc<RefCell<Document>>` (if any) is harmless: it points at a now-orphaned cell that
  Boa's GC reclaims later; we keep our own clone. **No panic, ever.**
- Drop the M1 `debug_assert_eq!(Rc::strong_count, 1)` and the `expect`/`panic!`. Keep the
  `drop(ctx)` ordering (drop first so the fast path usually wins).

This is the **only** change to `run_scripts`'s body beyond passing `&shared` into the new DOM
installer (already passed for the M1 title probe). The public signature is unchanged.

### 1.1 `SharedDoc` newtype (Trace-able handle)

Host objects can't carry a bare `Rc<RefCell<Document>>` directly as native data because Boa's
`JsData`/`Trace` must be implemented for the data type. Mirror `console.rs`'s `ConsoleSink`:

```rust
// crates/js/src/dom/mod.rs
use std::cell::RefCell;
use std::rc::Rc;
use boa_engine::{Finalize, JsData, Trace};
use starfish_dom::{Document, NodeId};

pub(crate) type SharedDoc = Rc<RefCell<Document>>;

/// Native data carried by every DOM wrapper object: the shared arena + which node.
#[derive(Clone, Finalize, JsData)]
pub(crate) struct NodeHandle {
    pub doc: SharedDoc,
    pub id: NodeId,
}

// SAFETY: holds only an Rc + a u32 NodeId — no Boa `Gc` pointers — empty trace.
unsafe impl Trace for NodeHandle {
    boa_gc::empty_trace!();
}
```

`NodeId: Copy` and the `Rc` clone is cheap. `NodeHandle` is the downcast target on every method.

## 2. Node wrapper objects

### 2.1 How a JS object represents a DOM node

A DOM node is a Boa `JsObject` whose **native data is a `NodeHandle`** and whose **prototype**
is the shared `Node`/`Element` prototype carrying the methods. Built with:

```rust
JsObject::from_proto_and_data(Some(node_proto.clone()), NodeHandle { doc, id })
```

Every native method downcasts `this`:

```rust
fn this_handle(this: &JsValue) -> JsResult<NodeHandle> {
    this.as_object()
        .and_then(|o| o.downcast_ref::<NodeHandle>().map(|h| h.clone()))
        .ok_or_else(|| JsNativeError::typ().with_message("not a DOM node").into())
}
```

then `let doc = handle.doc.borrow();` (or `borrow_mut()` for mutation), reads/mutates the arena
via the §4 methods, and returns a `JsValue` (a primitive, `null`, or another wrapper).

> Borrow discipline: a method takes **one** `borrow()`/`borrow_mut()` for the duration of its
> arena work and drops it **before** creating any child wrapper that itself may `borrow()` (the
> wrapper cache lookup borrows nothing of the `RefCell`, only the cache map — see §2.3 — so
> there's no re-entrant `RefCell` borrow). Methods never call back into JS while holding a
> borrow (no events in M2), so no re-entrancy hazard exists.

### 2.2 One prototype set (Node vs Element)

We use **two prototypes** built once at install time and stored in a small `Rc`-shared registry
(below): a `node_proto` (methods valid on any node: `nodeName`, `textContent`,
`parentNode`/`childNodes`/`firstChild`/`lastChild`/`nextSibling`/`previousSibling`,
`appendChild`/`removeChild`/`insertBefore`/`replaceChild`) and an `element_proto` whose
`[[Prototype]]` is `node_proto` and which adds the element-only surface (`tagName`, `id`,
`className`, `classList`, `getAttribute`/`setAttribute`/`removeAttribute`/`hasAttribute`,
`getElementsByTagName`/`ClassName`, `querySelector`/`All`, `style`, `innerHTML` read). Text/
Comment/Document nodes get `node_proto` directly (Document additionally carries the
`document`-only methods — §3). A wrapper picks its prototype from the node's `NodeKind` at mint
time. **Simplicity:** if splitting two prototypes is fiddly, a single `node_proto` carrying all
methods (element methods throwing/`null` on non-elements) is an acceptable fallback — but the
two-proto split is cleaner and `instanceof`-friendlier; prefer it.

### 2.3 Wrapper identity / caching — **cache, identity holds**

**Decision: cache `NodeId -> JsObject` so the SAME node always yields the SAME wrapper**
(`el === el`, `el.parentNode.firstChild === el`). This is needed for natural script idioms and
is the stable anchor M3 attaches event listeners to. The cost is one `HashMap` and a weak-ish
discipline; the win is correctness of identity, which scripts rely on.

```rust
// shared registry, installed alongside `shared`, captured by every wrapper-minting closure:
#[derive(Trace, Finalize)]   // see note: cache holds JsObjects → must really trace them
struct DomRegistry {
    #[unsafe_ignore_trace] doc: SharedDoc,
    #[unsafe_ignore_trace] node_proto: JsObject,
    #[unsafe_ignore_trace] element_proto: JsObject,
    cache: GcRefCell<HashMap<NodeId, JsObject>>,   // NodeId -> wrapper
}
```

> Trace subtlety: the cache holds `JsObject`s (GC pointers). If `DomRegistry` lives **inside**
> the GC heap it must trace `cache`. But the registry is simplest as a **Rust-side** `Rc<…>`
> captured by closures (like `ConsoleSink`), NOT stored as Boa native data — then it is outside
> the GC graph and an **empty trace is wrong only if** a cached `JsObject` would otherwise be
> collected while still reachable from JS. Because cached wrappers are also reachable from the
> live DOM graph (document → children) whenever the script can name them, and the cache is
> dropped wholesale when `run_scripts` returns (before the next GC that matters), **M2 keeps the
> registry Rust-side with an `Rc<RefCell<HashMap<NodeId, JsObject>>>` and `empty_trace`**,
> matching `ConsoleSink`. Tradeoff: a wrapper created, dropped by JS, and later re-fetched is a
> cache hit returning the same object — desirable. A wrapper for a node removed from the tree
> stays cached (minor leak until `run_scripts` ends) — acceptable for one-shot. *If a GC
> interaction surprises in practice, promote the registry into native data with a real `Trace`
> over `cache`; noted, not built.*

```rust
fn wrap(reg: &DomRegistry, id: NodeId) -> JsObject {
    if let Some(o) = reg.cache.borrow().get(&id) { return o.clone(); }
    let proto = if reg.doc.borrow().tag_name(id).is_some() {
        reg.element_proto.clone()
    } else {
        reg.node_proto.clone()
    };
    let o = JsObject::from_proto_and_data(Some(proto),
              NodeHandle { doc: reg.doc.clone(), id });
    reg.cache.borrow_mut().insert(id, o.clone());
    o
}
```

(If the two-proto split is deferred, `proto` is always `node_proto`.)

## 3. `document` object

`globals::install` **replaces** the M1 read-only stub with the real `document` host object,
built at the same seam (`register_global_property("document", …)`), so paint/`run_scripts` are
untouched.

`document` is a `JsObject` carrying a `NodeHandle { doc: shared.clone(), id: doc.root() }`
(the `NodeKind::Document` root), with a `document_proto` that adds the document-only methods.
Its methods create wrappers via the registry (§2.3):

| JS member | Impl |
|---|---|
| `getElementById(id)` | DFS the arena; first element whose `get_attribute(n,"id")==Some(id)` → `wrap`; miss → `null`. |
| `querySelector(sel)` | parse `sel` (§5.1); DFS; first element matching → `wrap`; none/invalid → `null`. |
| `querySelectorAll(sel)` | parse `sel`; DFS collect all matching → **static** JS `Array` of wrappers (§5.3). |
| `getElementsByTagName(tag)` | DFS collect elements with `tag_name==tag` (lowercased; `"*"` = all) → static Array. |
| `getElementsByClassName(cls)` | DFS collect elements whose `class` attr contains `cls` → static Array. (optional; cheap, include.) |
| `createElement(tag)` | `doc.create_element(tag)` → **detached** node → `wrap` (not yet in tree). |
| `createTextNode(text)` | `doc.create_text(text)` → detached → `wrap`. |
| `body` (getter) | first `<body>` element (DFS) → `wrap` or `null`. |
| `documentElement` (getter) | first `<html>` element (DFS) → `wrap` or `null`. |
| `title` (getter, keep) | first `<title>`'s text (reuse M1 `document_title`). (setter deferred — note.) |
| `URL` (keep) | `base.as_str()` (M1). |

`body`/`documentElement`/`title` are **accessors** (`ObjectInitializer::accessor`) so they
re-resolve against the current (possibly mutated) tree on each read. The rest are `function`s.

DFS traversal helper (one place, reused): pre-order over the arena from `root()`, pushing
children reversed (matching `collect.rs`). Element predicate via `tag_name(n).is_some()`.

## 4. Arena mutation methods needed (`starfish-dom` additions)

All additions keep the invariant **parent/first_child/last_child/prev_sibling/next_sibling
mutually consistent**. Each returns `Result`/`Option`/bool so the JS layer maps failures to a
thrown `TypeError` and the Rust side **never panics**.

### 4.1 Derive `Clone` (for §1 clone-out)
`#[derive(Clone)]` on `Document`, `Node`, `NodeKind`, `Element`, `Doctype` (`Attr` already
`Clone`). No other change.

### 4.2 Attribute mutation + missing accessors
```rust
impl Document {
    pub fn last_child(&self, id: NodeId) -> Option<NodeId> { self.node(id).last_child }
    pub fn prev_sibling(&self, id: NodeId) -> Option<NodeId> { self.node(id).prev_sibling }

    /// Set (or replace the first) attribute `name` (lowercased) on an element.
    /// No-op if `id` is not an element.
    pub fn set_attribute(&mut self, id: NodeId, name: &str, value: &str) {
        let name = name.to_ascii_lowercase();
        if let NodeKind::Element(e) = &mut self.node_mut(id).kind {
            match e.attrs.iter_mut().find(|a| a.name == name) {
                Some(a) => a.value = value.to_string(),
                None => e.attrs.push(Attr { name, value: value.to_string() }),
            }
        }
    }

    /// Remove all attributes named `name`. Returns whether any existed.
    pub fn remove_attribute(&mut self, id: NodeId, name: &str) -> bool {
        let name = name.to_ascii_lowercase();
        if let NodeKind::Element(e) = &mut self.node_mut(id).kind {
            let before = e.attrs.len();
            e.attrs.retain(|a| a.name != name);
            return e.attrs.len() != before;
        }
        false
    }
}
```
(`get_attribute`/`tag_name` already exist; `hasAttribute` = `get_attribute(...).is_some()`.)

### 4.3 `append_child` must detach an already-parented child first
Today `append_child` `debug_assert!`s the child is detached. JS `appendChild` of a node **already
in the tree** (a move) is legal and common. Add a private `detach` and have `append_child` call
it (and harden the assert into a guard):

```rust
impl Document {
    /// Unlink `id` from its current parent (fixing sibling links). No-op if detached.
    pub fn detach(&mut self, id: NodeId) {
        let (parent, prev, next) = {
            let n = self.node(id);
            (n.parent, n.prev_sibling, n.next_sibling)
        };
        let Some(parent) = parent else { return };
        match prev {
            Some(p) => self.node_mut(p).next_sibling = next,
            None    => self.node_mut(parent).first_child = next,   // was first child
        }
        match next {
            Some(nx) => self.node_mut(nx).prev_sibling = prev,
            None     => self.node_mut(parent).last_child = prev,    // was last child
        }
        let n = self.node_mut(id);
        n.parent = None; n.prev_sibling = None; n.next_sibling = None;
    }

    /// Append `child` as last child of `parent`, detaching it from any old parent first.
    pub fn append_child(&mut self, parent: NodeId, child: NodeId) {
        self.detach(child);                 // NEW: handle re-parenting / move
        // ... existing link-as-last-child body unchanged ...
    }
}
```
The existing `append_child` callers (tree builder) only ever pass detached nodes, so `detach`
is a cheap no-op for them — **behavior-preserving** for the parser. (The `debug_assert` is
removed; `detach` makes any input valid.)

### 4.4 `remove_child`, `insert_before`, `replace_child`
```rust
impl Document {
    /// Remove `child` iff it is currently a child of `parent`. Returns Ok(child) on
    /// success, Err(()) if `child`'s parent is not `parent` (JS throws NotFoundError).
    pub fn remove_child(&mut self, parent: NodeId, child: NodeId) -> Result<NodeId, ()> {
        if self.node(child).parent != Some(parent) { return Err(()); }
        self.detach(child);
        Ok(child)
    }

    /// Insert `child` immediately before `reference` (a child of `parent`). If
    /// `reference` is None, behaves like append. Detaches `child` first. Err if
    /// `reference` is Some but not a child of `parent`.
    pub fn insert_before(&mut self, parent: NodeId, child: NodeId, reference: Option<NodeId>)
        -> Result<(), ()>
    {
        match reference {
            None => { self.append_child(parent, child); Ok(()) }
            Some(r) => {
                if self.node(r).parent != Some(parent) { return Err(()); }
                self.detach(child);
                let prev = self.node(r).prev_sibling;
                self.node_mut(child).parent = Some(parent);
                self.node_mut(child).next_sibling = Some(r);
                self.node_mut(child).prev_sibling = prev;
                self.node_mut(r).prev_sibling = Some(child);
                match prev {
                    Some(p) => self.node_mut(p).next_sibling = Some(child),
                    None    => self.node_mut(parent).first_child = Some(child),
                }
                Ok(())
            }
        }
    }
    // replaceChild = insert_before(parent, new, Some(old)) then remove_child(parent, old)
    // — implement in the JS layer by composing the two (no extra arena method).
}
```

### 4.5 `textContent` set
`element.textContent = s` ⇒ **remove all children, append one Text node**. Done in the JS layer
by composing arena ops (no new arena method): collect `children(id)`, `detach` each (orphaning
them — fine; one-shot), then `let t = doc.create_text(s); doc.append_child(id, t)`. An empty
string removes all children and appends nothing (or an empty Text node — spec sets data to "";
we append a single empty Text node only if `s` non-empty, else leave empty — either is
acceptable; choose "non-empty ⇒ one Text node, empty ⇒ no children").

`textContent` **get** = concatenation of all descendant `Text` payloads (DFS) — JS-layer helper.

### 4.6 `classList` ops
`classList.{add,remove,contains,toggle}` operate on the `class` attribute as a space-split set,
re-serialized. Pure JS-layer string manipulation over `get_attribute(id,"class")` +
`set_attribute(id,"class", joined)`:
- `contains(c)` → split-whitespace `any(==c)`.
- `add(c)` → if absent, push, re-join, `set_attribute`.
- `remove(c)` → retain `!=c`, re-join (or `remove_attribute` if now empty).
- `toggle(c[,force])` → add/remove per presence (or `force`), return resulting presence (bool).
`className` get/set is the raw `class` attribute (`get_attribute`/`set_attribute`). `id` get/set
is the `id` attribute. `classList` is a small object built per-access (a fresh wrapper over the
same `NodeHandle`) carrying the four methods — **no live DOMTokenList**, just methods that
re-read/-write the attribute each call.

### 4.7 Cycle / detached guards (arena-level)
`append_child`/`insert_before` must reject making a node a descendant of itself (appending an
ancestor into its own subtree) to avoid a corrupt cycle. Add a cheap check in the **JS layer**
before calling the arena op: walk `parent`'s ancestor chain; if `child` is an ancestor of (or
equal to) the target parent, **throw** `HierarchyRequestError`-like `TypeError` (per WHATWG).
Keep it in the JS layer so the arena methods stay primitive. (Appending a node to itself, or an
ancestor — the common mistakes — are caught; full DOM pre-insertion validity is out of scope.)

## 5. `querySelector` / matching

### 5.1 Selector parsing — reuse `starfish-css`, no new API
`js` **adds a dep on `starfish-css`** (it already deps `dom`+`net`; `css` deps only `dom`-free
data, so **no cycle** — `css` does not depend on `js`). Parse a selector string by wrapping it
in a throwaway rule and lifting the parsed selectors:

```rust
fn parse_selector_list(sel: &str) -> Option<Vec<starfish_css::Selector>> {
    let sheet = starfish_css::parse_stylesheet(&format!("{sel}{{}}"));
    let rule = sheet.rules.into_iter().next()?;     // invalid/empty selector → no rule → None
    if rule.selectors.is_empty() { None } else { Some(rule.selectors) }
}
```
A pseudo-class/attribute selector (e.g. `:hover`, `[x]`) makes the parser **drop the rule**
(verified: `sel_pseudo_invalid_drops_rule`, `sel_attr_invalid_drops_rule`) → `None` → JS
`querySelector` returns `null` (or per spec should throw `SyntaxError`; returning `null` is the
pragmatic, non-fatal choice — **note**: spec-strict would throw; M2 returns `null`/empty for an
unparseable/unsupported selector). The supported subset is exactly the cascade's:
tag / id / class / compound / descendant / child — matching the brief.

### 5.2 Matching — **port a tiny matcher into `js`** (do NOT dep `starfish-style`)
`matching::matches` is `pub(crate)` in `starfish-style`, and `starfish-style` pulls the whole
style/cascade machinery. Adding it as a `js` dep just for one function is heavy coupling and
would require widening its visibility. **Decision (least coupling):** copy a ~40-line matcher
into `crates/js/src/dom/select.rs`, a faithful port of `matching.rs` (right-to-left,
backtracking, same `compound_matches` rules over `tag_name`/`get_attribute`). It operates on the
**same `Document` + `NodeId` + `starfish_css::Selector`** types, so it is a near-verbatim copy.

Tradeoff: ~40 lines duplicated between `style` and `js`. The alternative (dep `starfish-style` +
`pub` the matcher) couples `js` to the entire style crate and its future churn. Given the subset
is small and frozen (the same selector grammar the css parser accepts), **duplication is the
simpler, lower-risk choice** here (Simplicity First favors decoupling a leaf binding from the
style engine). *If the matcher grows (attribute/pseudo selectors later), revisit and share.*
A test asserts the js matcher agrees with the style matcher on a shared fixture set (§10).

`querySelector(sel)` = DFS document order, return first element where **any** selector in the
list `matches`. `getElementById` is a direct id-attr DFS (not via selectors — faster, and avoids
`#id` escaping concerns).

### 5.3 `querySelectorAll` / collections → static Array
Returns a plain JS **`Array`** of wrappers (a static snapshot), built by collecting matching
`NodeId`s then `wrap`-ing each and pushing into a `JsArray` (Boa `JsArray::from_iter`/push).
`length` + indexed access + `forEach` (Array's own) work. **No live NodeList** (non-goal §9).
`getElementsByTagName`/`ClassName` likewise return static Arrays. (Brief allows NodeList; a
static Array is the simplest object that satisfies `.length`/indexing/`forEach`.)

## 6. `element.style` + inline style in the cascade

### 6.1 Does `style_tree` honor `style=""` today? — **NO.**
`cascade::cascade` builds `matched` **only** from UA + author `Stylesheet` rules; it never reads
the element's `style` attribute. So `el.style.color='red'` writing to the `style` attribute would
**not** affect the render unless the cascade is extended. This is required for the visual test
(`el.style.background=...` changes the painted background).

### 6.2 Decision — minimal inline-style hook in the cascade
Add **one** step to `cascade`: after collecting author/UA `MatchedDecl`s, parse the element's
`style` attribute into declarations and apply them **last among normal declarations, at
higher precedence than any author rule** (inline style has, per spec, specificity above all
selectors for normal declarations; modeling it as "applied after author-normal, before
important" is the standard simplification).

Reuse the existing **declaration** parser — `starfish_css` parses a *stylesheet*, so wrap the
inline text as one rule and lift its declarations:

```rust
// in starfish-style cascade.rs, after the author/UA loop, before sorting/applying:
if let Some(inline) = doc.get_attribute(element, "style") {
    let sheet = starfish_css::parse_stylesheet(&format!("*{{{inline}}}"));   // "*{ color:red }"
    if let Some(rule) = sheet.rules.first() {
        for decl in &rule.declarations {
            matched.push(MatchedDecl {
                origin: Origin::Author,
                // give inline the max selector specificity so it beats author rules;
                // (a,b,c) = (255,0,0)-ish sentinel, or add an `inline: bool` to MatchedDecl
                // and order it just above author-normal in the sort key.
                specificity: INLINE_SPECIFICITY,
                source_order, declaration: decl,
            });
            source_order += 1;
        }
    }
}
```
Two clean implementation options for precedence (pick one in impl):
- (a) push inline decls with a **sentinel max `Specificity`** (e.g. `{a:u32::MAX,..}`) so they
  sort after all author selectors but `!important` ordering (via `origin_rank`) still wins for
  UA-important. `!important` **inside** the inline `style` is honored by `decl.important` (the
  parser sets it), so the existing `origin_rank(Author, true)` slot covers inline-important.
- (b) add an `inline: bool` to `MatchedDecl` and extend the sort key to
  `(origin_rank, inline, specificity, source_order)` — most faithful. **Recommend (b)** (one
  field, one tuple element; no magic sentinel).

This is a **small, real cascade feature** confined to `cascade.rs` (one block + one sort-key
field). It does **not** touch `style_tree`/`layout`/`paint` signatures. With it, `el.style.x=y`
writing the `style` attribute is **visible in the render** — satisfying the M2 visual goal.

### 6.3 `element.style` JS object
`el.style` returns a small object (built per access over the same `NodeHandle`) whose **property
sets** write the inline-style attribute. M2 scope: support **property assignment** (`style.color
= 'red'`, `style.backgroundColor = '#fff'`) and read-back. Implement via a Boa **Proxy**? — no
(heavier). Simpler: `style` is an object carrying the `NodeHandle` whose recognized CSS
properties are **accessors** that get/set by editing the `style` attribute string. Because the
set of CSS properties is large, the pragmatic M2 approach:

- Maintain a fixed list of supported camelCase↔kebab property names (the ones the cascade
  understands: `color`, `backgroundColor`→`background-color`, `background`, `width`, `height`,
  `display`, `margin`, `padding`, `border`, `fontSize`→`font-size`, `fontWeight`, `textAlign`,
  etc.). For each, register an **accessor** on the `style` object: getter reads the property out
  of the parsed `style` attribute; setter rewrites the `style` attribute with that property set
  to the new value (parse existing decls → upsert this one → re-serialize `name:value;…`).
- Also provide `setProperty(name,value)`/`getPropertyValue(name)`/`removeProperty(name)` and a
  `cssText` accessor (get/set the whole attribute) so unlisted properties still work via
  `setProperty`. **Recommend** making `setProperty`/`cssText` the primitive and the camelCase
  accessors thin wrappers — this keeps the property list from being a hard limit.
- Serialization: store as `"a: b; c: d"`; upsert/remove by re-parsing with the css declaration
  parser (the same `*{…}` trick) and re-joining `decl.name: decl.value.raw`.

**Simplicity note:** if the per-property accessor list is too broad to enumerate cleanly, M2 may
ship **`style.setProperty(name,value)` + `style.cssText` + a curated ~15 camelCase accessors**
(color, background, backgroundColor, width, height, display, margin, padding, border, fontSize,
fontWeight, textAlign, opacity, top, left). That covers the visual tests and common scripts; the
rest go through `setProperty`. The cascade hook (§6.2) is what makes any of it render.

## 7. Pipeline ordering (confirm)

`render_document` (paint) is **unchanged** from M1:

```
parse → run_scripts(&mut doc, base, loader)   // M2: scripts mutate `doc` via host objects
      → collect_author_sheets(&doc, …)        // sees post-script DOM (new/moved nodes)
      → style_tree(&doc, &author)             // M2: cascade now honors inline `style` attr (§6)
      → decode_images(&doc) → layout(&doc, …) → paint(…)
```

After `run_scripts` returns, `*doc` is the **cloned-out post-script arena** (§1) including all
DOM mutations and any `style`-attribute writes. Because CSS collection + style + layout + paint
all run **after** and read `&doc`, every DOM and inline-style change is visible in the PNG. No
reordering, no signature change in paint. ✔

## 8. Error / edge handling (never panic the Rust side)

- **Miss → `null`:** `getElementById`/`querySelector`/`body`/`documentElement`/`nextSibling`/…
  return JS `null` (`JsValue::null()`) when absent.
- **Wrong-type `this`:** `this_handle` downcast fail → throw `TypeError("not a DOM node")`.
- **Wrong-type args:** coerce with `arg.to_string(ctx)` (strings) / `as_object()` (nodes); a
  method expecting a node arg that gets a non-node → `TypeError`. Never index a missing arg
  (`args.get(0).cloned().unwrap_or_default()`).
- **`removeChild` of a non-child / `insertBefore` bad reference:** arena returns `Err(())` →
  throw `TypeError` (NotFoundError-like). Page still renders (caught by `run_scripts`).
- **Cycle (append an ancestor / a node to itself):** JS-layer ancestor check (§4.7) → throw
  `TypeError` (HierarchyRequestError-like); arena untouched.
- **Detached node ops:** reading `parentNode` of a detached node → `null`; appending a detached
  node is normal; `removeChild` on a detached node → `Err` → throw.
- **Arena methods return `Result`/`Option`/`bool`** — the JS layer maps them; **no `unwrap`/
  `panic!`/`expect` on script-reachable paths.** `node()`/`node_mut` index by a `NodeId` that
  is always valid (ids never invalidated; arena only grows) so indexing can't go OOB.
- **Unicode / garbage:** `to_std_string_escaped()` / `to_string` handle non-UTF-16-clean and
  multibyte (`é`, emoji) safely; attribute/text values are arbitrary `String`s. Selector parse
  of garbage → `None` → `null`/empty (non-fatal).
- **`run_scripts` stays infallible:** any thrown DOM error is captured into
  `ScriptOutcome.errors`; the render proceeds with whatever mutations committed before the throw.

## 9. Edge cases & non-goals (deliberate)

Delivered (pragmatic subset): `document.{getElementById, querySelector, querySelectorAll,
createElement, createTextNode, body, documentElement, getElementsByTagName, getElementsByClassName,
title(get), URL}`; `Node/Element.{nodeName/tagName, id, className, classList(add/remove/contains/
toggle), textContent(get+set), getAttribute/setAttribute/removeAttribute/hasAttribute, appendChild/
removeChild/insertBefore/replaceChild, parentNode/childNodes/children/firstChild/lastChild/
nextSibling/previousSibling, style(set), innerHTML(read)}`; wrapper identity via cache;
inline-style honored by the cascade.

**Non-goals (deferred / documented limits):**
- **`innerHTML` WRITE** (parse HTML into a node) — deferred. `innerHTML` **read** (serialize the
  subtree to HTML) is included as nice-to-have (reuse a simple serializer; if `dom::serialize`'s
  S-expr form is unsuitable, a tiny HTML serializer in the JS layer — small). If read-serialize
  is more than trivial, defer it too and **note**.
- **Live NodeLists / HTMLCollections** — all collections are **static Arrays** (snapshots).
- **MutationObserver**, **events / listeners / `on*`** — M3.
- **CSSOM beyond inline `style` set** — no `getComputedStyle`, no stylesheet objects, no
  `classList` `replace`/`item`/iteration protocol beyond the four ops.
- **Namespaces / SVG / XML**, `dataset`, `attributes` NamedNodeMap, `cloneNode`, `normalize`,
  `Document.createDocumentFragment`, comparator/`compareDocumentPosition` — out.
- **Spec-strict selector errors** — unsupported/invalid selector returns `null`/empty rather
  than throwing `SyntaxError`.
- **`document.write`** — not provided.

## 10. Test plan (concrete)

`js` crate unit tests drive `run_scripts` directly (returns `ScriptOutcome` + mutates `doc`);
visual tests go through `render_document` and assert pixels. Helpers reuse M1's `run(html)`.

**DOM read:**
1. `getElementById('x')` then `el.tagName`/`el.nodeName` → correct upper/lower; `el.id`,
   `el.className`, `el.getAttribute('data-y')` read existing attrs; miss → `null`
   (`document.getElementById('nope')===null`).
2. `textContent` get over nested text (`<p>a<span>b</span></p>` → `"ab"`).
3. `parentNode`/`firstChild`/`lastChild`/`nextSibling`/`previousSibling`/`childNodes.length`/
   `children.length` navigate correctly; `el === el.parentNode.firstChild` (**identity/cache**).

**DOM mutate (+ round-trip via `doc.serialize`):**
4. `setAttribute('class','c')` → `get_attribute` reflects it; `removeAttribute` clears it;
   `hasAttribute` true/false.
5. `createElement('div')` + `appendChild` adds a child (serialize shows it); `removeChild`
   removes it; `insertBefore(new, ref)` orders correctly; `replaceChild` swaps; **move**:
   `appendChild` of an already-parented node detaches it from the old parent (old parent loses
   it, sibling links stay consistent — assert via `children()`).
6. `textContent='hello'` replaces all children with one Text node (serialize: single `"hello"`).
7. `classList.add/remove/contains/toggle` mutate the `class` attribute set correctly
   (`toggle` returns the right bool; `add` idempotent).

**Selectors:**
8. `querySelector('#id')`, `querySelector('.cls')`, `querySelector('div p')` (descendant),
   `querySelector('div > p')` (child) each return the right node; `querySelectorAll('.cls')`
   length + element identity; unsupported `:hover` → `null`/empty (non-fatal).
9. **js matcher == style matcher** on a shared fixture set (tag/id/class/compound/descendant/
   child incl. the backtracking case from `matching.rs` tests).

**Visual (through `render_document`, assert pixels):**
10. Script `document.getElementById('b').className='hot'` with author CSS `.hot{color:red}` →
    the element's text paints **red** (DOM mutation + cascade re-run after scripts).
11. `el.style.background='#00ff00'` (or `.backgroundColor`) → the element's box paints **green**
    (proves §6 inline-style cascade hook + `style` setter).
12. `createElement`+`appendChild` of a styled block → a **new visible** block appears;
    `removeChild` of an existing block → it **disappears** vs baseline.

**Robustness:**
13. `removeChild` of a non-child throws but the page **still renders** (error captured, pixels
    of the rest intact).
14. Appending an ancestor into its own subtree throws (no panic, no arena corruption — a
    follow-up `serialize` is well-formed).
15. **Ownership clone-out:** after a script that holds a global reference to a node
    (`window.keep = document.body`), `run_scripts` returns and `doc.serialize` is well-formed
    and reflects mutations (proves the `Rc::try_unwrap`→`clone()` fallback recovers the arena
    even with a leaked handle). Unicode-safe: a script setting `textContent='héllo🌟'` round-trips.

`cargo test -p starfish-js`, `-p starfish-dom`, `-p starfish-style`, `-p starfish-paint`, and the
full `cargo test` green; smoke: render a page whose script recolors a block and confirm the PNG.
