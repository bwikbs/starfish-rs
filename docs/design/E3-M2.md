# E3-M2 — HTTP(S) fetching: `HttpLoader` + scheme router (design note)

Scope (per `docs/ROADMAP-epic3.md`): teach the engine to fetch a page **over the
network**. Add a blocking, pure-Rust `HttpLoader` (`http(s)://`) and a
scheme-routing loader so `render_document` — which already takes a single
`&dyn ResourceLoader` and resolves every `<link>`/`<img>` relative to the
document base — can pull the HTML, its linked CSS, and remote images over HTTP
without any change to the pipeline below the loader.

This builds directly on **E3-M1** (`docs/design/E3-M1.md`): the
`ResourceLoader` trait, `Resource { bytes, content_type }`, `LoadError`,
`LocalLoader`, `base_url_from_input`, and `render_document(html, base, width,
loader)` already exist and are quoted from source below. M2 is purely
**additive** in the `net` crate plus a small CLI rewire — no trait change, no
paint change.

Guiding rule (project CLAUDE.md "Simplicity First"): the thinnest possible
blocking HTTP loader + a scheme dispatcher. **No** cookies, cache, CORS,
mixed-content policy, auth, `data:` (M3), or streaming. Errors as values, never
panic. Deviations are called out in §8.

This note is pinned to the **real** current APIs read from source (signatures
quoted inline). The exact `ureq` / `tiny_http` call shapes (builder vs config,
header accessors) are confirmed by the companion **ANALYSIS agent**; where this
note shows a call it is marked *(analysis confirms exact form)* and the
implementation uses the analysis's verified signature. The trait shape and data
flow below are fixed regardless of those details.

## 1. HTTP client crate — `ureq` (blocking, rustls, no async runtime)

### 1.1 Choice & justification

| Candidate | Verdict |
|-----------|---------|
| **`ureq`** | **Chosen.** Blocking/synchronous API — fits our fetch-then-render, single-threaded loader with zero `async`/executor. Pure-Rust TLS via **rustls** (no OpenSSL/system C deps → reproducible, cross-compiles cleanly). Follows redirects itself, exposes status + headers + a body reader. Small dependency tree. Exactly a "GET bytes" client. |
| `reqwest` (blocking) | Rejected. Its `blocking` module still pulls in **tokio** (it runs an async runtime on a background thread under the hood) plus `hyper`/`h2`. Large tree + runtime for a synchronous one-shot GET. Overkill against Simplicity First. |
| hand-rolled `std::net::TcpStream` + TLS | Rejected. Re-implements HTTP/1.1, chunked transfer, redirects, TLS handshake — far more code and bugs than the milestone wants. |

`ureq` is the canonical "small blocking pure-Rust HTTP client" and is exactly
what the roadmap names (E3-M2 row: *"a blocking pure-Rust client, e.g. `ureq`
+rustls"*).

### 1.2 Version & features (in the **`net`** crate)

Pin **`ureq` 3.x** (3.0 reworked the API around an `Agent` + `Config` builder and
a typed `http::Response`; the 3.x line is current as of 2026-06). The
**ANALYSIS agent confirms the exact patch version and the precise builder
method names** (e.g. `Agent::config_builder()` / `Config::builder()`,
`.timeout_*`, `.user_agent`, `.max_redirects`, and the response `body`/`header`
accessors); pin that exact version in the committed `Cargo.lock`. MSRV 1.85
(workspace `rust-version`) is satisfied by ureq 3.x.

```toml
# crates/net/Cargo.toml
[dependencies]
url = "2"
ureq = { version = "3", default-features = false, features = ["rustls"] }
#   default-features = false  → drop the default native/platform-TLS &
#                               charset/json extras we don't use.
#   features = ["rustls"]     → pure-Rust TLS with webpki-roots (Mozilla CA
#                               bundle compiled in; no system trust store needed).
# (ANALYSIS agent confirms the exact feature name for the rustls+webpki-roots
#  combo in the pinned 3.x — historically "rustls"; if 3.x split it into e.g.
#  "rustls" + "platform-verifier", we take the webpki-roots variant so TLS works
#  with zero host config.)

[dev-dependencies]
tiny_http = "0.12"   # local fixture HTTP server for tests (§7); ANALYSIS confirms patch.
```

**Build cost note.** Adding `ureq`+rustls pulls in rustls, ring/aws-lc (crypto),
webpki-roots, and the `http` types crate — a one-time increase in cold-build time
and binary size (a few MB). This is the accepted cost of pure-Rust TLS with no
system OpenSSL dependency and is paid only in `net` (a leaf crate). No async
runtime, no proc-macro-heavy deps. Justified: it's the smallest path to working
HTTPS that cross-compiles without host C libraries.

The dep lives in **`net`** (not cli/paint) because the loader is the only thing
that speaks HTTP; everything above sees just `&dyn ResourceLoader`.

## 2. `HttpLoader` — a blocking GET behind the trait

`crates/net/src/http.rs` (new module; `lib.rs` adds `mod http; pub use
http::HttpLoader;`).

### 2.1 Struct & construction

```rust
use std::time::Duration;
use url::Url;
use crate::loader::{LoadError, Resource, ResourceLoader};

/// Blocking HTTP(S) loader. Holds a configured `ureq::Agent` (connection pool +
/// rustls config + redirect/timeout policy + our User-Agent) so repeated fetches
/// (the document, then each linked CSS/image) reuse one client. Never panics —
/// every failure is a `LoadError`.
pub struct HttpLoader {
    agent: ureq::Agent,
    /// Hard cap on response body bytes read into memory (anti-OOM, §6).
    max_body_bytes: usize,
}

/// User-Agent we advertise on every request.
const USER_AGENT: &str = concat!("starfish-rs/", env!("CARGO_PKG_VERSION"));
//   → "starfish-rs/0.0.0" (workspace version 0.0.0). A fixed, honest UA.

impl HttpLoader {
    /// Build with sensible defaults: 10 MiB body cap, 30 s connect+read timeout,
    /// ≤10 redirects, our User-Agent (§6).
    pub fn new() -> Self {
        Self::with_timeout(Duration::from_secs(30))
    }

    /// Build with a caller-chosen overall timeout (CLI `--timeout`, §4).
    pub fn with_timeout(timeout: Duration) -> Self {
        // ANALYSIS agent confirms the exact ureq 3.x builder calls; shape:
        //   let agent = ureq::Agent::config_builder()
        //       .user_agent(USER_AGENT)
        //       .timeout_global(Some(timeout))   // connect+read overall bound
        //       .max_redirects(MAX_REDIRECTS)
        //       .build()                         // -> Config
        //       .new_agent();                    // or Agent::new_with_config(cfg)
        let agent = build_agent(USER_AGENT, timeout, MAX_REDIRECTS);
        HttpLoader { agent, max_body_bytes: MAX_BODY_BYTES }
    }
}

impl Default for HttpLoader {
    fn default() -> Self { Self::new() }
}

const MAX_REDIRECTS: u32 = 10;
const MAX_BODY_BYTES: usize = 10 * 1024 * 1024; // 10 MiB
```

`build_agent` is a tiny private helper wrapping the exact ureq 3.x builder chain
the analysis agent verified, so the rest of the file is API-stable even if a
method name differs. The User-Agent and redirect/timeout policy are baked into
the `Agent`, so `fetch` stays trivial.

### 2.2 `fetch` — GET, follow redirects, cap body, capture content-type

```rust
impl ResourceLoader for HttpLoader {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        // 1. GET. ureq follows redirects up to MAX_REDIRECTS internally and
        //    returns the FINAL response (or an error). 4xx/5xx come back as a
        //    response with that status (ureq 3.x does NOT error on status by
        //    default — we map it ourselves in step 3), while transport failures
        //    (DNS, connect, TLS, timeout) are Err.
        let resp = match self.agent.get(url.as_str()).call() {
            Ok(resp) => resp,
            Err(e) => return Err(map_transport_error(e, url)),
        };

        // 2. Status gate: 4xx/5xx → LoadError::Http. (Redirect 3xx never reach
        //    here — already followed; a redirect loop / over-cap surfaces as a
        //    transport error in step 1.)
        let status = resp.status().as_u16();   // (analysis: exact accessor)
        if !(200..300).contains(&status) {
            return Err(LoadError::Http { status, url: url.clone() });
        }

        // 3. Content-Type header → Resource.content_type (raw value, lowercased
        //    not required; M3 parses mime/charset). Absent header → None.
        let content_type = resp
            .headers()
            .get("content-type")            // (analysis: exact header accessor)
            .and_then(|v| v.to_str().ok())
            .map(|s| s.to_string());

        // 4. Read the body with a hard byte cap (anti-OOM). Take a reader and
        //    read at most max_body_bytes+1; if we hit the extra byte the body is
        //    over the cap → Network error (refuse, don't truncate silently).
        let bytes = read_capped(resp, self.max_body_bytes)
            .map_err(|e| map_body_error(e, url))?;

        Ok(Resource { bytes, content_type })
    }
}
```

```rust
/// Read a ureq response body into a Vec, refusing bodies over `cap` bytes.
/// (ANALYSIS confirms the 3.x body-reader accessor, e.g. resp.into_body()
/// .into_reader() / .as_reader(); shape below uses a std::io::Read.)
fn read_capped(resp: ureq::http::Response<ureq::Body>, cap: usize)
    -> Result<Vec<u8>, ReadCapError>
{
    use std::io::Read;
    let mut reader = body_reader(resp);          // -> impl Read
    let mut buf = Vec::new();
    // read up to cap+1; (cap+1)-th byte present ⇒ over the limit.
    reader.by_ref().take(cap as u64 + 1).read_to_end(&mut buf).map_err(ReadCapError::Io)?;
    if buf.len() > cap {
        return Err(ReadCapError::TooLarge(cap));
    }
    Ok(buf)
}
```

Mapping (every branch is a `LoadError` value, never a panic):

| Failure | `LoadError` |
|---------|-------------|
| 4xx / 5xx final status | `Http { status, url }` |
| connect/read timeout, redirect-limit exceeded if surfaced as timeout | `Timeout(url)` |
| DNS failure, connection refused, TLS handshake/cert error, too many redirects | `Network(String)` (message includes the ureq cause) |
| body over `max_body_bytes` | `Network("response body exceeds 10 MiB cap")` |
| (anything else from ureq) | `Network(String)` |

`map_transport_error` matches the ureq 3.x error enum the analysis agent
verified (it distinguishes timeout from other I/O/TLS/redirect errors) and
collapses everything that isn't a clean timeout into `Network(String)` with a
human cause. We deliberately keep only three new variants (§5) — finer
granularity isn't needed by any caller (CSS/image callers treat *any* `Err` as
"skip"; the CLI just prints the message).

### 2.3 No panics, ever

Every `?`/`match` above yields a `LoadError`. There is no `unwrap`/`expect` on
network input. A malformed URL never reaches `HttpLoader` (the router only
forwards `http`/`https`, and `Url` is already a parsed absolute URL).

## 3. Scheme routing — `RouterLoader`

`crates/net/src/router.rs` (new; `lib.rs` adds `mod router; pub use
router::RouterLoader;`). This is the E3-M1 §3.4 "SchemeRouter sketch" made real,
with **no trait change** (it was designed for exactly this).

```rust
use url::Url;
use crate::http::HttpLoader;
use crate::loader::{LoadError, LocalLoader, Resource, ResourceLoader};

/// Dispatches a fetch by URL scheme to the right concrete loader. Holds one
/// `HttpLoader` (with its pooled agent) and one `LocalLoader`, so a single
/// `&dyn ResourceLoader` passed to `render_document` transparently handles a
/// page that mixes `http(s)://` and `file://` resources. Relative resources
/// resolve (via `base.join` upstream) to the document's own scheme, so a remote
/// page's relative CSS/images naturally route back through HTTP.
pub struct RouterLoader {
    local: LocalLoader,
    http: HttpLoader,
}

impl RouterLoader {
    pub fn new() -> Self {
        RouterLoader { local: LocalLoader, http: HttpLoader::new() }
    }
    /// With a custom HTTP timeout (CLI `--timeout`).
    pub fn with_http(http: HttpLoader) -> Self {
        RouterLoader { local: LocalLoader, http }
    }
}

impl Default for RouterLoader {
    fn default() -> Self { Self::new() }
}

impl ResourceLoader for RouterLoader {
    fn fetch(&self, url: &Url) -> Result<Resource, LoadError> {
        match url.scheme() {
            "file" => self.local.fetch(url),
            "http" | "https" => self.http.fetch(url),
            // "data" is E3-M3.
            other => Err(LoadError::UnsupportedScheme(other.to_string())),
        }
    }
}
```

- A **remote page referencing a `file://` resource** → routed to `LocalLoader`
  (allowed; this is a local rendering tool, not a sandbox — same posture as M1).
- A **remote page with relative `href`/`src`** → `base.join(href)` (in paint)
  produces an `http(s)://` URL (the base's scheme) → routed to `HttpLoader`.
- A **local page referencing `http://…`** → routed to `HttpLoader`. Mixed schemes
  "just work" because routing is per-resolved-URL, not per-document.
- Unknown scheme (`ftp:`, `data:` in M2) → `UnsupportedScheme` (CSS/image callers
  skip it; the CLI surfaces it for the top-level document).

`RouterLoader` is the single loader the CLI and `render_url` construct.

## 4. `render_url` convenience + CLI

### 4.1 `render_url` in **paint** (next to `render_path`)

paint already owns `render_document`/`render_path` and depends on `net`. Add a
sibling that fetches the document over the network through the router, then
renders with that same router (so CSS+images fetch over HTTP too):

```rust
// crates/paint/src/lib.rs
use starfish_net::RouterLoader;     // add to the existing net re-exports

/// Fetch and render a document by absolute `Url` (http/https/file) through a
/// scheme `RouterLoader`: GETs the document bytes, then `render_document` so
/// linked CSS + images resolve and fetch over the same router. The document's
/// own URL is the base, so relative resources resolve against it.
pub fn render_url(url: &Url, viewport_width: f32) -> Result<Pixmap, LoadError> {
    let loader = RouterLoader::new();
    let res = loader.fetch(url)?;                       // Http/Timeout/Network/NotFound → Err
    let html = String::from_utf8_lossy(&res.bytes);     // assume UTF-8 (charset → M3)
    Ok(render_document(&html, url, viewport_width, &loader))
}
```

`render_path` (file) is unchanged. `render_url` works for a `file://` URL too
(routes to `LocalLoader`), so it is the general entry point; `render_path` stays
as the path-string convenience. Re-export `RouterLoader` from paint's `lib.rs`
alongside the existing `LoadError, LocalLoader, ResourceLoader, Url`.

(We keep `render_url` in **paint**, not `net`, because it pulls the whole render
pipeline together — `net` stays a leaf crate with no paint dependency, exactly as
E3-M1 established.)

### 4.2 CLI — accept a URL, build the router, drop the http stub

`crates/cli/src/main.rs`. The only changes: swap `LocalLoader` for
`RouterLoader`, delete the `UnsupportedScheme("http")` stub branch, add an
optional `--timeout S` flag.

```rust
use starfish_net::{base_url_from_input, LoadError, ResourceLoader, RouterLoader, HttpLoader};
use std::time::Duration;

const USAGE: &str =
    "usage: starfish render <url|path> -o <out.png> [--width N] [--timeout S]";

// …arg loop: add a `--timeout` arm parsing seconds (u64) → Option<Duration>…
//   "--timeout" => { let v = iter.next()…; timeout = Some(Duration::from_secs(v.parse()…)); }

let base = base_url_from_input(&input).map_err(|e| format!("bad input '{input}': {e}"))?;

// One router handles file:// and http(s):// — for the document AND its resources.
let loader = match timeout {
    Some(t) => RouterLoader::with_http(HttpLoader::with_timeout(t)),
    None => RouterLoader::new(),
};

// Fetch the document itself through the router.
let bytes = match loader.fetch(&base) {
    Ok(res) => res.bytes,
    Err(LoadError::UnsupportedScheme(s)) =>
        return Err(format!("{s}:// URLs are not supported (use file/http/https)")),
    Err(e) => return Err(format!("fetching {input}: {e}")),   // 404/timeout/DNS → clean msg
};
let html = String::from_utf8_lossy(&bytes);

let pixmap = starfish_paint::render_document(&html, &base, width as f32, &loader);
pixmap.save_png(&output).map_err(|e| format!("writing {output}: {e}"))?;
println!("wrote {output} ({}x{})", pixmap.width(), pixmap.height());
```

Behavior:
- `starfish render https://example.com -o out.png --width 1000` → fetch the page
  + its CSS/images over HTTPS, render.
- `starfish render page.html -o out.png` / `file://…` → **unchanged** (router →
  `LocalLoader`).
- `--timeout 5` → 5 s overall HTTP timeout (else 30 s default).
- A `404` / DNS failure / timeout on the **document** → `LoadError` Display
  message printed via the existing `eprintln!("starfish: {e}")` + `ExitCode::
  FAILURE` (already in `main`). No panic. (A failure on a *sub*-resource — a CSS
  or image — is swallowed by `collect_author_sheets`/`ImageStore` and the page
  renders without it, exactly as M1.)

CLI flag summary: `render` subcommand, positional `<url|path>`, `-o/--output`
(required), `--width N` (default 800), `--timeout S` (seconds, optional). The CLI
manifest is unchanged (it already pulls `starfish-net` + `starfish-paint`).
`render_url` is available to library callers; the CLI inlines the equivalent
(fetch doc → render_document) because it needs the `UnsupportedScheme` →
friendly-message mapping for the *document* fetch.

## 5. `LoadError` extensions (minimal)

Add three variants to the existing enum in `crates/net/src/loader.rs` and extend
the two `match`es (`Display::fmt`, `Error::source`). Nothing else changes.

```rust
#[derive(Debug)]
pub enum LoadError {
    NotFound(Url),
    Io(std::io::Error),
    UnsupportedScheme(String),
    BadPath(PathBuf),
    BadUrl(url::ParseError),
    // --- E3-M2 ---
    /// A non-2xx HTTP final status (after redirects).
    Http { status: u16, url: Url },
    /// The request exceeded the connect/read timeout.
    Timeout(Url),
    /// A transport-level failure (DNS, connect refused, TLS, redirect loop,
    /// over-size body) — message carries the cause.
    Network(String),
}
```

```rust
// Display arms (add):
LoadError::Http { status, url } => write!(f, "HTTP {status} for {url}"),
LoadError::Timeout(u)           => write!(f, "request timed out: {u}"),
LoadError::Network(m)           => write!(f, "network error: {m}"),
// Error::source: the three new variants carry no nested std::error::Error
// (Network is a String) → fall in the existing `_ => None` arm. No change needed
// to source() beyond the new variants matching `_`.
```

Why a struct variant for `Http` (carrying `url`) and tuple for the others: the
CLI message wants the URL for `Http` (which resource 404'd), while `Timeout`
already names the URL and `Network` already embeds a full message. Three variants
is the minimum that lets the CLI print "HTTP 404 for …", "request timed out: …",
"network error: …". No `thiserror`, no per-cause subtyping — Simplicity First.

(`UnsupportedScheme`/`NotFound`/`Io` are reused: a `file://` 404 stays
`NotFound`; HTTP 404 is `Http { status: 404 }` — distinct because the CLI wording
differs and HTTP 404 isn't a missing *local* file.)

## 6. Redirects, limits, headers (the concrete policy)

| Concern | Policy | Rationale |
|---------|--------|-----------|
| **Redirects** | Follow `3xx` automatically (ureq default), **capped at 10** (`MAX_REDIRECTS`). Over the cap → transport error → `Network`/`Timeout`. | Handles the common `http→https` / canonical-host redirects without unbounded loops. |
| **Max body size** | `MAX_BODY_BYTES = 10 MiB`, enforced by `read_capped` (read `cap+1`, refuse if exceeded). Over → `Network("…exceeds 10 MiB cap")`. | Anti-OOM for hostile/huge responses; 10 MiB comfortably covers an HTML doc, a CSS file, or a typical image. |
| **Connect+read timeout** | Default **30 s** overall (`with_timeout`), CLI-overridable via `--timeout S`. | Avoids hanging forever on a dead server; tunable for slow/test servers. |
| **Request header we send** | `User-Agent: starfish-rs/<pkg-version>` only. | Honest UA; some servers 403 an empty UA. Nothing else (no `Accept`, no `Accept-Encoding` beyond ureq's default). |
| **Response header we read** | `Content-Type` → `Resource.content_type`. | Carried for M3 (mime/charset). Status is read but not stored. |
| **Compression** | Whatever ureq does transparently by default; we don't set `Accept-Encoding` ourselves and don't manually inflate. | Out of scope; if ureq decompresses for free, fine; otherwise servers see no `gzip` offer. |
| **Cookies / auth / cache / redirects-to-other-schemes** | **Ignored.** No cookie jar, no `Authorization`, no `Cache-Control`/`ETag`, no conditional requests. A redirect that ureq follows to another scheme is ureq's call; we don't special-case it. | Explicit non-goals (roadmap). |
| **TLS** | rustls + webpki-roots (Mozilla CA bundle compiled in). System trust store **not** consulted; **no cert pinning**. | Pure-Rust, host-independent. Self-signed test certs would fail — tests use **plain HTTP** on loopback (§7), not TLS. |

All four numeric limits live as `const`s at the top of `http.rs` so they're easy
to find/tune. The agent is configured once in `with_timeout`.

## 7. Testing strategy — local `tiny_http` fixture server

We cannot hit the real internet deterministically. Tests spin up a **local HTTP
server** on `127.0.0.1:0` (ephemeral port) in a background thread, serve fixed
fixtures, point `HttpLoader`/`RouterLoader` at `http://127.0.0.1:<port>/…`, and
assert. **TLS is not tested** (rustls + webpki-roots would reject a self-signed
loopback cert; HTTPS wiring is exercised by the type system / a manual smoke,
noted §8) — all automated tests use **plain HTTP on loopback**, which exercises
the full request/redirect/status/body/header path.

Server crate: **`tiny_http`** (`[dev-dependencies]` in `crates/net`) — a tiny
blocking server, no async, perfect for a fixture. The ANALYSIS agent confirms the
exact `tiny_http` API (`Server::http("127.0.0.1:0")`, `server.server_addr()` /
`.port()` to learn the chosen port, `server.recv()` → `Request`,
`Request::url()`, `Response::from_data`/`from_string`, `Header` for
`Content-Type`/`Location`, `Request::respond(resp)`).

### 7.1 Test harness (a helper in `http.rs` / `router.rs` tests)

```rust
// Spawn a tiny_http server on an ephemeral port in a thread; `handler` decides
// the response per request URL path. Returns (base_url, JoinHandle / drop-guard).
// The thread serves a fixed number of requests (or loops until a shutdown
// signal) so the test joins cleanly. (ANALYSIS confirms exact tiny_http calls.)
fn serve(routes: impl Fn(&str) -> CannedResponse + Send + 'static) -> (String, ServerGuard) { … }
```

Routes map a path → a canned `(status, content_type, body)` or a redirect
(`302` + `Location`). Bind to port 0, read the real port back, build
`http://127.0.0.1:<port>` as the base.

### 7.2 Concrete test cases (all loopback, deterministic)

In `crates/net` (`http.rs` / `router.rs` `#[cfg(test)]`):

1. **200 + bytes + content-type** — server returns `200` `text/css; charset=utf-8`
   body `p{color:red}`. `HttpLoader::new().fetch(url)` → `Ok(Resource)` with
   exact bytes and `content_type == Some("text/css; charset=utf-8")`.
2. **Binary body (PNG)** — server returns `200 image/png` + a 2×2 PNG. Loader
   returns the exact bytes; `image::load_from_memory` (in paint) decodes them.
   (Asserts binary safety: no UTF-8 mangling.)
3. **302 redirect followed** — `/a` → `302 Location: /b`, `/b` → `200` body
   `ok`. `fetch(/a)` transparently returns `/b`'s body. (Proves redirect
   following.)
4. **404 → `LoadError::Http`** — `/missing` → `404`. `fetch` → `Err(Http {
   status: 404, .. })` (matched; no panic).
5. **500 → `LoadError::Http { status: 500 }`** — same shape, server error class.
6. **Timeout** — server delays the response (sleep longer than the loader's
   timeout) for a path. Build `HttpLoader::with_timeout(Duration::from_millis(
   100))`; `fetch` → `Err(LoadError::Timeout(_))`. (Proves the timeout bound;
   use a short timeout so the test is fast.)
7. **Body cap** — server returns a body larger than a small test cap (construct
   an `HttpLoader` with a tiny `max_body_bytes` via a test-only ctor, or serve
   `> 10 MiB` — prefer a test ctor to keep the test cheap). `fetch` →
   `Err(LoadError::Network(_))` mentioning the cap; no OOM.
8. **DNS / connect failure → `Network`** — `fetch` a `http://127.0.0.1:1/` (a
   port with nothing listening) → `Err(LoadError::Network(_))`. (Connection
   refused path; fast, no external DNS.)
9. **`RouterLoader` dispatch** — one `RouterLoader`: `fetch(file://temp.txt)` →
   local bytes; `fetch(http://127.0.0.1:<port>/x)` → served bytes; `fetch(ftp://…)`
   → `UnsupportedScheme("ftp")`. (Proves per-scheme routing in one loader.)

### 7.3 End-to-end render-over-HTTP (paint or a `net`+`paint` integration test)

A `tiny_http` server serving a *page*: `GET /` → HTML
`<link rel=stylesheet href="theme.css"><body><p>hi</p><img src="px.png">`;
`GET /theme.css` → `p{color:blue}`; `GET /px.png` → the 2×2 PNG. Then:

```rust
let (base_str, _guard) = serve(page_routes);
let base = Url::parse(&format!("{base_str}/")).unwrap();
let loader = RouterLoader::new();
let html = String::from_utf8_lossy(&loader.fetch(&base).unwrap().bytes).into_owned();
let pm = render_document(&html, &base, 200.0, &loader);
// CSS fetched over HTTP applied → text is blue:
assert!(has_color(&pm, |r,g,b| b > 120 && r < 80 && g < 80));
// image fetched over HTTP decoded → its pixel present somewhere.
```

This proves the headline done-when: *rendering a remote URL fetches and applies
its CSS + images*, against a local fixture, deterministically. (If kept in
`paint`, add `tiny_http` to `crates/paint` `[dev-dependencies]` and a `net`
re-export of `RouterLoader`; alternatively put this in a `crates/net/tests/` or
`crates/cli/tests/` integration test. Implementation agent picks the lightest
placement — likely the `net` unit test for the loader cases (1–9) and one paint
integration test for the render-over-HTTP case.)

### 7.4 What we don't test automatically

- **HTTPS/TLS** (self-signed loopback cert rejected by webpki-roots) — covered by
  a manual smoke (`starfish render https://example.com …`) noted in §8, not CI.
- Real-internet hosts (non-deterministic) — never in unit tests.

## 8. Edge cases & non-goals (deliberate deviations)

**Handled:**
- `http://` and `https://` document + sub-resource fetch via `HttpLoader`.
- Mixed-scheme pages (remote page → `file://` or another `http` resource; local
  page → `http` resource) via `RouterLoader` per-resolved-URL routing.
- Relative `href`/`src` on a remote page resolve to the page's scheme/host
  (`base.join`, E3-M1) → routed back through HTTP.
- Redirects (≤10), 4xx/5xx → `Http`, timeout → `Timeout`, DNS/connect/TLS →
  `Network`, over-size body → `Network`. Sub-resource failures are skipped (page
  still renders); document failure → clean CLI error + non-zero exit. **No
  panics.**
- `Content-Type` captured into `Resource.content_type` (consumed in M3).
- `User-Agent: starfish-rs/<version>` on every request.

**Explicit non-goals (documented limitations):**
- **No cookies, no auth (`Authorization`), no cookie jar.**
- **No HTTP caching** — no `Cache-Control`/`ETag`/conditional requests; every
  fetch hits the network. (An in-memory per-URL dedupe cache is **E3-M3**.)
- **No CORS, no mixed-content policy** — any scheme/origin a resolved URL points
  at is fetched (local rendering tool, not a browser security context).
- **No `data:` URLs** — `UnsupportedScheme("data")` until E3-M3.
- **No streaming / incremental render** — fetch-then-render (body read fully,
  capped, before parsing). Consistent with the rest of the engine.
- **No manual compression handling** — only whatever ureq does by default; we
  set no `Accept-Encoding`.
- **No charset detection** — HTML/CSS bytes decoded as UTF-8
  (`from_utf8_lossy`); `content_type` charset is ignored in M2 (M3).
- **No HTTP/2-specific tuning** — whatever ureq negotiates by default over its
  rustls connection; we make no version assumptions.
- **TLS: rustls + webpki-roots (Mozilla roots), no system trust store, no cert
  pinning.** Real HTTPS to public sites with valid certs works; self-signed/test
  certs fail (hence loopback tests use plain HTTP). No client certs.
- **Redirect target schemes** aren't restricted beyond what ureq follows; we
  don't, e.g., block `https→http` downgrades (no mixed-content policy, above).

## 9. Module layout & implementation order

```
crates/net/
  Cargo.toml          # + ureq (rustls, no-default-features); + [dev] tiny_http
  src/lib.rs          # + mod http; mod router; pub use HttpLoader, RouterLoader
  src/loader.rs       # + LoadError::{Http,Timeout,Network} + Display arms (§5)
  src/http.rs         # NEW: HttpLoader, build_agent, read_capped, error mapping (§2,§6)
  src/router.rs       # NEW: RouterLoader scheme dispatch (§3)
  (tests in http.rs/router.rs use tiny_http; §7.1–7.2)
crates/paint/
  src/lib.rs          # + render_url(url, width) (§4.1); re-export RouterLoader
  (optional integration test: render-over-HTTP, §7.3)
crates/cli/
  src/main.rs         # RouterLoader instead of LocalLoader; drop http stub;
                      #   + --timeout flag; updated USAGE (§4.2)
```

Implementation order (each step independently verifiable):

1. **`LoadError` variants** (`loader.rs`) + Display/source arms. `cargo build -p
   starfish-net`. (No behavior yet; unblocks the loader.)
2. **`HttpLoader`** (`http.rs`) + `ureq` dep + `build_agent`/`read_capped`/error
   mapping. Add `tiny_http` dev-dep + the `serve` harness. Tests §7.2 cases 1–8.
   `cargo test -p starfish-net` green. **(This is the milestone's core.)**
3. **`RouterLoader`** (`router.rs`) + lib re-exports. Test §7.2 case 9. Green.
4. **paint `render_url`** + `RouterLoader` re-export; render-over-HTTP
   integration test §7.3. `cargo test -p starfish-paint` green.
5. **CLI**: swap to `RouterLoader`, drop the http stub, add `--timeout`, update
   `USAGE`. Manual smoke: `starfish render http://127.0.0.1:<fixture> -o out.png`
   (and, network permitting, a real `https://` site) renders.
6. Full `cargo test` (all crates) green. Confirm no panic on 404/timeout/DNS via
   the CLI error path.
