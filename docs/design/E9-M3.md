# E9-M3 — SVG `<text>`/`<tspan>`, `<g>`+`transform`, gradient fills (DESIGN)

Final Epic-9 milestone — completes inline SVG. Builds on the M1 painter
(`emit_svg` walks the `<svg>` DOM subtree at display-list-build time, emits
self-contained `PaintCmd::SvgShape`; `draw_svg_shape` rasterizes) and M2 (the
`<path>`/`polygon` op list). M3 adds three orthogonal features, **all inside the
paint crate's SVG painter** — no parser / layout / DOM / css changes (M1 already
lands the svg subtree case-preserved with attrs intact; gradient/text/g elements
arrive as ordinary skipped tags today):

1. **`transform="…"`** on any SVG element (translate/scale/rotate/skew/matrix),
   threaded down the DOM walk and composed with the inherited viewBox + ancestor
   `<g>` transforms.
2. **`<g>`** grouping — no geometry; recurses into children carrying the
   accumulated transform (+ basic inherited fill/stroke presentation attrs).
3. **`<text>`/`<tspan>`** — glyph runs placed at the SVG baseline `(x,y)`,
   transformed by the effective matrix.
4. **gradients** — `linearGradient`/`radialGradient` collected from `<defs>`
   (or anywhere) into an `id→gradient` registry; a `fill`/`stroke` of
   `url(#id)` resolves to a tiny-skia gradient shader (objectBoundingBox /
   userSpaceOnUse).

> **Dependency on the ANALYSIS agent (E9-M3 analysis note).** This design
> references its findings for the exact tiny-skia 0.11.4 `RadialGradient::new`
> /`LinearGradient::new`/`GradientStop` API, the SVG `transform`-list grammar,
> the gradient/`stop` grammar, and `gradientUnits`/`objectBoundingBox` mapping.
> I verified the load-bearing APIs directly against this repo's source:

## 1. `transform` attribute on any SVG element

### 1.1 Threading the current transform down the walk

Today `emit_svg` computes the viewBox transform `t:[f32;6]` once and passes it as
a fixed `transform` to `build_shape` for each **direct** child. M3 generalises
this to an **accumulated current-transform** threaded through a recursive walk:
the effective transform of an element is `parent_transform · this_element's
transform-attr matrix`. Shapes/text paint with their **effective** transform.

The current `emit_svg` body (the per-child `build_shape` loop) is replaced by a
call to a new recursive `walk_svg` seeded with the viewBox transform:

```rust
fn emit_svg(b:&LayoutBox, styled:&StyledTree, doc:&Document, out:&mut Vec<PaintCmd>) {
    let svg_id = b.style.node();
    let dest = b.dimensions().content;
    if dest.width <= 0.0 || dest.height <= 0.0 { return; }
    let vb = parse_view_box(doc.get_attribute(svg_id, "viewBox"));
    let root_t = svg_transform(dest, vb);                 // [f32;6] (M1)

    // M3: collect id→gradient once over the whole subtree (§4.2).
    let grads = collect_gradients(doc, svg_id);

    // M3: recurse the svg children with the accumulated transform + inherited
    // presentation context (fill/stroke from ancestor <g>, §2).
    let ctx = SvgCtx::root();
    for child in doc.children(svg_id) {
        walk_svg(doc, styled, child, root_t, &ctx, &grads, out);
    }
}
```

### 1.2 `parse_transform_attr` — the function list → `[f32;6]`

A `transform` attribute is a whitespace/comma-separated list of functions
applied **left-to-right** (the first transforms the coordinate system first, so
matrix-wise `M = f1·f2·…·fn`). This is the **same composition rule** as CSS
(E5-M3 §2.3): accumulate with `Transform::pre_concat`. **Reuse the tiny-skia
`Transform` math from E5-M3** (`from_row`, `from_translate`, `pre_concat`,
`from_rotate`). SVG specifics vs CSS:

- **angles are degrees** (no `deg`/`rad`/`turn` units; bare numbers in degrees) —
  unlike CSS `rotate(45deg)`. So `rotate(45)`, `skewX(30)`.
- **`rotate(angle, cx, cy)`** — optional rotation centre: rotate about `(cx,cy)`
  = `Translate(cx,cy)·Rotate(angle)·Translate(-cx,-cy)`.
- **`translate`/`scale`/`skewX`/`skewY`/`matrix(a..f)`** behave like CSS
  (translate args are user-space lengths, unitless).

```rust
/// Parse an SVG `transform` attribute (a list of functions) into a 3×2 matrix
/// a,b,c,d,e,f. LENIENT: an unknown/malformed function is skipped; an empty/
/// absent string → identity. Reuses tiny-skia `Transform` (E5-M3).
fn parse_transform_attr(s: &str) -> [f32; 6] {
    let mut acc = Transform::identity();
    for (name, args) in transform_fns(s) {            // splits "name(a,b,…) name(…)"
        if let Some(t) = transform_fn_matrix(&name, &args) {
            acc = acc.pre_concat(t);                  // f1·f2·…·fn (E5-M3 §2.3)
        }
    }
    [acc.sx, acc.ky, acc.kx, acc.sy, acc.tx, acc.ty]
}

fn transform_fn_matrix(name: &str, a: &[f32]) -> Option<Transform> {
    Some(match name {
        "translate" => Transform::from_translate(*a.first()?, a.get(1).copied().unwrap_or(0.0)),
        "scale"     => { let sx=*a.first()?; Transform::from_scale(sx, a.get(1).copied().unwrap_or(sx)) }
        "rotate"    => {
            let deg = *a.first()?;
            let r = Transform::from_rotate(deg);      // from_rotate takes DEGREES
            match (a.get(1), a.get(2)) {
                (Some(&cx), Some(&cy)) => Transform::from_translate(cx, cy)
                    .pre_concat(r).pre_concat(Transform::from_translate(-cx, -cy)),
                _ => r,
            }
        }
        "skewX" => Transform::from_row(1.0, 0.0, a.first()?.to_radians().tan(), 1.0, 0.0, 0.0),
        "skewY" => Transform::from_row(1.0, a.first()?.to_radians().tan(), 0.0, 1.0, 0.0, 0.0),
        "matrix" => { if a.len()!=6 { return None; }
                      Transform::from_row(a[0],a[1],a[2],a[3],a[4],a[5]) }
        _ => return None,                             // unknown → skip
    })
}
```

`transform_fns(s)` is a tiny scanner: read an identifier, then a parenthesised
number list (numbers split on `,`/whitespace via the existing `parse_len`-style
float scan). Lenient: stop at the first malformed token. (≈30 lines; SVG
`transform` numbers don't have the sign-as-separator quirk of path data — plain
comma/space split is fine, but `from the path lexer` may be reused if convenient.)

> `from_rotate(deg)` already exists in tiny-skia and takes **degrees** (E5-M3
> verified: `[cos,sin,-sin,cos]`, clockwise in y-down — matches SVG). So no
> `to_radians()` for rotate, but `skewX/Y` use `tan(angle.to_radians())`.

### 1.3 Composing with the inherited matrix

`walk_svg` carries `parent_t:[f32;6]` (starting at the viewBox transform). For an
element with a `transform` attr, the **effective** matrix is
`parent_t · attr_matrix` (parent applied to points last):

```rust
fn effective_transform(parent: [f32;6], attr: Option<&str>) -> [f32;6] {
    let p = Transform::from_row(parent[0],parent[1],parent[2],parent[3],parent[4],parent[5]);
    let m = match attr { Some(s) => {
        let a = parse_transform_attr(s);
        p.pre_concat(Transform::from_row(a[0],a[1],a[2],a[3],a[4],a[5]))
    }, None => p };
    [m.sx, m.ky, m.kx, m.sy, m.tx, m.ty]
}
```

This effective transform replaces the fixed `transform` argument that
`build_shape` (and the new text emitter) receive — so a `<rect transform=…>`,
a shape inside `<g transform=…>`, and a `<text transform=…>` all paint correctly
transformed, with nesting composed.

## 2. `<g>` grouping

A `<g>` has no geometry. It (a) may carry its own `transform`, composed into the
effective transform for its subtree, and (b) carries presentation attributes
(`fill`/`stroke`/`stroke-width`/…) that children **inherit** unless they override
them. M3 supports the transform fully and a **basic** fill/stroke inheritance.

### 2.1 The walk context

```rust
/// Inherited presentation context threaded down the svg walk (E9-M3 §2). Only
/// the cheap, common SVG-inherited paints; everything else is read per-element.
#[derive(Clone)]
struct SvgCtx {
    fill:    Option<String>,   // last ancestor `fill` value (verbatim), or None
    stroke:  Option<String>,
    stroke_width: Option<String>,
}
impl SvgCtx { fn root() -> Self { SvgCtx { fill:None, stroke:None, stroke_width:None } } }
```

`resolve_paints` (M1) currently reads only the element's own attrs/inline-style.
For inheritance, extend its `prop(name)` lookup with one more fallback level:
**element inline-style → element attr → inherited ctx → SVG initial**. Concretely
`resolve_paints` gains a `&SvgCtx` param; its `prop` closure tries `ctx.fill`
(resp. stroke / stroke_width) before falling to the initial. `currentColor` and
opacity stay per-element (not threaded — keep simple). This is a small, additive
change to the existing M1 function.

### 2.2 The recursion

```rust
fn walk_svg(doc, styled, id:NodeId, parent_t:[f32;6], ctx:&SvgCtx,
            grads:&GradientRegistry, out:&mut Vec<PaintCmd>) {
    let Some(tag) = doc.tag_name(id) else { return };   // skip text/comment nodes here
    let eff = effective_transform(parent_t, doc.get_attribute(id, "transform"));

    match tag {
        "g" | "svg" => {                                // nested <svg> treated as a group (M1 note)
            let child_ctx = ctx.inherit(doc, id);       // fold this g's fill/stroke into ctx
            for c in doc.children(id) {
                walk_svg(doc, styled, c, eff, &child_ctx, grads, out);
            }
        }
        "defs" => {}                                    // collected separately (§4.2); paints nothing
        "linearGradient" | "radialGradient" | "stop" | "title" | "desc" | "metadata" => {}
        "text" => emit_svg_text(doc, styled, id, eff, ctx, grads, out),
        // rect/circle/ellipse/line/path/polygon/polyline → M1/M2 build_shape,
        // now resolving url(#…) paints + inherited ctx (§4.3).
        _ => {
            if let Some(cmd) = build_shape(doc, styled, id, eff, ctx, grads) {
                out.push(cmd);
            }
        }
    }
}
```

`ctx.inherit(doc, id)` returns a child `SvgCtx` where each of fill/stroke/
stroke_width is the element's own attr/inline-style value if present, else the
parent's (so a `<g fill=red>` sets red for descendants that don't override).
Cheap: three `get_attribute`/`svg_style_prop` reads.

> `<g>` does not clip or establish a new viewport; its only effects in M3 are the
> transform composition and the inherited paints. `opacity` on a `<g>` (group
> opacity) is deferred (§6).

## 3. `<text>` / `<tspan>`

### 3.1 SVG text positioning

`<text x y …>` renders its text content with the **baseline** start at `(x, y)`
(user space) — note SVG `y` is the baseline, **not** the top-left (unlike the
HTML `GlyphRun` whose `origin` is the content-box top-left and baseline =
`origin.y + ascent`). Glyphs advance rightward from `x`. The font face comes from
`font-family`/`font-size`/`font-weight`/`font-style` attrs (or inline `style`);
`fill` is the text color. The whole run is painted **transformed by the effective
matrix** (so a rotated/translated `<text>` rotates/translates).

### 3.2 Emitting text — reuse `GlyphRun`, wrap in a transform layer

`GlyphRun` does **not** carry a transform, and the glyph rasterizer
(`draw_glyph_run` → `blit_coverage`) blits fontdue coverage masks directly with
no matrix (fontdue exposes no public outline path, only coverage bitmaps —
verified). Two options:

- **(A) New `PaintCmd::SvgText{ origin, text, font…, fill, transform }`** + a new
  `draw_svg_text` that rasterizes glyphs into a temp pixmap and composites with
  the transform — heavy, duplicates glyph logic.
- **(B chosen) Reuse `GlyphRun`, bracketed by `PushTransform/PopTransform`.**
  The E5-M3 transform-layer machinery already paints a subtree into a full-canvas
  offscreen pixmap and composites it back through a `[f32;6]` matrix
  (`composite_transform_layer`, bilinear). Emit the SVG glyph run **in canvas
  coords with the effective matrix's translation already giving the baseline
  origin** — but a glyph run can't bake a full affine (rotation/scale) into its
  pen walk. So: wrap the run in a `PushTransform{matrix:eff}` / `PopTransform`
  pair and emit the `GlyphRun` in **user space** (origin at `(x, y-ascent)` so the
  baseline lands at `y`). The transform layer then applies `eff` (viewBox · g ·
  text) to the rasterized glyphs.

**(B)** reuses the font system, the existing `GlyphRun` command, AND the existing
transform compositor — zero new raster code, zero new command. This matches the
milestone "reuse the font system + a transform" guidance.

```rust
fn emit_svg_text(doc, styled, id:NodeId, eff:[f32;6], ctx:&SvgCtx,
                 grads:&GradientRegistry, out:&mut Vec<PaintCmd>) {
    // 1. Font + fill from attrs/inline-style (+ inherited ctx for fill).
    let font = svg_font(doc, styled, id, ctx);           // FontQuery-shaped owned data
    let fill = resolve_text_fill(doc, styled, id, ctx, grads, /*bbox*/ None);
    let Some(color) = fill_solid(fill) else { return };  // gradient text → §3.5 note

    // 2. Baseline origin (x,y); text-anchor shifts x (§3.4).
    let x0 = attr_f(doc, id, "x");
    let y  = attr_f(doc, id, "y");
    let lm = fonts.line_metrics(&font.query());          // ascent

    // 3. Concatenate this <text> + <tspan> runs (§3.3) → segments with x/anchor.
    let runs = collect_text_runs(doc, id, x0, y, &font);

    // 4. Wrap in the effective transform; emit a GlyphRun per segment in user
    //    space (origin.y = baseline_y - ascent so the baseline lands at y).
    out.push(PaintCmd::PushTransform { matrix: eff });
    for seg in runs {
        out.push(PaintCmd::GlyphRun {
            origin: (seg.x, y - lm.ascent),
            text: seg.text, font_size: font.size, weight: font.weight,
            style: font.style, family: font.family.clone(),
            color, ascent: lm.ascent, letter_spacing: 0.0, word_spacing: 0.0,
        });
    }
    out.push(PaintCmd::PopTransform);
}
```

> Why `origin.y = y - ascent`: `draw_glyph_run` computes `baseline = origin.1 +
> ascent`, then places each glyph at `baseline - g.top`. So to put the baseline at
> SVG `y`, set `origin.1 = y - ascent`. `origin.0 = x` directly (pen starts at x).

`svg_font` reads:
- `font-size`: `parse_len` (px/unitless), default 16.
- `font-family`: split on `,`, trim quotes → `Vec<String>`; empty → the
  element's CSS `font_family` (`styled.get(id)`) or sans-serif default.
- `font-weight`: `bold`→700, numeric→that, else 400. `font-style`:
  `italic`/`oblique`→that, else normal.
All also readable from inline `style` via the existing `svg_style_prop`.

### 3.3 `<tspan>` (basic)

A `<text>` may contain bare text **and** `<tspan>` children. M3 supports:
- **inline continuation**: a `<tspan>` with no `x`/`y` continues the pen from
  where the previous run ended (advance accumulates across segments).
- **absolute repositioning**: a `<tspan x=… y=…>` starts a new segment at its own
  baseline `(x,y)` (a `tspan` may override either axis; M3: if `x` set use it,
  if `y` set use it, else inherit the running pen / parent baseline).
- a `<tspan>` may carry its own `fill`/`font-*` — basic: read them, falling back
  to the parent text's. (M3 keeps one font per text element if simplest; a
  per-tspan font is a cheap extension — note.)

`collect_text_runs(doc, text_id, x0, y, font)` walks `doc.children(text_id)`:
- a `NodeKind::Text(s)` child → a segment `{ x: pen_x, text: s }`; advance
  `pen_x += measure(s, font)` (reuse `FontDb::advance_width` via the measurer, or
  sum `rasterize_glyph().advance` — but display.rs has the `FontDb` already for
  `line_metrics`; use `fonts.advance_width`).
- a `<tspan>` child → recurse: its own text contributes a segment at its `x`
  (anchor-resolved) or the running pen; nested tspans handled by recursion.
- whitespace handling: SVG default `xml:space` collapses runs of whitespace to a
  single space (like HTML). M3: apply the same simple collapse used elsewhere, or
  pass the text through verbatim and accept minor spacing differences (note).

`measure` needs the `FontDb`; thread `fonts:&FontDb` into the svg walk (emit_svg
already only has `styled`/`doc`/`out` — **add `fonts:&FontDb`**, available at the
`emit_self` call site which already passes `fonts` to `emit_text`/`emit_image`).

### 3.4 `text-anchor` (basic)

`text-anchor: start|middle|end` shifts the run's x by `0 / -w/2 / -w` where `w`
is the measured run width. M3: measure the full text width once, apply the shift
to the start x. (`start` is the default.) Multi-segment tspan anchoring is
approximated by anchoring the whole concatenated run. Note in §6.

### 3.5 Gradient/transform on text

- The effective matrix already rotates/scales the run via the transform layer.
- A `fill="url(#g)"` on `<text>` (gradient text) is **deferred**: `GlyphRun`
  carries a solid `color` only. M3 resolves a `url(#…)` text fill to the
  gradient's **first stop color** (a reasonable solid fallback) rather than a
  per-glyph shader — noted §6. (Gradient-filled shapes are fully supported; only
  gradient *text* falls back to a solid.)

## 4. Gradients (`linearGradient`/`radialGradient` + `url(#id)`)

### 4.1 The gradient model (paint-local)

A resolved gradient carries its stops + geometry + units. Define a paint-local
type (display.rs); the `SvgShape.fill`/`.stroke` become an `SvgPaint` that is
either a solid color or a gradient:

```rust
/// A resolved SVG paint: a solid color or a gradient (E9-M3 §4).
#[derive(Debug, Clone, PartialEq)]
enum SvgPaint {
    Color(Rgba),
    Gradient(SvgGradient),
}

/// A gradient fully resolved at build time except the objectBoundingBox→user
/// mapping, which raster applies once it knows the shape's bbox (E9-M3 §4.4).
#[derive(Debug, Clone, PartialEq)]
struct SvgGradient {
    kind: GradKind,                 // Linear{x1,y1,x2,y2} | Radial{cx,cy,r}
    stops: Vec<starfish_style::GradientStop>,   // reuse {color, pos} (resolve_stops-compatible)
    units: GradUnits,               // ObjectBoundingBox (default) | UserSpaceOnUse
}
#[derive(Debug, Clone, Copy, PartialEq)]
enum GradKind {
    Linear { x1:f32, y1:f32, x2:f32, y2:f32 },  // defaults 0,0,1,0 (objBox) per spec
    Radial { cx:f32, cy:f32, r:f32 },           // defaults .5,.5,.5
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum GradUnits { ObjectBoundingBox, UserSpaceOnUse }
```

`SvgShape.fill: Option<Rgba>` / `.stroke: Option<Rgba>` widen to
`fill: Option<SvgPaint>` / `stroke: Option<SvgPaint>`. The `SvgShape` command
also gains the shape's **user-space bbox** so raster can map objectBoundingBox
gradients without re-deriving geometry:

```rust
SvgShape {
    geom: SvgGeom, transform:[f32;6],
    fill: Option<SvgPaint>,           // CHANGED from Option<Rgba>
    fill_rule: SvgFillRule,
    stroke: Option<SvgPaint>,         // CHANGED
    stroke_width: f32, stroke_cap, stroke_join,
    bbox: Rect,                       // NEW: user-space bounding box of `geom`
}
```

`bbox` is computed in `build_shape` from the geometry (rect → its x/y/w/h;
ellipse → cx±rx,cy±ry; line → endpoints; path → min/max over the op points). A
helper `geom_bbox(&SvgGeom) -> Rect`.

### 4.2 The gradient registry (collected once)

At the start of `emit_svg`, walk the whole svg subtree collecting every
`linearGradient`/`radialGradient` by `id` into an `id→SvgGradient` map. Gradients
may live in `<defs>` or anywhere; collect regardless of nesting.

```rust
type GradientRegistry = std::collections::HashMap<String, SvgGradient>;

fn collect_gradients(doc:&Document, svg_id:NodeId) -> GradientRegistry {
    let mut reg = HashMap::new();
    collect_gradients_rec(doc, svg_id, &mut reg);
    reg
}
// DFS: on a linearGradient/radialGradient with an `id`, parse it (+ its <stop>
// children) into an SvgGradient and insert. Recurse into all element children.
```

Parsing one gradient:
- **common**: `id` (required to be referenced), `gradientUnits`
  (`userSpaceOnUse` → UserSpaceOnUse, else ObjectBoundingBox default),
  `<stop offset stop-color stop-opacity>` children → `GradientStop{ color, pos }`
  where `color = parse_color(stop-color)` with alpha folded by `stop-opacity`,
  `pos = parse_offset(offset)` (`"50%"`→0.5, `"0.5"`→0.5; clamp 0..1). Stops are
  read in document order; `resolve_stops` (M1) already spreads `None`/enforces
  monotonic — but here offsets are usually explicit. Need ≥1 stop; <1 → the
  gradient resolves to no paint (treated as none).
- **linearGradient**: `x1 y1 x2 y2` (objBox defaults `0,0,1,0` = left→right;
  userSpace defaults likewise but in user units). Coords parsed by `parse_len`
  (and `%` → fraction for objBox; for userSpace `%` is relative to viewport —
  M3 treats `%` as a fraction only under objBox, plain number under userSpace).
- **radialGradient**: `cx cy r` (objBox defaults `0.5,0.5,0.5`). `fx`/`fy` focal
  point deferred (§6).
- `gradientTransform`, `spreadMethod`, `xlink:href` stop inheritance → deferred
  (§6): `spreadMethod` always Pad; no gradientTransform.

### 4.3 Resolving `fill`/`stroke` → `SvgPaint`

`resolve_paints` (M1) currently returns `Option<Rgba>` for fill/stroke. Extend
its paint resolution: if the value matches `url(#id)`, look up `id` in the
registry → `SvgPaint::Gradient(g.clone())`; else the existing solid path →
`SvgPaint::Color`. A `url(#missing)` → **no paint** (`None`) per the simplest
lenient rule (spec actually says fall back to any following color or none; M3:
none — note §6).

```rust
fn parse_svg_paint(value:Option<&str>, default:Option<Rgba>, current:Rgba,
                   grads:&GradientRegistry) -> Option<SvgPaint> {
    let v = value?.trim();
    if let Some(id) = parse_url_ref(v) {                 // "url(#g)" → "g"
        return grads.get(id).cloned().map(SvgPaint::Gradient);   // missing → None
    }
    parse_paint(Some(v), default, current).map(SvgPaint::Color)  // reuse M1 (none/currentColor/color)
}
```

`parse_url_ref("url(#g)") -> Some("g")` is a trivial prefix/suffix strip. Opacity
folding: for a solid `SvgPaint::Color`, fold `op*fo` as M1 does; for a gradient,
fold the alpha into each stop's color (cheap; or skip and note — M3: fold into
stops so `fill-opacity` works on gradients too).

### 4.4 raster: build the tiny-skia shader

`draw_svg_shape` gains the `bbox` + takes `fill/stroke: Option<SvgPaint>`. For a
solid it does exactly what M1 does. For a gradient it builds the shader, mapping
objectBoundingBox coords through the shape's bbox:

```rust
fn svg_gradient_shader(g:&SvgGradient, bbox:&Rect) -> Option<Shader<'static>> {
    let stops = resolve_stops(&g.stops);                 // REUSE M1 (Vec<SkStop>)
    // Map a (possibly 0..1 objBox) coordinate to user space.
    let map = |ux:f32, uy:f32| -> (f32,f32) {
        match g.units {
            GradUnits::ObjectBoundingBox =>
                (bbox.x + ux*bbox.width, bbox.y + uy*bbox.height),
            GradUnits::UserSpaceOnUse => (ux, uy),
        }
    };
    match g.kind {
        GradKind::Linear { x1,y1,x2,y2 } => {
            let (sx,sy)=map(x1,y1); let (ex,ey)=map(x2,y2);
            SkGradient::new(Point::from_xy(sx,sy), Point::from_xy(ex,ey),
                            stops, SpreadMode::Pad, Transform::identity())
        }
        GradKind::Radial { cx,cy,r } => {
            let (ccx,ccy)=map(cx,cy);
            // objBox radius scales by the bbox; approximate with the mean extent
            // (a true objBox radial is elliptical — M3 uses an averaged radius, §6).
            let rr = match g.units {
                GradUnits::ObjectBoundingBox => r * (bbox.width + bbox.height) / 2.0,
                GradUnits::UserSpaceOnUse => r,
            };
            let c = Point::from_xy(ccx, ccy);
            SkRadial::new(c, c, rr, stops, SpreadMode::Pad, Transform::identity())  // start==end center
        }
    }
}
```

Then in `draw_svg_shape`, for the fill (and stroke) branch:

```rust
match fill {
    Some(SvgPaint::Color(c)) if c.a != 0 => { /* M1 solid path: set_color_rgba8 + fill_path */ }
    Some(SvgPaint::Gradient(g)) => {
        if let Some(shader) = svg_gradient_shader(g, bbox) {
            let paint = Paint { anti_alias:true, shader, ..Default::default() };
            pixmap.fill_path(&path, &paint, fr, t, None);   // t = effective transform
        }
    }
    _ => {}
}
```

Add `RadialGradient as SkRadial` to the `tiny_skia::{…}` import in raster.rs
(`LinearGradient as SkGradient`, `Point`, `SpreadMode`, `Shader` already
imported). The gradient is built in **user/bbox space** and the existing
effective `transform t` maps it to canvas — so a transformed gradient-filled
shape's gradient transforms with the shape. (`gradientTransform` would add a
further pre-concat; deferred.)

## 7. Test plan

Unit tests in `display.rs` (build-time emission) + `lib.rs` (pixel). Reuse the
`list(html, css)` helper (builds doc→style→layout→display list) and the `px(&pm,
x,y)` pixel helper.

### 7.1 transform attribute (`display.rs`, parse-level + emission)
- `parse_transform_attr("translate(50,0)")` → `[1,0,0,1,50,0]`.
- `parse_transform_attr("rotate(90)")` ≈ `[0,1,-1,0,0,0]` (tolerance 1e-4).
- `parse_transform_attr("rotate(90,10,10)")` → a 90° rotation about (10,10);
  maps (10,10)→(10,10) (fixed point), (20,10)→(10,20) (within 1e-3).
- `parse_transform_attr("scale(2) translate(5,5)")` → composed `f1·f2`:
  point (0,0)→(10,10) (translate first in the local frame, then scaled).
- `parse_transform_attr("matrix(1,0,0,1,30,40)")` → `[1,0,0,1,30,40]`.
- composition: a `<g transform="translate(50,0)"><rect x=0 …></g>` → the emitted
  `SvgShape.transform` translates the rect's effective matrix by +50 in x vs the
  same rect outside the `<g>` (compare `transform[4]`).

### 7.2 `<g>` (`display.rs`)
- `<g transform="translate(50,0)"><rect x=0 y=0 width=10 height=10 fill=red/></g>`
  → one `SvgShape` whose effective `transform` = viewBox·translate(50,0).
- `<g fill="red"><rect …/></g>` (rect has no own fill) → the rect's resolved
  `fill == SvgPaint::Color(red)` (inherited from the `<g>`).
- `<g>` with no transform/fill → children paint identically to being direct svg
  children (regression).

### 7.3 `<text>` (`display.rs` + pixel)
- `<text x=10 y=30 fill=red font-size=20>Hi</text>` → a `GlyphRun` bracketed by
  `PushTransform`/`PopTransform`; `text=="Hi"`, `color==red`,
  `origin == (10, 30 - ascent)` (baseline at y=30), `font_size==20`.
- pixel: render "Hi" → red pixels near `(10..~30, ~15..30)` (above the baseline),
  white well below y=30. (Sample a coarse band, not exact glyph pixels.)
- `text-anchor="middle"` → the run's start x shifts left by half the measured
  width vs `start`.
- rotated text: `<text x=0 y=0 transform="rotate(90) translate(10,0)" …>X</text>`
  → the `PushTransform.matrix` ≈ rotate90·translate; glyph lands rotated (pixel:
  colored where the rotated glyph is, not at the un-rotated position).
- `<tspan>`: `<text x=10 y=20>A<tspan>B</tspan></text>` → two GlyphRuns, the
  second starting at x = 10 + advance("A") (inline continuation). A
  `<tspan x=50 y=40>` → its GlyphRun origin uses (50, 40-ascent).

### 7.4 gradients (`display.rs` + pixel)
- registry: `<defs><linearGradient id="g"><stop offset=0 stop-color=red/>
  <stop offset=1 stop-color=blue/></linearGradient></defs>` → `collect_gradients`
  yields `g` with 2 stops (red,pos 0; blue,pos 1).
- `<rect … fill="url(#g)"/>` → `SvgShape.fill == Some(SvgPaint::Gradient(..))`,
  `bbox` = the rect's user rect.
- **linear pixel** (objBox default, 100×100 svg, rect 10,10,80,80, gradient
  red→blue x1=0→x2=1): left edge of the rect (≈x=15) red-dominant, right edge
  (≈x=85) blue-dominant; r decreases / b increases left→right.
- **userSpaceOnUse**: `linearGradient gradientUnits="userSpaceOnUse" x1=0 y1=0
  x2=100 y2=0` over the same rect → gradient spans the user viewport, not the
  rect; assert a different left/right split than objBox.
- **radialGradient**: `<radialGradient id=r cx=.5 cy=.5 r=.5>` red→blue on a rect
  → center red-dominant, corners blue-dominant.
- composition: nested `<g transform>` around a gradient rect → the gradient
  transforms with the shape (the gradient axis rotates).
- `url(#missing)` → `fill == None` → no `SvgShape` emitted for that rect (no fill,
  no stroke). Assert no paint command for it.
