# E8-M1 — DOM surface APIs for JS: `innerHTML`/`outerHTML`, `getComputedStyle`, `cloneNode`, `insertAdjacentHTML`, `remove`, element navigation (design note)

Scope (per `docs/ROADMAP-epic8.md`): extend the existing E4-M2/M3 Boa DOM bindings with the
DOM-surface APIs real scripts reach for:

- `innerHTML` — **read** (serialize the element's child subtrees to an HTML string) +
  **write** (parse an HTML fragment and replace the element's children with the parsed nodes).
- `outerHTML` — **read** (serialize the element itself, open tag → children → close tag).
- `getComputedStyle(el)` — a **read-only** object of resolved computed-style values (color,
  font-size, display, width, …) as strings.
- `cloneNode(deep)` — deep/shallow copy a node subtree, returning a new **detached** node.
- `insertAdjacentHTML(position, html)` — parse a fragment + graft at
  `beforebegin`/`afterbegin`/`beforeend`/`afterend`.
- `Element.remove()` — detach self from its parent.
- Element-navigation helpers: `children` (already present), `firstElementChild`,
  `lastElementChild`, `nextElementSibling`, `previousElementSibling`, `childElementCount`
  (reusing the E7-M1 `starfish-dom` element-sibling helpers).

All on the **existing** `Node` Boa class (`crates/js/src/dom/`); no new class. The companion
ANALYSIS agent is the authority on the Boa 0.21.1 accessor/object/getter-setter shapes; this note
pins to the **real current source** (quoted as read) for `starfish-{dom,html,css,style,js}`.

Guiding rule (project CLAUDE.md "Simplicity First / Surgical Changes"): a serializer + a
fragment-parse-and-graft arena copy (reused by `cloneNode`), an **on-demand cascade** for
`getComputedStyle` over a **subset** of properties, and the navigation/`remove` thin wrappers.
**Defer:** `outerHTML` write, `DOMParser`/`XMLSerializer`, used-value/layout geometry
(`offsetWidth`/`getBoundingClientRect`), inserted-`<script>` execution (spec: they don't run — we
keep that). Non-goals are §7.

## 1. HTML serialization (`innerHTML` / `outerHTML` read)

### 1.1 Where it lives — a new `serialize_html` in `starfish-dom`

The existing `Document::serialize` emits an S-expr test form; we need **real HTML**. Add a small
sibling method on `Document` in `crates/dom/src/lib.rs` (the arena is the natural owner — it knows
`NodeKind`, void elements, attribute order; and the `js` layer already borrows `&Document`):

```rust
impl Document {
    /// Serialize the CHILDREN of `id` to an HTML string (innerHTML read).
    pub fn inner_html(&self, id: NodeId) -> String {
        let mut out = String::new();
        for c in self.children(id) {
            self.serialize_html_into(c, &mut out);
        }
        out
    }

    /// Serialize `id` ITSELF (open tag → children → close tag) to HTML
    /// (outerHTML read). For a non-element root, falls back to inner content.
    pub fn outer_html(&self, id: NodeId) -> String {
        let mut out = String::new();
        self.serialize_html_into(id, &mut out);
        out
    }

    fn serialize_html_into(&self, id: NodeId, out: &mut String) {
        match self.kind(id) {
            NodeKind::Element(e) => {
                out.push('<');
                out.push_str(&e.name);
                for a in &e.attrs {
                    out.push(' ');
                    out.push_str(&a.name);
                    out.push_str("=\"");
                    escape_attr(&a.value, out);   // escapes & and "
                    out.push('"');
                }
                out.push('>');
                if is_void(&e.name) {
                    return;                        // void: no children, no close tag
                }
                for c in self.children(id) {
                    self.serialize_html_into(c, out);
                }
                out.push_str("</");
                out.push_str(&e.name);
                out.push('>');
            }
            NodeKind::Text(t) => escape_text(t, out),   // escapes & < >
            NodeKind::Comment(c) => {
                out.push_str("<!--");
                out.push_str(c);                          // comments are NOT escaped
                out.push_str("-->");
            }
            NodeKind::Doctype(d) => {
                out.push_str("<!DOCTYPE ");
                out.push_str(&d.name);
                out.push('>');
            }
            NodeKind::Document => {
                for c in self.children(id) {
                    self.serialize_html_into(c, out);
                }
            }
        }
    }
}
```

### 1.2 Escaping rules (HTML5 fragment-serialization algorithm, the pragmatic subset)

Two contexts, matching the spec's "escaping a string":

- **Text node** (`escape_text`): `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;`. (Quotes are NOT escaped in
  text.)
- **Attribute value** (`escape_attr`): `&`→`&amp;`, `"`→`&quot;`. (`<`/`>` are NOT escaped inside
  attribute values per the spec; `\u{00A0}`→`&nbsp;` is part of the spec but **deferred** — plain
  NBSP round-trips fine for our renderer; note §7.)

```rust
fn escape_text(s: &str, out: &mut String) {
    for ch in s.chars() {
        match ch {
            '&' => out.push_str("&amp;"),
            '<' => out.push_str("&lt;"),
            '>' => out.push_str("&gt;"),
            _ => out.push(ch),
        }
    }
}
fn escape_attr(s: &str, out: &mut String) {
    for ch in s.chars() {
        match ch {
            '&' => out.push_str("&amp;"),
            '"' => out.push_str("&quot;"),
            _ => out.push(ch),
        }
    }
}
```

### 1.3 Void elements

```rust
fn is_void(name: &str) -> bool {
    matches!(name,
        "area"|"base"|"br"|"col"|"embed"|"hr"|"img"|"input"|"link"|
        "meta"|"param"|"source"|"track"|"wbr")

```

## 2. HTML fragment parse + graft (`innerHTML` write / `insertAdjacentHTML`)

### 2.1 The deep-graft: copy a subtree from a throwaway Document into the live arena

The core primitive — copy a node + descendants **from one `Document` into another** (or within
the same one, §3), minting **new** `NodeId`s in the destination, returning the new root. Lives in
`starfish-dom` (it needs `node_mut`/creation and only the arena can mint ids):

```rust
impl Document {
    /// Deep-copy the subtree rooted at `src_id` (which lives in `src`) into
    /// `self`, minting fresh detached nodes. Returns the new root's NodeId in
    /// `self`. The new subtree is DETACHED (caller attaches it). Skips nothing —
    /// elements, text, comments are copied; Document/Doctype roots are not
    /// expected as a graft root (callers pass element/text/comment children).
    pub fn import_subtree(&mut self, src: &Document, src_id: NodeId) -> NodeId {
        let new_id = match src.kind(src_id) {
            NodeKind::Element(e) => {
                let id = self.create_element(&e.name);
                for a in &e.attrs {
                    self.set_attribute(id, &a.name, &a.value);
                }
                id
            }
            NodeKind::Text(t) => self.create_text(t),
            NodeKind::Comment(c) => self.create_comment(c),
            NodeKind::Doctype(d) => self.create_doctype(&d.name),
            NodeKind::Document => self.create_element("div"), // defensive; not reached
        };
        for child in src.children(src_id) {
            let new_child = self.import_subtree(src, child);
            self.append_child(new_id, new_child);
        }
        new_id
    }
}
```

`set_attribute` re-lowercases the name (already lowercased in `src`) and preserves value verbatim,
so attributes survive. `create_element` re-lowercases the tag (already lowercased). Children are
appended in document order, links stay consistent (reuses `append_child`).

### 2.2 The fragment parse + replace (innerHTML write)

`set_inner_html` parses the HTML string as a **throwaway full Document**, lifts the **`<body>`'s
child subtrees** (the implied-skeleton parse always nests content under `html>body`), imports each
into the live arena, removes the target's existing children, then appends the imports:

```rust
fn set_inner_html(this: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let html = arg_str(args, 0, ctx)?;                 // existing helper (node.rs:56)
    let frag = starfish_html::parse(&html);            // throwaway Document
    let body = find_body(&frag);                       // first <body> in `frag`
    let roots: Vec<NodeId> = body.map(|b| frag.children(b)).unwrap_or_default();

    let mut doc = h.shared.borrow_mut();
    // 1. remove all existing children of the target.
    for c in doc.children(h.id) {
        doc.detach(c);
    }
    // 2. import each fragment-body child and append under the target.
    for r in roots {
        let new = doc.import_subtree(&frag, r);
        doc.append_child(h.id, new);
    }
    Ok(JsValue::undefined())
}
```

- **`find_body`** is the same DFS already in `lib.rs:173` (first `tag_name == "body"`); a tiny
  copy in `dom/node.rs` or a shared `dom::find_body(&Document)` helper. If the fragment somehow
  has no `<body>` (it always does given the parser's skeleton), `roots` is empty → the element is
  emptied (matches `el.innerHTML=""`).
- **Inserted `<script>`s do NOT execute** (HTML5: scripts inserted via innerHTML are not run).
  This falls out for free: `run_scripts` already collected + ran the page scripts **before** any
  innerHTML write; the grafted `<script>` element is just an inert DOM node — we never re-scan for
  scripts. Note §7.
- The throwaway `frag` Document is dropped at function end; only the imported (re-id'd) copies
  remain in the live arena. No stale `NodeId`s leak across documents.
- **Borrow discipline:** the parse happens **before** `borrow_mut()`; the import + append all run
  under one `borrow_mut`, dropped at scope end. No JS re-entry while borrowed.

### 2.3 `insertAdjacentHTML(position, html)` — graft at a relative position

A **method** on the `Node` class. Same parse+import, but the imported roots attach relative to the
target per `position` (case-insensitive):

```rust
fn insert_adjacent_html(this: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let pos = arg_str(args, 0, ctx)?.to_ascii_lowercase();
    let html = arg_str(args, 1, ctx)?;
    let frag = starfish_html::parse(&html);
    let roots: Vec<NodeId> = find_body(&frag).map(|b| frag.children(b)).unwrap_or_default();

    let mut doc = h.shared.borrow_mut();
    match pos.as_str() {
        "afterbegin" => {
            // import in reverse, insert_before the current first child each time
            // so document order is preserved at the front.
            let first = doc.first_child(h.id);
            for r in roots {
                let new = doc.import_subtree(&frag, r);
                let _ = doc.insert_before(h.id, new, first);
            }
        }
        "beforeend" => {
            for r in roots {
                let new = doc.import_subtree(&frag, r);
                doc.append_child(h.id, new);
            }
        }
        "beforebegin" | "afterend" => {
            // insert as siblings of the target in its parent.
            let Some(parent) = doc.parent(h.id) else { return Ok(JsValue::undefined()) };
            let reference = match pos.as_str() {
                "beforebegin" => Some(h.id),                  // before target
                _ /* afterend */ => doc.next_sibling(h.id),   // after target
            };
            for r in roots {
                let new = doc.import_subtree(&frag, r);
                let _ = doc.insert_before(parent, new, reference);
            }
        }
        _ => {
            // invalid position → throw (spec: SyntaxError). Use JsNativeError::syntax()
            // if available in 0.21 (ANALYSIS to confirm); else JsNativeError::typ() — the
            // codebase currently only uses typ(). Caught non-fatally either way.
            return Err(JsNativeError::typ()
                .with_message("invalid insertAdjacentHTML position").into());
        }
    }
    Ok(JsValue::undefined())
}
```

For `afterbegin`, importing in forward order and inserting each `insert_before(first)` would
**reverse** the fragment; the clean fix is to import all roots first into a `Vec<NodeId>`, then
insert that vec in order before `first` (or import reversed). Implementation picks the order-
correct path; the snippet shows intent. `beforebegin`/`afterend` on a parentless (root/detached)
element are no-ops (spec throws, but a no-op is the non-fatal pragmatic choice — note §7).

## 3. `cloneNode(deep)` — copy a subtree within the SAME arena

Reuses the deep-graft logic, source == destination == the live arena. A shallow clone copies only
the node itself (tag + attrs, or text/comment data); a deep clone copies descendants.

Arena method (mirrors `import_subtree` but `src == self`, so it can't hold an `&self` + `&mut
self` simultaneously — split shallow-copy + recurse):

```rust
impl Document {
    /// Shallow-copy `id` (tag+attrs, or text/comment data) into a new detached
    /// node. No children.
    pub fn clone_node_shallow(&mut self, id: NodeId) -> NodeId {
        match self.kind(id).clone() {            // NodeKind: Clone (lib.rs:31)
            NodeKind::Element(e) => {
                let new = self.create_element(&e.name);
                for a in &e.attrs { self.set_attribute(new, &a.name, &a.value); }
                new
            }
            NodeKind::Text(t) => self.create_text(&t),
            NodeKind::Comment(c) => self.create_comment(&c),
            NodeKind::Doctype(d) => self.create_doctype(&d.name),
            NodeKind::Document => self.create_element("div"), // not reached
        }
    }

    /// Deep clone `id` (subtree) into a new detached subtree; returns its root.
    pub fn clone_node_deep(&mut self, id: NodeId) -> NodeId {
        let new = self.clone_node_shallow(id);
        for child in self.children(id) {
            let nc = self.clone_node_deep(child);
            self.append_child(new, nc);
        }
        new
    }
}
```

`self.kind(id).clone()` takes a snapshot so the subsequent `&mut self` creation is borrow-clean.
`children(id)` is a fresh `Vec` (no borrow held during the recursive `&mut` calls). The clone is
**detached** (no parent) — matching `cloneNode`'s contract.

JS binding (`dom/node.rs`), a method:
```rust
fn clone_node(this: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let deep = args.first().map(|v| v.to_boolean()).unwrap_or(false);
    let new_id = {
        let mut doc = h.shared.borrow_mut();
        if deep { doc.clone_node_deep(h.id) } else { doc.clone_node_shallow(h.id) }
    };
    Ok(wrap_node(new_id, ctx)?.into())   // wrap → identity cache (returns a NEW wrapper)
}
```
Wired: `method(class, "cloneNode", 1, clone_node)`. The cloned node is new + detached; the script
attaches it with `appendChild`/`insertBefore` (existing).

## 4. `getComputedStyle(el)` — the hard part: on-demand cascade

### 4.1 The ordering problem

In `render_document` the order is `parse → run_scripts → collect_author_sheets → style_tree`. So
**at script time neither the author sheet list nor the `StyledTree` exists**. `getComputedStyle`
must produce **resolved/computed** values (cascade + inheritance) for an element on demand.

### 4.2 Decision — collect author sheets BEFORE scripts; cascade on demand via `style_tree`

The **only** public cascade entry is `style_tree(&Document, &[Stylesheet]) -> StyledTree`
(whole-tree). Rather than expose a per-element cascade (would require widening `cascade::cascade`
to `pub` and re-implementing inheritance threading — overkill), `getComputedStyle` runs
`style_tree` over the **current** (post-mutation-so-far) DOM + the author sheets, then reads the
queried element's `ComputedStyle` out of the returned tree.

This requires threading `&[Stylesheet]` into `run_scripts`. Two parts:

1. **Pipeline (§6):** `render_document` collects author sheets **before** `run_scripts` and passes
   them in. `run_scripts` signature gains a `sheets: &[Stylesheet]` parameter.
2. **`DomState`:** store the sheets so `getComputedStyle` can reach them. Since `Stylesheet` is
   plain data (no Boa `Gc`), add an `#[unsafe_ignore_trace]` field:

```rust
// crates/js/src/dom/mod.rs — extend DomState
#[derive(Trace, Finalize, JsData)]
pub(crate) struct DomState {
    #[unsafe_ignore_trace] pub doc: SharedDoc,
    pub cache: boa_gc::GcRefCell<HashMap<u32, JsObject>>,
    pub listeners: boa_gc::GcRefCell<HashMap<(u32, String), Vec<JsObject>>>,
    pub timers: boa_gc::GcRefCell<timer::TimerQueue>,
    /// E8-M1: author stylesheets collected BEFORE scripts, for on-demand
    /// `getComputedStyle` cascade. Plain data → ignored by the GC trace.
    #[unsafe_ignore_trace] pub author_sheets: std::rc::Rc<Vec<starfish_css::Stylesheet>>,
}
```

`install(ctx, shared, sheets)` stores `author_sheets: Rc::new(sheets.to_vec())` (or takes an
`Rc<Vec<Stylesheet>>` to avoid the clone). `run_scripts` passes the sheets through to
`dom::install` / `globals::install`.

> **Cost note:** running `style_tree` per `getComputedStyle` call is O(nodes) each call. For the
> one-shot renderer this is acceptable (getComputedStyle is rare in test/real scripts). If a hot
> loop calls it, a per-`run_scripts` memoized `StyledTree` keyed on a DOM-mutation counter is the
> obvious optimization — **not built** (Simplicity First; note §7).

### 4.3 The `getComputedStyle` global function

`getComputedStyle` is a **global function** (like `setTimeout`), registered in
`globals::install`, NOT a `document`/`Node` method (matches `window.getComputedStyle(el)`):

```rust
fn get_computed_style(_t: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<JsValue> {
    let el = match args.first().and_then(|v| v.as_object())
                       .and_then(|o| o.downcast_ref::<NodeHandle>().map(|h| h.clone())) {
        Some(h) => h,
        None => return Err(JsNativeError::typ()
            .with_message("getComputedStyle: argument is not an element").into()),
    };
    // Snapshot the sheets + run the cascade over the current DOM.
    let (computed, found) = {
        let state = ctx.realm().host_defined().get::<DomState>()
            .ok_or_else(|| JsNativeError::typ().with_message("DOM not initialized"))?;
        let sheets = state.author_sheets.clone();          // Rc clone, cheap
        let doc = state.doc.borrow();
        let tree = starfish_style::style_tree(&doc, &sheets);
        match tree.get(el.id) {
            Some(c) => (c.clone(), true),                  // ComputedStyle: Clone
            None    => (starfish_style::ComputedStyle::initial(), false),  // detached/未styled
        }
    };
    Ok(build_computed_style_object(&computed, ctx)?)       // §4.4
}
```

`tree.get(id)` returns `None` for a **detached** element (not reachable from the root walk) or a
non-element — we return the **initial** style (the spec returns resolved values; for a detached
element the pragmatic choice is the cascaded-with-no-match ≈ initial; note §7). `ComputedStyle`
and `Rgba`/`Display`/`Length` need `pub` exposure (`style_tree`, `ComputedStyle`, `initial`,
`ComputedStyle::initial` — `initial` is currently `pub` on `ComputedStyle`; the field enums are
`pub`). `ComputedStyle: Clone` (computed.rs:391 derives Clone).

### 4.4 The returned object — a read-only `CSSStyleDeclaration`-like subset

A plain Boa object (built with `ObjectInitializer`, like `el.style` in `dom/style.rs`) carrying
**string** values for a **pragmatic subset**, plus a `getPropertyValue(name)` method. The values
are formatted from the typed `ComputedStyle`:

| JS property (camelCase) | source field | format |
|---|---|---|
| `color` | `color: Rgba` | `rgb(r, g, b)` if `a==255` else `rgba(r, g, b, a/255)` |
| `backgroundColor` | `background` | `Background::Color(c)` → `rgb(...)`/`rgba(...)`; gradient → `""` |
| `display` | `display: Display` | keyword: `Display::Block`→`"block"`, `Inline`→`"inline"`, `None`→`"none"`, `Flex`→`"flex"`, `Grid`→`"grid"`, … |
| `fontSize` | `font_size: f32` | `"{n}px"` (e.g. `"16px"`) |
| `fontWeight` | `font_weight: FontWeight(u16)` | the number as a string (`"400"`, `"700"`) |
| `width` | `width: Length` | `Length::Px(n)`→`"{n}px"`, `Percent(n)`→`"{n}%"`, `Auto`→`"auto"` |
| `height` | `height: Length` | same `Length` formatting |
| `marginTop`/`Right`/`Bottom`/`Left` | `margin_*: Length` | `Length` formatting |
| `paddingTop`/`…` | `padding_*: Length` | `Length` formatting |
| `textAlign` | `text_align: TextAlign` | `"left"`/`"right"`/`"center"`/`"justify"` |
| `opacity` | `opacity: f32` | the number as a string (`"1"`, `"0.5"`) |

Helper formatters (in `dom/style.rs` or a new `dom/computed.rs`):

```rust
fn fmt_rgba(c: Rgba) -> String {
    if c.a == 255 { format!("rgb({}, {}, {})", c.r, c.g, c.b) }
    else { format!("rgba({}, {}, {}, {})", c.r, c.g, c.b, (c.a as f32) / 255.0) }
}
fn fmt_length(l: Length) -> String {
    match l {
        Length::Px(n)      => format!("{}px", fmt_num(n)),
        Length::Percent(n) => format!("{}%", fmt_num(n)),
        Length::Auto       => "auto".to_string(),
    }
}
fn fmt_num(n: f32) -> String {  // "16" not "16.0", "0.5" stays
    if n.fract() == 0.0 { format!("{}", n as i64) } else { format!("{n}") }
}
```

`build_computed_style_object` registers each property as a **data property** (read-only — the
object is a snapshot; per spec getComputedStyle is read-only, mutation throws/no-ops; we make them
plain read-only data values) and a `getPropertyValue(kebabName)` method that maps a kebab name to
the same value (a small match, reusing the formatters). The subset above covers the test plan +
common scripts; unlisted properties return `""` from `getPropertyValue`.

> **Computed, not used/layout:** these are the **cascaded+resolved** values, NOT post-layout
> geometry. `offsetWidth`/`offsetHeight`/`getBoundingClientRect`/`clientWidth` need the layout tree
> (only built in `paint` after scripts) and are **deferred** (§7). `width:"auto"` stays `"auto"`
> (we don't resolve it to the used pixel width — that's layout).

## 5. Navigation helpers + `Element.remove()`

All thin wrappers over the **existing** E7-M1 arena element-sibling helpers (dom/lib.rs:313-389).
Added as **accessors/methods** on the `Node` class in `dom/node.rs`:

```rust
accessor(class, "firstElementChild", get_first_element_child, None);
accessor(class, "lastElementChild",  get_last_element_child,  None);
accessor(class, "nextElementSibling", get_next_element_sibling, None);
accessor(class, "previousElementSibling", get_prev_element_sibling, None);
accessor(class, "childElementCount", get_child_element_count, None);
method(class, "remove", 0, remove_self);
```

Implementations (each: downcast `this`, one short borrow):

```rust
fn get_first_element_child(this, _a, ctx) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let id = {
        let doc = h.shared.borrow();
        doc.children(h.id).into_iter().find(|&c| doc.tag_name(c).is_some())
    };
    wrap_opt(id, ctx)
}
fn get_last_element_child(this, _a, ctx) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let id = {
        let doc = h.shared.borrow();
        doc.children(h.id).into_iter().rev().find(|&c| doc.tag_name(c).is_some())
    };
    wrap_opt(id, ctx)
}
fn get_next_element_sibling(this, _a, ctx) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let id = h.shared.borrow().next_element_sibling(h.id);   // E7-M1 helper
    wrap_opt(id, ctx)
}
fn get_prev_element_sibling(this, _a, ctx) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let id = h.shared.borrow().prev_element_sibling(h.id);   // E7-M1 helper
    wrap_opt(id, ctx)
}
fn get_child_element_count(this, _a, _ctx) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    let doc = h.shared.borrow();
    let n = doc.children(h.id).into_iter().filter(|&c| doc.tag_name(c).is_some()).count();
    Ok(JsValue::from(n as u32))
}
fn remove_self(this, _a, _ctx) -> JsResult<JsValue> {
    let h = NodeHandle::from_this(this)?;
    h.shared.borrow_mut().detach(h.id);   // detach from parent; no-op if already detached
    Ok(JsValue::undefined())
}
```

`next_element_sibling`/`prev_element_sibling` are the exact E7-M1 helpers. `remove()` is just
`detach` (already arena-supported, re-parent-safe). No new arena method for navigation/remove.
(`firstElementChild`/`lastElementChild` don't have a dedicated arena helper, but the
`children().find(tag_name)` one-liner is trivial and matches the existing `get_children` filter in
node.rs:178; not worth a new arena method.)

## 6. Pipeline change — collect author CSS BEFORE scripts

### 6.1 The reorder

`render_document` (paint/lib.rs:179) changes from:
```
parse → run_scripts(&mut doc, base, loader) → collect_author_sheets(&doc, …) → style_tree(…) → …
```
to:
```
parse
  → author = collect_author_sheets(&doc, base, loader)     // BEFORE scripts (pre-script DOM)
  → run_scripts(&mut doc, base, loader, &author)           // sheets threaded in (§4.2)
  → author2 = collect_author_sheets(&doc, base, loader)    // RE-collect post-script (see §6.2)
  → style_tree(&doc, &author2) → load_font_faces → decode_images → layout → paint
```

`run_scripts` gains a `sheets: &[Stylesheet]` parameter (passed to `dom::install` → `DomState`).
Because `paint` depends on `js`, `collect_author_sheets` **stays in `paint`** and `render_document`
does the collecting; `js` never calls it (no cycle). `Stylesheet` is `starfish_css::Stylesheet`,
already in both crates' dep trees.

### 6.2 Collecting before scripts is sound — with one documented limitation

CSS collection (`<style>` text + `<link rel=stylesheet href>` fetch) does **not** depend on script
execution for the **initial** DOM. The one gap: a `<style>`/`<link>` **added by a script** (via
`innerHTML`/`createElement`/`insertAdjacentHTML`) won't be in the sheet list passed into
`getComputedStyle` (collected pre-script).

**Decision:** for the **final render**, **re-collect** author sheets **after** `run_scripts`
(`author2` above) so a script-injected `<style>` DOES affect the rendered PNG (the final
`style_tree` sees it). For **`getComputedStyle` during scripts**, the sheets are the **pre-script**
snapshot — a script that injects a `<style>` and immediately calls `getComputedStyle` won't see its
own injected rules. This is an **acceptable M1 limitation** (script-injected stylesheets affecting
mid-script getComputedStyle is rare); note §7. The double-collect is cheap (two DOM walks; the
`<link>` fetches hit the loader twice — for `file://`/`data:` negligible; if a real cost shows up,
cache the fetch — not built).

> Alternative considered + rejected: collect once pre-script and reuse for the final render. Then
> script-injected `<style>` wouldn't render. The double-collect is the simpler correct choice for
> the visual goal; the only cost is a second cheap walk.

## 7. Edge cases & non-goals (deliberate)

**Delivered:** `innerHTML` read (serialize children) + write (fragment parse + graft, replacing
children); `outerHTML` read; `getComputedStyle(el)` → read-only object over a resolved-value subset
(color, backgroundColor, display, fontSize, fontWeight, width, height, margins, paddings,
textAlign, opacity) + `getPropertyValue`; `cloneNode(deep)`; `insertAdjacentHTML` (4 positions);
`Element.remove()`; `firstElementChild`/`lastElementChild`/`nextElementSibling`/
`previousElementSibling`/`childElementCount`.

**Non-goals / documented limits:**
- **`outerHTML` write** (replace the element itself with parsed nodes) — **deferred** (read only).
  It needs parent-context-aware parsing; rare. Note.
- **`DOMParser`/`XMLSerializer`/`document.write`** — out.
- **Inserted `<script>` execution** — innerHTML/insertAdjacentHTML-grafted `<script>`s do **NOT**
  run (HTML5 spec; we keep this by never re-scanning for scripts after the initial run). Inline
  event handler attributes on grafted nodes likewise won't auto-fire (no event after quiescence).
- **getComputedStyle used/layout values** — `offsetWidth`/`offsetHeight`/`clientWidth`/
  `getBoundingClientRect`/`scrollWidth` need the layout tree (built post-script in `paint`) — all
  **deferred**. getComputedStyle returns **computed** values, not used geometry (`width:auto` stays
  `"auto"`). Note.
- **getComputedStyle of a detached/未styled element** → the **initial** computed style (no cascade
  match), not a throw. Pragmatic.
- **getComputedStyle ignoring script-injected `<style>` mid-script** — sheets are the pre-script
  snapshot (§6.2). The **final render** does see script-injected `<style>` (re-collect).
- **getComputedStyle property subset** — only the ~12 listed properties + `getPropertyValue`;
  unlisted → `""`. The pseudo-element second arg (`getComputedStyle(el, "::before")`) is **ignored**
  (returns the element's style); the cascade does compute `::before`/`::after` but exposing them is
  out.
- **Serialization fidelity** — round-trip NOT guaranteed (attribute order, whitespace, entity
  normalization, implied `<tbody>`/quoting). Void elements emit open-tag-only (`<br>`). NBSP→`&nbsp;`
  not emitted (plain NBSP). Comments serialized verbatim (not escaped).
- **`innerHTML` write on a void element** (`img.innerHTML="x"`) — the parse runs and children are
  appended (the arena allows it); serialization then skips them (void = no children emitted). No
  throw. Harmless.
- **Malformed HTML in a fragment** — handled by the lenient parser (unclosed tags closed, stray end
  tags dropped) — no throw, no panic.
- **`insertAdjacentHTML` beforebegin/afterend on a parentless element** — no-op (spec throws; we
  no-op for non-fatality). Invalid position string → `SyntaxError` (thrown, caught non-fatally).
- **No memoized `StyledTree`** — each `getComputedStyle` re-runs `style_tree` (O(nodes)). Fine for
  one-shot; memoize later if hot.

All script-path failures are caught by `run_scripts` (never panic, never propagate) — a thrown
getComputedStyle/insertAdjacentHTML error lands in `ScriptOutcome.errors`; the page still renders.

## 8. Test plan (concrete)

`js` unit tests drive `run_scripts` directly (mutates `doc` + returns `ScriptOutcome`); reuse the
existing `run`/`log_of`/`lines_of`/`find_id` helpers (lib.rs tests). `run_scripts` gains the
`&[Stylesheet]` arg — the test `run` helper passes `&[]` (or a parsed sheet for getComputedStyle
tests). Visual tests go through `render_document` and assert pixels.

**Serialization (innerHTML/outerHTML read):**
1. `<div id='d'><span>x</span></div>` → `document.getElementById('d').innerHTML` === `"<span>x</span>"`.
2. text escaping: `<p id='p'>a&b<c</p>` → `innerHTML` of the parent === `...&amp;b&lt;c...`
   (verify `&`/`<`/`>` escaped in text).
3. attribute escaping: `<a id='a' title='x&\"y'>L</a>` → `outerHTML` contains
   `title="x&amp;&quot;y"`.
4. void element: `<div id='d'><br></div>` → `innerHTML` === `"<br>"` (no `</br>`).
5. `outerHTML` of `<b id='b'>hi</b>` === `"<b>hi</b>"`.

**Fragment write (innerHTML / insertAdjacentHTML):**
6. `el.innerHTML="<b>hi</b>"` rebuilds children: assert the arena (via `doc`) — one `<b>` child
   with text `"hi"`, old children gone (`doc.children`/`serialize`).
7. `el.innerHTML="<p>a</p><p>b</p>"` → two `<p>` children in order.
8. `el.innerHTML=""` removes all children (`childElementCount`===0).
9. malformed `el.innerHTML="<b>oops"` → one `<b>` child (parser closed it); no error.
10. inserted script inert: `el.innerHTML="<script>window.X=1</script>"` then check `typeof
    window.X === 'undefined'` (script did NOT run).
11. `insertAdjacentHTML('beforeend','<i>z</i>')` appends; `'afterbegin'` prepends; `'beforebegin'`
    + `'afterend'` insert as siblings (assert order via `doc.children` of the parent).

**cloneNode:**
12. `var c=document.getElementById('d').cloneNode(true)` → `c` is detached
    (`c.parentNode===null`), deep-copies the subtree (`c.innerHTML` matches the original's);
    `cloneNode(false)` copies the element with attributes but **no** children
    (`c.childElementCount===0`); mutating `c` does not affect the original (independent ids).

**getComputedStyle:**
13. with author CSS `#b{color:red;font-size:20px}` and `<span id='b'>x</span>`:
    `getComputedStyle(document.getElementById('b')).color` === `"rgb(255, 0, 0)"`;
    `.fontSize` === `"20px"`.
14. inherited/UA default: a plain `<p id='p'>` → `getComputedStyle(p).fontSize` === `"16px"`,
    `.display` === `"block"` (UA), `.color` === `"rgb(0, 0, 0)"`.
15. inline-style honored (cascade reads `style=""`, E4-M2 §6): `el.style.color='#00ff00'` then
    `getComputedStyle(el).color` === `"rgb(0, 255, 0)"`.
16. detached: `getComputedStyle(document.createElement('div')).display` returns the initial
    (`"inline"`) — no throw.

**Navigation + remove:**
17. `<ul id='u'>t<li id='a'>a</li>c<li id='b'>b</li>t</ul>` (text/comment between):
    `u.firstElementChild===a`, `u.lastElementChild===b`, `a.nextElementSibling===b`,
    `b.previousElementSibling===a`, `u.childElementCount===2`.
18. `document.getElementById('a').remove()` → `a.parentNode===null` and `u.childElementCount===1`
    (assert via `doc` too).

**Visual (through `render_document`, assert pixels):**
19. a script doing `document.getElementById('box').innerHTML="<span style='color:#ff0000'>hi</span>"`
    → the rendered text paints **red** (proves write rebuilds + the post-script re-style/render
    reflects it).
20. `insertAdjacentHTML('beforeend', '<div style="background:#00ff00;width:50px;height:50px"></div>')`
    on a container → a **new green block** appears in the PNG.
21. script-injected `<style>`: `document.body.insertAdjacentHTML('beforeend','<style>p{color:blue}</style>')`
    with a `<p>` present → the `<p>` paints **blue** (proves §6.2 post-script re-collect).

**Pipeline / regression:**
22. a script-free page renders byte-identically to pre-E8-M1 (the `&[]` sheets path + the
    double-collect must not change pixels for the no-script case — `collect_author_sheets` is
    idempotent over an unmutated DOM).

`cargo test -p starfish-dom` (serializer + `import_subtree`/`clone_node_*` unit tests),
`-p starfish-js`, `-p starfish-paint`, and the full `cargo test` green; smoke: render a page whose
script sets `innerHTML` and confirm the PNG.
