# E7-M2 — `::before` / `::after` generated content (design note)

Scope: support the pseudo-**elements** `::before` / `::after` (and the legacy
single-colon `:before` / `:after`) with the `content` property. A matching
`div::before { content: "x" }` rule creates a **generated inline box** inserted
as the first (`::before`) or last (`::after`) child of the originating element,
carrying the resolved content text and styled by the pseudo-element's own
cascaded `ComputedStyle`.

`content` values in scope:

- a **string** literal (`"…"`, adjacent strings concatenated),
- `attr(name)` — the element's attribute value at style time (empty string if
  the attribute is absent),
- `none` / `normal` → **no box**.

Deferred (non-goals, §6): `counter()` / `counters()`, `url()` images, `open-quote`
/ `close-quote`, `::first-line` / `::first-letter` / `::marker` / `::selection`,
`display:block`/`list-item` pseudos (inline-level only for M2), pseudo-elements
on non-rightmost compounds.

Pinned to the **real** current API (verified against source, June 2026 — the repo
is well past the M1/M3/M4 design notes; those describe historical states):

- `starfish_css::selector` — `Compound { tag, universal, ids, classes, attrs,
  pseudos }`; `PseudoClass` enum; `Selector::from_parts` computes `Specificity
  {a,b,c}` via `add_compound_specificity`. The parser (`parser.rs`)
  `parse_complex_selector` handles `Token::Colon` and **currently invalidates**
  on the `::`/pseudo-element path (`_ => b.invalidate()` in the `Colon` arm).
  `SelectorBuilder::push_pseudo` exists; the builder owns `current: Compound`.
- `starfish_style` — `StyledTree { styles: HashMap<NodeId, ComputedStyle> }`
  with `computed(id)` / `get(id) -> Option<&ComputedStyle>`; `style_tree(doc,
  author_sheets)` does a pre-order DFS calling `style_node` → `cascade(doc,
  node, sheets, ctx, &mut style)`. `ComputedStyle` has `display`, `color`,
  `background`, `font_*`, box-model fields, plus `inherit_from()` / `initial()`.
  `cascade()` iterates `(Origin, &Stylesheet)` sheets and, per rule, takes the
  **max specificity among matching selectors** then pushes each declaration.
  `apply_declaration(style, decl, ctx) -> bool` is the per-property dispatcher
  (`properties.rs`).
- `starfish_layout::boxtree` — `BoxKind { BlockContainer, InlineBox, InlineBlock,
  AnonymousBlock, TextRun, LineBox, Marker, Image }`; `BoxStyleRef { Node(NodeId),
  Anonymous(NodeId) }` with `node() -> NodeId`; `LayoutBox { kind, style, text:
  Option<String>, dimensions, children }`; `build_node` / `build_children`
  generate boxes from the DOM walk reading the `StyledTree`. `LayoutBox::style<'a>
  (&self, styled: &'a StyledTree) -> Option<&'a ComputedStyle>` resolves
  `styled.get(self.style.node())`; `style_of(styled, b) -> ComputedStyle` (clones).
  The marker prepend in `build_node` (`b.children.insert(0, marker)`) is the
  exact precedent for inserting a synthetic first child.
- `starfish_paint::display` — `emit_self` dispatches on `b.kind()`; `emit_box` /
  `emit_text` call `b.style(styled)` to read bg/border/font/color. **All style
  access goes through `b.style(styled)` → `styled.get(node)`**, so paint reads a
  generated box's style automatically iff the generated `BoxStyleRef` resolves
  through `StyledTree`.
- `starfish_dom::Document::get_attribute(id, name) -> Option<&str>` (name already
  lowercased) — used for `attr()` resolution.

Guiding rule (project "Simplicity First"): exactly `::before`/`::after` + a
string / `attr()` / their concatenation + an inline generated box. No counters,
quotes, url, block pseudos, first-line. See §6.

## 1. Selector model — pseudo-element on the rightmost compound

A pseudo-element is metadata on the **subject** (rightmost) compound only. It
does not change *which element* the selector matches — `div::before` matches the
`div` element exactly as `div` does — it tags the matched element so the
cascade/layout know to build a pseudo. (CSS forbids combinators or further
compounds to the right of a pseudo-element; only the rightmost compound may carry
one.)

### 1.1 `selector.rs`

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum PseudoElement {
    Before,
    After,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Compound {
    pub tag: Option<String>,
    pub universal: bool,
    pub ids: Vec<String>,
    pub classes: Vec<String>,
    pub attrs: Vec<AttrSelector>,
    pub pseudos: Vec<PseudoClass>,
    /// `::before` / `::after` on this compound. At most one; only ever set on
    /// the rightmost compound (the parser rejects it elsewhere). NEW.
    pub pseudo_element: Option<PseudoElement>,
}
```

`Compound::new()` initializes `pseudo_element: None`. `is_empty()` is **extended**
so a bare `::before` compound (e.g. the selector `::before`, equivalent to
`*::before`) is **not** treated as empty:

```rust
pub(crate) fn is_empty(&self) -> bool {
    self.tag.is_none()
        && !self.universal
        && self.ids.is_empty()
        && self.classes.is_empty()
        && self.attrs.is_empty()
        && self.pseudos.is_empty()
        && self.pseudo_element.is_none()   // NEW
}
```

A small accessor used by the cascade/layout (`selector.rs`):

```rust
impl Selector {
    /// The pseudo-element on the subject (rightmost) compound, if any.
    pub fn pseudo_element(&self) -> Option<PseudoElement> {
        self.parts.iter().rev().find_map(|p| match p {
            SelectorPart::Compound(c) => Some(c.pseudo_element),
            SelectorPart::Combinator(_) => None,
        })?
    }
}
```

(`find_map` returns on the **first** compound walking from the right — i.e. the
subject. `Some(c.pseudo_element)` wraps an `Option`; the outer `?` flattens.)

### 1.2 Specificity

Per CSS Selectors §16, a pseudo-element contributes **element-level** `(0,0,1)`
— the same weight as a type selector. In `add_compound_specificity`:

```rust
fn add_compound_specificity(spec: &mut Specificity, c: &Compound) {
    spec.a += c.ids.len() as u32;
    spec.b += c.classes.len() as u32;
    spec.c += c.tag.is_some() as u32;
    spec.b += c.attrs.len() as u32;
    for p in &c.pseudos { /* … unchanged … */ }
    spec.c += c.pseudo_element.is_some() as u32;   // NEW: pseudo-element → c+1
}
```

So `div::before` → `(0,0,2)` (tag `c=1` + pseudo-element `c=1`); `.x::after` →
`(0,1,1)`; bare `::before` → `(0,0,1)`.

### 1.3 Parsing (`parser.rs`)

Today the `Token::Colon` arm in `parse_complex_selector` handles a single colon
(`Ident` → `bare_pseudo`, `Function` → functional pseudo) and **invalidates** on
a leading `::` (the `_ => b.invalidate()` fallthrough). We add: a **second**
`Token::Colon` immediately following the first denotes a pseudo-element; a
single colon followed by `before`/`after` is the legacy form.

Replace the `Colon` arm's logic with:

```rust
Token::Colon => {
    // `::name` — pseudo-element (modern). Two adjacent Colon tokens.
    if matches!(self.toks.get(i + 1).map(|s| &s.tok), Some(Token::Colon)) {
        match self.toks.get(i + 2).map(|s| &s.tok) {
            Some(Token::Ident(name)) => {
                match pseudo_element(name) {
                    Some(pe) => b.set_pseudo_element(pe),  // Before/After
                    None => b.invalidate(),                // ::first-line etc → drop
                }
                i += 2; // consume the 2nd colon + the ident
            }
            _ => b.invalidate(), // `::` then non-ident / functional `::foo()`
        }
    } else {
        // single `:` — existing pseudo-class path, EXCEPT legacy `:before`/`:after`.
        match self.toks.get(i + 1).map(|s| &s.tok) {
            Some(Token::Ident(name)) => {
                match pseudo_element(name) {
                    // legacy single-colon pseudo-element.
                    Some(pe) => { b.set_pseudo_element(pe); i += 1; }
                    None => { b.push_pseudo(bare_pseudo(name)); i += 1; }
                }
            }
            Some(Token::Function(name)) => { /* … existing functional path … */ }
            _ => b.invalidate(),
        }
    }
}
```

```rust
/// Map a pseudo-element name to its variant; `None` for any other `::name`
/// (first-line/first-letter/marker/selection/unknown) → caller invalidates.
fn pseudo_element(name: &str) -> Option<PseudoElement> {
    if name.eq_ignore_ascii_case("before") {
        Some(PseudoElement::Before)
    } else if name.eq_ignore_ascii_case("after") {
        Some(PseudoElement::After)
    } else {
        None
    }
}
```

`SelectorBuilder` gains:

```rust
pub(crate) fn set_pseudo_element(&mut self, pe: PseudoElement) {
    self.before_simple();
    // A pseudo-element must be the LAST simple selector and unique: a second
    // one, or any simple selector appearing AFTER it, is invalid.
    if self.current.pseudo_element.is_some() {
        self.invalid = true;
    }
    self.current.pseudo_element = Some(pe);
}
```

Enforcing "rightmost compound only" / "nothing after the pseudo-element": in
`before_simple()` and `push_combinator()`, if `self.current.pseudo_element
.is_some()` set `self.invalid = true`. That makes `::before .x` (combinator
after a pseudo-element) and `::before::after` (two on one compound) and
`div::before.x` (a class after the pseudo-element) all drop the rule — matching
CSS (a pseudo-element terminates the selector). The simplest single chokepoint:
add the `pseudo_element.is_some()` guard at the **top of `before_simple()`** (it
runs before every simple selector and before materializing a pending
combinator), so any further token after a pseudo-element invalidates.

Leniency invariant preserved: every new path either succeeds or
`invalidate()`s; a recognized-but-unsupported pseudo-element (`::first-line`)
drops the **rule** (conservative — it carries box-generating semantics we don't
model), consistent with how unknown functional pseudos already drop rules.

### 1.4 Matcher — no change to *matching*

`matches()` / `compound_matches()` in `style/matching.rs` **ignore**
`pseudo_element` entirely: `div::before` matches the `div` element. The
pseudo-element is consumed only by the cascade (§3) and layout (§4). No edit to
`matching.rs`. (`querySelector` in `js` likewise treats `div::before` as
matching the `div` — acceptable; pseudo-elements are not selectable as DOM nodes
anyway, and Selectors L1 historically allowed this.)

## 2. The `content` property

### 2.1 `ComputedStyle` field + type (`computed.rs`)

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum Content {
    /// `normal` (and the initial value): no generated box on a pseudo-element.
    Normal,
    /// `none`: no generated box.
    None,
    /// A resolved text string (may be empty: `content:""` → an empty box).
    Text(String),
}
```

Added to `ComputedStyle`:

```rust
pub content: Content,   // NOT inherited; initial = Content::Normal
```

`initial()` sets `content: Content::Normal`; `inherit_from()` resets it to
`Content::Normal` (content is **not** inherited). Re-export `Content` from
`style/lib.rs`.

`Content::Text` resolution happens **at style time** (the `attr()` lookup needs
the element), so the field already holds the final string — layout never
re-resolves.

### 2.2 Parsing (`properties.rs`, `apply_declaration`)

`content` is resolved against the **declaration components** plus the element
(for `attr()`). Because the existing `apply_declaration(style, decl, ctx)` does
not receive the `NodeId`/`Document`, `attr()` cannot be resolved there. Two clean
options; we pick the one with the least new plumbing:

**Decision:** resolve `content` **in the pseudo-element cascade pass (§3)**, not
in the generic `apply_declaration`. The §3 pass already has `doc` + the element
`NodeId` in scope, so it can call a small free function:

```rust
// properties.rs (pub(crate))
/// Resolve a `content` declaration's value to a `Content`, given the originating
/// element so `attr()` can look up an attribute. M2 grammar:
///   none | normal                                  → None / Normal (no box)
///   <string>+                                       → Text(concat)
///   attr( <ident> )                                 → Text(attr value or "")
///   any mix of <string> and attr() components       → Text(concat in order)
/// Anything else (counter(), url(), open-quote, …)  → None (treated as no box;
///   we don't generate for unsupported content — conservative, §6).
pub(crate) fn resolve_content(
    doc: &Document,
    element: NodeId,
    decl: &Declaration,
) -> Content {
    let comps = &decl.value.components;
    // Single keyword none/normal.
    if comps.len() == 1 {
        if let Component::Keyword(k) = &comps[0] {
            if k.eq_ignore_ascii_case("none") { return Content::None; }
            if k.eq_ignore_ascii_case("normal") { return Content::Normal; }
        }
    }
    let mut out = String::new();
    for c in comps {
        match c {
            Component::Str(s) => out.push_str(s),
            Component::Function { name, raw_args } if name == "attr" => {
                let attr_name = raw_args.trim().trim_matches('"').trim();
                // attr() name is ASCII-CI; get_attribute keys are lowercased.
                let v = doc
                    .get_attribute(element, &attr_name.to_ascii_lowercase())
                    .unwrap_or("");
                out.push_str(v);
            }
            // Unsupported component (counter()/url()/keyword/number) anywhere
            // in the value → don't generate (treat the whole content as absent).
            _ => return Content::None,
        }
    }
    Content::Text(out)
}
```

Notes:

- **String concatenation:** adjacent `Component::Str` (CSS allows `content: "a"
  "b"`) and `<string> attr(x) <string>` concatenate left-to-right. This covers
  the "string + attr concatenation" requirement.
- **`attr()` parsing:** `attr(data-label)` arrives from the css parser as
  `Component::Function { name: "attr", raw_args: "data-label" }` (the function
  arg is captured raw — see `parse_function`). We trim and strip a stray pair of
  quotes; M2 ignores `attr()`'s optional `<type>` / fallback (e.g.
  `attr(x px, 0)`) — those make `raw_args` contain a comma/ident and we just use
  the leading token as the name (`trim()` of the whole raw is fine for the bare
  `attr(name)` form; a comma'd form yields a bogus name → empty string, which is
  acceptable for M2 and noted §6).
- **Missing attribute** → `""` → `Content::Text("")` → an **empty** generated box
  (per spec: `attr()` of an absent attribute is the empty string, which still
  generates a box).
- **`content` on a normal element** (not a pseudo) has **no effect**: we only
  read `style.content` for the `::before`/`::after` pseudo styles (§3/§4); the
  element's own `content` field is computed but never consumed. (CSS: `content`
  on a regular element only matters for replaced-element / `::marker` cases we
  don't model.) Documented, not enforced.

`apply_declaration` itself does **not** handle `content` (it would need the
element). To keep the element's own `ComputedStyle.content` correct-ish for
completeness we *may* leave it `Normal` always; since it's unused on real
elements that's fine. The §3 pass owns content resolution for pseudos.

## 3. Pseudo-element cascade

### 3.1 Side tables in `StyledTree` (`style/lib.rs`)

```rust
pub struct StyledTree {
    styles: HashMap<NodeId, ComputedStyle>,
    /// Generated ::before pseudo: element NodeId → (pseudo style, content text).
    before: HashMap<NodeId, (ComputedStyle, String)>,   // NEW
    /// Generated ::after pseudo.
    after: HashMap<NodeId, (ComputedStyle, String)>,    // NEW
}

impl StyledTree {
    /// The computed style for `id`'s ::before/::after pseudo, if one was
    /// generated (matching rule with a box-generating `content`).
    pub fn pseudo(&self, id: NodeId, side: PseudoElement) -> Option<&(ComputedStyle, String)> {
        match side {
            PseudoElement::Before => self.before.get(&id),
            PseudoElement::After  => self.after.get(&id),
        }
    }
    /// The pseudo style alone (for paint/layout style resolution via BoxStyleRef).
    pub fn pseudo_style(&self, id: NodeId, side: PseudoElement) -> Option<&ComputedStyle> {
        self.pseudo(id, side).map(|(s, _)| s)
    }
}
```

`PseudoElement` is re-exported from `starfish_css` through `starfish_style`
(layout/paint import it from `starfish_style`).

### 3.2 Cascade pass — extend `style_node`

After an element's own style is cascaded in `style_node` (`lib.rs`), compute its
two pseudos. The pseudo is a **child** of the element: its base style is
`element_style.inherit_from()` (inherited props seeded from the element, the
rest initial), and only declarations whose selector carries the **matching**
`pseudo_element` are cascaded onto it. A pseudo whose resolved `content` is
`Normal`/`None` generates **no** entry (no box).

```rust
fn style_node(doc, node, parent_style, sheets, root_font_size, tree) {
    if doc.tag_name(node).is_none() { return; }
    let mut style = parent_style.inherit_from();
    let ctx = EmContext { parent_font_size: parent_style.font_size,
                          root_font_size: *root_font_size };
    cascade(doc, node, sheets, ctx, &mut style);
    if doc.tag_name(node) == Some("html") { *root_font_size = style.font_size; }

    // E7-M2: ::before / ::after pseudo-element styles.
    for side in [PseudoElement::Before, PseudoElement::After] {
        if let Some((pstyle, text)) =
            cascade_pseudo(doc, node, side, &style, sheets, ctx, tree.skip /*see below*/)
        {
            match side {
                PseudoElement::Before => tree.before.insert(node, (pstyle, text)),
                PseudoElement::After  => tree.after.insert(node, (pstyle, text)),
            };
        }
    }

    for child in doc.children(node) { style_node(doc, child, &style, …); }
    tree.styles.insert(node, style);
}
```

`cascade_pseudo` (new, in `cascade.rs`) mirrors `cascade()` but (a) only
considers selectors whose `pseudo_element() == Some(side)`, and (b) resolves
`content` from the winning declaration:

```rust
pub(crate) fn cascade_pseudo(
    doc: &Document,
    element: NodeId,
    side: PseudoElement,
    element_style: &ComputedStyle,  // the originating element's computed style
    sheets: &[(Origin, &Stylesheet)],
    ctx: EmContext,                 // parent = element here; see below
) -> Option<(ComputedStyle, String)> {
    // Collect declarations from rules that (a) match `element` AND (b) whose
    // matching selector targets this pseudo-element side.
    let mut matched: Vec<MatchedDecl> = Vec::new();
    let mut source_order = 0usize;
    for (origin, sheet) in sheets {
        for rule in &sheet.rules {
            let mut best: Option<Specificity> = None;
            for sel in &rule.selectors {
                if sel.pseudo_element() == Some(side) && matches(doc, element, sel) {
                    best = Some(best.map_or(sel.specificity, |b| b.max(sel.specificity)));
                }
            }
            let Some(spec) = best else { continue };
            for decl in &rule.declarations {
                matched.push(MatchedDecl { origin: *origin, inline: false,
                    specificity: spec, source_order, declaration: decl });
                source_order += 1;
            }
        }
    }
    if matched.is_empty() { return None; }  // no ::side rule at all → no box

    // Base = inherit from the originating ELEMENT (the pseudo is its child).
    let mut style = element_style.inherit_from();
    // pseudo's em-basis: the element's font-size (the pseudo inherits it).
    let pctx = EmContext { parent_font_size: element_style.font_size,
                           root_font_size: ctx.root_font_size };

    matched.sort_by_key(|m| (origin_rank(m.origin, m.declaration.important),
                             m.inline, m.specificity, m.source_order));

    // Resolve `content` from the winning (last) content declaration; apply the
    // rest of the properties normally. font-size first (em), as in cascade().
    let mut content = Content::Normal;
    let mut border_color_set = false;
    for m in matched.iter().filter(|m| m.declaration.name == "font-size") {
        apply_declaration(&mut style, m.declaration, pctx);
    }
    for m in matched.iter().filter(|m| m.declaration.name != "font-size") {
        if m.declaration.name == "content" {
            content = resolve_content(doc, element, m.declaration); // last wins
        } else if apply_declaration(&mut style, m.declaration, pctx) {
            border_color_set = true;
        }
    }
    if !border_color_set { style.border_color = style.color; }

    // Generate iff content yields a box: Text(_) (incl. "") generates; a `content`
    // of none/normal (or no `content` declaration at all) → no box.
    match content {
        Content::Text(s) => Some((style, s)),
        Content::None | Content::Normal => None,
    }
}
```

Key behaviors:

- **Inheritance source:** the pseudo inherits from the **originating element**
  (color/font flow into `::before`), exactly as a first/last child would. Using
  `element_style.inherit_from()` gives that for free.
- **No `::side` rule, or rule but no `content`, or `content:none/normal`** → no
  side-table entry → no box generated.
- **`content:""`** → `Content::Text("")` → an entry **is** created (an empty
  inline box; its background/border can still paint — §4/§5).
- The element's own `inline style=""` does not target pseudos (CSS has no
  inline pseudo styling), so `cascade_pseudo` does not read the `style`
  attribute — `inline` stays `false` and the inline branch of `cascade()` is
  omitted here.

(`cascade_pseudo` reuses `MatchedDecl`, `origin_rank`, `Origin`, `apply_declaration`
already in `cascade.rs`; only `pseudo_element()` filtering and `resolve_content`
are new. The two passes share the collect/sort/apply skeleton — factor the common
collect+sort if it reads cleanly, but a focused copy is acceptable given the
filter and the content branch differ.)

## 4. Layout integration — the generated inline box

### 4.1 `BoxStyleRef` — a generated variant resolving through `StyledTree`

The generated box has **no real `NodeId`**, but `LayoutBox::style<'a>(&self,
styled: &'a StyledTree) -> Option<&'a ComputedStyle>` returns a reference
**borrowed from `StyledTree`** (used everywhere in layout/paint). To keep that
borrow valid, the pseudo style must **live in `StyledTree`** (the §3 side tables)
— not be owned by the box. So `BoxStyleRef` gains a variant keyed by the
originating element + side, resolved against the side tables:

```rust
#[derive(Debug, Clone)]
pub enum BoxStyleRef {
    Node(NodeId),
    Anonymous(NodeId),
    /// A ::before/::after generated box: resolve via `styled.pseudo_style`.
    Generated { origin: NodeId, side: PseudoElement },   // NEW
}

impl BoxStyleRef {
    pub fn node(&self) -> NodeId {
        match self {
            BoxStyleRef::Node(id)
            | BoxStyleRef::Anonymous(id)
            | BoxStyleRef::Generated { origin: id, .. } => *id,
        }
    }
}
```

`LayoutBox::style` (`layout/lib.rs`) resolves the new variant:

```rust
pub fn style<'a>(&self, styled: &'a StyledTree) -> Option<&'a ComputedStyle> {
    match self.style {
        BoxStyleRef::Generated { origin, side } => styled.pseudo_style(origin, side),
        _ => styled.get(self.style.node()),
    }
}
```

`style_of(styled, b)` (`boxtree.rs`) gets a matching arm:

```rust
BoxStyleRef::Generated { origin, side } =>
    styled.pseudo_style(*origin, *side).cloned().unwrap_or_else(ComputedStyle::initial),
```

The two `match style_ref { Node|Anonymous => styled.get(*id) }` arms in
`inline.rs` (word fragment + marker, lines ~605 and ~733) extend with a
`Generated { origin, side } => styled.pseudo_style(*origin, *side)` arm. (These
are the only `BoxStyleRef` `match`es that don't go through `.node()`.)

This is the **minimal** style-carrying change: one enum variant + four resolve
sites, all delegating to the §3 side table. No owned-`ComputedStyle` in the box,
so no lifetime churn in `style()`.

### 4.2 Inserting the generated boxes (`boxtree.rs`, `build_node`)

In `build_node`, for an `Element` that produces a container box (the
`NodeKind::Element` arm, after `b.children = build_children(...)` and the
marker insert), insert generated children using the §3 side tables. The
`make_marker` → `insert(0, …)` precedent is reused:

```rust
// E7-M2: ::before / ::after generated boxes (after children + marker).
if let Some(before) = make_pseudo(styled, id, PseudoElement::Before) {
    b.children.insert(0, before);
}
if let Some(after) = make_pseudo(styled, id, PseudoElement::After) {
    b.children.push(after);
}
```

```rust
/// Build the generated inline box for `id`'s ::before/::after, or None if no
/// pseudo was generated (no entry in the side table).
fn make_pseudo(styled: &StyledTree, id: NodeId, side: PseudoElement) -> Option<LayoutBox> {
    let (pstyle, text) = styled.pseudo(id, side)?;
    // M2: inline-level only. `display:none` on the pseudo → no box. `display:block`
    // (and other non-inline) is NOT supported — fold to inline (noted §6).
    if pstyle.display == Display::None {
        return None;
    }
    // The generated box is an InlineBox carrying a single TextRun child with the
    // content string. (An empty string still yields a box for bg/border.)
    let mut gen = LayoutBox::new(BoxKind::InlineBox, BoxStyleRef::Generated { origin: id, side });
    if !text.is_empty() {
        let mut run = LayoutBox::new(BoxKind::TextRun,
            BoxStyleRef::Generated { origin: id, side });
        run.text = Some(text.clone());
        gen.children.push(run);
    }
    Some(gen)
}
```

Design points:

- The generated box is an **`InlineBox`** (display:inline default); its `TextRun`
  child carries the content string and the same `Generated` style ref (so the
  text paints with the pseudo's color/font). This mirrors how a real
  `<span>text</span>` becomes `InlineBox → TextRun`.
- Insertion happens **inside `build_node` for the element**, so the generated
  boxes are already among `b.children` **before** `wrap_anonymous_blocks` would
  run for the *parent* — but anonymous-block wrapping is applied in
  `build_children` to the element's *own* children list, which now includes the
  pseudos. Because the pseudos are inline-level, they participate in the same
  inline run / line boxes as the element's inline content (correct: `::before`
  text sits on the same line, before the element's text). If the element has
  block children, the inline `::before`/`::after` are wrapped into anonymous
  blocks by the existing rule — acceptable for M2 (matches how stray inline text
  beside blocks is handled).
- **Order:** `::before` is `insert(0, …)` → first child (before the marker?
  No — the marker is inserted first at index 0, then `::before` inserts at 0,
  landing *before* the marker. For M2 that's an acceptable, rare interaction;
  list markers + `::before` on the same `<li>` is an edge case. Documented §6.)
  `::after` is `push` → last child.
- **Replaced elements:** the `<img>` branch returns **before** this code (its
  `return Some(b)` for the Image box), so `::before`/`::after` are **not**
  generated on `<img>` — correct (replaced elements have no content box for
  generated content). Noted §6.
- A pseudo on a `display:none` **element**: the element's `build_node` returns
  `None` before reaching pseudo insertion, so no pseudo box — correct.

`PseudoElement` and `Display` are already importable from `starfish_style` in
`boxtree.rs` (it already imports `Display`, `StyledTree`, etc.).

## 5. Paint

**No paint-crate change is required.** `emit_self` (`paint/display.rs`)
dispatches on `b.kind()`:

- The generated `InlineBox` → `emit_box` → `b.style(styled)` → (via the §4.1
  `Generated` arm) the pseudo's `ComputedStyle` → background/border/box-shadow/
  radius paint exactly like any styled inline element box.
- The generated `TextRun` → `emit_text` → `b.style(styled)` → the pseudo style →
  `GlyphRun` with the pseudo's color/font-size/weight/family/spacing.

Because **all** paint style access already routes through `b.style(styled)`, and
§4.1 makes that resolve `Generated` via `styled.pseudo_style`, paint transparently
reads the generated box's style. `role()` only reclassifies `Node`-backed element
boxes for float/position; the generated `InlineBox` carries a `Generated` ref and
its pseudo style has `position:static`/`float:none` (initial, since those reset on
`inherit_from`), so it stays `Role::InFlow` — correct. (We do **not** support
`position`/`float` on pseudos in M2; the initial values keep them in flow.)

The only requirement on paint is that `b.style(styled)` for a `Generated` box must
not panic when the side-table entry is missing — it returns `Option` and
`emit_text`/`emit_box` already handle `None` (`let Some(style) = … else { return }`).

## 6. Edge cases & non-goals

Handled:

- `::before` / `::after` modern (`::`) **and** legacy (`:`) syntax.
- `content` = string / `attr()` / `string+attr` concatenation; missing attribute
  → empty string → empty box; `content:""` → empty box (bg/border may still
  paint); `content:none`/`normal` → no box.
- Pseudo style inherits from the originating element; cascades only `::side`
  rules; specificity `(0,0,1)` for the pseudo-element.
- `::before` on a `display:none` element → no box (element produces no box).
- `::before` with `display:none` on the **pseudo** → no box.
- Pseudo-element on a non-rightmost compound, two pseudo-elements on one
  compound, or any simple selector after a pseudo-element → **rule dropped**.
- Generated content is **layout-only**: not in the DOM, not selectable, not
  matched by `querySelector` (correct — it has no `NodeId`).
- `<img>` and other replaced elements: no generated content box (the `<img>`
  branch returns before pseudo insertion).

Deferred (non-goals):

- `content: counter()` / `counters()` / `url()` / `open-quote` / `close-quote`
  / mixed unsupported components → `resolve_content` returns `Content::None`
  (no box). No counters engine in M2.
- `attr()` with a type/unit/fallback (`attr(x px, 0)`) — only bare `attr(name)`
  (as a string) is honored; a comma'd form degrades to empty.
- `display:block` / `list-item` / flex / grid on a pseudo — **inline only** for
  M2 (a non-`none` non-inline display is treated as the inline generated box).
- `::first-line` / `::first-letter` / `::marker` / `::selection` → unsupported
  pseudo-element → rule dropped.
- Interaction of `::before` with a list-item marker on the same `<li>` (both
  prepend) — order is `::before` then marker; rare, not specially handled.
- `position`/`float`/`transform` on pseudos: initial (static/none/empty), so
  they stay in normal inline flow.

## 7. Test plan

### 7.1 css (parse + specificity) — `crates/css/src/lib.rs` / `selector.rs` tests

- `div::before` → subject compound `pseudo_element == Some(Before)`, specificity
  `(0,0,2)`; `a::after` → `Some(After)`, `(0,0,2)`; `.x::before` → `(0,1,1)`;
  bare `::before` → `(0,0,1)`.
- Legacy `:before` / `:after` parse to `Some(Before/After)` (same as `::`).
- `::first-line` / `::first-letter` / `::marker` / `::selection` → rule dropped.
- `div::before .x` (combinator after pseudo-element), `div::before::after`,
  `div::before.x` → rule dropped.
- `div::before` still **matches the `div` element** in the matcher (a matcher
  test: `matches(doc, div, sel("div::before"))` is `true`).

### 7.2 style (pseudo cascade) — `crates/style/src/lib.rs` / `cascade.rs` tests

- `div::before { content: "x" }` on `<div>` → `tree.pseudo(div, Before)` is
  `Some((style, "x"))`; `tree.pseudo(div, After)` is `None`.
- `content: none` / `content: normal` → no entry; no `content` declaration → no
  entry.
- `content: ""` → `Some((_, ""))` (entry exists with empty text).
- `[data-label]::before { content: attr(data-label) }` on
  `<span data-label="Hi">` → pseudo text `"Hi"`; missing `data-label` → `""`
  (entry exists).
- `content: "a" "b"` → `"ab"`; `content: "[" attr(x) "]"` with `x="v"` → `"[v]"`.
- Pseudo **inherits** color from the element: `div { color: red }
  div::before { content:"x" }` → pseudo style `color == red`.
- Pseudo's **own** rule wins for its props: `div::before { content:"x";
  color: blue }` under `div { color: red }` → pseudo `color == blue`.
- Specificity in the pseudo cascade: `div::before{content:"a"}` vs
  `.c::before{content:"b"}` on a `div.c` → `"b"` (class beats tag at the pseudo
  cascade too).

### 7.3 layout (box generation) — `crates/layout/src/...` tests

- `div::before { content:"→ " }` → the `div`'s box has a first child `InlineBox`
  with a `TextRun` child `"→ "`, before the div's own text run.
- `a::after { content:" ↗" }` → last child `InlineBox`→`TextRun` `" ↗"`.
- `content:none` → no generated child box.
- `content:""` → a generated `InlineBox` with **no** `TextRun` child (empty), but
  the box exists (so bg/border can lay out).
- `<img>` with an `img::before` rule → no generated child (replaced element).
- The generated box's `style(styled)` resolves to the pseudo's `ComputedStyle`
  (e.g. its `background`/`color`).

### 7.4 paint — `crates/paint/src/display.rs` tests

- `div::before { content:"x"; color:#ff0000 }` → a `GlyphRun{ text:"x",
  color: red }` is emitted (from the generated TextRun).
- `span::before { content:""; background:#00ff00; width:… }` (or padding) → a
  `FillRect` in green for the empty generated box (bg paints with no text).
- `li::before { content:"• "; color:#ff0000 }` → a red `"• "` GlyphRun before the
  list item's text.
