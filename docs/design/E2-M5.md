# E2-M5 — Backgrounds & visual effects (design note)

Final Epic-2 milestone. Scope: four paint-time visual effects layered onto the
existing flat display-list painter — **linear-gradient backgrounds**,
**border-radius**, **box-shadow**, and **opacity**. Touches `style` (new
`ComputedStyle` fields + parsing) and `paint` (new `PaintCmd` variants + raster
work using tiny-skia 0.11's shader / path / mask APIs). Layout is untouched
(geometry already baked into `Dimensions`; these are pure paint effects).

Guiding rule (CLAUDE.md "Simplicity First"): a **pragmatic** subset. Circular
border-radius only (no elliptical `/` syntax), linear gradients only (no
radial/conic), a single outset box-shadow with a cheap box-blur approximation,
opacity via a correct offscreen-layer composite. Deviations are called out in §6.

This note is pinned to the **real** current APIs read from source:
- `ComputedStyle` (`crates/style/src/computed.rs`) — `Rgba`, `Length`,
  `background_color: Rgba` initial transparent, the border fields.
- `Component` (`crates/css/src/model.rs`) — `Function { name, raw_args }`,
  `Color(Rgba)`, `Dimension { value, unit }`, `Keyword`, `Comma`. A
  `linear-gradient(...)` value arrives as **one** `Component::Function { name:
  "linear-gradient", raw_args: "<verbatim inner text>" }` (verified: the parser
  only specializes `rgb()/rgba()` into `Color`; every other function is kept
  verbatim — `crates/css/src/lib.rs::function_kept_verbatim`).
- `apply_declaration` (`crates/style/src/properties.rs`) — the `match decl.name`
  dispatch; `background-color | background` currently calls `first_color`.
- `PaintCmd` + `build_display_list` (`crates/paint/src/display.rs`) — the
  pre-order walk, `emit_self`, `emit_background`, `emit_borders`.
- `rasterize` (`crates/paint/src/raster.rs`) — `fill_rect`, `src_over_pixel`,
  `blit_image`, `draw_glyph_run`; manual premultiplied src-over into
  `pixmap.data_mut()`.
- tiny-skia 0.11.4 (verified in the vendored source): `LinearGradient::new(start:
  Point, end: Point, stops: Vec<GradientStop>, mode: SpreadMode, transform:
  Transform) -> Option<Shader<'static>>`; `GradientStop::new(position: f32,
  color: Color) -> GradientStop`; `SpreadMode::{Pad, Reflect, Repeat}`;
  `Paint { shader: Shader<'a>, anti_alias, .. }`; `Pixmap::fill_path(path, paint,
  fill_rule, transform, mask: Option<&Mask>)` and `fill_rect(rect, paint,
  transform, mask)`; `PathBuilder::{move_to, line_to, quad_to, cubic_to, close,
  push_rect, push_circle, finish() -> Option<Path>}`; `Mask::new(w,h)`,
  `Mask::fill_path(path, FillRule, anti_alias, Transform)`,
  `Mask::intersect_path(...)`; `Color::from_rgba8`; `FillRule::{Winding, EvenOdd}`.

## 1. Linear-gradient backgrounds

### 1.1 Style model (`crates/style/src/computed.rs`)

A background is **either** a solid color **or** a gradient. The least-disruptive
model that keeps the common case identical is to **replace** the existing
`background_color: Rgba` field with a single richer `background: Background`
field. (There are only ~6 read sites of `background_color`, all in `style` tests
and `paint`'s `emit_background`; replacing is a small, mechanical edit and avoids
the ambiguity of having both a color *and* an image field with precedence rules.)

```rust
/// `background` (color or single linear-gradient image). Replaces the old
/// `background_color: Rgba` field. Initial = `Color(transparent)`.
#[derive(Debug, Clone, PartialEq)]
pub enum Background {
    Color(Rgba),
    Gradient(LinearGradient),
}

/// A parsed `linear-gradient(...)` — the M5 subset (§1.2). The angle is stored
/// in CSS degrees (0deg = to top, 90deg = to right, growing clockwise). `stops`
/// is ≥ 2 entries; `pos` is a 0..1 fraction along the gradient line, or `None`
/// (auto — the painter spreads `None` stops evenly, §1.4).
#[derive(Debug, Clone, PartialEq)]
pub struct LinearGradient {
    pub angle_deg: f32,
    pub stops: Vec<GradientStop>,
}

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct GradientStop {
    pub color: Rgba,
    pub pos: Option<f32>, // 0..1 along the line; None = auto-spaced
}

impl Background {
    /// The solid color, or `None` for a gradient. Lets call sites that only care
    /// about a flat color (none today, but future-proofing) stay terse.
    pub fn solid(&self) -> Option<Rgba> {
        match self { Background::Color(c) => Some(*c), _ => None }
    }
}
```

`ComputedStyle`:

```rust
// replaces `pub background_color: Rgba,`
pub background: Background,
```

`initial()` sets `background: Background::Color(TRANSPARENT)`. `inherit_from()`
already does not copy background (not inherited) — no change. Update the ~6
`background_color` references (`style` lib tests, `paint::emit_background`) to
read through `style.background`.

### 1.2 Parsed subset (the grammar)

```
linear-gradient( [ <angle> | to <side-or-corner> ]? ,? <color-stop>{2,} )
<color-stop> = <color> <length-percentage>?
<side-or-corner> = [left | right] || [top | bottom]
```

- **`<angle>`**: `<n>deg` only (no `rad`/`turn`/`grad` — folded to 0deg if seen,
  documented). `0deg`→to top, `90deg`→to right, `180deg`→to bottom, `270deg`→to
  left (CSS clockwise convention, NOT math angle).
- **`to <side>`** keyword form → fixed angle: `to top`=0, `to right`=90,
  `to bottom`=180, `to left`=270, `to top right`=45, `to bottom right`=135,
  `to bottom left`=225, `to top left`=315. (Corner forms use the simple 45°
  diagonal, not the exact gradient-line-to-corner geometry — §6.)
- Default direction when omitted = `to bottom` (180deg), per CSS.
- **`<color>`** per stop = `#hex`, `rgb()/rgba()`, or a named color (reuse
  `starfish_style`'s color helpers — see §1.3).
- **`<length-percentage>`** per stop: `<n>%` → `pos = n/100`; `<n>px` → mapped to
  a fraction at paint time once the gradient-line length is known. To keep
  `GradientStop.pos` resolution-independent we store **percent → fraction now**
  and **px → resolved to a fraction at paint time** (we keep px stops as a
  separate variant? — No: simpler, store `pos: Option<f32>` as a *fraction* and
  **only support `%` and bare keyword stops** in M5; a `px` stop position is
  parsed-but-ignored (treated as `None`/auto). Documented in §6.) This keeps the
  stop a plain `Option<f32>`.

### 1.3 Parsing (`crates/style/src/properties.rs`)

`background-color | background` and a new `background-image` arm. The component
for a gradient is `Component::Function { name, raw_args }`; we parse `raw_args`
(verbatim CSS text) with a small dedicated tokenizer-free splitter:

```rust
"background-color" | "background" | "background-image" => {
    if let Some(bg) = parse_background(comps) {
        style.background = bg;
    }
}

/// `background` value → a `Background`. A `linear-gradient(...)` function wins;
/// else the first color (existing behaviour); else leave unchanged (None).
fn parse_background(comps: &[Component]) -> Option<Background> {
    for c in comps {
        if let Component::Function { name, raw_args } = c {
            if name.eq_ignore_ascii_case("linear-gradient") {
                return parse_linear_gradient(raw_args).map(Background::Gradient);
            }
        }
    }
    first_color(comps).map(Background::Color)
}

/// Parse the verbatim inner args of `linear-gradient(...)`.
/// Splits on **top-level commas** (commas not inside parens, so `rgba(...)` is
/// kept whole), then: the first segment is an optional `<angle>`/`to <side>`
/// (if it parses as one), and the remaining segments are color stops.
fn parse_linear_gradient(raw_args: &str) -> Option<LinearGradient> {
    let segs = split_top_level_commas(raw_args);   // ~15 lines, paren-depth aware
    let mut iter = segs.iter().peekable();
    let mut angle_deg = 180.0; // default: to bottom

    if let Some(first) = iter.peek() {
        if let Some(a) = parse_angle_or_side(first) {
            angle_deg = a;
            iter.next();
        }
    }
    let mut stops = Vec::new();
    for seg in iter {
        if let Some(s) = parse_color_stop(seg) { stops.push(s); }
    }
    if stops.len() < 2 { return None; }            // need ≥2 stops to be useful
    Some(LinearGradient { angle_deg, stops })
}
```

Helpers:
- `split_top_level_commas(&str) -> Vec<String>` — walk chars, track `(`/`)`
  depth, split on `,` at depth 0. Trims each segment.
- `parse_angle_or_side(&str) -> Option<f32>` — `"<n>deg"` → `n`;
  `"to top"`/`"to right"`/… (case-insensitive, words in any order for corners) →
  the fixed angle table above. Returns `None` if the segment is actually a color
  stop (so the caller treats it as the first stop).
- `parse_color_stop(&str) -> Option<GradientStop>` — split the segment on
  whitespace into `[color, position?]`; parse the color via a shared
  `parse_color_token(&str) -> Option<Rgba>` (hex via `parse_hex`, `rgb()/rgba()`
  via `parse_rgb`, named via `named` — these are `pub(crate)` in
  `crates/style`'s re-exported `starfish_css::color` / `crate::color`; expose a
  thin `pub(crate) fn parse_color_token` in `properties.rs` reusing them, OR add
  a `pub fn parse_color(&str) -> Option<Rgba>` to `starfish_css`). Position:
  `"<n>%"` → `Some(n/100)`; `"<n>px"`/missing → `None` (px ignored, §6).

> Note: the existing `Component::Color` path already pre-resolves bare colors,
> but **inside** `raw_args` colors are verbatim text (the parser does not recurse
> into function args), so we must parse colors from the string ourselves. Reuse
> the existing color parsers; do not reimplement.

### 1.4 Painting — `PaintCmd::GradientRect`

A new command carrying the rect and the resolved gradient. Border-radius (§2)
adds an optional `radius`; both share it:

```rust

Emission replaces the body of `emit_background` (§5.1):

### 1.5 Rasterizing the gradient (`raster.rs`)

Map the CSS angle to start/end points on the **border-box** rect, build a
tiny-skia `LinearGradient` shader, and fill the rect (or rounded path, §2) with
it. The gradient line through the box center at angle θ (CSS deg), with the line
长 spanning the box so the two endpoints touch the box edges:

```rust
fn gradient_shader(g: &LinearGradient, rect: &Rect) -> Option<Shader<'static>> {
    // CSS: 0deg points "to top" (up). Convert to a direction vector. In device
    // space y grows downward, so "to top" = (0, -1). Clockwise from there:
    //   dir = ( sin(θ), -cos(θ) )   with θ in radians.
    let theta = g.angle_deg.to_radians();
    let (dx, dy) = (theta.sin(), -theta.cos());

    // Gradient-line length so endpoints reach the box corners along `dir`
    // (CSS "magic corners": the line length is |w·sin θ| + |h·cos θ|).
    let (w, h) = (rect.width, rect.height);
    let len = (w * theta.sin().abs()) + (h * theta.cos().abs());
    let (cx, cy) = (rect.x + w / 2.0, rect.y + h / 2.0);
    let start = Point::from_xy(cx - dx * len / 2.0, cy - dy * len / 2.0);
    let end   = Point::from_xy(cx + dx * len / 2.0, cy + dy * len / 2.0);

    let stops = resolve_stops(&g.stops);   // Vec<GradientStop> (tiny-skia)
    LinearGradient::new(start, end, stops, SpreadMode::Pad, Transform::identity())
}

/// Resolve our stops (with optional positions) to tiny-skia GradientStops with
/// monotonic 0..1 positions: fill `None` positions by even spacing between the
/// nearest fixed neighbours (CSS default), clamp to non-decreasing.
fn resolve_stops(stops: &[crate_GradientStop]) -> Vec<tiny_skia::GradientStop> {
    let n = stops.len();
    let mut pos: Vec<f32> = (0..n).map(|i| stops[i].pos.unwrap_or(
        // even spread: first=0, last=1, interior i/(n-1)
        i as f32 / (n - 1).max(1) as f32)).collect();
    // enforce non-decreasing (CSS clamps a stop to the previous one's position)
    for i in 1..n { if pos[i] < pos[i-1] { pos[i] = pos[i-1]; } }
    stops.iter().zip(pos).map(|(s, p)| {
        tiny_skia::GradientStop::new(
            p.clamp(0.0, 1.0),
            Color::from_rgba8(s.color.r, s.color.g, s.color.b, s.color.a),
        )
    }).collect()
}
```

Then fill:

```rust
PaintCmd::GradientRect { rect, gradient, radius } => {
    let Some(shader) = gradient_shader(gradient, rect) else { return };
    let mut paint = Paint { anti_alias: true, ..Default::default() };
    paint.shader = shader;
    if radius_is_zero(radius) {
        if let Some(r) = SkRect::from_xywh(rect.x, rect.y, rect.width.max(0.0), rect.height.max(0.0)) {
            pixmap.fill_rect(r, &paint, Transform::identity(), None);
        }
    } else if let Some(path) = rounded_rect_path(rect, radius) {
        pixmap.fill_path(&path, &paint, FillRule::Winding, Transform::identity(), None);
    }
}
```

`LinearGradient::new` returns `None` only for empty stops (we guarantee ≥2), but
it may also return a `SolidColor` shader for 1 stop — harmless. The shader
composites src-over through tiny-skia, so a semi-transparent gradient over
existing pixels blends correctly.

## 2. border-radius

### 2.1 Style model

`border-radius` shorthand, 1–4 values (px or %), **circular only** (the
elliptical `<h> / <v>` slash syntax is ignored — only the part before `/` is
read; §6). Store four corner radii:

```rust
// ComputedStyle, new field. Order: TL, TR, BR, BL (CSS shorthand order).
pub border_radius: [f32; 4],
```

`initial()` → `[0.0; 4]`. Not inherited (already the default for new fields via
`inherit_from` resetting to initial).

Percentages resolve against the border-box size at **paint** time (a `%` radius
is relative to the box dimension). To keep the stored value resolution-free we
store **px now**, and for `%` store a sentinel? — Simpler per CLAUDE.md: M5
supports **px and `%`**, but resolves `%` against box width at parse time is
impossible (box size unknown in style). So: store the raw `Length`-like value
and resolve at paint. Concretely store `[Length; 4]`? That complicates the paint
side. **Decision:** store `[f32; 4]` in px and **support px only** for M5; a `%`
radius is parsed and converted using `0` (ignored) — documented §6. (Most test
pages use px radii.) If `%` is desired later, widen to `[Length;4]` and resolve
in `emit_background` against `border_box()`.

> Rationale: 4-corner `[f32;4]` matches the real shorthand and is what the
> painter needs; px-only keeps the paint path a pure function of the box rect.

### 2.3 Painting — radius rides on the fill commands

Rather than new "RoundedRect" commands, **`FillRect` and `GradientRect` gain a
`radius: [f32;4]` field** (all-zero ⇒ existing sharp behaviour, zero
regression). The background emits its rounded fill (§1.4). Borders also round.

`FillRect` change:

```rust
PaintCmd::FillRect { rect: Rect, color: Rgba, radius: [f32; 4] },
```

All existing `FillRect` constructions (borders, text-decoration, image
placeholder) pass `radius: [0.0; 4]`. A tiny helper avoids churn:

```rust
fn fill(rect: Rect, color: Rgba) -> PaintCmd {
    PaintCmd::FillRect { rect, color, radius: [0.0; 4] }
}
```

### 2.4 Rounded-rect path + rasterizing

```rust
/// Build a rounded-rect Path. Each corner radius is clamped so opposite radii
/// on a side don't exceed that side's length (CSS overlap rule, simplified:
/// clamp each r to min(width, height)/2 per-corner-pair). Corners use cubic
/// Béziers (κ ≈ 0.5523) for a true circular quarter-arc.
fn rounded_rect_path(rect: &Rect, radius: [f32; 4]) -> Option<Path> {
    let (x, y, w, h) = (rect.x, rect.y, rect.width, rect.height);
    if w <= 0.0 || h <= 0.0 { return None; }
    let m = (w.min(h)) / 2.0;
    let [tl, tr, br, bl] = radius.map(|r| r.clamp(0.0, m));
    const K: f32 = 0.5522847498;
    let mut pb = PathBuilder::new();
    pb.move_to(x + tl, y);
    pb.line_to(x + w - tr, y);                                  // top edge
    pb.cubic_to(x + w - tr + tr*K, y, x + w, y + tr - tr*K, x + w, y + tr); // TR
    pb.line_to(x + w, y + h - br);                              // right edge
    pb.cubic_to(x + w, y + h - br + br*K, x + w - br + br*K, y + h, x + w - br, y + h); // BR
    pb.line_to(x + bl, y + h);                                  // bottom edge
    pb.cubic_to(x + bl - bl*K, y + h, x, y + h - bl + bl*K, x, y + h - bl); // BL
    pb.line_to(x, y + tl);                                      // left edge
    pb.cubic_to(x, y + tl - tl*K, x + tl - tl*K, y, x + tl, y); // TL
    pb.close();
    pb.finish()
}
```

- **Background** (color or gradient): when `radius != 0`, fill the rounded path
  (§1.5) instead of `fill_rect`. For a solid color this is a `fill_path` with a
  solid-color `Paint`.
- **Borders**: the simplest correct approach for a **uniform** border (the only
  thing `ComputedStyle` can express — one width/style/color, M4) is to **fill
  the outer rounded path and then clip-erase the inner**. Pragmatic M5 route:
  emit the rounded background/border as **two rounded fills** — outer rounded
  rect in the border color over the border-box, then the (inner) rounded
  background over the padding-box (with corner radii reduced by the border
  width). This paints a uniform rounded border without per-edge geometry. The
  per-edge `FillRect`s in `emit_borders` are bypassed when `radius != 0` (use a
  rounded border path); when `radius == 0`, keep the existing 4-edge fills (no
  regression). This means: for rounded boxes the border may overpaint the
  background area then the background paints on top — order: border-box rounded
  fill (border color) → background rounded fill (inset by border width). See
  §5.1 for the exact emission order.

```rust
PaintCmd::FillRect { rect, color, radius } => {
    if radius_is_zero(radius) {
        fill_rect(&mut pixmap, rect, *color);          // existing path, unchanged
    } else if let Some(path) = rounded_rect_path(rect, *radius) {
        let mut paint = Paint { anti_alias: true, ..Default::default() };
        paint.set_color_rgba8(color.r, color.g, color.b, color.a);
        pixmap.fill_path(&path, &paint, FillRule::Winding, Transform::identity(), None);
    }
}
```

> Clipping the **content** (text/images) to the rounded shape is **not** done in
> M5 (a rounded box's text can in theory poke the corner, but text sits in the
> content box well inside the corner radius in practice). Documented §6
> (`overflow` clipping is already a non-goal from M5-paint). The background and
> border are what visibly round.

## 3. box-shadow

### 3.1 Style model

`box-shadow: <offset-x> <offset-y> <blur-radius>? <spread-radius>? <color>`,
**outset only**, **single** shadow (no comma list; the `inset` keyword and
comma-separated multiple shadows are deferred, §6).

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct BoxShadow {
    pub offset_x: f32,
    pub offset_y: f32,
    pub blur: f32,    // ≥ 0
    pub spread: f32,
    pub color: Rgba,
}

// ComputedStyle, new field:
pub box_shadow: Option<BoxShadow>,
```

`initial()` → `None`. Not inherited.

### 3.2 Parsing

```rust
"box-shadow" => {
    if let Some(s) = parse_box_shadow(comps) { style.box_shadow = Some(s); }
}

/// `<len>{2,4} && <color>`, in CSS order: x y [blur] [spread], color anywhere.
/// `none` → leaves None. `inset` keyword → ignored (treated as outset, §6).
fn parse_box_shadow(comps: &[Component]) -> Option<BoxShadow> {
    let mut lengths = Vec::new();   // px values in source order
    let mut color = Rgba { r:0, g:0, b:0, a:255 }; // default: currentColor≈black
    for c in comps {
        match c {
            Component::Dimension{..} | Component::Number(_) =>
                if let Some(px) = as_px_with(std::slice::from_ref(c), 16.0, 16.0) { lengths.push(px); }
            Component::Color(rgba) => color = *rgba,
            Component::Keyword(k) if k.eq_ignore_ascii_case("none") => return None,
            _ => {}
        }
    }
    match lengths.as_slice() {
        [x, y]              => Some(BoxShadow{offset_x:*x, offset_y:*y, blur:0.0, spread:0.0, color}),
        [x, y, b]           => Some(BoxShadow{offset_x:*x, offset_y:*y, blur:*b,  spread:0.0, color}),
        [x, y, b, s]        => Some(BoxShadow{offset_x:*x, offset_y:*y, blur:*b,  spread:*s,  color}),
        _ => None,
    }
}
```

(`em_basis`/`rem` for `as_px_with` use the element font-size like other lengths.)

### 3.3 Painting — `PaintCmd::BoxShadow`

Emitted **first** within a box (behind everything else):

```rust
PaintCmd::BoxShadow {
    rect: Rect,        // the border-box
    radius: [f32; 4],  // same corner radii as the box
    color: Rgba,
    blur: f32,
    spread: f32,
    offset: (f32, f32),
},
```

### 3.4 Rasterizing the shadow (cheap box-blur over an alpha mask)

The shadow shape = the border-box, expanded by `spread`, translated by `offset`,
with the same (radius + spread) corners, blurred by `blur`. tiny-skia has **no
built-in blur**, so we approximate:

1. Compute the shadow rect: `sr = rect` grown by `spread` on all sides,
   translated by `offset`; corner radii = `radius[i] + spread` (clamped ≥0).
2. Build a single-channel **alpha `Mask`** the size of the pixmap; rasterize the
   rounded shadow path into it (`Mask::fill_path`) → a hard-edged coverage of the
   shadow shape (value 255 inside).
3. **Blur the mask** with a **separable box blur** approximating a Gaussian: run
   a horizontal then vertical moving-average pass over `mask.data_mut()` with a
   kernel radius `≈ blur / 2` (CSS blur radius ≈ 2σ; a single box-blur pass of
   radius `r ≈ blur/2` is a coarse but acceptable falloff — repeat 3× for a
   smoother Gaussian-like result if cheap, §6 notes the approximation). When
   `blur == 0` skip the blur entirely (crisp shadow).
4. **Composite the shadow color through the blurred mask** into the pixmap:
   for each pixel, `alpha = mask[i] * color.a / 255`; `src_over_pixel(buf, idx,
   color, alpha)` — exactly the existing glyph-coverage blend, reused.

```rust
PaintCmd::BoxShadow { rect, radius, color, blur, spread, offset } => {
    let sr = expand_and_offset(rect, *spread, *offset);
    let srad = radius.map(|r| (r + spread).max(0.0));
    let Some(path) = rounded_rect_path(&sr, srad) else { return };
    let mut mask = Mask::new(pixmap.width(), pixmap.height())?; // None-guard → skip
    mask.fill_path(&path, FillRule::Winding, true, Transform::identity());
    if *blur > 0.0 { box_blur_mask(&mut mask, (*blur / 2.0).round() as usize); }
    composite_mask_color(&mut pixmap, &mask, *color);  // src_over per pixel
}
```

`box_blur_mask(mask, r)`: two passes (H then V) of a sliding-window sum over the
mask's `u8` data; O(W·H) regardless of `r`. ~40 lines. The shadow is painted
**before** the box background, so the box covers the shadow under itself
(outset-shadow look). We do **not** subtract the box interior from the shadow
mask (a fully-opaque box hides it; a semi-transparent box would show a faint
shadow beneath — acceptable for M5, noted §6).

> Simplification accepted: a separable box-blur (1–3 passes) instead of a true
> Gaussian; visually close for typical small blur radii. No spread-to-mask AA
> beyond the path's own anti-aliasing.

## 4. opacity

### 4.1 Style model

```rust
// ComputedStyle, new field. Initial 1.0; NOT inherited (opacity is per-element,
// but it visually affects the subtree via group compositing — handled in paint).
pub opacity: f32,
```

Parsing:

```rust
"opacity" => {
    if let Some(n) = single_number(comps) { style.opacity = n.clamp(0.0, 1.0); }
    else if let Some(p) = single_percent(comps) { style.opacity = (p/100.0).clamp(0.0,1.0); }
}
```

### 4.2 Painting — offscreen layer via `PushLayer`/`PopLayer`

`opacity < 1` must composite the element **and its whole subtree** as a group,
then multiply by alpha (so overlapping children inside the group don't
double-darken). This is the only correct approach and is implemented with an
**offscreen layer**: bracket the box's commands between a push/pop pair.

```rust
PaintCmd::PushLayer { opacity: f32 },   // start an offscreen layer
PaintCmd::PopLayer,                     // composite the layer at `opacity`
```

Display-list emission (§5.1): in `emit_self`/the subtree walk, when a box's
`style.opacity < 1.0`, push `PushLayer { opacity }` **before** emitting the box
(shadow/bg/border) and its descendants, and push `PopLayer` **after** the whole
subtree. Because the existing walk already emits a box then recurses into its
children contiguously (within the in-flow pass), the bracket cleanly wraps the
group. (Floats/positioned descendants that are *re-ordered* out of the subtree
are a known edge: M5 wraps the in-flow subtree; an opacity box that itself is the
root of a positioned subtree still works since `paint_subtree` emits it then its
deferred children within the same `paint_subtree` call — bracket there. See §5.2
for the exact insertion point: wrap inside `paint_subtree` around the
`emit_self + collect_inflow + floats + positioned` block.)

### 4.3 Rasterizing layers — a pixmap stack

`rasterize` keeps a **stack of pixmaps**. Normally commands draw to the top of
the stack (initially the base canvas).

```rust
let base = Pixmap::new(width, height)?;  base.fill(WHITE);
let mut stack: Vec<(Pixmap, f32)> = vec![]; // (layer pixmap, its opacity)
// `target()` = top layer pixmap if any, else base.

for cmd in cmds {
    match cmd {
        PaintCmd::PushLayer { opacity } => {
            let mut layer = Pixmap::new(width, height).unwrap();
            // transparent (Pixmap::new is zero-filled = transparent black)
            stack.push((layer, *opacity));
        }
        PaintCmd::PopLayer => {
            let (layer, opacity) = stack.pop().unwrap();
            let dst = stack.last_mut().map(|(p,_)| p).unwrap_or(&mut base);
            composite_layer(dst, &layer, opacity);   // src-over, global alpha ×opacity
        }
        // every other command draws into `current target` (top of stack or base)
        other => draw_into(target_mut(&mut base, &mut stack), other, fonts, images),
    }
}
base
```

- A pushed layer is a **transparent** full-size pixmap (`Pixmap::new` is
  zero-filled = transparent black, so premultiplied src-over works directly).
- `composite_layer(dst, layer, opacity)`: per-pixel src-over of the layer's
  **premultiplied** RGBA over `dst`, scaling the layer's contribution by
  `opacity` (multiply each of the layer's premultiplied R,G,B,A by `opacity`
  before the over). This is correct group opacity: the subtree is fully drawn,
  then faded as a unit.
- **Nested opacity** works automatically: an inner `PushLayer` adds another
  pixmap; its `PopLayer` composites into the enclosing layer (not the base), so
  the inner alpha multiplies, then the outer alpha multiplies the result.

`target_mut`/`draw_into` are thin: existing `fill_rect`/`fill_path`/
`draw_glyph_run`/`blit_image` take a `&mut Pixmap` already — just pass the
current target instead of always the base. Full-size layers (not bounded to the
box) keep coordinates absolute and the code trivial (an empty layer composites to
a no-op). Memory: one extra `width×height×4` per active nesting level — bounded
by `MAX_DIMENSION` and shallow nesting; acceptable for static rendering.

> A box with `opacity == 1.0` emits **no** layer commands — the fast path is
> unchanged (no extra pixmap, identical output).

## 5. Display list / rasterizer changes (consolidated)

### 5.1 New / changed `PaintCmd` variants

```rust
pub enum PaintCmd {
    FillRect   { rect: Rect, color: Rgba, radius: [f32; 4] },     // +radius
    GlyphRun   { /* unchanged */ },
    ImageBlit  { dest: Rect, src: String },                       // unchanged
    GradientRect { rect: Rect, gradient: LinearGradient, radius: [f32; 4] }, // NEW
    BoxShadow  { rect: Rect, radius: [f32;4], color: Rgba, blur: f32, spread: f32, offset: (f32,f32) }, // NEW
    PushLayer  { opacity: f32 },   // NEW
    PopLayer,                      // NEW
}
```

(`LinearGradient`/`GradientStop` re-exported from `starfish_style` into
`starfish_paint`, or duplicated as a tiny paint-local type — prefer re-export to
avoid drift.)

### 5.2 Emission order within a box (`emit_self` / `paint_subtree`)

For an element box with style `s`, the order is:

1. **`PushLayer { opacity }`** if `s.opacity < 1.0` — wraps everything below.
2. **`BoxShadow`** if `s.box_shadow.is_some()` — behind the box.
3. **Background**: `GradientRect` or rounded/sharp `FillRect` (border-box,
   carrying `s.border_radius`).
4. **Border**: if `s.border_radius == 0` → existing 4-edge `FillRect`s
   (unchanged); else the rounded uniform border (outer rounded fill then the
   background is emitted inset — see §2.4). Concretely with rounding we emit, in
   §3 order: shadow → border-box rounded fill in **border color** → padding-box
   rounded fill in the **background** (color/gradient) inset by border widths
   with reduced corner radii. (When there is no border, step 4 is skipped and the
   background fills the border-box directly.)
5. **Children** (recurse — text/images/nested boxes).
6. **`PopLayer`** if a layer was pushed in step 1.

The bracket is placed in `paint_subtree` so it spans the box **and** its
re-ordered float/positioned descendants:

```rust
fn paint_subtree(b, ..., out) {
    let layer = b.style(styled).map(|s| s.opacity).filter(|o| *o < 1.0);
    if let Some(o) = layer { out.push(PaintCmd::PushLayer { opacity: o }); }
    emit_self(b, ...);                 // shadow→bg→border (or text/image)
    for child in b.children() { collect_inflow(child, ...); }
    for f in floats { paint_subtree(f, ...); }
    for p in positioned { paint_subtree(p, ...); }
    if layer.is_some() { out.push(PaintCmd::PopLayer); }
}
```

`emit_self` is extended only for the element arm (`_ =>`): it now also reads
`border_radius`, `box_shadow`, and emits shadow/gradient. `TextRun`/`Marker`/
`Image` arms are unchanged.

### 5.3 Rasterizer dispatch

`rasterize` switches from "always draw into `pixmap`" to "draw into the **current
target**" (§4.3 stack), and adds arms:

| Command | Raster handling |
|---------|-----------------|
| `FillRect` (radius 0) | existing `fill_rect` (unchanged) |
| `FillRect` (radius ≠ 0) | `rounded_rect_path` + `fill_path` solid |
| `GradientRect` | `gradient_shader` + `fill_rect`/`fill_path` with shader paint |
| `BoxShadow` | rounded mask + box-blur + `composite_mask_color` (reuses `src_over_pixel`) |
| `PushLayer`/`PopLayer` | push/pop offscreen pixmap; composite at opacity |
| `GlyphRun`/`ImageBlit` | unchanged, but draw into current target |

**No regression**: a box with no gradient, `border_radius == [0;4]`,
`box_shadow == None`, `opacity == 1.0` emits exactly the same commands as today
(`FillRect`s with `radius:[0;4]` + `GlyphRun`/`ImageBlit`), and the radius-0
`FillRect` arm is byte-identical to the current `fill_rect`. The display-list
ordering tests (`background_before_border_before_text`,
`inflow_only_display_list_unchanged` — which asserts `cmds.len() == 6`) must be
updated only if the radius field changes their pattern matches (it does not break
them since they match on `color`/`rect`, but `inflow_only_display_list_unchanged`
counts commands — still 6 with no effects, OK).

## 6. Edge cases & non-goals

Handled:
- Transparent solid background (`a == 0`) → no fill (unchanged).
- `border_radius == 0` everywhere → sharp `FillRect` path (no `fill_path`, no AA
  change) → pixel-identical to pre-M5.
- `opacity == 1.0` → no layer (fast path).
- `blur == 0` shadow → crisp rounded shadow, no blur pass.
- Gradient with `< 2` stops → not built (falls back to leaving the prior
  background; or transparent).
- Degenerate rect (w/h ≤ 0) → `rounded_rect_path`/`gradient_shader` return
  `None` → skipped.
- Nested opacity → correct via the pixmap stack.

Explicit **non-goals** (deviations from real CSS, documented):
- **Gradients**: linear only (no `radial-gradient`/`conic-gradient`). Angle:
  `deg` + `to <side/corner>` only (no `rad`/`turn`/`grad`; corner forms use 45°
  diagonals, not exact gradient-line-to-corner geometry). Stop **positions**:
  `%` only; `px` stop positions are parsed-but-ignored (treated as auto). No
  `background-position/size/repeat` — the gradient fills the border-box. No
  multiple background layers / comma-separated backgrounds (single background).
- **border-radius**: **circular only** — the elliptical `/`-separated vertical
  radii are ignored (only the horizontal radii are read). `%` radii ignored (px
  only). No clipping of **content** (text/images) to the rounded shape — only the
  background and border visibly round (consistent with M5's no-`overflow`-clip
  non-goal). Rounded **borders** are a uniform outer-fill + inset-background
  approximation (single color/width — matching `ComputedStyle`), not per-edge
  mitred rounded borders.
- **box-shadow**: **outset only** (`inset` ignored), **single** shadow (no
  comma list). Blur is a **separable box-blur approximation** (1–3 passes), not a
  true Gaussian. The shadow is not punched-out under the box (a semi-transparent
  box shows a faint shadow beneath). No `currentColor` resolution beyond using
  black when no color is given.
- **opacity**: implemented via a full-size offscreen layer per active level
  (correct group compositing; memory cost bounded by `MAX_DIMENSION` and
  shallow nesting). No `mix-blend-mode`/`isolation`/`backdrop-filter`.
- A list-form (`box-shadow: a, b` or `background: g1, g2`) is **cheap to add
  later** (Vec on the field + emit per entry) but is **not** in M5 — single each.

## 7. Test plan (font-independent pixel sampling)

All pixel asserts use `body{margin:0}` and explicit box `width/height` so the
sampled coordinates are deterministic and font-version independent. Helper:
`px(&pm, x, y) -> (u8,u8,u8,u8)` already exists in `paint/src/lib.rs` tests.

### 7.1 Style parsing (`crates/style` unit tests)
- `background: linear-gradient(to right, red, blue)` → `style.background` is
  `Background::Gradient` with `angle_deg == 90`, 2 stops red→blue.
- `background: linear-gradient(45deg, #000, #fff)` → `angle_deg == 45`.
- `background: linear-gradient(red, lime, blue)` (no direction) → `angle_deg ==
  180` (to bottom), 3 stops.
- `background: red` → still `Background::Color(red)` (no regression).
- `border-radius: 8px` → `[8,8,8,8]`; `border-radius: 1px 2px` →
  `[1,2,1,2]`; `1px 2px 3px 4px` → `[1,2,3,4]`.
- `box-shadow: 2px 3px 4px 1px #000` → `BoxShadow{2,3,4,1, black}`;
  `box-shadow: 2px 2px red` → blur/spread 0; `box-shadow: none` → `None`.
- `opacity: 0.5` → `0.5`; `opacity: 2` → clamped `1.0`; `opacity: -1` → `0.0`.

### 7.2 Display list (`paint/src/display.rs` tests, no pixmap)
- A `div{background:linear-gradient(...)}` emits exactly one
  `PaintCmd::GradientRect` (no `FillRect` background).
- A `div{box-shadow:...}` emits a `PaintCmd::BoxShadow` **before** its
  background fill (index check).
- A `div{opacity:0.5}<p>x</p>` emits `PushLayer{0.5}` as the first command of the
  subtree and `PopLayer` as the last, with the bg/border/glyph between.
- A plain `div{background:#f00;border:2px solid #00f}` (no effects) still emits 6
  commands in bg→border→glyph order (`inflow_only_display_list_unchanged` still
  passes with `radius:[0;4]`).

### 7.3 Gradient pixels (`render_html_cwd`)
- `div{width:100px;height:100px;background:linear-gradient(to bottom, #ff0000,
  #0000ff)}`: sample `(50, 2)` ≈ red-dominant (`r` high, `b` low) and `(50, 97)`
  ≈ blue-dominant (`b` high, `r` low); the midpoint `(50, 50)` has both channels
  partway (`r` and `b` each ~100–150). Assert `r` strictly decreases and `b`
  strictly increases top→bottom (tolerance bands, not exact, since AA).
- `to right` variant: sample left vs right instead of top vs bottom.

### 7.4 border-radius
- `div{width:100px;height:100px;background:#ff0000;border-radius:30px}` on a
  white canvas: a **corner** pixel `(1,1)` is white (background-through — the
  rounded fill doesn't cover the corner), while the **center** `(50,50)` is red.
  Also `(50,1)` (top edge mid) is red (the straight part).

### 7.5 box-shadow
- `div{width:50px;height:50px;background:#ffffff;box-shadow:10px 10px 0 0 #000}`
  on white (blur 0 for a crisp assert): a pixel just outside the box at the
  offset (e.g. `(70, 70)`, inside the shadow rect but outside the 50×50 box) is
  **dark** (≈ black), while a pixel far from both (e.g. `(120, 120)`) is white,
  and the box interior `(25,25)` is white (box covers its own shadow).
- With blur > 0: assert the shadow edge is a **gradient** of alpha (a pixel near
  the shadow boundary is grey, between black-inside and white-outside).

### 7.6 opacity
- `div{width:50px;height:50px;background:#000000;opacity:0.5}` over the white
  canvas: sample `(10,10)` ≈ `(128,128,128)` (black at 50% over white = mid-grey;
  tolerance ±8). Confirms group composite × alpha.
- **Nested**: outer `div{opacity:0.5}` containing inner
  `div{opacity:0.5;background:#000;...}` over white → the inner black ends up at
  effective alpha 0.25 → sample ≈ `(191,191,191)` (white·0.75 + black·0.25),
  ±8. Confirms nested layers multiply, not double-composite.
