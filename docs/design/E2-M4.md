# E2-M4 — `<img>` images (design note)

Scope: decode a local PNG/JPEG referenced by an `<img>` element's `src`, treat
the element as a **replaced element** with an **intrinsic size**, lay it out
(used size from `width`/`height` attributes or intrinsic), and **paint the
decoded bitmap** scaled (nearest-neighbour) into its content box. `src` is
resolved relative to the input HTML file's directory — **no networking**.

Touches `dom` (already parses `<img>`; nothing to add), `layout` (new replaced
box + sizing), `paint` (new `image`-loading module + `ImageBlit` paint command),
`cli` (passes the input file's parent dir).

Guiding rule (project CLAUDE.md "Simplicity First"): minimal — decode +
replaced sizing + blit. Defer `object-fit`, `srcset`/`<picture>`, `data:` URLs,
SVG, GIF animation. Deviations from real CSS are called out in §8.

This note is pinned to the **real** current APIs read from source (signatures
quoted inline), not an idealized model.

---

## 0. Inputs (recap of the real APIs touched)

From `starfish-dom` (`crates/dom/src/lib.rs`):

- `<img>` is a **void element** (`tree_builder.rs` `VOID_ELEMENTS` includes
  `"img"`), so it parses to a childless `NodeKind::Element` with `name == "img"`
  and its attributes in `Element::attrs`. The existing html test asserts
  `(element img src="i.png")`.
- `Document::get_attribute(id, name) -> Option<&str>` — read `src`, `width`,
  `height` (attribute names are already lowercased). `Document::tag_name(id) ->
  Option<&str>` returns `Some("img")`.

From `starfish-style` (`crates/style/src/computed.rs`):

- `Display::{Block, Inline, InlineBlock, Flex, InlineFlex, None}`. `<img>` has no
  UA rule, so its computed `display` is the **initial `Inline`**.
- `Length::{Px(f32), Percent(f32), Auto}`; `width`/`height` initial `Auto`.
- The UA sheet has **no `img` rule**; CSS `width`/`height` on `img` therefore
  arrive as the computed `Length` like any element (we use them only as a
  fallback — see §5).

From `starfish-layout` (`crates/layout/src/…`):

- `BoxKind::{BlockContainer, InlineBox, InlineBlock, AnonymousBlock, TextRun,
  LineBox, Marker}`. `LayoutBox { kind, style: BoxStyleRef, text: Option<String>,
  dimensions: Dimensions, children }`, with `is_inline_level()` =
  `InlineBox | InlineBlock | TextRun | Marker`.
- `build_node(doc, styled, id, parent_elem)` dispatches `display` →
  `BoxKind`. The **inline-block atom path** is the exact model an inline `<img>`
  reuses:
  - `CollectedItem::Atomic { atom, width, height, space_before }` in `inline.rs`
    — a pre-laid-out box measured by its `margin_box()`, placed on the line like
    an over-wide word, contributing its height to the line-height max, then
    committed via `translate_box`.
  - `block.rs::layout_inline_block(b, cb, styled, m)` runs the box's own block
    layout to get a used size, then re-pins specified margins (auto→0) for a
    tight margin-box.
- `layout(doc, styled, viewport_width, measurer) -> LayoutBox` is the entry.
- `calculate_block_width`/`calculate_block_height` resolve `Length` against the
  containing block; `Dimensions::margin_box()` etc. are the geometry accessors.

From `starfish-paint` (`crates/paint/src/…`):

- `render_html(html, viewport_width) -> Pixmap` (lib.rs) runs the whole pipeline:
  `parse → extract_css → style_tree → FontDb::load → layout(.., &FontMeasurer)
  → paint`. **This is the signature that must gain a base dir** (§3).
- `PaintCmd::{FillRect, GlyphRun}` (display.rs); `build_display_list` walks the
  tree; `emit_self` matches on `BoxKind`. `rasterize(cmds, w, h, fonts) ->
  Pixmap` (raster.rs) iterates `PaintCmd`s, writing into `pixmap.data_mut()`
  (RGBA, premultiplied, row-major). `src_over_pixel` is the per-pixel blend.
- `crates/cli/src/main.rs`: `input` is the HTML path string; `render_html` is
  called with `(&html, width as f32)`.

## 1. Third-party crate — `image`

Added to `crates/paint/Cargo.toml` (the crate that both loads pixels and
paints). `Cargo.lock` is committed, so the version is pinned there; the manifest
uses a caret at the current release (2026-06).

```toml
[dependencies]
# ... existing starfish-* + tiny-skia + fontdue ...

[dependencies.image]
version = "0.25"            # current 0.25.x; PNG + JPEG decode
default-features = false   # drop the ~20 default codecs to limit build cost
features = ["png", "jpeg"] # only the two formats the milestone requires
```

Rationale: `image` is the de-facto pure-Rust decoder hub and gives a uniform
`image::open(path) -> DynamicImage` plus `.to_rgba8() -> RgbaImage` (an
`ImageBuffer<Rgba<u8>, Vec<u8>>` whose `.into_raw()` is exactly the RGBA8
`Vec<u8>` we need). `default-features = false` + `features = ["png", "jpeg"]`
keeps the dependency tree small (no GIF/WebP/TIFF/BMP/etc. codecs compiled).
This is the minimal fit per Simplicity First.

We rely on guessing the format from the file's magic bytes (`image::open`
sniffs), so a `.jpg` named `.png` still decodes — good enough and no extra code.

## 2. Image loading + cache (`crates/paint/src/image_store.rs`, new module)

Decoding is needed at **two** stages: **layout** needs the intrinsic
`(width, height)`; **paint** needs the RGBA pixels. To decode each file **once**
and consult it from both stages, introduce a shared `ImageStore` keyed by the
**resolved** path, created up front in `render_html` and passed by `&` into both
`layout` and `paint`.

### 2.1 Types

```rust
use std::collections::HashMap;
use std::path::{Path, PathBuf};

/// One decoded image: tightly-packed RGBA8, row-major, `width*height*4` bytes.
#[derive(Clone)]
pub struct DecodedImage {
    pub width: u32,
    pub height: u32,
    pub rgba: Vec<u8>,
}

/// Cache of decoded images keyed by **resolved absolute path**. Each `src` is
/// decoded at most once; both layout (intrinsic size) and paint (pixels) read
/// from here. A failed decode is cached as `None` so we don't retry / re-log.
#[derive(Default)]
pub struct ImageStore {
    base: PathBuf,
    cache: HashMap<PathBuf, Option<DecodedImage>>,
}
```

### 2.2 API

```rust
impl ImageStore {
    /// Create a store resolving relative `src` against `base` (the input HTML
    /// file's directory).
    pub fn new(base: impl Into<PathBuf>) -> ImageStore {
        ImageStore { base: base.into(), cache: HashMap::new() }
    }

    /// Resolve a raw `src` attribute to the absolute path we key on. Absolute
    /// `src` is used as-is; relative `src` joins `self.base`. (No URL parsing,
    /// no `file://`, no `data:` — §8.)
    fn resolve(&self, src: &str) -> PathBuf {
        let p = Path::new(src);
        if p.is_absolute() { p.to_path_buf() } else { self.base.join(p) }
    }

    /// Load + decode (or fetch from cache) the image at `src`. Returns `None`
    /// for a missing / undecodable file (cached so repeats are cheap). Never
    /// panics. `&mut self` because decoding mutates the cache.
    pub fn get(&mut self, src: &str) -> Option<&DecodedImage> {
        let key = self.resolve(src);
        self.cache.entry(key.clone()).or_insert_with(|| decode(&key));
        self.cache.get(&key).and_then(|o| o.as_ref())
    }

    /// Read-only lookup used by paint *after* layout has populated the cache for
    /// every `src` it sized. Falls back to `None` (broken image) if absent.
    pub fn peek(&self, src: &str) -> Option<&DecodedImage> {
        self.cache.get(&self.resolve(src)).and_then(|o| o.as_ref())
    }
}

/// Decode one file to RGBA8; `None` on any I/O or decode error (never panics).
fn decode(path: &Path) -> Option<DecodedImage> {
    let img = image::open(path).ok()?;       // sniffs PNG/JPEG by magic bytes
    let rgba = img.to_rgba8();
    let (width, height) = rgba.dimensions();
    Some(DecodedImage { width, height, rgba: rgba.into_raw() })
}
```

### 2.3 Threading: who calls `get` vs `peek`

- **Layout calls `get`** (decoding on demand) when it builds/sizes an `<img>`
  box, so the cache is fully populated by the end of layout. Layout therefore
  needs `&mut ImageStore`.
- **Paint calls `peek`** (read-only) — every `src` it encounters was already
  decoded during layout, so a shared `&ImageStore` suffices.

`render_html` owns the store, calls `layout(.., &mut store)`, then
`paint(.., &store)`. (Re-keying by resolved path means a `src` appearing twice
decodes once.)

### 2.4 The image **key** carried by the box

The layout box must carry enough to re-find the image at paint time. The
**resolved path string** is the natural key, but to avoid re-resolving (and to
keep `layout` the single place that touches the store) the box stores the **raw
`src` string**; paint re-resolves via the same `ImageStore::peek(src)` (the store
holds the base dir). One field, no new key type. (See §4 — `BoxKind::Image`
carries `text: Some(src)`.)

## 3. Pipeline / API changes (base dir threading)

### 3.1 `render_html` gains a base dir

```rust
// crates/paint/src/lib.rs

/// End-to-end: HTML string → rendered pixmap. `base_dir` is the directory that
/// relative `<img src>` paths resolve against (the input file's parent).
pub fn render_html(html: &str, viewport_width: f32, base_dir: &Path) -> Pixmap {
    let doc = starfish_html::parse(html);
    let css = extract_css(&doc);
    let sheet = starfish_css::parse_stylesheet(&css);
    let styled = style_tree(&doc, &[sheet]);
    let fonts = FontDb::load().expect("embedded faces load");
    let mut images = ImageStore::new(base_dir);

    // layout decodes intrinsic sizes into `images`...
    let root = layout(&doc, &styled, viewport_width, &FontMeasurer(&fonts), &mut images);

    let width = clamp_dimension(viewport_width);
    let height = clamp_dimension(root.dimensions().margin_box().height);

    // ...paint reads pixels back out of the same store.
    paint(&root, &styled, &fonts, &images, width, height)
}
```

A convenience that keeps old call sites compiling and uses the current working
directory:

```rust
/// `render_html` resolving relative images against the current directory.
pub fn render_html_cwd(html: &str, viewport_width: f32) -> Pixmap {
    let base = std::env::current_dir().unwrap_or_else(|_| PathBuf::from("."));
    render_html(html, viewport_width, &base)
}
```

(Existing paint unit tests that don't use images switch to `render_html_cwd`;
behaviour is unchanged for image-free pages.)

`paint` also takes `&ImageStore`:

```rust
pub fn paint(
    layout_root: &LayoutBox,
    styled: &StyledTree,
    fonts: &FontDb,
    images: &ImageStore,
    width: u32,
    height: u32,
) -> Pixmap {
    let cmds = build_display_list(layout_root, styled, fonts, images);
    rasterize(&cmds, width, height, images)   // ImageBlit needs pixels (§7)
}
```

### 3.2 `layout` gains `&mut ImageStore`

`ImageStore` lives in `starfish-paint`, but `starfish-layout` must size `<img>`
boxes from intrinsic dimensions and therefore needs the `(w,h)` lookup. To avoid
a `layout → paint` dependency cycle, layout depends only on a **tiny trait**, and
paint's `ImageStore` implements it:

```rust
// crates/layout/src/measure.rs (next to TextMeasurer) — layout-side trait.

/// Supplies intrinsic image sizes to layout. paint's `ImageStore` implements
/// it; tests use a stub. Mirrors the `TextMeasurer` injection pattern.
pub trait ImageSource {
    /// Intrinsic `(width, height)` in px of the image at `src`, or `None` for a
    /// missing/undecodable image (→ broken-image sizing, §5).
    fn intrinsic_size(&self, src: &str) -> Option<(f32, f32)>;
}
```

```rust
// crates/paint/src/image_store.rs — paint-side impl. `&self` because layout
// only needs sizes; decoding happens eagerly when paint builds the store, OR
// lazily via interior mutability. Simpler: decode eagerly in a pre-pass.
impl starfish_layout::ImageSource for ImageStore {
    fn intrinsic_size(&self, src: &str) -> Option<(f32, f32)> {
        self.peek(src).map(|d| (d.width as f32, d.height as f32))
    }
}
```

> **Decode timing decision.** `intrinsic_size` takes `&self`, but decoding needs
> `&mut`. Two clean options:
>
> 1. **Pre-pass (chosen):** before `layout`, `render_html` walks the DOM for
>    every `<img src>` and calls `images.get(src)` to populate the cache. Then
>    layout and paint both read via `&self`/`peek`. One DFS, trivial, keeps the
>    layout signature `&dyn ImageSource` (immutable). This is the simplest
>    threading and avoids `RefCell`.
> 2. Interior mutability (`RefCell<HashMap<…>>`) so `intrinsic_size(&self)`
>    decodes lazily. More moving parts; rejected for M4.
>
> With the pre-pass, `layout`'s new parameter is `images: &dyn ImageSource`
> (not `&mut`), matching the existing `measurer: &dyn TextMeasurer` style:

```rust
pub fn layout(
    doc: &Document,
    styled: &StyledTree,
    viewport_width: f32,
    measurer: &dyn TextMeasurer,
    images: &dyn ImageSource,
) -> LayoutBox;
```

`render_html` does the pre-pass, then passes `&images` (which derefs to
`&dyn ImageSource`) to `layout` and `&images` to `paint`.

## 4. DOM / box generation (`crates/layout/src/boxtree.rs`)

### 4.1 New `BoxKind::Image`

```rust
pub enum BoxKind {
    BlockContainer,
    InlineBox,
    InlineBlock,
    AnonymousBlock,
    TextRun,
    LineBox,
    Marker,
    Image,   // NEW: a replaced element (<img>). Carries `src` in `text`,
             // its used size in `dimensions`, no children.
}
```

`is_inline_level()` must include `Image` **only when the element is inline-level**
— but a `BoxKind` is kind-level, not display-level. We model it like the
inline-block/block split: an inline `<img>` becomes `BoxKind::Image` (inline-level
atomic), and a `display:block` `<img>` becomes a `BlockContainer`-style replaced
box. To keep one variant, `Image` is **always inline-level**, and a block `<img>`
is handled by wrapping (see §4.3). Concretely:

```rust
pub(crate) fn is_inline_level(&self) -> bool {
    matches!(
        self.kind,
        BoxKind::InlineBox | BoxKind::InlineBlock | BoxKind::TextRun
            | BoxKind::Marker | BoxKind::Image
    )
}
```

### 4.2 Generating the image box in `build_node`

`<img>` is a void element, so the existing `NodeKind::Element` arm handles it; we
special-case it **before** the generic `display → kind` match:

```rust
NodeKind::Element(_) => {
    // Replaced element: <img> with a src. Build a leaf Image box (no children).
    if doc.tag_name(id) == Some("img") {
        if let Some(src) = doc.get_attribute(id, "src") {
            let display = styled.get(id).map(|s| s.display).unwrap_or(Display::Inline);
            if display == Display::None {
                return None;
            }
            let mut b = LayoutBox::new(BoxKind::Image, BoxStyleRef::Node(id));
            b.text = Some(src.to_string());        // the raw src (resolved at size/paint)
            // `display:block` is recorded so layout sizes it as a block (§6).
            // No children are generated (replaced element).
            return Some(b);
        }
        return None; // <img> without a src → no box
    }
    // ... existing element handling (display dispatch) ...
}
```

Notes:

- The box stores the **raw `src`** in `text` (reusing the existing field, like
  `Marker`/`TextRun`). Paint re-resolves through the store. No new field on
  `LayoutBox`.
- HTML `width`/`height` **attributes** are read at sizing time (§5), not stored
  separately — they're cheap to re-read via `get_attribute` and keep box
  generation tiny.
- An `<img>` whose `src` doesn't decode still gets an `Image` box (a broken-image
  placeholder, sized per §5); we never drop it for a bad file.

### 4.3 Block vs inline image

`<img>` default `display` is `Inline` → the `Image` box is inline-level and
flows on a line (§6). For `display:block` (or `display:inline-block`) we keep the
single `Image` kind but let block layout size it: the simplest correct route is

- **inline / inline-block `<img>`** → `BoxKind::Image`, inline-level, placed by
  the inline atom path (§6.1).
- **block `<img>`** → still `BoxKind::Image`, but because it is inline-level by
  `is_inline_level()`, a lone block-displayed image inside a block container
  would be wrapped in an anonymous block and flow as a one-item line. That is
  visually correct (the image sits on its own line at the left), so for M4 we
  **accept the inline-atom path for block images too** and note the deviation
  (§8): a `display:block` image is laid out as an atomic inline on its own line
  rather than as a true block box. This avoids a second code path. (If exact
  block sizing is wanted later, dispatch `display==Block && tag==img` to a
  `layout_image_block` mirroring `layout_inline_block`.)

> Simplicity decision: one `Image` kind, always inline-level, always sized via
> the atom path. Block display only changes that it tends to land alone on its
> line (true in practice because an image is usually the sole/leading inline on
> the line). Documented as a non-goal nuance in §8.

## 5. Replaced sizing (used size resolution)

Define a single function, called from the atom layout (§6.1):

```rust
/// Resolve an <img>'s used content size (CSS replaced-element sizing, M4 subset).
/// `intrinsic` is the decoded (w,h) or `None` for a broken image.
/// `attr_w`/`attr_h` are the HTML width/height attributes parsed as px (None if
/// absent/invalid). Returns (used_w, used_h), each ≥ 0.
fn replaced_size(intrinsic: Option<(f32, f32)>, attr_w: Option<f32>, attr_h: Option<f32>)
    -> (f32, f32)
{
    match (attr_w, attr_h, intrinsic) {
        // both attrs → use them verbatim
        (Some(w), Some(h), _) => (w, h),
        // one attr + intrinsic → scale the other preserving aspect ratio
        (Some(w), None, Some((iw, ih))) if iw > 0.0 => (w, w * ih / iw),
        (None, Some(h), Some((iw, ih))) if ih > 0.0 => (h * iw / ih, h),
        // one attr, no usable intrinsic → square-ish fallback (the attr in both)
        (Some(w), None, _) => (w, w),
        (None, Some(h), _) => (h, h),
        // no attrs → intrinsic size
        (None, None, Some((iw, ih))) => (iw, ih),
        // no attrs, broken image → zero box (§8 broken-image handling)
        (None, None, None) => (0.0, 0.0),
    }
}
```

Rules, precisely:

1. **Both `width` and `height` attributes present** → used size is exactly those.
2. **Exactly one present** + decoded intrinsic available → the given dimension is
   used and the other is computed to **preserve the intrinsic aspect ratio**.
3. **Exactly one present** + broken image → the given dimension is used for both
   axes (a square placeholder; rare).
4. **Neither present** + decoded → the **intrinsic** decoded size.
5. **Neither present** + broken → a **0×0** box (collapses; the broken-image
   border in §7 then draws nothing). This is the "broken image → placeholder of
   the width/height attrs or 0, never panic" requirement.

**Attribute parsing.** HTML presentational `width="100"` is an integer pixel
count; we parse it leniently:

```rust
fn attr_px(doc: &Document, id: NodeId, name: &str) -> Option<f32> {
    doc.get_attribute(id, name)
        .and_then(|v| v.trim().trim_end_matches("px").parse::<f32>().ok())
        .filter(|v| *v >= 0.0)
}
```

**CSS width/height (deferred to a thin override).** For M4 the **attributes are
the supported path**. If the computed `style.width`/`style.height` are definite
(`Length::Px` or `Percent` resolved against the containing block) we let them
**override** the attribute by feeding them in as `attr_w`/`attr_h` (CSS wins over
presentational hints, matching the cascade). Resolution reuses
`block::resolve(len, cb_width)`:

```rust
let attr_w = resolve(style.width, cb_width).or_else(|| attr_px(doc, id, "width"));
let attr_h = match style.height { Length::Auto => attr_px(doc, id, "height"),
                                  h => resolve(h, cb_height_or_0) };
```

(Heights as percent against an indefinite CB stay `Auto`, consistent with the
existing block height rule.) This is a few lines and gives both
`<img width=100>` and `img { width: 100px }`. The aspect-preserving branch fires
whenever exactly one of the two ends up definite.

## 6. Layout integration

### 6.1 Inline atomic image (`crates/layout/src/inline.rs`)

The `Image` box is sized and placed by **extending the existing inline atom
path** — it behaves like an inline-block whose size comes from
`replaced_size` instead of from inner block layout. In `collect_items`, add an
arm beside `BoxKind::InlineBlock`:

```rust
BoxKind::Image => {
    let src = child.text.clone().unwrap_or_default();
    let id = child.style.node();
    let style = style_of(c.styled, child);
    let cbw = c.cb.content.width;
    let intrinsic = c.images.intrinsic_size(&src);   // &dyn ImageSource on Collector
    let attr_w = resolve(style.width, cbw).or_else(|| attr_px(c.doc, id, "width"));
    let attr_h = /* as §5 */;
    let (w, h) = replaced_size(intrinsic, attr_w, attr_h);

    // Build a fully-sized leaf box: content rect (w,h), no margins/border for M4
    // (an <img> rarely has them; CSS box-model on replaced elements is §8).
    let mut sub = child.clone();
    sub.dimensions = Dimensions::default();
    sub.dimensions.content.width = w;
    sub.dimensions.content.height = h;
    // margins from style (auto→0), so margin_box width is the line advance:
    sub.dimensions.margin.left  = resolve_or_zero(style.margin_left, cbw);
    sub.dimensions.margin.right = resolve_or_zero(style.margin_right, cbw);
    sub.dimensions.margin.top   = resolve_or_zero(style.margin_top, cbw);
    sub.dimensions.margin.bottom= resolve_or_zero(style.margin_bottom, cbw);

    let mb = sub.dimensions.margin_box();
    let atom = c.atomics.len();
    c.atomics.push(sub);
    c.out.push(CollectedItem::Atomic { atom, width: mb.width, height: mb.height,
                                       space_before: c.pending_space });
    c.pending_space = false;
}
```

This requires the `Collector` to also carry `doc: &Document` and
`images: &dyn ImageSource` (two new immutable refs; `layout_inline`'s signature
gains `images`, threaded from `layout_block` → `layout`). After collection the
**existing** greedy line breaking and `PlacedItem::Atomic` commit path handle the
image with **no further change**: it advances `cursor_x` by its margin-box width,
wraps when it overflows, sets the line height to its margin-box height, and is
re-positioned by `translate_box` when committed to a `LineBox`. The image needs
**no child block layout** — its size is fully determined by §5, so unlike
inline-block we do **not** call `layout_inline_block` on it.

> Because the `Image` box is built leaf-and-sized here (no recursion), it
> reports its size purely from intrinsic/attrs — satisfying "reports its size
> without running child block layout."

### 6.2 Block / standalone image

Per §4.3, a `display:block` `<img>` is still an inline-level `Image` and gets
wrapped in an anonymous block by `wrap_anonymous_blocks` when it sits among block
siblings, then flows as a single-atom line at the left of that anonymous block —
visually "the image on its own line." No dedicated block-image code for M4.

## 7. Paint — `PaintCmd::ImageBlit` + raster blit

### 7.1 New command (`crates/paint/src/display.rs`)

```rust
pub enum PaintCmd {
    FillRect { rect: Rect, color: Rgba },
    GlyphRun { /* ... unchanged ... */ },
    /// Blit a decoded image scaled into `dest`. `src` is the raw <img> src; the
    /// rasterizer looks the pixels up in the ImageStore. A broken image (missing
    /// from the store) paints nothing (the optional placeholder border is emitted
    /// as separate FillRects here, §7.3).
    ImageBlit { dest: Rect, src: String },
}
```

Emission in `emit_self`:

```rust
fn emit_self(b, styled, fonts, out) {
    match b.kind() {
        BoxKind::TextRun | BoxKind::Marker => emit_text(b, styled, fonts, out),
        BoxKind::Image => emit_image(b, out),                 // NEW
        _ => { emit_background(b, styled, out); emit_borders(b, styled, out); }
    }
    // ... existing child recursion ...
}

fn emit_image(b: &LayoutBox, out: &mut Vec<PaintCmd>) {
    let Some(src) = b.text() else { return };
    let dest = b.dimensions().content;          // absolute content rect (used size)
    if dest.width <= 0.0 || dest.height <= 0.0 { return; }  // 0×0 broken → nothing
    out.push(PaintCmd::ImageBlit { dest, src: src.to_string() });
}
```

(`role()` already returns `InFlow` for any non-`BlockContainer/InlineBlock/
InlineBox` kind, so `Image` paints in the in-flow pass — correct.)

### 7.2 Rasterizing the blit (`crates/paint/src/raster.rs`)

`rasterize` gains `images: &ImageStore` and a new match arm:

```rust
PaintCmd::ImageBlit { dest, src } => blit_image(&mut pixmap, dest, src, images),
```

```rust
/// Nearest-neighbour scale the decoded RGBA into `dest`, src-over into the
/// pixmap, clipped to bounds. Missing image (broken) → no-op (placeholder
/// border, if any, was emitted as separate FillRects).
fn blit_image(pixmap: &mut Pixmap, dest: &Rect, src: &str, images: &ImageStore) {
    let Some(img) = images.peek(src) else { return };
    if img.width == 0 || img.height == 0 { return; }
    let dx0 = dest.x.round() as i32;
    let dy0 = dest.y.round() as i32;
    let dw = dest.width.round().max(0.0) as i32;
    let dh = dest.height.round().max(0.0) as i32;
    let (pw, ph) = (pixmap.width() as i32, pixmap.height() as i32);
    let buf = pixmap.data_mut();
    for ry in 0..dh {
        let py = dy0 + ry;
        if py < 0 || py >= ph { continue; }
        // nearest source row
        let sy = (ry as u32 * img.height / dw.max(1) as u32).min(img.height - 1); // see note
        let sy = (ry as u32 * img.height / dh.max(1) as u32).min(img.height - 1);
        for rx in 0..dw {
            let px = dx0 + rx;
            if px < 0 || px >= pw { continue; }
            let sx = (rx as u32 * img.width / dw.max(1) as u32).min(img.width - 1);
            let si = ((sy * img.width + sx) * 4) as usize;
            let (r, g, b, a) = (img.rgba[si], img.rgba[si+1], img.rgba[si+2], img.rgba[si+3]);
            if a == 0 { continue; }
            let idx = ((py * pw + px) as usize) * 4;
            src_over_pixel(buf, idx, Rgba { r, g, b, a }, a);  // reuse the glyph blender
        }
    }
}
```

(The duplicated `sy` line above is a typo guard — the **`dh`-based** mapping is
correct: `sy = ry * img.height / dh`. The implementation uses the `dh` form.)

`src_over_pixel(buf, idx, color, a)` is the **existing** glyph blender: it
premultiplies `color` by `a` and composites over the premultiplied destination —
exactly right for an opaque-or-alpha image pixel. Fully-opaque images overwrite;
PNGs with alpha composite over the white canvas / underlying boxes correctly.

### 7.3 Broken / missing image

- `replaced_size` gives **0×0** when neither attr is set and the file is broken →
  `emit_image` emits nothing (collapsed box). No panic.
- When `width`/`height` attrs *are* set but the file is broken, the box has a
  non-zero `dest` but `peek(src)` returns `None` → `blit_image` is a no-op. We
  optionally draw a **1px grey placeholder border** around `dest` to signal the
  broken image. M4 choice: **emit the placeholder border** (cheap, helps the
  visual test). In `emit_image`, when the store has no pixels, push four 1px
  `FillRect`s (grey `#808080`) around `dest` instead of the `ImageBlit`:

```rust
fn emit_image(b, images_known: &dyn Fn(&str) -> bool, out) {
    // if the image is known-decodable → ImageBlit; else placeholder border.
}
```

(Whether the image decoded is known to the display-list builder via the same
`&ImageStore` it already receives — `build_display_list` gains `images:
&ImageStore`. So `emit_image` checks `images.peek(src).is_some()`.) Keeping the
border tiny and grey, no panic on any input.

## 8. Edge cases & non-goals (deliberate deviations)

Handled:
- Relative `src` resolved against the input file's dir; absolute `src` used
  as-is (§2.1).
- Missing / undecodable file → cached `None`, **never panics**; box sized per §5
  (0×0 if no attrs, attr-sized placeholder with a grey border otherwise, §7.3).
- Same `src` used twice decodes once (path-keyed cache).
- PNG alpha composites src-over; opaque JPEG overwrites.
- `<img>` without `src` → no box.
- Aspect-ratio preservation when exactly one of width/height is given (§5).

Explicit **non-goals** (documented limitations):
- **No networking / no `http(s)`/`file://`/`data:` URLs** — local filesystem
  paths only. (`data:` base64 is a possible later add; deferred.)
- **No SVG, no GIF animation, no WebP/AVIF/TIFF/BMP** — only PNG + JPEG codecs
  are compiled (`image` features `png`,`jpeg`). A GIF/SVG `src` → broken image.
- **No `srcset` / `<picture>` / `sizes`** — only the `src` attribute.
- **No `object-fit` / `object-position`** — the bitmap is **stretched** to fill
  the content box (no letterboxing / cover / contain).
- **Nearest-neighbour scaling only** (no bilinear) — fast, slightly blocky on
  upscale; acceptable for M4. (Bilinear is an optional follow-up.)
- **No CSS box-model interplay on the replaced box beyond margins** — padding /
  border on `<img>` are ignored for M4 sizing/paint (the content box == used
  size). Backgrounds on `<img>` are not painted.
- **`display:block` image** is laid out as an atomic inline on its own line, not
  as a true block-level replaced box (§4.3). Centering via `margin:auto` on a
  block image is therefore **not** honoured.
- **No `min/max-width/height`, no `box-sizing`** on images.
- **No lazy loading / `loading=lazy`**, no decode async — everything is eager
  and synchronous.
- **No image-rendering / colour-management / ICC** — raw RGBA8 as decoded.

/// Write a 2×2 RGBA PNG (TL red, TR green, BL blue, BR white) into `dir`,
/// return its path. Deterministic; uses the `image` encoder.
fn write_2x2_png(dir: &Path) -> PathBuf {
    use image::{Rgba, RgbaImage};
    let mut img = RgbaImage::new(2, 2);
    img.put_pixel(0, 0, Rgba([255, 0, 0, 255]));

    img.save(&path).unwrap();   // PNG by extension

}
