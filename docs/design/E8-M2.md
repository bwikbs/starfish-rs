# E8-M2 — `fetch()` + minimal synchronous `XMLHttpRequest` (design note)

Scope (per `docs/ROADMAP-epic8.md`): networking from JS, backed by the **existing**
`starfish-net::ResourceLoader`, drained through Boa's job queue during the existing
run-to-quiescence loop:

- **`fetch(url[, init])`** → a `Promise` resolving to a **Response**
  (`.ok`/`.status`/`.statusText`/`.url`/`.headers.get(name)`/`.text()`/`.json()`). Since this is a
  one-shot run-to-quiescence renderer, the load happens **synchronously** against the loader the
  moment `fetch` is called, but `fetch` still returns a **resolved** `JsPromise` so `.then(...)`
  reactions queue as Boa jobs and drain through the existing `ctx.run_jobs()` in the quiescence loop.
- **minimal synchronous `XMLHttpRequest`** — `open`/`send`/`responseText`/`status`/`statusText`/
  `readyState`/`getResponseHeader`. Always synchronous (the `async` flag is accepted and ignored).

Guiding rule (project CLAUDE.md "Simplicity First / Surgical Changes"): a sync-backed `fetch`
returning a **resolved** Promise + a minimal sync XHR; **reuse the loader** (no new net code). Defer
streaming, `Response.body`, `arrayBuffer` (or a thin extra), `AbortController`, CORS policy, the full
`Headers` surface, async XHR + XHR events. Non-goals are §6.

The companion ANALYSIS agent is the authority on Boa 0.21.1 `JsPromise` + native-class shapes; this
note pins to the **real current source** (quoted as read) for `starfish-{net,js}` and the **verified
0.21.1** `JsPromise`/JSON shapes (§0.3).

## 0. Inputs — the real APIs touched (verified against source)

### 0.1 `starfish-net` — the loader (reused verbatim, no new net code)

- `trait ResourceLoader { fn fetch(&self, url: &Url) -> Result<Resource, LoadError>; }`
  (`net/src/loader.rs:86`). Implementations **never panic** — every failure is a `LoadError` value.
- `Resource { bytes: Vec<u8>, content_type: Option<String>, final_url: Option<Url> }`
  (`loader.rs:75`), `#[derive(Clone)]`.
- `LoadError` (`loader.rs:11`) variants: `NotFound(Url)`, `Io`, `UnsupportedScheme(String)`,
  `BadPath`, `BadUrl(ParseError)`, **`Http { status: u16, url }`**, **`Timeout(Url)`**,
  **`Network(String)`**, `BadDataUrl(Url)`. These drive the fetch reject-vs-resolve decision (§2.4).
- The binary's real loader is `RouterLoader` (`net/src/router.rs`) routing `file`/`http(s)`/`data`;
  `LocalLoader` + `DataLoader` are used in tests. `Url::join(base, rel)` resolves relative URLs
  (precedent: `js/src/collect.rs:91` resolves `<script src>` exactly this way).

### 0.2 `starfish-js` run_scripts + the loader-lifetime problem (THE crux)

`run_scripts` (`js/src/lib.rs:77`) — **the loader is a borrow `&dyn ResourceLoader` for this call**:

```rust
pub fn run_scripts(
    doc: &mut Document,
    base: &Url,
    loader: &dyn ResourceLoader,                  // <-- borrowed ONLY for this call
    sheets: Rc<Vec<starfish_css::Stylesheet>>,
) -> ScriptOutcome {
    let (scripts, load_errors) = collect::collect_scripts(doc, base, loader);  // eager pre-fetch
    // ... build Context, globals::install(&mut ctx, &shared, base, sheets) ...
    for src in scripts { ctx.eval(...) }          // scripts run HERE
    run_to_quiescence(&mut ctx, &shared, &mut errors);  // .then/timers drain HERE
    // ... drop(ctx); reclaim doc ...
}
```

- **Pre-script script-src fetches** (`collect_scripts` → `fetch_external`, `collect.rs:90`) happen
  **eagerly** while `loader` is in scope — that pattern can't serve `fetch()`/XHR, which are called
  **arbitrarily later** from a `'static` Boa `NativeFunction` (during `eval` + during
  `run_to_quiescence`), where the `loader` borrow is no longer reachable through any value the native
  fn can hold. **This is the crux** (§1).
- `DomState` (`js/src/dom/mod.rs:53`) is the realm host-defined struct, `#[derive(Trace, Finalize,
  JsData)]`, read by every native fn via `ctx.realm().host_defined().get::<DomState>()`. It already
  carries `#[unsafe_ignore_trace]` non-GC fields (`doc: SharedDoc`, `author_sheets:
  Rc<Vec<Stylesheet>>`). **This is where the loader pointer + base go** (§1.2).
- `dom::install(ctx, shared, sheets)` (`dom/mod.rs:160`) seeds `DomState`; `globals::install(ctx,
  shared, base, sheets)` (`globals.rs:26`) calls it + registers global callables via
  `ctx.register_global_callable(name, len, NativeFunction::from_fn_ptr(f))`. **fetch/XHR register
  here** (§5).
- The run-to-quiescence loop already calls `run_microtasks` (= `ctx.run_jobs()`) after scripts, after
  each lifecycle event, and after each timer (`lib.rs:168,202,212,230,234`). **`.then` reactions
  drain for free** (§4) — no loop change needed.
- Native-fn precedents to mirror: `timer::set_timeout` (global callable reading `DomState`),
  `event::event_constructor` + the `FunctionObjectBuilder...constructor(true)` pattern
  (`globals.rs:129`) for a constructible class, `computed::get_computed_style` (snapshots out of
  `DomState`, drops the borrow, then works). `node::arg_str(args, i, ctx) -> JsResult<String>`
  (`dom/node.rs:73`) coerces an argument to a Rust `String`.

### 0.3 Boa 0.21.1 — the verified API surface (registry-checked)

- **`JsPromise`** (`object/builtins/jspromise.rs`): `JsPromise::resolve<V: Into<JsValue>>(value,
  ctx) -> JsPromise` (:399) — a **resolved** promise; `JsPromise::reject<E: Into<JsError>>(error,
  ctx) -> JsPromise` (:440) — a **rejected** one. `impl From<JsPromise> for JsValue` (:1335) and
  `for JsObject` (:1328) — so a native fn returns `Ok(JsPromise::resolve(resp, ctx).into())`. A
  `.then(...)` on the returned promise queues a **promise job**; `ctx.run_jobs()` drains it (the
  E4-M3 quiescence loop already calls it). **No new job plumbing.**
- **JSON.parse for `.json()`:** Boa's `Json::parse` is `pub(crate)` (`builtins/json/mod.rs:83`) —
  **NOT reachable** from `js`. Call it through the realm: fetch the global `JSON` object, get its
  `parse` property (a callable `JsObject`), and `call(&JsValue::undefined(), &[text.into()], ctx)`.
  A parse error comes back as `Err(JsError)` → reject the `.json()` promise (§2.5). (Helper in §2.5.)
- **Native class with data** (for `Response` + `XMLHttpRequest` if we choose the class route):
  `impl Class for T` with `data_constructor` + `init`, registered via
  `ctx.register_global_class::<T>()` (precedent: `impl Class for NodeHandle`, `dom/mod.rs:90`) — or a
  constructible global function via `FunctionObjectBuilder::new(&realm, nf).constructor(true).build()`
  (precedent: the `Event` constructor, `globals.rs:129`). XHR uses the **class** route (it needs
  mutable per-instance native data); Response uses a **plain object** (§2.3 — simpler, no class).
- `JsObject::call(this, &[args], ctx) -> JsResult<JsValue>`, `obj.get(key, ctx)`,
  `obj.set(key, v, throw, ctx)`, `ObjectInitializer`, `NativeFunction::from_copy_closure_with_captures`
  — all as used across `dom/*.rs`.

## 1. Reaching the loader from a native fn — THE crux

### 1.1 The problem restated

`fetch(url)` and `xhr.send()` are `'static` `NativeFunction`s. They run **during** `ctx.eval(...)` and
**during** `run_to_quiescence(...)` — both **inside** `run_scripts`, where `loader: &dyn
ResourceLoader` is a live borrow. But a native fn can only reach state through the realm host-defined
`DomState`, which is `'static`/GC-managed and **cannot** hold a non-`'static` borrow. We need the
native fn to call `loader.fetch(&url)` using **the same loader** that `run_scripts` borrowed.

### 1.2 Decision — a raw `*const dyn ResourceLoader` + base `Url` in `DomState`, set/cleared around the script phase

Store, in `DomState`, a **raw pointer** to the borrowed loader plus an owned copy of the base `Url`.
Set both at `dom::install` time (where `loader` is in scope) and **clear the pointer before
`run_scripts` returns** (before the borrow it points at could end). The pointer is **only ever
dereferenced during `run_scripts`**, while the original borrow is provably still alive — so it never
dangles in use.

```rust
// crates/js/src/dom/mod.rs — extend DomState
#[derive(Trace, Finalize, JsData)]
pub(crate) struct DomState {
    #[unsafe_ignore_trace] pub doc: SharedDoc,
    pub cache: boa_gc::GcRefCell<HashMap<u32, JsObject>>,
    pub listeners: boa_gc::GcRefCell<HashMap<(u32, String), Vec<JsObject>>>,
    pub timers: boa_gc::GcRefCell<timer::TimerQueue>,
    #[unsafe_ignore_trace] pub author_sheets: Rc<Vec<starfish_css::Stylesheet>>,

    // --- E8-M2 ---
    /// The document base URL (owned copy) for resolving `fetch`/XHR relative URLs.
    #[unsafe_ignore_trace] pub base: Url,
    /// A raw pointer to the `&dyn ResourceLoader` borrowed by `run_scripts`. VALID
    /// only for the duration of `run_scripts` (set at install, cleared before
    /// return). Dereferenced ONLY by fetch/XHR native fns, which run exclusively
    /// inside `run_scripts` — so the pointee borrow is always still alive. Never
    /// escapes, never stored elsewhere, never used after `run_scripts`.
    #[unsafe_ignore_trace] pub loader: *const (dyn ResourceLoader + 'static),
}
```

> `dyn ResourceLoader` has no lifetime param in the trait (`net/src/loader.rs:86`); a
> `&dyn ResourceLoader` coerces to `*const (dyn ResourceLoader + 'static)` by erasing the borrow's
> lifetime into the raw pointer. We bound the *use* by hand (§1.4), not by the type system.

### 1.3 Setting + the safe accessor

`dom::install` / `globals::install` gain a `loader: &dyn ResourceLoader` parameter, threaded from
`run_scripts`. `install` records the pointer:

```rust
// dom/mod.rs install(): the &dyn coerces to a raw pointer.
ctx.realm().host_defined_mut().insert(DomState {
    /* ... existing fields ... */
    base: base.clone(),
    loader: loader as *const dyn ResourceLoader,
});
```

The only place that dereferences it — a single `unsafe` choke point, with the safety argument inline:

```rust
/// The loader + base for a fetch/XHR call. SAFETY: `state.loader` was set from the
/// `&dyn ResourceLoader` borrowed by the enclosing `run_scripts` call and is cleared
/// before that call returns (§1.4). Every fetch/XHR native fn runs *inside* that same
/// `run_scripts`, so the pointee borrow is still alive here. The reborrow does not
/// outlive this function. Returns None if the pointer was already cleared (defensive).
fn loader_and_base(ctx: &mut Context) -> Option<(&'static dyn ResourceLoader, Url)> {
    let host = ctx.realm().host_defined();
    let state = host.get::<DomState>()?;
    if state.loader.is_null() { return None; }
    // SAFETY: see doc comment above; valid for the lifetime of this fetch call.
    let loader: &'static dyn ResourceLoader = unsafe { &*state.loader };
    Some((loader, state.base.clone()))
}
```

The `'static` in the return is a deliberate lie scoped to the call: the caller resolves the URL +
calls `loader.fetch(&url)` immediately and never stashes the reference. (If a reviewer prefers, this
can be expressed as a closure `with_loader(ctx, |loader, base| { ... })` that contains the reference's
scope; the choke-point fn above is the minimal shape.)

### 1.4 Clearing on exit — the lifetime guarantee

`run_scripts` **must** null the pointer before returning, even on the (impossible-by-contract but
defensive) panic path. Place it right before `drop(ctx)`:

```rust
// lib.rs run_scripts, after run_to_quiescence, BEFORE drop(ctx):
if let Some(state) = ctx.realm().host_defined().get::<DomState>() {
    // erase the dangling-after-return pointer so it can never be dereferenced post-call.
    // (a tiny helper since the field is *const; use a Cell<*const> OR re-insert — see note)
}
drop(ctx);
```

> Implementation detail: `host_defined().get::<T>()` yields `&T` (shared); to null a `*const` field
> through it, make `loader` a `Cell<*const dyn ResourceLoader>` (a `Cell` of a raw pointer is `Trace`-
> ignorable plain data, interior-mutable, no `&mut` needed) — then `state.loader.set(ptr::null())`.
> `loader_and_base` reads `state.loader.get()`. This keeps the clear a cheap shared-borrow write.
> Because `drop(ctx)` then tears down the whole realm + `DomState`, the cleared pointer is doubly safe.

**Safety argument (the whole of it):** (1) the pointer is *written* only inside `run_scripts` while
`loader` is borrowed; (2) it is *read/deref'd* only by fetch/XHR native fns, which execute only inside
the `eval` + `run_to_quiescence` region of that same `run_scripts` call — i.e. strictly before the
clear, while the borrow is alive; (3) it is *cleared* before `run_scripts` returns, so no later code
(and no later `run_scripts` call) can observe a stale pointer; (4) it never escapes `DomState` and is
never copied into any longer-lived value. Therefore every deref is of a live borrow. This is the
minimal, sound mechanism — no thread-locals, no `Rc<dyn>` re-architecture of the loader, no eager
"fetch everything up front" (impossible: URLs aren't known until the script computes them).

> **Alternative considered + rejected — a thread-local guard.** A `thread_local!` holding
> `Cell<*const dyn ResourceLoader>` + base, set by an RAII guard at `run_scripts` entry and cleared on
> drop, gives the same lifetime story without touching `DomState`. It's equally sound. We pick the
> `DomState` field because every native fn already reaches `DomState` (one lookup, same as `doc`/
> `author_sheets`), keeping all host state in one place; the thread-local would be a second parallel
> channel. Either is acceptable for the implementer; the `DomState` field is the recommendation.

> **Alternative considered + rejected — `Rc<dyn ResourceLoader>` everywhere.** Would make the loader
> `'static`-storable with zero `unsafe`, but requires changing `render_document` + every
> `run_scripts`/`collect_*` signature across `paint`/`js`/tests from `&dyn` to `Rc<dyn>`. Too invasive
> for M2 (Surgical Changes); the scoped raw pointer touches only `DomState` + the install seam.

### 1.5 Borrow discipline

`loader_and_base` drops the `host_defined()` borrow (it clones `base`, copies the pointer) **before**
`loader.fetch(...)` runs — `fetch` does not re-enter JS, so no re-entrant `GcRefCell` hazard. The
arena `RefCell` is **not** borrowed across `loader.fetch`. Building the Response object + resolving the
promise happen after the fetch returns, each with their own short borrows. Mirrors the existing
"never hold a borrow across a JS call / never re-enter JS while borrowed" rule.

## 2. `fetch(url[, init])` → `Promise<Response>`

### 2.1 The native fn

A global callable registered in `globals::install`:

```rust
// crates/js/src/dom/fetch.rs (new)
pub(crate) fn fetch(_t: &JsValue, args: &[JsValue], ctx: &mut Context) -> JsResult<JsValue> {
    let input = arg_str(args, 0, ctx)?;                 // URL string (Request object DEFERRED, §6)
    // init (args[1]) is accepted and mostly ignored for M2 (§6): method/headers/body parsed but
    // only `method` is read for XHR-parity; fetch always GETs via the loader (no body send).

    let (loader, base) = match loader_and_base(ctx) {
        Some(lb) => lb,
        None => return Ok(JsPromise::reject(type_err("fetch unavailable", ctx), ctx).into()),
    };
    let url = match base.join(&input) {
        Ok(u) => u,
        Err(e) => return Ok(JsPromise::reject(type_err(&format!("{e}"), ctx), ctx).into()),
    };

    match loader.fetch(&url) {
        Ok(res) => {
            let response = build_response(&res, &url, /*ok*/ true, /*status*/ 200, ctx)?;
            Ok(JsPromise::resolve(response, ctx).into())
        }
        Err(e) => settle_fetch_error(e, &url, ctx),     // §2.4: reject (network) or resolve(!ok)
    }
}
```

### 2.2 Status from the loader

The loader returns **bytes** on success — it does not surface a numeric HTTP status on the happy path
(a non-2xx is already a `LoadError::Http{status}`, §0.1). So:
- **`Ok(Resource)`** → the load succeeded → Response with `ok=true`, `status=200`,
  `statusText="OK"`. (`file://`/`data:` have no real status; 200 is the pragmatic stand-in. A real
  2xx from `HttpLoader` also lands here as 200 — the loader doesn't expose the exact 2xx; acceptable
  for M2, note §6.)
- **`Err(LoadError::Http{status, url})`** → HTTP error status → per the fetch spec this is **NOT** a
  network error: **resolve** with `ok=false`, the real `status`, the body unavailable (the loader
  discards a non-2xx body) → `responseText`/`.text()` = `""` (§2.4).
- other `Err` → network error → **reject** (§2.4).

### 2.3 The Response object — a plain Boa object carrying the body

`Response` is a **plain `JsObject`** built with `ObjectInitializer` (like `location`/the Event object)
— **no native class needed**. It exposes data properties + three method closures that capture the body.
The **body bytes are captured by the method closures** (and stashed as an internal own-property for
robustness), so `.text()`/`.json()` can read them without a back-reference into Rust state:

```rust
fn build_response(res: &Resource, url: &Url, ok: bool, status: u16, ctx: &mut Context)
    -> JsResult<JsObject> {
    let body = String::from_utf8_lossy(&res.bytes).into_owned();   // UTF-8 lossy (text bodies)
    let content_type = res.content_type.clone().unwrap_or_default();
    let status_text = if ok { "OK" } else { "" }.to_string();
    let headers = build_headers(&content_type, ctx);               // §2.6: { get(name) }

    // .text() — capture `body`, return a RESOLVED promise of the string.
    let body_for_text = body.clone();
    let text_fn = NativeFunction::from_copy_closure_with_captures(
        |_t, _a, cap, ctx| Ok(JsPromise::resolve(JsString::from(cap.as_str()), ctx).into()),
        body_for_text,
    );
    // .json() — capture `body`, JSON.parse it (§2.5), resolve/reject accordingly.
    let body_for_json = body.clone();
    let json_fn = NativeFunction::from_copy_closure_with_captures(
        |_t, _a, cap, ctx| Ok(match json_parse(cap, ctx) {
            Ok(v)  => JsPromise::resolve(v, ctx),
            Err(e) => JsPromise::reject(e, ctx),
        }.into()),
        body_for_json,
    );

    let obj = ObjectInitializer::new(ctx)
        .property(js_string!("ok"),         ok,                         Attribute::READONLY)
        .property(js_string!("status"),     status as f64,              Attribute::READONLY)
        .property(js_string!("statusText"), JsString::from(status_text),Attribute::READONLY)
        .property(js_string!("url"),        JsString::from(url.as_str()),Attribute::READONLY)
        .property(js_string!("headers"),    headers,                    Attribute::READONLY)
        .function(text_fn, js_string!("text"), 0)
        .function(json_fn, js_string!("json"), 0)
        .build();
    Ok(obj)
}
```

- **Where the body lives:** captured by the `text`/`json` closure captures (a cloned `String`). This
  is the simplest "stash the body where `.text()`/`.json()` can read it" — no second class, no
  arena, no host-defined entry per Response. `.arrayBuffer()` is **deferred** (§6); if wanted later it
  captures `res.bytes.clone()` and builds a `JsArrayBuffer` the same way.
- **`.text()` returns a Promise** (resolved), matching the spec (body methods are async). A
  `.then(t => ...)` on it queues a job that drains in the quiescence loop (§4).
- **Body-already-used** (the spec's `bodyUsed`/locking) is **not** modeled — `.text()`/`.json()` can
  be called repeatedly (each reads the captured copy). Acceptable for M2 (note §6).

### 2.4 Reject vs resolve — the fetch spec rule

> Per the Fetch spec, `fetch()` rejects **only on a network error**; an HTTP error *status* (404,
> 500) **resolves** with `ok=false`. We map `LoadError` accordingly:

```rust
fn settle_fetch_error(e: LoadError, url: &Url, ctx: &mut Context) -> JsResult<JsValue> {
    match e {
        // HTTP error status → NOT a network error → resolve with ok=false + the status.
        LoadError::Http { status, .. } => {
            let empty = Resource { bytes: Vec::new(), content_type: None, final_url: None };
            let resp = build_response(&empty, url, false, status, ctx)?;
            Ok(JsPromise::resolve(resp, ctx).into())
        }
        // file:// 404 has no HTTP status → treat as a 404 resolve (ok=false, status 404),
        // matching "the resource wasn't there" without inventing a network error.
        LoadError::NotFound(_) => {
            let empty = Resource { bytes: Vec::new(), content_type: None, final_url: None };
            let resp = build_response(&empty, url, false, 404, ctx)?;
            Ok(JsPromise::resolve(resp, ctx).into())
        }
        // genuine network/transport failures + unsupported scheme + malformed URL → REJECT
        // (a TypeError, as the Fetch spec rejects with).
        LoadError::Network(_) | LoadError::Timeout(_) | LoadError::UnsupportedScheme(_)
        | LoadError::BadUrl(_) | LoadError::BadDataUrl(_) | LoadError::BadPath(_)
        | LoadError::Io(_) => {
            Ok(JsPromise::reject(type_err(&format!("fetch failed: {e}"), ctx), ctx).into())
        }
    }
}
```

- **Decision on `NotFound`:** a `file://` miss is the closest analogue to an HTTP 404 → **resolve**
  with `ok=false`/`status=404` (so a test can assert `r.ok===false && r.status===404` against a
  missing `file://`). A genuine transport failure (`Network`/`Timeout`) → **reject**, matching the
  spec's network-error semantics. `UnsupportedScheme` (e.g. `fetch("ftp://...")`) → reject (a network
  error — no loader can fetch it). This split is the test plan's two fetch-failure cases (§7).
- `type_err(msg, ctx) -> JsError` builds `JsError::from_opaque(TypeError)` (the Fetch spec rejects with
  a `TypeError`); a one-line helper using `JsNativeError::typ().with_message(msg)`.

### 2.5 `.json()` — JSON.parse via the realm

Boa's `Json::parse` is `pub(crate)` (§0.3). Invoke the engine's `JSON.parse`:

```rust
fn json_parse(text: &str, ctx: &mut Context) -> JsResult<JsValue> {
    let json = ctx.global_object().get(js_string!("JSON"), ctx)?;         // the JSON intrinsic
    let parse = json.as_object().and_then(|o| o.get(js_string!("parse"), ctx).ok())
        .ok_or_else(|| JsError::from_native(JsNativeError::typ().with_message("JSON.parse missing")))?;
    let parse = parse.as_callable().ok_or_else(|| /* typeerror */)?;
    parse.call(&JsValue::undefined(), &[JsString::from(text).into()], ctx)  // throws on bad JSON
}
```

A malformed body → `parse` throws → `Err(JsError)` → the `.json()` promise **rejects** (so
`fetch(...).then(r=>r.json()).catch(...)` works). (`JSON` is always present on the Boa global; the
defensive `Option`s never trigger in practice.)

### 2.6 `.headers.get(name)` — minimal Headers

`headers` is a plain object with a single `get(name)` method closure capturing the `content_type`
string. Only `content-type` is known (the loader surfaces just that). `get("content-type")` (case-
insensitive) → the content type; any other name → `null`. No `set`/`has`/`append`/iteration (§6).

```rust
fn build_headers(content_type: &str, ctx: &mut Context) -> JsObject {
    let ct = content_type.to_string();
    let get = NativeFunction::from_copy_closure_with_captures(
        |_t, a, cap, ctx| {
            let name = a.first().and_then(|v| v.as_string()).map(|s| s.to_std_string_escaped())
                        .unwrap_or_default().to_ascii_lowercase();
            Ok(if name == "content-type" && !cap.is_empty() {
                JsString::from(cap.as_str()).into()
            } else { JsValue::null() })
        }, ct);
    ObjectInitializer::new(ctx).function(get, js_string!("get"), 1).build()
}
```

## 3. `XMLHttpRequest` (synchronous)

A **native class** (it needs mutable per-instance state across `open`→`send`→reads). Registered via
`ctx.register_global_class::<XhrData>()` (precedent: `NodeHandle`). The native data holds the request +
response fields; methods downcast `this` and mutate them.

```rust
// crates/js/src/dom/xhr.rs (new)
#[derive(Trace, Finalize, JsData, Default)]
pub(crate) struct XhrData {
    #[unsafe_ignore_trace] pub method: String,          // set by open()
    #[unsafe_ignore_trace] pub url: String,             // raw (resolved against base at send())
    #[unsafe_ignore_trace] pub ready_state: u16,        // 0=unsent .. 4=done
    #[unsafe_ignore_trace] pub status: u16,             // 0 until send(); HTTP-ish after
    #[unsafe_ignore_trace] pub status_text: String,
    #[unsafe_ignore_trace] pub response_text: String,
    #[unsafe_ignore_trace] pub content_type: Option<String>,  // for getResponseHeader
}
// XhrData holds no GC pointers → all fields unsafe_ignore_trace; the class is JsData.
```

Boa native data is accessed via `this.as_object().downcast_ref::<XhrData>()` / `downcast_mut`. The
class:

- **`new XMLHttpRequest()`** — `data_constructor` returns `XhrData::default()` (`ready_state=0`).
- **`open(method, url[, async])`** — store `method` (uppercased) + `url`; `async` is **accepted and
  ignored** (always synchronous — note §6). Set `ready_state = 1` (OPENED). No fetch yet.
- **`send([body])`** — resolve `url` against `base`, fetch **synchronously** via the loader (same
  `loader_and_base` mechanism, §1), populate fields, set `ready_state = 4` (DONE). `body` is
  **ignored** for M2 (no request-body upload — note §6).

```rust
fn xhr_send(this: &JsValue, _args: &[JsValue], ctx: &mut Context) -> JsResult<JsValue> {
    let (method, raw_url) = {                            // read out, drop the borrow
        let d = downcast::<XhrData>(this)?;             // &XhrData
        (d.method.clone(), d.url.clone())
    };
    let (loader, base) = match loader_and_base(ctx) {
        Some(lb) => lb, None => return finish_xhr(this, 0, "", "", None, ctx),  // lenient: status 0
    };
    let url = match base.join(&raw_url) {
        Ok(u) => u, Err(_) => return finish_xhr(this, 0, "", "", None, ctx),
    };
    let _ = method;                                      // method recorded; loader always GETs (M2)
    match loader.fetch(&url) {
        Ok(res) => {
            let text = String::from_utf8_lossy(&res.bytes).into_owned();
            finish_xhr(this, 200, "OK", &text, res.content_type.clone(), ctx)
        }
        // A failed load → status 0 (or the HTTP status), readyState 4, responseText "". LENIENT:
        // no throw (real XHR throws a NetworkError on some sync failures; M2 stays lenient — §6).
        Err(LoadError::Http { status, .. }) => finish_xhr(this, status, "", "", None, ctx),
        Err(LoadError::NotFound(_))         => finish_xhr(this, 404, "Not Found", "", None, ctx),
        Err(_)                               => finish_xhr(this, 0, "", "", None, ctx),
    }
}
```

`finish_xhr` writes the response fields into the instance's `XhrData` (via `downcast_mut`), sets
`ready_state = 4`, and returns `undefined`.

- **`.readyState`** — accessor reading `ready_state` (4 after `send`).
- **`.status`** / **`.statusText`** — accessors.
- **`.responseText`** — accessor reading `response_text` (UTF-8 lossy of the body; `""` on failure).
- **`.getResponseHeader(name)`** — `content-type` (case-insensitive) → the stored `content_type`, else
  `null` (mirrors `Headers.get`, §2.6). No other headers (the loader surfaces only content-type).
- **No events** (`onreadystatechange`/`onload`) and **no `responseXML`/`response`/`responseType`** —
  synchronous-only, no event model (note §6).

> XHR being **synchronous** means by the time `send()` returns, all fields are populated — a script
> reads `xhr.responseText` on the next line. No promise, no job, no quiescence interaction.

## 4. Promise job draining (ordering)

**No quiescence-loop change.** The existing loop (`lib.rs`) already drains Boa jobs:
`run_microtasks` (= `ctx.run_jobs()`) is called after the initial scripts, after each lifecycle event,
and after each timer (`lib.rs:202,212,230,234`). Since `fetch` resolves its Promise **synchronously**
(the load already happened), a `.then(...)` registered on it is enqueued as a Boa **promise job** the
moment the script attaches it; `ctx.run_jobs()` drains it.

Ordering for `fetch(u).then(r=>r.text()).then(t=>{ document.body.innerHTML = t })`:

1. script calls `fetch(u)` → loader.fetch runs **synchronously** → returns an **already-resolved**
   Promise P0 (Response).
2. `.then(r=>r.text())` on the resolved P0 enqueues job J1 → returns Promise P1.
3. `.then(t=>{...innerHTML...})` on P1 enqueues (later) → returns P2. (The chain is set up
   synchronously; the reaction jobs run on drain.)
4. the script returns; the quiescence loop's first `run_microtasks` runs J1 → `r.text()` returns a
   resolved Promise of the string → its reaction enqueues J2.
5. next `run_jobs()` iteration runs J2 → the `innerHTML = t` mutation lands in the arena.
6. `run_jobs()` drains to empty (the chain is finite) → quiescence continues → final style/layout/
   paint sees the mutated DOM.

`ctx.run_jobs()` **drains to empty in one call** (it loops internally over the job queue), so a
multi-`.then` chain whose every link is synchronously-resolved fully settles within the **first**
`run_microtasks` after scripts — well before the final render. A `.then` that itself calls `fetch`
again (sync) + chains more `.then`s adds more jobs to the **same** queue, still drained by the same
`run_jobs()` loop. **The whole fetch chain drains before the final render** (the ordering contract).

> Because all loads are synchronous, there is **no pending-I/O** that could outlive the job queue — the
> renderer never "waits" on a network reply; the reply is already in hand when the Promise is created.
> This is the key simplification that makes a one-shot renderer's `fetch` work without an event loop.

## 6. Edge cases & non-goals (deliberate)

**Delivered:** `fetch(url[, init])` → resolved `Promise<Response>` (`ok`/`status`/`statusText`/`url`/
`headers.get` + `.text()`/`.json()` returning promises); spec-faithful reject-on-network-error vs
resolve-on-HTTP-status; a minimal **synchronous** `XMLHttpRequest`
(`open`/`send`/`responseText`/`status`/`statusText`/`readyState=4`/`getResponseHeader`); `.then`
chains draining through the existing `ctx.run_jobs()` quiescence loop.

**Non-goals / documented limits:**
- **`fetch` init** — `args[1]` (`{method, headers, body, mode, credentials, ...}`) is **accepted and
  mostly ignored**. `fetch` always issues a GET via the loader; no request `body` upload, no custom
  request headers, no `mode`/CORS. (`method` may be recorded for symmetry but doesn't change the
  load.) Note.
- **CORS** — **no policy.** The loader fetches whatever URL resolves (the ROADMAP non-goal: "CORS
  enforcement from fetch … the loader fetches; no policy"). Cross-origin `fetch` "succeeds" with the
  body. Note.
- **Exact success status** — a successful load reports `status=200` (the loader doesn't surface the
  precise 2xx for `http`, and `file://`/`data:` have none). Note.
- **`Request` object** — `fetch(new Request(...))` unsupported; URL must be a string (coerced via
  `arg_str`). Deferred.
- **`Response.body` / streaming / `ReadableStream`** — out. **`.arrayBuffer()` / `.blob()` /
  `.formData()`** — deferred (`.arrayBuffer()` is a thin future add: capture `res.bytes`, build a
  `JsArrayBuffer`). **`bodyUsed` locking** — not modeled (`.text()`/`.json()` re-readable).
- **`Headers` full surface** — only `get(name)`, and only `content-type` is ever populated. No
  `set`/`has`/`delete`/`append`/iteration/`entries`. Note.
- **`AbortController` / `AbortSignal` / `signal`** — deferred (no async to abort).
- **Redirects** — handled **inside** the loader (`HttpLoader`); `response.url` reflects the requested
  resolved URL (the loader's `final_url` is available but M2 reports the requested URL for simplicity;
  could use `res.final_url` later). Note.
- **Async XHR + XHR events** — `open(method, url, true)` is treated as **synchronous** (the `async`
  flag is ignored). No `onreadystatechange`/`onload`/`onerror`/`onprogress`, no intermediate
  `readyState` transitions (jumps 0/1→4), no `responseType`/`response`/`responseXML`,
  no `setRequestHeader` effect, no `withCredentials`/`timeout`/`abort()`. Note.
- **XHR failure leniency** — a failed sync load sets `status` (0 / 404 / the HTTP status),
  `readyState=4`, `responseText=""`, and does **NOT throw** (real XHR throws `NetworkError` on some
  sync failures; M2 stays lenient to keep scripts running). Note.
- **Real network non-determinism** — `http(s)` fetch works via `HttpLoader`, but tests use
  `data:`/`file://` (via `LocalLoader`/`DataLoader`) for determinism — **no real network in tests**
  (§7).
- **The `unsafe` loader pointer** — sound by the §1.4 argument (set/used/cleared strictly within one
  `run_scripts`, never escapes). The single deref site is documented.

All fetch/XHR native-fn errors are caught by `run_scripts` (a thrown native error lands in
`ScriptOutcome.errors`; a rejected fetch promise with no `.catch` surfaces as an unhandled-rejection
job — drained, non-fatal). The page always renders.

## 7. Test plan (concrete)

`js` unit tests drive `run_scripts` directly (the `run`/`log_of`/`lines_of`/`find_id` helpers in
`lib.rs` tests; `run` passes `&LocalLoader` + `Rc::new(Vec::new())`). All network tests use **`data:`
URLs** (via `DataLoader`, deterministic, no real network) or a **`LocalLoader` temp dir** for
`file://` 404. The test `run` helper must route to a loader that handles `data:` — add a small
`run_with_loader(html, &dyn ResourceLoader)` helper (or have `run` use a `RouterLoader`/a
`Local+Data` composite) so `fetch("data:...")` resolves. (`DataLoader` alone suffices for the data:
tests; the 404 test uses `LocalLoader`.)

**fetch → text:**
1. `fetch("data:text/plain,hello").then(r=>r.text()).then(t=>{ globalThis.out = t });` then a probe
   (a second script or `console.log(globalThis.out)` after quiescence) → `out === "hello"`. Proves
   the resolved-promise + `.then` chain drains through `run_jobs` before quiescence ends.
2. `r.ok === true`, `r.status === 200` for a successful `data:` load.

**fetch → json:**
3. `fetch("data:application/json,%7B%22a%22%3A1%7D").then(r=>r.json()).then(j=>{ globalThis.a =
   j.a });` → `a === 1` (the body `{"a":1}` percent-encoded; `.json()` calls JSON.parse).
4. malformed JSON body → `.json()` rejects → `.catch(e=>{ globalThis.err = true })` sets `err`.

**fetch failure modes:**
5. **404 resolve (not reject):** a missing `file://` (via `LocalLoader` temp dir, a path that doesn't
   exist) → `fetch(u).then(r=>{ globalThis.ok=r.ok; globalThis.st=r.status })` → `ok===false`,
   `st===404`. (Proves HTTP-error-status resolves, per spec.)
6. **network-error reject:** `fetch("ftp://x/y")` (unsupported scheme → `LoadError::UnsupportedScheme`)
   → the promise **rejects** → `.catch(()=>{ globalThis.caught = true })` sets `caught`. (Proves fetch
   rejects on a network error.)

**fetch → DOM mutation (integration, through `run_scripts`):**
7. `fetch("data:text/html,%3Cb%3Ehi%3C/b%3E").then(r=>r.text()).then(t=>{
   document.body.innerHTML = t });` → after `run_scripts`, the arena's `<body>` has a `<b>` child with
   text `hi` (assert via `doc`). Proves the fetched text mutates the DOM before the final render.

**fetch → DOM mutation (VISUAL, through `render_document`):**
8. a page whose script does
   `fetch("data:text/html,%3Cspan%20style='color:%23ff0000'%3Ehi%3C/span%3E").then(r=>r.text())
   .then(t=>{ document.getElementById('box').innerHTML = t });` → the rendered text paints **red**
   (the fetch chain drained, the mutation landed, the post-script re-style/render reflects it). Uses a
   `data:`-capable loader in the render path (the binary's `RouterLoader` handles `data:`).

**headers:**
9. `fetch("data:text/css,p%7B%7D").then(r=>{ globalThis.ct = r.headers.get("content-type") })` →
   `ct === "text/css"`; `r.headers.get("x-bogus") === null`.

**XMLHttpRequest (sync):**
10. `var x=new XMLHttpRequest(); x.open("GET","data:text/plain,world"); x.send();
    console.log(x.responseText, x.status, x.readyState)` → `"world 200 4"`.
11. `x.getResponseHeader("content-type")` for a `data:text/plain,...` → `"text/plain"`; an unknown
    header → `null`.
12. XHR of a missing `file://` (LocalLoader) → `x.status === 404` (or 0), `x.readyState === 4`,
    `x.responseText === ""`, **no throw** (the next script line runs).

**Regression:**
13. a script-free page renders byte-identically to pre-E8-M2 (the new `DomState` fields default-empty,
    the loader pointer set/cleared, fetch/XHR registered but unused — no pixel change). Confirms the
    install seam + pointer clear don't perturb the no-fetch path.

`cargo test -p starfish-js` (fetch/XHR unit tests) + `-p starfish-paint` (visual §8) + full
`cargo test` green; smoke: render a page whose script `fetch`es a `data:` HTML fragment into
`innerHTML` and confirm the PNG.
